# MediaFlow「缺集待补」模块需求与交互方案 v2.5.53

修订日期：2026-11-20。本轮基于实际源码 v2.5.52 修订至 v2.5.53，适用于所有初检目录。需求规则、已实现改动与验证边界分别说明；文档版本不表示所有设计目标已验收。

全局导航顺序为 **待复核清理 → 异常剧集 → 缺集待补 → 齐全可归档 → 连载留源**。有副本、规范化归并或归档已齐清源动作时先处理清理，再处理具体异常，之后按播期和内容覆盖分流。播期判断在下载资格之前，已确认连载的季继续留源。

各模块共用作品身份、期／集／段、内容类别、剪辑版本和技术副本的识别结果。旧状态仅供兼容，独立决定数、作品季数、目录组数和文件数分别统计。一次处理后自动核验、刷新及分流，无需另点重新初检。

设计依据为[五模块处理流程重构与智能清理方案 v2.5.44](MediaFlow五模块处理流程重构与智能清理方案-v2.5.44.md)，其中已包含按初检目录名称与完整路径确定动漫默认规则的修订。

关联方案：[待复核清理](MediaFlow待复核清理模块需求与交互方案-v2.5.53.md)、[异常剧集](MediaFlow异常剧集模块需求与交互方案-v2.5.53.md)、[缺集待补](MediaFlow缺集待补模块需求与交互方案-v2.5.53.md)、[齐全可归档](MediaFlow齐全可归档模块需求与交互方案-v2.5.53.md)、[连载留源](MediaFlow连载留源模块需求与交互方案-v2.5.53.md)。
## v2.5.53 当前任务核查与交互修订（2026-11-20）

本节优先于下文历史说明。核查任务 `82bd486a4b6145d4ba87dfaf0e1de2d8`，初检目录 `/115/Library_incs/nas/电视剧/综艺/`。全量核查 485 条物理季记录、443 个活动作品季，强读 34 个目录组，并回放重点案例文件清单。详见[本轮核查报告](MediaFlow当前初检核查与识别展示优化报告-v2.5.53.md)。核查与计划生成不等于已执行媒体操作。

全模块详情首先显示当前结论、资料收录数、播期、明确标注的源端和归档目标；目标路径不代表已归档。完整依据、文件和历史折叠。豆瓣查询先汇总原因，逐渠道诊断再展开，不直接展示 `ValueError` 等异常类名。来源名称使用中文，记录候选标题与 ID，不以查询失败证明网站无收录。

已核实作品、本季播毕、资料收录的正片完整覆盖且没有其他冲突时，少量相邻扩展集号独立保留，不改写资料总数，不假定扩展文件就是特辑，也不仅因它们存在而挂异常。缺口、播期未知、大幅越界、明确身份冲突仍分别核实。真实冗余清理仍以内容等价为前提。

本次核查的 234 个待补作品季均有已播毕依据；未发现未播季被归入该模块。保留逐集缺口及在途台账，不以会员版、特别节目或同集多文件数量推导缺口。当前用户要求的单季主动放弃删源入口继续有效，须预览及确认，不混入自动推荐清理。

## v2.5.52 本次修订（2026-11-20）

本节覆盖旧版冲突规则，以下 v2.5.51 说明作为历史实现记录保留。展示顺序改为 **待复核清理 → 异常剧集 → 缺集待补 → 齐全可归档 → 连载留源**；实际判断继续先核实播期。

同一 TMDB ID、分类路径一致且源端规范目标唯一时，推荐批次自动处理归并或目标记录对齐。仅对真实冲突、读取失败和无法唯一确定的目标列出具体阻塞，不把所有“确认归档目标”都交给人工。确认目标不等于证明归档已有完整内容。

豆瓣查询由已核验绑定、搜索建议、MoviePilot 搜索、豆瓣条目搜索页、通用搜索页以及多路详情读取组成。各路记录关键词、候选数与错误类型；动态壳页、验证页和接口空结果都不能表述为网站没有条目。成功匹配后独立保存 TMDB＋季号→豆瓣 ID，下轮优先读详情并重新核实身份；空结果不覆盖成功绑定。不用总集数证明播毕，不根据候选集数改写当前作品身份。无常驻后台重查任务。

用户本轮明确调整缺集模块规则：允许单季“主动放弃补缺并删除源端”，经独立预览与明确确认执行；该动作不属于归档安全清源，也不进入批量推荐处理。旧删源接口仍保留原门禁，整剧级联删除不开放。

### 单季主动放弃与界面精简

条目不再显示“非动漫（自动）”“动漫（手动）”等分类标签。后台分类与站点排序规则继续生效，在详情中查看依据及调整设置。

默认待补条目追加“删除源端（本季）”。弹窗显示确切季目录、视频/字幕/其他文件数、容量和可展开文件清单，说明独有内容也会被删除且不保证已有归档副本；用户点击“放弃本次补缺并删除此源季”才授权本次删除。

新接口为 `/api/archive/discard-source-season/preview` 与 `/api/archive/discard-source-season`。执行必须携带本季有效预览标识和 `confirm_abandon=true`；重新读取目录并比较目录 ID、每层完整清单、文件大小及修改时间。默认预览有效 30 分钟；变更、过期、任务进行中、共享/平铺目录、在途台账或活跃下载均明确拦截。MP 已配置但下载状态读取失败时也不能视为没有下载。

始终只删除独立季目录，不因数据库没有其他季而升级为整剧删除。删除后强读父目录核验，更新主动放弃原因、季状态和本季台账；不计入补缺或归档成功，不自动取消外部下载。已推送待入库页不显示删源按钮。批量删除和连载删源不在本次开放范围。

### 本轮验证边界

新增回归见 [test_v2552_recommended.py](tests/test_v2552_recommended.py)，使用内存数据库、模拟云盘和 HTTP；前端检查包含无进展按钮、分类标签和页面顺序。运行服务未重启，未操作真实媒体；豆瓣真实联通及现有条目的重新取证尚未在运行环境验收，不宣称豆瓣条目已取得或剩余项已经清零。

## v2.5.51 清理衔接与台账汇总修订（2026-11-20）

清理结束后以已保全的内容覆盖重新分流，保留按期映射的识别结果。源端清理、归档、缺集三者不能用相同的“已完成”标记替代。仍有清理动作时在清理批次结果中列明，不能隐去后直接推送补缺。

| 事实 | 准入要求 |
| --- | --- |
| 已确认分期编号超出总期数 | 先按期段映射计算覆盖，不把 Part4 或分段编码当作新的正片缺号 |
| 豆瓣仅提供总期数 | 只补全总数，仍须独立证明本季已播毕 |
| 目录读取失败 | 明确失败，不认定零媒体或全季缺失 |
| 仅有 NFO、海报等附件 | 完整读取并核实身份、播毕、应有内容及其他端后，才准入全季待补；没有删除附件的隐含授权 |
| 衍生内容或独有配音 | 不作为普通正片的可替代副本，也不因清理更新而丢失其保护语义 |

汇总计算把分集台账、季运行记录和历史补缺回执批量预读，再在内存按路径与身份分配。分集台账继续跨任务核对，不能为了减少查询而丢失防重复提交能力；季运行记录仍以当前任务、路径和身份匹配。空数组字符串 `[]` 不再让所有季无条件触发补缺台账查询。

现有动漫／非动漫站点选择与排序、整季包／散集策略、最低做种门槛、逐集台账和在途防重继续使用。导航顺序不改变播期优先规则；本模块仅通过独立预览确认提供单季主动放弃删源。

新增验收：30 季汇总的读取查询次数保持固定上限，不随季数逐一查询三类台账；批量预读与单季读取得到一致的缺口、在途及失败状态；同一文件的跨任务在途记录继续阻止重复提交。

## 一、用户打开这个模块，应该看到什么

默认清单只展示**已经确认有缺口，而且仍有至少一个缺号可以搜索或重试**的作品季。每季一张卡。用户可以直接按系统推荐推送，无需自己逐个查 Emby、核对上下段或在站点之间比较种子。

点击「完成并刷新」后，四种结果应一眼能分清：

| 本次结果 | 默认待补清单如何变化 |
|---|---|
| 全部缺号已由 MoviePilot（MP）明确受理 | 整季移出默认清单，进入同模块「等待入库」。收到文件后再按实物分流 |
| 仅部分受理 | 保留一张卡，仅对剩余缺号提供推送；已受理的集号在同卡标明 |
| 没有合格资源 | 原卡保留，显示缺号、搜索时间和具体原因，例如“E09 找到 3 个候选，最高 1 人做种，本次要求至少 2 人” |
| 请求已发出但未收到可靠回执 | 对受影响的缺号暂停重推，显示“提交结果待确认”。系统先核对队列与历史；不能把超时算作成功或普通失败 |

## 二、本轮统一的职责与算法边界

本模块只处理已核实的缺口、选源推送及下载回执。原「真缺集待补」统一更名为「缺集待补」，名称调整不放宽真实缺口与本季播毕的准入条件。副本清理、同 ID 目录归并和归档已齐清源全部交给待复核清理，处理后自动带着有效台账返回相应模块。

保留逐集台账、待补／等待入库双视图、最低做种门槛、同站同档容量比较及整季包回退。缺号大于 3 优先合格整季包，不超过 3 优先散集，详细顺序见第六节。两套补缺站点规则首先读取 MoviePilot 站点管理，由用户分别勾选及排序；每季分类先从初检目录及所属分类路径建立默认值。

旧版取消的常规清源及整剧删除仍禁止；本轮仅新增明确放弃补缺的单季预览确认入口，不再以数据库没有其他季为依据级联删除剧根。已有下载任务不因更名或跨模块流转被清空、重复提交或自动取消。

## 三、准入、排除和分流

**准入同时满足**：作品与季的身份可信；已确认本季播毕；至少一个应有正片集、期或段有可验证的季级依据；已核查与这些缺号有关的源端、归档及可用的可信 Emby 分集资料；这些缺号在所有可成立的编号解释下确实缺失。写明查询范围和证据时间。旧记录中的“已完结”、文件总数或者一个空数组本身不构成完整证据。

| 情形 | 应放在哪里 |
|---|---|
| 源端 6/10，归档补足其中 2 集，另 2 集确认无覆盖 | 缺集待补，只列最后 2 集；展示两端各自覆盖及去重后的覆盖 |
| 已播毕，全季均无正片 | 身份、应有集合以及相关位置均核实后，可按全季待补；接口超时或看不到子目录时不能把全季判成零 |
| 同号多个版本，同时有真缺号 | 先进入待复核清理辨别内容等价及清理真实副本，完成后自动进入缺集待补；不同内容版本分别保留，已确认的保留结论不重复生成清理待办 |
| 分段歧义仅涉及少数期 | 已确认的缺号仍可补；未定期在同卡详情说明。唯一缺口也无法确认时先自动补取期段映射，仍不能确定才进入异常剧集，写明具体缺失字段与最小所需信息，不安排后台跟踪 |
| 同 ID 多目录、错季或归属冲突可能改变缺口 | 同 ID 同作品目录先在待复核清理按规范名称归并；真正错季、身份冲突进入异常剧集。处理后自动重算，待补列表不复制目录组 |
| 确认连载或已公布集数尚未播出 | 确认连载走连载留源；播出状态或节目表不足时自动取证，仅剩影响分流的具体问题进入异常剧集。预告、花絮、S00 和未播正片分别识别 |
| 已有全部正片，或缺号全部入库 | 移出补缺模块。符合条件的整季进入齐全可归档或待复核清理；归档已齐且有源端冗余时进入待复核清理的清源核验 |

**覆盖口径。** 先建立同一季的正片内容单元。普通电视剧以正式季集号为单位，综艺允许“第 8 期下”等细分单元。源端、归档以及可信 Emby 明细按同一身份映射后取并集，重复集只计一次。Emby 的整季数量、空响应或不同版本的同名剧均不能直接抵扣缺号。已整理历史只提供核验线索。无法读取但可能含有目标集的位置，需保留不确定性。

## 六、MoviePilot 怎样选资源、怎样解释结果

1. **取最新目标。** 本轮目标＝用户确认的缺号 ∩ 最新确认缺号，再扣除有效在途和回执待查内容。匹配同一作品、同季、同一编号口径及用户已配置的质量要求，再剔除不达实际做种门槛的候选。相同种子跨站去重。
2. **站点范围与顺序可核对。** 新方案以本季适用的动漫／非动漫规则为唯一允许站点范围，按 6.1–6.8 节执行。替代原「MP 默认站点＋天空、观众」自动扩展逻辑；旧规则仅用于首次迁移草稿。按 ID 搜索、标题／别名回退、整季补搜采用相同已选站点范围，未勾选站点不得参与候选或下载。分别记录请求范围、返回来源和错误，不能由“没返回候选”推断某站搜索成功。
3. **同站同档优先省容量。** 沿用默认门槛 2 人做种、同档容差 max(1，最高做种数的 10% 向下取整)，以本次设置为准。在相同策略阶段、相同站点等级与可覆盖目标内比较做种档位和容量，不让低优先站仅因更小或更多做种越过合格的高优先站。相同覆盖和匹配条件下，同站 10 人做种的 2 GiB 与 9 人做种的 600 MiB 同档，选 600 MiB。多集比较方案实际下载总量，包按完整体积计一次，组合以其中最低做种衡量可用性。未知大小排在同档已知大小之后，详情列出入选与次选差异。
4. **缺集规模与整季包策略。**
   - **缺集数量 > 3 集（`len(missing) > 3`）**：**优先选择整季包（Season Pack）下载**。若首轮候选无整季包，系统主动触发一次别名/原名+季号整季补搜；只要检索到合格整季包且与在途队列无重叠冲突，直接选用整季包；若整季包不可用或存在在途队列重叠，平滑回退至省容量散集拼包；
   - **缺集数量 $\le 3$ 集**：**优先采用省容量散集拼包**，避免为少量缺号拉取大容量整包；散集补不全时才回退至合格整季包。
   - 整季包必须严格核实同作品、唯一目标季、实际包含目标缺号、满足做种门槛，排除假全集、跨季包和与已提交任务重叠的整包。
5. **准确解释没有下载的原因。** 0 命中、做种不足、作品／季不匹配、编号映射不明、整季包覆盖无法验证、站点故障、队列占用与 MP 明确拒绝分别编码。能定位到具体缺号的理由逐号保存；站点范围不完整时只写“已响应范围内无匹配资源”。一季 0 个合格资源属于“未找到可推资源”，不计为程序故障。

### 6.1 站点来源与两套独立配置（新增，待实现）

站点目录首先来自用户所连接 MoviePilot 的「站点管理」。MediaFlow 只读取目录和可用状态，在自身保存补缺专用规则；勾选、排序不修改 MP 全局站点启用状态、默认搜索顺序、订阅规则或其他模块配置，也不创建 MP 订阅。

| 配置 | 适用对象 | 独立保存内容 |
| --- | --- | --- |
| 动漫补缺站点 | 已确认属于动画类的剧集，包括国漫、日漫及其他地区动画剧集 | 勾选站点 ID、有序优先级、规则版本、更新时间 |
| 非动漫补缺站点 | 已确认非动画类的电视剧、综艺等当前可准入的作品季 | 独立勾选集合与顺序，不随动漫配置联动 |

两套规则可选不同站点，也可选相同站点但采用不同顺序。动画电影不因分类进入本模块。动漫指作品类型，不按语言、地区或片名偶然含有某个词判断；分类路径及文件明确类型标记的使用见 6.3。

站点关联键采用「MP 实例标识＋站点 ID」；名称只用于显示。改名不丢失勾选和顺序，同名不同 ID 独立显示；删除后重建的新 ID 不按名称自动继承。切换 MP 实例后重新读取并配置，不能复用另一实例的数字 ID。

### 6.2 设置面板与首次配置

从「缺集待补」工具栏进入「补缺站点设置」。面板顶部显示 MP 实例名称、站点目录读取时间与「刷新站点」；下方为「动漫」「非动漫」两个页签。每页按优先级展示已选站点，再列出未选站点，支持名称筛选。

| 控件／信息 | 行为 |
| --- | --- |
| 站点行 | 勾选框、名称、ID、无敏感参数的域名、MP 可用状态、本规则优先序号 |
| 勾选／取消 | 勾选后追加到当前规则末尾；取消后立即从该规则移除，其他规则不受影响 |
| 拖动排序／上移下移 | 只调整已选站点，序号从 1 连续生成；明确提示「数字越小越优先」 |
| 复制另一套规则 | 用户主动点击后复制为当前页草稿，可继续调整，保存后两套仍独立 |
| 保存规则 | 原子保存两页草稿并生成新版本，不搜索、不下载；有未保存修改时关闭面板提示保存或放弃 |
| 刷新站点 | 只刷新站点目录，不重置草稿、勾选或顺序；新增站点默认不勾选，失效站点保留原位及原因 |

首次打开先读取 MP 站点清单，可把旧版解析得到的默认站点及「天空、观众」填入两套**待确认草稿**。旧配置无业务优先顺序时，展示确定的初始排列并标注「请确认顺序」，不把 ID 大小说成 MP 推荐优先级。用户保存后才启用新规则。首次读取失败则显示错误，可查看旧快照但不能伪造空站点目录或自动采用全部站点。

允许保存某一套空规则，含义为「暂停该类别补缺」。推送时该类别明确显示「未启用站点」并跳过；不得把空数组、全部失效或未初始化解释为全部站点。未初始化与用户主动停用是不同状态。

### 6.3 每季如何选择动漫或非动漫规则

保留动漫和非动漫两套启用站点及优先级。类型判断由系统完成，主卡、单季推送、批量推送均取消强制“类型待确认”按钮和选择框。

**先根据初检目录名称及完整路径建立默认规则。** 这一步在读取任务时即可完成，元数据类型字段缺失或接口暂时不可用时，继续采用已有目录依据。初检选择到剧集目录或 `Season N` 时，向上找到最近的有效分类目录；初检选择到混合总目录时，按每部作品所属子目录分别判定。

| 目录／路径中的分类信息 | 自动采用的默认规则 |
| --- | --- |
| 动漫、动画、国漫、日漫、国产动漫、日本动漫、欧美动漫、Anime、Animation 等明确分类目录 | 动漫规则 |
| 综艺、真人秀、脱口秀、真人剧集等明确分类目录 | 非动漫规则 |
| `动漫/日本/作品名/Season 1` | 继承上级“动漫”，采用动漫规则 |
| `电视剧/综艺/作品名/Season 4` | 采用最近明确分类“综艺”的非动漫规则 |
| 电视剧、媒体库、下载、待整理等宽泛或混合目录 | 继续检查作品所在子目录、剧集目录名称、文件名中的明确类型标记及有效作品资料 |

目录匹配采用分类名称及明确词组，兼容简繁体和英文大小写。按路径层级从具体分类向上查找，不能因为祖先路径有“电视剧”就覆盖“动漫”子目录，也不能把片名偶然含某个字当成分类标签。文件名的明确类型标记作为补充线索，标题语言、国家和发行组本身不决定动漫类别。

在目录默认值上应用作品级证据，优先级为用户既有有效设置 → 已核实同作品的元数据／可信 NFO 类型 → 最近明确分类目录 → 剧集目录名、文件名及已取得标签的综合判断。若“综艺”目录中误放一部有明确动画类型资料的作品，该作品自动使用动漫规则，其他作品继续采用目录默认值。详情写明“根据初检目录‘动漫’采用动漫规则”或具体作品依据，保留自愿修改入口。

删除无依据时统一归入非动漫的兜底。目录及文件信息均无类型线索时，系统定向补取该作品资料并复用有效历史分类；取证请求实际失败时记录具体读取失败及恢复步骤，不生成强制“类型待确认”选择项。两套规则仍各自遵守已勾选站点范围。

同一批次逐作品固定类型与规则快照，后续识别更准确时应用于新批次。已受理下载继续对账。保存的人工修改按作品复用，不要求下一次初检重复选择。

### 6.4 搜索范围与优先级的准确含义

**优先级由 MediaFlow 选种器执行，不依赖 MP 返回顺序或请求中站点 ID 的顺序。** 在本轮所有允许站点中搜索并汇总结果，可受控并发；同一策略阶段按用户顺序选资源。不是最快响应的站点先下载，也不是只查第一个站点。

有效站点范围＝该类别勾选集合 ∩ 当前 MP 实例中已存在且未停用、具备搜索能力的站点。站点管理中的状态及搜索资格字段需按实际接入版本验证；缺失字段不能直接宣称健康。MP 的默认搜索集合仅用于首次导入参考，不在用户保存规则后重新扩展或替代名单。

- 按作品 ID、中文标题、别名、原名和季号搜索，以及整季包回退，全部携带显式有效站点 ID；任何分支都不能省略站点范围以回退到 MP 默认或全站。
- 返回候选再次按允许 ID 校验。未知站点、未选站点和已停用站点的资源不可提交；无法从结果可靠确定来源时，不靠相似站名猜测。
- 每个搜索阶段等待参与请求完成或到达有界超时，再进行该阶段选择；不以低优先站先返回抢占高优先站。
- 同一批次共享只读站点目录和两套规则快照，搜索缓存按实例、规则版本、有效站点集合、作品季和查询条件隔离；排序用独立的有序规则快照，不能复用错误类别的选种结果。

### 6.5 站点优先级与现有选种策略的顺序

统一顺序为：**身份／编号／质量／最低做种／在途去重等硬条件 → 整季包或散集策略阶段 → 站点优先级 → 同站做种档位 → 同档容量 → 稳定键破同分。** 高优先级不能让错季、低于做种门槛或未知覆盖的资源合格；低优先站更多做种、更小容量也不能在同一阶段抢占高优先站的合格资源。

| 缺口规模 | 阶段与站点应用方式 |
| --- | --- |
| 缺号大于 3 | 先在所有已选有效站点中找合格整季包（必要时完成同范围别名补搜），选有合格包的最高优先站，再在该站按做种档位和容量选包；所有已选站点均无可用整包才转散集 |
| 缺号不超过 3 | 先进行散集方案，按站点顺序填充缺口；散集组合覆盖不全时才评估合格整季包回退，避免为少量缺号直接下载整包 |

散集阶段按站点逐层形成**尚未提交的计划**：第一站在满足硬条件的候选中最大化覆盖目标缺号，再按同站做种和容量选择；后续站只填前面未覆盖的缺号。跨站组合不重复提交同一集或同一种子，多集文件存在不可拆分重叠时重新规划，不能简单按单集贪心重复下载。

若散集补不全，先评估整包能否合法替代暂定散集计划，再提交最终计划；不能先把散集全部提交、再下载覆盖相同集的整包。整包不合法或与既有在途记录冲突时，可提交不冲突的散集部分，其余仍待补。重规划时优先保持更高站点已可覆盖的目标；必须替换高站资源才能增加覆盖时，按整包回退阶段处理并记录原因。

跨站相同种子去重须保留每个来源的站点 ID、独立下载凭据和有效候选。不能先按最高做种选出低优先站、丢掉高优先来源；也不能把一个站的做种数、链接或 Tracker 套到另一个站。选定下载来源按规则排名决定，某来源不合格才使用下一合格来源。

示例（A、B 仅为占位站点）：

- 动漫设置 A → B。A 的 E03 有 3 人做种、1 GiB；B 有 20 人做种、600 MiB。两者均符合要求且最低为 2 时选 A。若 A 只有 1 人做种，选 B 并注明 A 未达门槛。
- 缺 E03、E04：A 有合格 E03，B 有 E03 和 E04，形成 A:E03＋B:E04，不重复下载 B:E03。
- 缺 4 集：A 仅有散集、B 有合格整季包，按照现有「大于 3 集优先整包」选择 B，解释为「整季包策略优先」，不是站点排序失效。
- 非动漫设置 B → A，同样的候选应按 B 优先评估；两套规则互不影响。

### 6.6 站点异常、规则变更与提交恢复

| 情况 | 预期处理 |
| --- | --- |
| 部分已选站点删除／停用 | 保留失效配置并具名提示，只在剩余已选有效站点中补缺；不自动启用新站、未选站或另一类别站点 |
| 全部已选站点失效 | 本季不搜索、不提交，显示「没有可用的已选站点」，保留缺号 |
| 站点目录读取失败或响应结构异常 | 旧快照仅供展示，不能把错误解析为空列表；本批暂停新搜索／提交，已有下载继续对账，提供重试读取 |
| 高优先站搜索超时或失败 | 记录该站异常，在其有界超时结束后可使用已响应的低优先站；明确「高优先站未完成，已降级」，不能写高优先站无资源 |
| 搜索无候选但缺少逐站回执 | 只称「已返回结果中无合格资源／部分站点结果未确认」，不推断所有站点搜索成功 |
| 提交被 MP 明确拒绝且确定未受理 | 可在本次授权的规则快照内选择下一合格候选，重新检查在途与覆盖，有限次回退并记录原因 |
| 提交超时或结果不确定 | 暂停同一缺号和相同包的跨站重投，先核对台账、下载队列及历史，不以换站规避幂等保护 |
| 用户修改或取消站点勾选 | 新批次使用新规则；运行批次固定使用确认时的旧规则，保存面板和进度页明确说明。需要立即应用时先「停止后续推送」，剩余缺号新建批次；不取消已受理下载 |
| 运行中 MP 停用／删除站点 | 提交前更新站点可用状态并剔除失效来源；只收缩旧计划范围，不因 MP 新增站点扩大范围，读取失败则暂停未提交部分 |

保存规则采用版本校验，另一窗口已修改时提示冲突，不能静默覆盖。目录刷新不自动恢复已停用规则；失效站点恢复后可按原勾选参与下一批，面板明确显示恢复状态。重试与批次恢复必须保留原执行快照，使用最新规则需重新生成用户可见的计划。

### 6.7 执行前展示与结果解释

推送确认框增加「本次使用的站点规则」，按动漫／非动漫分组显示季数、规则版本、站点有序名称、失效跳过项、逐季分类及目录／作品依据。用户可以打开站点设置再返回确认；快照从最终点击「开始评估并推送」时固定，配置版本发生变化时刷新确认内容，不提交过期预览。

逐季结果记录分类与依据、规则版本、请求站点、实际响应情况、候选来源、最终站点及排名、策略阶段、降级原因。无资源结果应写「本次所选站点内无合格资源」，不能声称全网无资源。记录详情示例：

> 使用动漫规则 v3：A → B → C。E03 选用 B（优先级 2）；A 候选最高 1 人做种，低于本次门槛 2。E04 的 A 请求超时，B 无匹配结果，C 资源合格，使用 C 并标注本次搜索范围未完整响应。

更改站点规则不清空无资源历史、已受理回执、待查状态或实物覆盖，不把已受理集号重新变成可推。用户主动「重新搜索」时，对仍可补的缺号应用新规则。

## 七、操作边界与处理后的自动分流

本模块默认待补单季卡提供「删除源端（本季）」；详情不重复放置，批量栏与等待入库页不提供。服务端复核最新主分类、独立季路径、在途状态、预览标识和文件指纹；缺少明确确认不得删除。普通归档清源与整剧删除的旧接口仍不能绕过。

| 本轮结果 | 下一步 |
| --- | --- |
| 无合格资源或仅部分提交 | 保留仍可补缺号与具体原因，不以无资源推断用户放弃 |
| 全部受理，实物尚未入库 | 同模块等待入库／回执视图，实物计数不虚增 |
| 入库后存在同内容副本，或同 ID 多目录待归并 | 转待复核清理；完成后重算，不等待剩余缺号补完才清理 |
| 入库后仍缺，且无前置清理或异常 | 继续缺集待补，仅保留实际缺号 |
| 新证据确认本季仍在播 | 转连载留源，保留已有下载台账；不撤单重下 |
| 本季播毕、内容齐全且源端仍有需迁入归档的内容 | 转齐全可归档 |
| 归档独立完整，源端只余可清冗余 | 转待复核清理，核验通过后才提供「删除源端（本季）」 |
| 真实身份冲突、读取失败或编号问题影响判断 | 转异常剧集，附已自动执行的取证结果和具体待解决项 |

跨模块移交携带作品季身份、内容映射、目录组、保留结论、下载意向及回执，不创建重复主卡。仅附件、两端完整枚举无视频、身份及本季播毕和应有集合已核实，且可信入库资料也无覆盖时，可直接全季待补；陌生视频格式、有效 STRM、目录不可读及未扫完均不能当作零覆盖。

删除权限及目录刷新细节统一见[待复核清理方案](MediaFlow待复核清理模块需求与交互方案-v2.5.53.md)。本方案不再继承旧版“没有其他有效季记录就删整个剧根”的规则。

## 八、按缺号记账，保证刷新与下次初检一致

| 缺号状态 | 可以推送吗 | 如何离开 |
|---|---|---|
| 已确认缺失，未搜索／无合格资源／明确未提交 | 可以 | 发现实物后抵扣；提交前先写意向 |
| 提交中、提交超时、回执不确定 | 暂停重推 | 查同一下载标识、种子标识、队列和历史。只有明确未受理，或在本次有界核对或用户后续主动核对中，经过配置的观察窗口、多次完整查无匹配且实物仍缺时，才释放回待补 |
| MP 已受理／下载中／待整理 | 暂停重推 | 有可信实物则标入库；确认取消／失败且仍缺才退回 |
| 已入库 | 移出补缺 | 其余集照常处理；全季齐全时走统一分流 |
| 身份或期段映射变化 | 暂停引用旧判断 | 旧账保留审计，按新身份重新核查；防止旧回执污染新作品，也防止跳过实际仍在运行的同一下载 |

台账以作品身份、季、有效映射及缺号为基础。按期综艺需能表达“第 8 期下”，旧版只保存整数集号的记录需按原口径读取，不能自动扩成上下段均已受理。任务 ID 用于展示来源，跨次初检需核对仍有效的在途记录。同一下载包涉及多个缺号时记录一份下载意向，多条缺号引用同一回执。入队前作并发互斥与持久化；服务重启从意向核验，不盲目重发。季数、缺号数、下载任务数分别统计，避免“1 个整季包覆盖 3 个缺号”显示成提交了 3 个下载。

## 九、实施和验收

| 验收场景 | 必须观察到的结果 |
|---|---|
| 《一路繁花》S02，合格资源明确覆盖第 7–10 期 | 能直接推送。仅个别候选编号含混时跳过该候选，不提示整季人工核对 |
| 《24小时主厨生死门》S03，两个来源总数冲突 | 对映射一致的缺号可独立补；E09 的处理显示具体季级依据或暂缓原因 |
| 缺 E03、E07、E09，只受理 E03、E07 | 刷新后仍是一张卡，按钮仅推 E09。三个号都受理后默认清单移出，实物覆盖数仍按实际值 |
| 缺失集数 > 3 集（如缺 4 集及以上），且存在合格整季包 | 优先选择整季包下载；整季包不可用时回退散集方案 |
| 缺失集数 $\le 3$ 集（如缺 1–3 集） | 优先选择省容量散集拼包下载；散集不全时才回退整季包 |
| 缺集季只有本季，打开主卡、详情、更多及批量操作，另测旧接口直接调用 | 仅默认待补单季卡提供主动放弃删源，必须预览和确认；旧接口仍拒绝绕过。数据库无其他季不能扩大到整剧 |
| 缺集同时有真实副本，另测归档补足全季、源端已冗余 | 均先进入待复核清理；前者清理后返回缺集待补，后者满足核验后清源结案 |
| 《非正式会谈》S09 仅附件、源归档完整枚举无视频，已核实播毕及内容映射 | 全季待补；与枚举失败、未识别视频和有效 STRM 对照测试，后三者不按零媒体处理 |
| 等待入库后 MP 取消／整理成功但挂载延迟／文件确实到达 | 分别退回待补、等待复核、扣除实物缺号。单次队列未命中不能立即重推 |

### 站点规则与自动分类验收（实现后执行）

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| S01 | 首次打开设置 | 先读取 MP 站点目录，两套草稿可分别勾选与排序；显示读取时间及真实状态，不自动提交下载 |
| S02 | 两套规则独立 | 动漫 A→B、非动漫 B→C 保存后刷新或重启仍保持；更改一套不改变另一套，不修改 MP 全局配置 |
| S03 | 动漫与非动漫混合批次 | 逐季采用不同集合和排名；已知动画使用动漫规则，人工指定覆盖自动判断；初检目录「动漫」及其子季目录默认动漫，「电视剧/综艺」默认非动漫；混合根逐子目录判断，可信作品资料可纠正误放目录，不以语言或第一条记录决定整批 |
| S04 | 空规则与未初始化 | 分别显示「暂停该类补缺」与「请配置站点」；均不省略 sites 参数后发起全站搜索，不借用另一套规则 |
| S05 | 各搜索分支一致 | ID、中文名、别名、原名、整季补搜及重试均只使用对应已选集合；额外返回的未选站候选不可提交，天空／观众不再被强制追加 |
| S06 | 优先级真实参与选种 | 同一阶段高优先站资源合格时，即使低优先站更多做种、更小容量、返回更早，仍选高优先站；站点 ID 数值排序不影响业务顺序 |
| S07 | 硬条件优先 | 高优先站错季、做种不足、质量不符或覆盖不明时跳过，并具名解释使用低优先站的原因 |
| S08 | 跨站散集组合 | A 覆盖 E03、B 覆盖 E03–E04，最终 A:E03＋B:E04；多集重叠重规划，缺号与包不重复提交 |
| S09 | 整包与散集策略 | 缺 4 集时低优先站合格整包可优先于高优先站散集；缺 1–3 集先散集，整包回退在散集提交前决定，且不覆盖已有在途内容 |
| S10 | 跨站去重与来源 | 同种子多个来源保留独立凭据及排名；不以低站高做种提前丢弃高站来源，不混用站点链接、做种和 Tracker |
| S11 | 站点目录变化 | 改名保留 ID 关联，新增默认未选，删除／停用具名标记；同名不同 ID 不替换，切换实例不继承旧 ID；全部失效不搜索 |
| S12 | 站点错误及读取异常 | 目录读取失败不变空列表、不使用未验证旧快照提交；单站超时有界降级并记录未完成，不能伪装该站无资源或全网无资源 |
| S13 | 保存与执行并发 | 多窗口版本冲突不覆盖；预览版本过期重新展示；执行批次按旧快照，新批次用新规则，MP 停用站点可收缩计划但新增站不扩展 |
| S14 | 提交回退与恢复 | 明确未受理可有限次换候选；超时不跨站重投，先对账；重启恢复沿用原快照，修改规则不抹掉已受理和待查台账 |
| S15 | 缓存隔离及解释 | 相同作品在不同类别、实例或规则版本下不串用选种结果；详情显示请求范围、来源站点、策略阶段、排名与具体降级原因 |
| S16 | 权限范围与回归 | 规则仅影响缺集待补；不改变播毕准入、质量和最低做种门槛、不自动创建订阅或改动文件；前端及日志不暴露站点密钥，原逐集台账、等待入库、停止后续推送行为保持正确；仅允许已预览确认的单季主动放弃删源，无批量删源或后台定时跟踪 |

补充 S17：类型字段缺失但路径为「动漫/日本/作品/Season 1」，直接使用动漫规则；路径为「电视剧/综艺/作品/Season 4」，直接使用非动漫规则。泛目录无分类线索时定向补取作品资料，读取失败显示具体错误，不默认非动漫、不要求强制类型选择。
