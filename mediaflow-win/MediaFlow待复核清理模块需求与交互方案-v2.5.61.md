分流短路计算遵循**“清理优先、播期先于补缺”**原则：存在同内容可替代副本、同 TMDB ID 多目录规范化归并或归档已齐待清源动作时，优先进入「待复核清理」；具体身份／口径／读取争议进入「异常剧集」；其余再按播期（连载留源优先）与集数覆盖（缺集待补／齐全可归档）互斥分流。

各模块共用作品身份、期／集／段、内容类别、剪辑版本和技术副本的统一识别结果。作品季数、目录组数、物理记录数与文件数严格分开统计，绝不混加。一次确认执行后自动完成双端核验、网盘目录刷新与五模块重算分流，无需重新跑整任务初检。

## 一、模块职责、准入边界与无重叠计数规范

本模块集中收敛三类源端治理待办：**① 同 TMDB ID 多目录规范化归并与空壳回收**、**② 单季同内容重复版本择优清理**、**③ 归档已齐后的源端冗余清理（含剧集外层收尾）**。作品季即使尚未播毕或存在缺集，只要存在已证实可替代的稳定副本或同 ID 多目录待归并，均可在本模块先行处理。

### 1.1 初检状态与准入分流矩阵

| 初检实物情况 | 本模块处理方式与后续自动去向 |
| :--- | :--- |
| 已播毕且缺集，同时存在同内容技术副本 | 先在本模块清理可替代副本，完成后携带准确缺号自动转入「缺集待补」 |
| 正在连载／待播，存在稳定技术副本或同 ID 多目录 | 先完成稳定副本清理或源端目录归并（活动写入文件单独延后），完成后回「连载留源」 |
| 已播毕、正片齐全且存在可淘汰技术副本 | 清理冗余副本后自动转入「齐全可归档」 |
| 正片齐全且仅附带第 0 集先导片／特别篇（即使有多个不同特辑文件，无正片重复） | **不进入本模块卡单**：直接判定 `archive_ready` 进入「齐全可归档」（归档时智能移入 `Season 0`） |
| 同集号多文件实为上下段、正片与加更／Vlog、普通版与加长版／独有配音 | 自动确认各自独立保留（写入 `review_resolution.all_distinct_retained` 与资产指纹），直接按播期与覆盖分流，不在清理与异常间死循环 |
| 同分类同 TMDB ID 存在多个源目录／归档目录，或旧异名空壳目录 | 生成组级规范化全季归并／空壳回收计划；合并收尾后释放各季按真实状态分流 |
| 归档端已完整覆盖本季应保留正片，源端仍有残留季目录或剧根外壳 | 先保全源端独有衍生内容、字幕与纯附件目录，核验后执行「删除源端（本季）」或「继续清理剧集外层」，完成后结案退出五模块待办 |
| 局部存在异作品 ID、错季或无法解析视频，其余副本已证实 | 争议范围最小化隔离至「异常剧集」，已证实的独立安全部分按规则处理 |
| 仅有孤儿附件，无视频副本且无归档清源资格 | 附件原样保留，不因清空列表而误删，直接按正片覆盖与播期分流 |

### 1.2 计数与边界铁律

1. **一作品季一主卡**：同一作品季在五模块中仅生成一张主卡，满足全局不变量 `review + anomaly + download + airing + archive + held == total_work_seasons`。
2. **目录组与单季清理无重叠展示与计数（v2.5.73）**：
   - 上方「待确认归档目标」区块以独立平铺卡片按**目录组（组）**展示；
   - 下方单季列表仅展示含「重复版本清理」或「归档已齐清源」的剧季卡片，**纯目录归并项不在下方重复渲染**（同时存在目录归并与副本清理的混合项仍保留）；
   - 顶部汇总采用无重叠口径：`N 季清理（review_clean_seasons）+ 另待归并 M 组目录（pending_directory_groups）`，严禁将“目录组数”与“作品季数”直接相加称为“季”。
3. **跨模块删源严格隔离**：缺集待补模块中的「主动放弃补缺并删除源端（本季）」属于用户显式放弃动作，采用独立预览与确认链路，**绝不纳入本模块批量冗余清理范围**，也不支持整剧级联删源。

## 二、单季同内容副本清理规则

必须先证明两个文件属于**同一作品、同一季、同一期／集、同一分段、同一内容／剪辑版本**；只有可替代等价关系成立，才允许在组内比较技术规格并淘汰劣质副本。

### 2.1 内容等价与独立资产保护矩阵

| 内容形态 | 判定与保留规则 |
| :--- | :--- |
| 同集同版本普通编码差异（如 4K vs 1080p、H.265 vs H.264、带 `(1)` 副本后缀） | 属于同内容技术副本，在等价组内按质量与规整度择优保留 1 份 |
| 正片与衍生特辑（`Vlog`、`加更`、`纯享`、`彩蛋`、`先导片`、`超前企划`、`采访`、`日记/Diary`、`Clip`、`Extra`、`SP`、`E00`） | 由 `EXTRA_REGEX` 与 `SPECIAL_E00_REGEX` 识别为独立受保护资产（如 `specials_e00`），100% 纳入 `to_keep`，绝不与正片混组淘汰 |
| 专访、陪看、直播、电台、连麦、搜证事件簿、圆桌复盘局 | 作为独立衍生单元各自保留，不与普通正片或彼此混作技术副本 |
| 普通版、加长版、未删减版、导演剪辑版、独有配音／语言版、未知“××版” | 不同版本各自成组保留；仅在相同版本内部比较技术副本，严禁以“时长更长／体积更大”跨版本淘汰 |
| 分段文件（上／中／下、`Part 1..N`，含 `Part 4` 及更高段号）与整期合并版 | 按具体段号独立成组，同段同版本内部择优；整期文件与分段文件默认各自保留 |
| 多集连号合并文件（如 `S01E01-E02`）与单集文件（`S01E01`） | 分别记录覆盖单元并各自保留，严禁把多集合并文件当作单集副本删除 |
| 无法解析集号或身份待核实的视频 | 原样保留并列出具体文件名，不盲猜、不混入删除列表 |

### 2.2 版本组完整度与梯级打分仲裁

1. **完整版本优先（防残卷鸠占鹊巢）**：
   - 提取 `SxxE{集}` 版本模板统计全季覆盖完整度；
   - **单一完整版本 vs 零散残版**：坚决保留完整版本，淘汰仅含部分集数的零散残版；
   - **多个完整版本并存**：按版本组综合质量分（`score_group`：2160p/4K > 1080p > 720p + 均集体积）保留最优整套版本；
   - **混版拼齐**：无单一完整版时，仅在各版本合集完整覆盖全季（或局部已证实同集多本）时，按单集 `rank_copy` 逐集优选最佳版本；缺集状态下的孤本正片绝对保护。
2. **单集副本梯级打分（`rank_copy`）**：
   - 优先级依次为：**分辨率规格（4K > 1080p > 720p） → 命名规整度（无 `(1)` / `copy` / `副本` 标记优先） → 文件体积 → 编码偏好（HEVC/H.265 > H.264/AVC） → 修改时间**。
   - 兼容 CloudDrive2 对 115 同名文件动态附加 `(N)` 展示后缀的剥离比对（`_strip_cd2_dup_suffix`）。
3. **写前安全熔断与活动文件延后**：
   - `0` 字节文件、无法取得大小的文件、临时下载后缀（`.part / .tmp / .download / .!qb / .aria2 / .crdownload`）及命中 MoviePilot 活跃下载／做种路径依赖的文件一律暂缓处理，不执行删除。
4. **伴生文件精确绑定清理**：
   - 公共刮削资产（`tvshow.nfo`、`season.nfo`、`poster`、`fanart`、`banner`、`clearlogo`、`landscape` 等）绝对保护；
   - 单集外挂字幕、单集 `.nfo` 与缩略图（`-thumb.jpg`）须通过 `companion_matches_video` 精确匹配基名（严禁将 `A` 与 `A2` 模糊匹配），且**仅在对应主视频已核实删除成功且无其他保留视频依赖时**级联清理；历史残留缩略图仅凭已核验成功的 `clean_duplicate` 操作回执收尾。

## 三、同 TMDB ID 规范化与多目录全季智能归并

针对同一分类路径下同 TMDB ID 出现多个源端目录（如译名差异、刮削前后异名目录、残留空壳目录）或归档目标待确认的场景，提供组级原子归并闭环。

### 3.1 规范目录命名与目标自动选择

1. **规范目录名生成（G06）**：按 `规范剧名 (作品首播年) [tmdbid=ID]` 生成；剧名优先级为 **TMDB 简体中文规范名 → 有效中文别名 → 作品原名 → 清洗后的现有目录名**，首播年取作品级年份（剥离已有重复年份／ID 标签防重拼）。
2. **源端位置与归档指向分离（M02）**：
   - 本次物理合并发生在源库（`source_root`）受控分类目录内：已有同名（含大小写等价）规范目录则直接复用，全部旧目录均异名时才受控新建（且仅在确有待迁入文件／附件时允许新建，禁止创建空目标目录）；
   - 完结归档库路径（`archive_root`）仅保存为 `confirmed_target_path` 归档指向，连载剧集在源端合并后继续安全留源。
3. **单条弹窗与批量通道全季对齐（v2.5.83）**：
   - 单条目录组接口（`POST /api/tasks/{task_id}/directory-groups/{group_id}/merge-preview` 与 `/merge-execute`）与批量推荐通道全面对齐，前端默认启用 **`all_seasons=True, smart_collision=True`**，自动发现并覆盖旧目录下的全部季度（彻底根治仅含 `S04 / S05` 等非 `S01` 多季剧因默认按 `S01` 扫描导致旧目录漏季卡死的问题）；
   - 同时保留 API 显式传入 `season_number`（不带 `all_seasons`）或 `season_numbers` 的按季局部归并能力（满足 M10 旧目录保留未选季的场景）。

### 3.2 `SxxE…` 边界重命名与同名智能防覆盖

1. **命名前缀统一（M03–M05）**：
   - 严格以匹配当前季号的有效季集标记 `SxxEyy`（含连集 `S01E01-E02`，排除普通英文单词首字母 `S`）为唯一拆分边界：`S` 之后的季集号、分段、版本标签、压制组与扩展名 **100% 逐字保留**；
   - 目标同季已有统一前缀则沿用；存在多种前缀时优先采用与规范剧名一致的模板，次选票数最多模板；目标无样本时采用 `规范剧名 - ` 标准前缀；外挂字幕与分集伴生文件同步对齐基名并保留 `.zh-Hans.srt` 等语言属性后缀。
2. **冲突隔离与同名防覆盖（M06–M08, G07, G09）**：
   - 文件名显式携带异作品 `[tmdbid=...]` 或错季标记（如 S01 目录内混入 `S02E01`）时，在全季模式下仅局部隔离争议文件并保留其所在目录，不阻断其他干净季；
   - 改名后若与目标同季已有文件重名，开启 `smart_collision=True` 时先校验是否为同内容等价正片且目标体积不劣于源端：若是则安全转入 `collision_dedup_items` 回收源端冗余副本；否则保留原区分前缀或原名迁入 `{目标季}/合并保留/{旧目录名}`，**严禁覆盖任何已有文件**。

### 3.3 附件保全、Season 0 特辑、纯空壳与系统垃圾自动收尾（v2.5.83）

1. **公共资产与季级无集号附件保全（M09）**：
   - 旧剧根的 `tvshow.nfo`、`poster.*`、`fanart.*`、`banner.*`、`clearlogo.*`、`logo.*` 若目标剧根尚无同名文件则迁入目标剧根，若已存在同名文件或其他未知附件则原名保全至 `{目标剧根}/合并保留/{旧目录名}`；
   - 季内不含 `SxxEyy` 的 `season.nfo`、季海报等附件原名保全至 `{目标季}/合并保留/{旧目录名}`；所有附件均须在计划中记录 `source_snapshot` 并在移动前后执行双端大小与消失核验。
2. **`Season 0 / Specials` 特辑自动纳入（v2.5.83）**：
   - 全季归并（`all_seasons=True`）自动扫描旧目录下的 `Season 0`、`Season 00` 与 `Specials`：若内部为空直接纳入空目录回收；若含先导片／SP 特辑文件，不强改前缀，原名安全迁入 `{目标剧根}/Season 0`（重名则保全至 `{目标剧根}/Season 0/合并保留/{旧目录名}`），不再因 `Season 0` 阻断旧剧根收尾。
3. **纯空壳目录与系统隐藏垃圾自动识别回收（v2.5.83）**：
   - 新增只读递归盘点 `inspect_empty_subtree`（最大深度 3 层）：对季外未知子目录、季内子目录及整个旧源目录，若确认内部 **0 视频、0 字幕、0 有效附件**（完全为空，或仅含操作系统自动生成的 `.DS_Store`、`Thumbs.db`、`desktop.ini` 白名单隐藏垃圾文件），不再误报“季外／季内子目录未盘点”阻塞，而是：
     - 将白名单垃圾文件记录指纹纳入 `junk_files_to_clean`（执行前再次校验指纹与白名单）；
     - 将所有空子目录与旧剧根按**路径深度倒序（自底向上，最深子目录优先、剧根最后）**纳入 `directories_to_clean`；
     - 当整个旧目录无任何有效媒体／附件需迁移时，计划显式标记 `is_empty_shell_cleanup = True`（前端展示绿色「纯空壳目录 · 可直接安全回收」提示）；
     - 旧剧根核验清理完成后，自动将该旧目录路径名下所有残留的 0 集假缺集 `SeasonRecord` 统一收敛为 `source_absent`，立即释放主目录齐全季进入「齐全可归档」。
4. **严禁放行无动作“空计划”（v2.5.83）**：
   - 若预览生成的计划满足 `0 移动 + 0 同名去重 + 0 附件保全 + 0 空目录清理 + 0 垃圾清理` 且非 `align_only`（例如单季调用漏选了旧目录实际存在的其他季），预览阶段直接强制置 `can_execute = False` 并明示未纳入目录名称，杜绝前端亮起可执行按钮后点击必败。

### 3.4 115 / CloudDrive2 一致性短退避重试与可解释残留诊断（v2.5.83）

1. **快照漂移前置拦截**：执行合并前逐一比对 `inventory_snapshots` 与源文件指纹；若预览后目录新增文件、文件 ID／大小／修改时间变化，立即中止并列出新增、缺失、变化字段明细（至多前 5 项），要求更新预览。
2. **删子目录后的父目录短退避核验（`delete_dir_robust_detailed`）**：
   - 空目录删除必须先经 `force_refresh=True` 强读返回合法空列表 `[]`，且 `delete_file` 返回明确 `{"success": True}` 才计入 `cleaned_dirs`（读取异常或回执不明绝不删除、绝不计成功）；
   - 针对 115 网盘 + CloudDrive2 在刚删完子目录（如 `Season 4`）或系统垃圾文件后毫秒级强读父目录偶发仍返回已删子项缓存的一致性延迟：若父目录剩余项**全部属于本轮刚确认删除成功的子项名称**，自动执行最多 3 次短退避重读（`0.4s → 0.8s → 1.5s`）；
   - 若存在任何非本轮已删的真实文件／子目录，立即停止重试、保留目录，并在报错信息中精准列出具体残留项名称（如：`旧目录仍有内容（「xxx」仍残留：Season 2、extra.mkv），未完成空目录收尾`），彻底告别黑盒报错。

## 四、归档已齐后的源端清理与剧集外层收尾

当归档库已独立、完整覆盖本季应保留的全部正片（且已核实播毕、无活动下载写入，连载期局部清理绝不扩大为整季清源）时，进入源端冗余清理流程。

### 4.1 季内附件与「合并保留」目录前置保全（v2.5.59）

1. 源端独有的加更、Vlog、加长版、外挂字幕及刮削附件必须在删源前全部迁入归档端并完成双端核验。
2. 若源季内含有历史归并产生的 `合并保留` 子目录：系统强读展开（最多 3 层、500 项），仅当确认全部为允许的纯附件（`nfo / jpg / jpeg / png / webp / txt`）或空目录时，先整体保全至归档端（同名冲突时存入独立的 `清源-唯一标识/合并保留` 路径，绝不覆盖既有归档附件）；若内含视频、STRM、未知类型或读取失败，则安全拦截删源并提示具体原因。
3. 附件保全前先持久化源路径、目标路径与清单回执；中断重试时沿用回执继续后验，已确认到达的文件不重复移动，但绝不因源端消失而跳过目标到达核验。

### 4.2 剧集外层（剧根）收尾与真实三态回执（v2.5.60）

1. 本季目录经明确删除回执及强读确认消失后，先持久化本季完成标记，再检查源剧集外层根目录。
2. 若源剧根仍有其他季度、视频或未核实内容，安全保留源剧根；若源剧根仅剩已知公共刮削资产及已核实的纯附件 `合并保留` 目录，则将该资料外壳整体保全至归档剧根独立的 `合并保留/清源标识/原剧名` 下，双端核验到达后再回收空源剧根并刷新父目录。
3. **三态真实回执（严禁写死虚假“残留已清除”文案）**：
   - `本季已清理，外层已移除`：源季与源剧根均已核验消失，彻底结案；
   - `本季已清理，外层因其他内容保留`：源剧根因存在其他季合理保留，本季结案；
   - `本季已清理，外层待处理`：外层附件保全或空壳删除未完成，记录保留在「待复核清理」且主按钮自动切换为 **「继续清理剧集外层」**（再次点击仅执行外层收尾与归档复核；若发现源季目录重新出现则立即停止并要求重新核对）。

### 5.2 工具栏双批量按钮拆分与职责隔离（v2.5.83）

为避免“多目录结构整理”与“冗余媒体文件删除”混在同一批次造成心智负担与不必要云盘扫描，待复核清理顶部工具栏正式拆分为四个职责清晰的操作入口：

1. **「批量处理多目录问题 (N)」**（调用 `openRecommendedBatchModal('merge_directory')` → `POST /api/archive/recommended-plan` 传 `mode="merge_directory"`）：
   - **专职范围**：仅并发盘点全部 `pending_confirm` 待确认归档目标／同作品多目录组（启用 `all_seasons=True, auto_canonical_target=True, smart_collision=True`），**不扫描单季副本与清源项**；
   - **预览看板**：统计「同作品目录归并组数」「其中纯空壳回收组数」「拟迁移／保全文件数」「预览暂未纳入项」，对纯空壳条目高亮标记 `空壳回收` 徽章；
   - **范围隔离**：`scope_record_ids` 严格限定在关联目录组涉及的作品季内，执行完成后的结果去向汇总不混入无关的单季副本待办。
2. **「批量冗余清理」**（调用 `openRecommendedBatchModal('redundant_clean')` → `POST /api/archive/recommended-plan` 传 `mode="redundant_clean"`）：
   - **专职范围**：仅并发盘点全任务可自动执行的「同季重复版本清理（`clean_items`）」与「已归档源端清理（`redundant_source_items`）」，**不扫描与执行多目录归并**；
   - **依赖保护**：若某清源季所属作品仍存在未确认的多目录组阻塞，自动归入「预览暂未纳入」并提示 *“请先点击「批量处理多目录问题」完成目录归并”*；
   - **预览看板**：统计「重复版本清理季数」「已归档源端清理季数」「预计释放空间」「预览暂未纳入项」，默认 100% 保全加长版、Vlog、加更与先导特辑。
3. **「查看最近执行结果」**：按任务维度从会话存储恢复最近一次批量作业（`job_id`）的实时进度或最终四类去向回执。
4. **「清理所选冗余 (N 季)」**（勾选框联动按钮 `#batchActionButton`）：仅对用户在下方列表手动勾选的特定季执行针对性冗余清理预览与确认。
5. **向后兼容契约**：后端 `POST /api/archive/recommended-plan` 默认 `mode="all"` 仍保留三类动作联合规划能力，确保历史自动化脚本与回归契约无缝兼容。

### 5.3 执行前指纹复核、实时进度与中断恢复

- **并发指纹复核门禁（G24）**：点击确认执行后，后台作业先并发强读待清理目录复核文件大小、修改时间与文件标识（`id`）；发现新增视频或信息不一致时立即暂停为 `needs_repreview`，首屏仅展示受影响季数与折叠的文件差异明细，主按钮切换为保持当前 `mode` 的 **「更新预览」**，绝不静默扩大删除范围。
- **异步作业与优雅停止（G23）**：通过 `/recommended-execute-start` 与 `/recommended-execute-status/{job_id}` 轮询展示阶段与逐项进度条；点击「完成当前步骤后停止」在当前原子步骤核验落盘后安全停机，已完成步骤写入 `recommended_batches` 持久化日志，重试时不重复操作已完成项；若服务重启遇到未结算 `inflight_step`，强制要求先更新剩余项预览对账后再继续。
- **诚实结果定性（G28）**：仅当本批次内 `0 失败 + 0 剩余待复核 + 0 未决异常 + 0 跳过项` 时才显示「本批次已全部解决」；若整轮 `0 进展` 且存在阻塞，按钮置灰显示「本轮无进展 · 请查看原因」，切断无效的“更新预览 → 确认”死循环。

## 六、跨模块衔接与完成后自动分流

1. **与「缺集待补 · 核对入库」的衔接（v2.5.58）**：用户在缺集模块点击「核对入库」后，系统对受影响季执行完整实物重核——若整季包补缺带来了新的同集技术副本，自动重新生成待复核清理状态与最新副本清单（绝不沿用下载前的旧副本列表直接归档）；若读取失败、指纹变化或 MP 仍在下载整理，则保持“补缺后待复核”暂停归档与删源。
2. **本轮执行完成后的四类自动去向汇总**：

| 执行并双端核验后的最新事实 | 自动流转去向 |
| :--- | :--- |
| 仍在连载或待播（无剩余可清理副本／目录阻塞） | **连载留源**（源端继续保留） |
| 已播毕，正片仍有确定缺口 | **缺集待补**（保留既有在途下载台账与到位回执） |
| 已播毕，正片覆盖齐全且目录组／副本已收尾 | **齐全可归档**（含仅附带 E00 先导特辑的齐全季） |
| 归档已齐且源季与外层均核验清理完毕 | **完成记录**（`cleaned_redundant` / `source_absent`，退出五模块待办） |
| 存在显式异作品 ID、错季、未识别视频或口径冲突 | **异常剧集**（仅隔离最小受影响范围） |
| 媒体动作已完成但剧根外层收尾或目录刷新未完成 | 留在 **待复核清理** 展示独立收尾项（如「继续清理剧集外层」），重试不重复移动或删除媒体 |

## 七、验收标准（R01–R22）与代码映射索引

### 7.1 核心验收矩阵

| 编号 | 验收场景 | 通过标准 |
| :---: | :--- | :--- |
| **R01** | 缺集同时存在技术副本 | 先安全清理可替代副本，再携带准确缺号自动转入「缺集待补」 |
| **R02** | 连载同时存在副本或多目录 | 清理稳定副本／源库内归并后回「连载留源」，活动写入文件单独延后 |
| **R03** | 综艺正片与衍生特辑（如《中餐厅》Vlog／加更／先导 E00） | 正片普通编码组内择优；Vlog、加更、先导片／E00 100% 保护保留；正片齐且仅多 E00 直通「齐全可归档」 |
| **R04** | 加长版、未删减版、独有配音版 | 不同内容／剪辑版本各自独立保留，质量打分绝不跨版本淘汰 |
| **R05** | 连号合并集、上下分段（含 Part4+） | 合并集与单集、不同分段各自保留，不因覆盖重叠误删 |
| **R06** | 同 ID 异名目录均无规范目录 | 受控新建规范目录，按 `SxxE…` 边界统一前缀并同步伴生文件，核验后清空壳并刷新 |
| **R07** | 同 ID 多季及局部异 ID 文件 | 默认全季一次组级处理；显式异 ID／错季文件局部隔离，不阻断同组干净季 |
| **R08** | 目标同名碰撞与预览后新增文件 | 同名等价副本安全去重，异内容入 `合并保留` 零覆盖；预览后目录／指纹变化立即暂停要求重预览 |
| **R09** | 归档已齐且源端含独有字幕／特辑 | 先迁移独有内容并双端核验到达，再删源季并刷新父目录 |
| **R10** | 预览后文件替换（同大小同时间但 ID 变） | 严格校验文件 `id`／大小／修改时间，发现替换立即使旧预览失效 |
| **R11** | 主视频删除失败／`A` 与 `A2` 相似前缀 | 主视频未删成功则保留其缩略图与字幕；严禁前缀模糊连坐删除未知附件 |
| **R12** | 中断、重复提交与多窗口并发 | 同任务批次锁互斥；中断后保留已完成步骤回执，重启遇未决写入强制先重预览对账 |
| **R13** | 全部为需保留的不同内容版本 | 持久化 `all_distinct_retained` 与指纹，直接按播期／覆盖分流，不在模块间循环 |
| **R14** | 旧剧根仍含未选季或其他有效内容 | 仅清理已空季目录，安全保留旧剧根并如实说明留存原因（M10） |
| **R15** | 媒体操作成功但网盘缓存刷新失败 | 媒体完成与刷新待重试分开提示，不掩盖已完成回执、不触发重复删除 |
| **R16** | 单条操作与批量操作一致性 | 同一初始实物通过单条弹窗或批量入口处理，得到一致的保留集合与最终分流 |
| **R17** | 清源遇到季内／剧根纯附件 `合并保留`（v2.5.59–60） | 自动强读核实纯附件并迁入归档独立路径，源季与外层分步核验消失；外层未完显示「继续清理剧集外层」 |
| **R18** | 外部手动删除或移走源目录（v2.5.61–62） | 点击「确认源已移删」强读确认 `NotFound` 后移出待办；目录仍存在（含空目录）或读取错误绝不误标消失 |
| **R19** | 目录组独立行卡片与无重叠计数（v2.5.73） | 平铺 `app-card` 展示，下方列表剔除纯归并重复项，矩阵不产笛卡尔积 `0/N集` 假行，季数与组数严格分计 |
| **R20** | 非 S01 多季／纯空壳旧目录收尾（v2.5.83，如 TMDB 127635） | 单条与批量默认全季覆盖，自动识别纯空壳自底向上回收，并将旧空壳残留假缺集记录收敛为 `source_absent`；单季漏季空计划前置置 `can_execute=False` |
| **R21** | `Season 0` 特辑、系统垃圾与 115/CD2 延迟退避（v2.5.83） | `Season 0` 自动迁入或空壳回收；`.DS_Store / Thumbs.db / desktop.ini` 核验指纹后清理；删子目录后父目录延迟自动短退避重读，真实残留精准列出文件名 |
| **R22** | 「批量处理多目录问题」与「批量冗余清理」双按钮隔离（v2.5.83） | `mode="merge_directory"` 与 `mode="redundant_clean"` 严格隔离扫描范围、统计卡片与结果去向，互不串扰 |
