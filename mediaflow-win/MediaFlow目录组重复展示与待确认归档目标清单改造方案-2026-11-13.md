# MediaFlow 目录组重复展示与待确认归档目标清单改造方案

2026-11-13 · 核查版本 v2.5.20（2f54a6a）。任务为综艺，初检目录为 `/115/Library_incs/nas/电视剧/综艺`。

## 现场结论

“确认归档目标”是对一组实际目录作一次决定。“补哪几集”是某个剧季的工作。当前页面在切换季清单分类时同时重画整批目录组，因此用户在两个分类里看到了同一件待办。数据库中三例各只有一条待确认组记录。

| 作品 | 最近一次该路径任务中的待确认目录组 | 该作品的季记录 |
|---|---:|---|
| 乘风（104716） | 1 组 | S06 有两条按期补缺记录，S07 有两条普通补缺记录 |
| 我是歌手（107467） | 1 组 | 3 条均为连载留源，涉及 S10、S11，未发现缺集状态记录 |
| 密室大逃脱 大神版（109096） | 1 组 | S07 有两条普通补缺记录 |

这个任务共 33 个 pending_confirm 组。《我是歌手》即使没有待补季，仍能在补缺页面出现完整确认卡，是识别问题的直接例子。同一季出现多条源记录是另一件事：不同目录可能各有不同文件，不能为消除视觉重复而删掉其中一条。

## 根因与改动范围

前端先把任务目录组接口返回的 groups 存进 task.directoryGroups。每次渲染季列表又调用 renderDirectoryGroupsPanel(task)，函数直接遍历整组 groups，未按当前分类或确认状态过滤。directoryGroupsContainer 是共用容器，切换分类后沿用同一组内容；已确认和有意共存也会生成完整卡。

首版建议只调整展示与导航，复用目录组记录、确认弹窗及原有确认接口。身份识别、缺号计算、归档目标选择和后端操作限制应分别验证。尤其不能仅因卡片从补缺页消失，就允许对歧义目录执行清理或归档。

## 推荐页面行为

1. **唯一处理位置放在“待复核清理”。** 在该页增加可折叠的“待确认归档目标（33 组）”区块，与逐季的重复版本清理分开计数。列表默认只呈现 pending_confirm，标题直接使用作品名，如“乘风 · 确认归档目标”。每组一行，点击再看各路径、源库／归档库、覆盖季和正式确认操作。目录组不参与“全选清理冗余”。
2. **“真缺集待补”专注缺号。** 移除共用的整批目录组面板。对确实关联待确认组的季卡，仅在与操作相关时显示“归档目标待确认 · 查看目录”链接。点击跳转到上述唯一位置并展开对应组，返回后恢复原筛选。无缺集的《我是歌手》不因目录待确认而进入补缺列表。
3. **区分作品组、季和路径。** 目录动作以当前任务和现有 group.id 定位，关联时同时校对分类、TMDB ID 及路径成员关系。不能仅凭显示标题，或全库按 TMDB ID 合并。相同 S07 的两条记录可展示成可展开的路径明细；首版保留各路径原始季记录与缺号，不猜测多个版本之间是否互补。
4. **确认后同步更新。** 选择归档目标或“有意共存”成功后，重新读取当前任务的目录组及相关季清单，从待确认区移出该组，更新所有关联链接与组数。需要回看时在区块内提供“查看已处理”。确认本身不视为已补集、已清理或已入库。目录集合变化使确认失效时，只在待确认区重新出现一次。
5. **保留操作边界。** 目录提示应列出该操作实际受限的原因。补缺、清源、退订清理、归档分别沿用后端资格判断；普通补缺和“退订并删除源端”的影响不同。后端要求确认时，按钮提供到对应组的直接入口。接口读取失败显示“目录状态暂未更新”，不能把缓存中的其他任务或无效状态显示成当前确认结果。

## 上线及验收

先交付“完整组卡只有一个入口”、分开计数和跨页定位；再依据实际需要优化同季多路径的折叠展示。首版无需迁移数据库。用同一份任务快照比较改造前后，确保只有页面组织和导航变化。

| 验收操作 | 预期 |
|---|---|
| 打开当前综艺任务的待复核清理，再切真缺集、连载、已推送待入库 | 快照下待确认区为 33 组；其他清单不出现整批 33 张组卡 |
| 在补缺页查看三个示例 | 乘风和大神版保留实际待补季及路径；我是歌手没有待补季卡。任一关联链接准确定位本任务的一张组卡 |
| 在两页间来回切换、刷新或重新打开 | 组数与季数各按自己的单位统计，卡片不累加；不会新增目录组或重复提交确认 |
| 在测试副本确认乘风且目录未变化 | 待确认组从 33 降至 32；与该组关联的提示同步更新；无关季缺号、MP 受理记录和文件路径保持一致 |
| 选择有意共存、出现新路径、两页同时确认 | 分别显示当前真实状态；陈旧确认先刷新；失效时仅恢复一条组级待办 |
| 只有目录待确认、没有普通复核季；勾选批量清理或补缺 | 待复核入口依旧可见，目录组不占批量选择数；实际请求只包含用户选中的合格季记录 |

本次为只读诊断与改造设计，未确认任何目录、修改任务记录或执行媒体操作。
