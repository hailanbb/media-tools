# MediaFlow「订阅清理」电影智能治理需求与交互方案

评审稿 · 2026-11-18 · 本地 MediaFlow v2.5.40，提交 `6bb34cc` · 当前连接 MoviePilot v2.15.6。

本文对应「MoviePilot 运维 → 订阅清理（剧集 / 电影）→ 电影」。基于当前实现、电影订阅实查与上游接口，设计电影专用的诊断、自动暂停、退订、恢复和来源控制。与《剧集订阅智能清理》共用执行、审计和页面框架，电影的发行阶段、版本目标、查库和搜索规则在本文独立定义。时间阈值、执行周期与默认策略均为建议参数，待功能实施后启用。

## 1. 用户希望得到的结果

用户配置一次自动治理范围后，已满足收藏目标的电影自动退订，发行后长期无有效资源的订阅自动暂停观察，观察结束仍无进展的自动来源项目按政策退订。等待首映、数字版、蓝光或指定版本的项目有清楚的保留理由。网络、下载和整理故障按根因集中提示，避免用户逐部片判断。

自动治理以订阅记录为动作对象，已有电影文件、下载任务和做种任务各自保留。用户可随时将关注影片设为「始终保留」，或主动批量仅退订。影片没有豆瓣 ID、名字为外文、年代久远，都只作为查询上下文，不能单独决定清理。

## 3. 电影的有效目标是什么

先识别“用户想收藏哪一部电影、哪一种版本”，再判定完成。执行对象以实例和订阅 ID 定位；身份至少包含媒体类型 movie、媒体来源和作品 ID。版本目标记录剪辑版、画质、音轨/字幕要求、介质及保存范围。TMDB 的电影 ID 与电视剧 ID 属于不同命名空间，相同数字也必须隔离。

| 场景 | 判断要求 |
|---|---|
| 普通电影订阅，继承默认规则 | 读取当前生效规则，核对入库文件是否满足硬性条件。策略启用时保存解释，后续规则变化使旧计划失效 |
| 想收藏 4K 国语版，库内只有 1080p 原声版 | 显示“已有版本，目标版本仍待满足”。片名和 ID 一致不能直接退订 |
| 洗版订阅 | 默认保留。用户单独启用“最高目标已满足可退订”时，才核对 MP 优先级与实际文件的对应关系 |
| 导演剪辑版、加长版、修复版、IMAX 或 3D 版 | 按用户已表达的目标区分，不能只以同一电影 ID 当成等效完成 |
| 电影分上下文件、CD1/CD2、蓝光目录或 ISO | 验证整部影片所需组成齐备。单文件交付只是常见情况，不能成为强制假设 |
| 片名相同的不同年份电影、翻拍版、电视电影 | 优先按类型和来源 ID 绑定，年份与别名辅助核对。未知类型进入核实，不能默认归成电视剧 |
| 系列电影、合集包 | 每部电影按独立 ID 和版本目标核验。第一部入库不结束续集订阅，合集标题也不代表已包含所有目标作品 |
| 明确手动长期收藏或稀有版本 | 「始终保留」优先于停滞天数，正常查询和完成提示仍可展示 |

关键词命中“收藏、原盘、keep”等只作为旧数据意图线索，需要显示命中字段。标题自然含这些词时，提供一次解除误判的入口；显式保留标记是后续自动化的稳定依据。

## 4. 上映与资源发行怎样判断

电影至少区分未定档、已定档待映、院线阶段、目标家庭发行待到、目标发行已到，以及资料待核实。TMDB 的发行日期按地区和类型提供，类型 1 为首映、2 为有限院线、3 为院线、4 为数字发行、5 为实体发行、6 为电视播出。系统需保存来源、地区、日期和发行类型，不能把年份或电影节首映时间直接当作可下载资源的出现时间。[发行日期接口](https://developer.themoviedb.org/reference/movie-release-dates) · [地区规则](https://developer.themoviedb.org/docs/region-support)

| 可验证情况 | 默认处理 |
|---|---|
| 已定档且首映尚未来到 | 自动来源可暂停等待，临近目标发行日再复查 |
| 已院线上映，只有首映/院线日期 | 显示「等待家庭发行」。没有数字或实体发行依据时，不计长期无有效资源 |
| 用户要 WEB 版本，数字发行日期已确认 | 该日期用于安排资源检查；实际是否有符合要求的站点资源仍需核查 |
| 用户要蓝光/REMUX，已有数字版但实体版未发售 | 显示「等待目标介质发行」，数字版不自动满足原盘目标 |
| 只在某地区发行，或发行语言与目标不匹配 | 记录地区差异。按用户目标选择适用发行事件，不自动以全球最早日期启动清理倒计时 |
| 改档、撤档、发行取消或日期前后矛盾 | 失效旧计划，保留待核实并降低搜索频率。取消发行本身不能证明永远没有收藏价值 |
| 旧电影缺少数字发行日期，但有可靠的发行记录或曾匹配目标版本资源 | 可记录“目标版本已可获取”的替代依据，再按资源观察判断；年代只作线索 |
| 没有发行日期，但已经存在可验证的合格完整入库文件 | 可按入库目标满足判定完成；缺失发行资料不额外阻挡已核实的完成事实 |

日期只精确到天时，保留来源日期精度，避免通过服务器时区换算把日期提前。年份为空写“年份待核实”。资料只给出院线日期时不自动估算“上映 30/90 天必有数字版”。外国标题与豆瓣未收录不影响可信发行资料的使用。

## 5. 自动治理规则与动作

### 5.1 已满足收藏目标后自动退订

同时具备稳定身份、完整电影内容、可用文件或可验证 STRM 目标、满足订阅硬性版本要求，且没有待结算的相关下载/整理/修复任务，才能进入完成退订。下载历史成功、MP 索引存在、电影封面或 NFO、文件名命中、下载进度 100% 都只能提供线索。

当前年新片、上一年电影和老片都使用同一完成检查。正常做种任务可继续存在；有第二个目标版本正在下载或整理时，应先核实其意图。P 状态先解释待定原因，不能直接当已完成；R 状态也必须检查是否早已满足目标。

媒体服务器返回多个版本时列出用于证明完成的具体文件及属性；缺少版本属性或文件可用性证据时显示“已见入库条目，待核实版本/文件”。接口健康、库范围、身份和实物证据均明确后，系统按启用策略自动仅退订。

### 5.2 已发行但长期无有效资源

推荐自动来源使用下列初始参数。手动添加的 2 条电影默认保留收藏意图，用户可在设置中一次性允许同样的停滞策略。

| 阶段 | 建议条件与动作 |
|---|---|
| 进入候选 | 订阅创建至少 60 天；与目标匹配的发行/可获取依据已达到至少 90 天；连续 60 天无可验证的入库或有效下载进展 |
| 形成资源结论 | 至少 3 次有效搜索，跨至少 14 天，最近一次在 7 天内，均没有满足身份与版本目标的可用资源 |
| 暂停观察 | 条件满足后自动置为 S，记录原因和暂停前状态；观察 30 天，继续低频检查 |
| 观察期恢复 | 发现合格资源、有效下载进展或新的目标入库内容，重新诊断。符合追更条件时恢复本系统暂停的订阅 |
| 观察后退订 | 30 天届满，最近 7 天完成复查且条件仍满足，自动仅退订并写来源抑制记录 |
| 证据不完整 | 暂缓退订，标具体缺口。用户可按意愿批量「仅退订」，人工决定单独审计 |

MP last_update 为空时不代填“无进展 60 天”。可用下载/整理历史及连续快照建立活动时间；历史不能覆盖观察区间时从本轮开始积累。先前成功核查可复用，避免每轮重新等待完整周期。

“有效搜索”须覆盖该订阅生效的站点集合，且每个参与站点均完成可信查询。某站点失败，该轮不能累计全范围无匹配；已成功站点结果仍保存。当前站点集合明显过时，可在一个修复项中调整并重新建观察基线。

### 5.3 不能直接归为长期无资源的情况

| 证据 | 推荐动作 |
|---|---|
| 有匹配电影，但被分辨率、音轨、字幕、价格/促销条件或过滤规则排除 | 「有资源，条件未满足」。显示阻挡规则，用户可一次调整所选范围；自动处理保留原有硬性目标 |
| 只有预告、花絮、样片、枪版或身份不符候选 | 不计目标可用资源，记录排除理由。合格搜索可累计目标未命中 |
| 有正确资源，持续零做种或下载无进展 | 查看多轮下载变化与替代资源。短时零速度不判失效，持续停滞达条件可暂停订阅，已有下载单列状态 |
| 下载已完成，整理失败、媒体库未刷新或目录不可访问 | 「需要修复」。不因订阅沉寂自动退订 |
| 站点认证失败、限流、下载器空间不足、媒体服务器离线 | 聚合故障并退避重试，不累计无资源次数 |
| 正版/家庭发行资料缺失，自动来源长期占位 | 可低频等待或暂停为「资料待定」，以减少活跃请求；资料待定天数不直接转自动退订 |
| 高品质或稀有剪辑版尚无可靠发行依据 | 明确“目标版本待发行/待核实”，按收藏政策保留 |

暂时停止活跃搜索与最终取消订阅各有明确理由。用户手动暂停、随后开启洗版或改了版本目标时，系统暂停前的恢复计划失效。仅恢复由 MediaFlow 暂停且未被用户改动的项目。

## 6. 来源控制、防重复与恢复

本轮 363 条电影标记来自豆瓣榜单。建议将新导入的电影先按“已在库、身份明确、目标发行已到、是否有有效资源”筛选，合格项恢复追更；待发行项进入等待，未知项留在待筛选。片名语言只影响别名补充，不作为准入门槛。

现有订阅助手有按新增用户自动暂停的功能，但该字段按用户匹配，会同时涉及同一用户的剧集。电影策略须增加媒体类型隔离，或通过共享准入组件分别执行剧集与电影配置。两个模块由一个调度和执行机制管理，避免对「豆瓣榜单」反复改设置。

来源界面可复用剧集方案，按 RSS/榜单显示新增量、成功入库、停滞、退订和重复创建。历史只有 username 时标“具体来源未知”。调整榜单、评分或语言偏好前显示影响范围与样例。评分无数据时保留未知，不能当作 0 分；配置为空时说明采用哪个默认。

退订后的抑制键包含实例、媒体类型、稳定作品身份、版本目标与自动来源。已完成项目在目标仍被满足时持续抑制；长期无资源的自动来源项目建议抑制 90 天，届满重新诊断后再决定准入。不同续集、不同用户认可版本或用户主动重新收藏分别处理。

上游插件不会天然读取 MediaFlow 抑制表，需在来源导入或统一订阅事件适配中落地。无法事前拦截时，新增后及时识别并暂停，按政策复核，记录实际生效延迟。源插件历史应保留用于防重复；更名、换 RSS 或清空历史时以稳定身份补足。持续重建形成一个来源冲突事项，避免无限创建—删除。

每次取消保存可恢复配置。恢复时先核现有订阅、媒体库和在途，再使用 MP 新建接口恢复，记录新订阅 ID；旧运行计数、历史、状态等字段不能承诺全部原样回写。用户可选择恢复为暂停状态先查看，也可明确恢复追更。

## 7. 界面与交互

顶部保留「电视剧／电影」标签，电影页显示总订阅数、最近取数时间、「立即诊断」「自动治理设置」和「处理记录」。打开页面只加载已有结果，诊断与调度按范围执行远程查询。

| 清单 | 条目要回答的问题 | 主要动作 |
|---|---|---|
| 待处理 | 哪些已核实完成可退订，哪些已符合暂停条件 | 执行推荐操作、仅退订、始终保留、查看详情 |
| 等待发行 | 等待哪个地区、数字/实体发行，何时复查 | 查看发行依据、修改收藏目标 |
| 暂停观察 | 为什么暂停、已观察多久、最近搜过哪些范围 | 立即复查、继续等、仅退订 |
| 正常保留 | 下载有进展、版本目标未满足或用户明确保留 | 查看进度、修改保留设置 |
| 需要修复 | 哪个接口、身份、文件或规则阻碍判断 | 查看受影响项、修复后复查 |
| 处理记录 | 已暂停/退订/恢复/跳过/失败及待核实结果 | 恢复订阅、重新核对、查看批次 |

主清单按实际订阅条数计数。已执行完成的历史不占当前总量；多来源相同目标可折叠，但展开列明每个订阅 ID。采用互斥展示顺序“结果待核实/修复 → 显式保留 → 暂停观察 → 可执行 → 等待发行 → 正常保留”；发行、语言与来源可作为附注，不重复计数。

每条显示片名、原名、登记年份、收藏目标、当前入库版本、主要原因与下次动作。电影进度用“未取得入库证据／已入库待核实／目标已满足／下载中／等待整理”，不显示 0/1 集或 S01。年份未知时直接显示未知；院线日期与数字版日期分别标注。

以下界面示例均为虚构。

> **海边来信（2026）**  
> 目标为 1080p 原声、中文字幕。已核实媒体库中的完整文件满足要求。  
> 建议取消本片订阅。查看依据

> **冬日档案（2026）**  
> 院线上映已确认，数字发行日期待公布。源自自动榜单。  
> 当前暂停等待发行，下次资料核查为 7 天后。查看发行记录

> **旧城夜航（1980）**  
> 目标版本已发行；3 次完整查询跨 21 天未找到可用资源。已暂停观察 30 天。  
> 本轮复查仍无变化，将按策略仅退订。继续等／始终保留

批量诊断先读取订阅与继承规则，再检查身份、入库、发行和候选资源。诊断中逐步展示“已完成入库核对 N/M、资源候选剩余 K 条”，尚未检查的项目明确显示待核查。

手动模式生成一次确认清单，例如“退订 8 条、暂停 16 条，另 3 条证据变化已排除”，数字来自本轮计划。全选说明是当前筛选的所有结果，跨页选择保存到计划；确认后按冻结的订阅 ID、范围及政策执行。自动模式在用户一次启用具体政策后处理同类计划，日常只需看摘要。

进度窗可以关闭后重开；「停止后续操作」只取消尚未派发的项目。已发出请求先对账再结算。「完成并刷新」读取 MP 当前电影列表与逐项结果，成功项移除，受阻项保留并说明原因。请求超时显示“结果待核实”，不会靠总体 ok 值推定整批完成。

电影页自动操作不显示「退订并清理源视频」。若以后增加电影文件清理，须先建立独立的电影文件实体与范围预览；现有 SeasonRecord 清源路径不适用于电影。

## 8. 接口、数据与执行要求

### 8.1 电影适配必须完成的工作

| 接口或现有代码 | 当前能力/问题 | 实施要求 |
|---|---|---|
| MP 查询订阅与插件配置 | 本轮读取成功 | 保留原字段，合并生效的全局、站点和订阅级规则。明确返回是否分页读全 |
| MoviePilotClient.search_resources | 目前以电视剧类型查询并可能追加季号 | 增加显式媒体类型参数。电影按 movie 身份请求电影检索，关键词不加 S01，结果不要求季集字段；现有 TV 调用保持原接口兼容 |
| `POST /api/v1/mediaserver/exists_remote` | v2.15.6 返回季集号映射，四条电影抽查均为空对象 | 从电影完成判断中移出该解释路径，空对象标为电影存在性未知 |
| `GET /api/v1/mediaserver/exists` | 本地索引查询，本轮六条候选均未命中 | 用作查库线索。索引正命中或负命中都不能代替实时文件和版本核查 |
| `POST /api/v1/mediaserver/notexists` | 对应版本源码区分电影与剧集，电影分支已存在返回空列表，未存在返回缺失对象列表 | 作为电影存在性适配候选，实施时验证服务健康、失败语义与认证；补齐实际媒体条目、版本属性和文件可用性读取 |
| 电影条目与文件明细 | 现有客户端没有完整的电影专用实时核验结果 | 通过 MP 可用的完整明细能力或已配置媒体服务器只读适配获得；能力缺失时返回具体未验证字段，禁止伪报完成 |
| TMDB 客户端 | 本地主要封装电视剧信息 | 增加电影详情、发行日期与必要别名读取。官方日期类型和地区可参考，当前片目的实际日期须取证 |
| 暂停、取消与恢复 | v2.15.6 源码提供状态变更、按 ID 删除及新增订阅接口 | 模拟及测试实例验证后接入，所有写入前后核对，保留逐项结果 |

身份、缓存键、队列匹配、来源抑制和日志全部带媒体类型。电影从接口到清理服务都不补默认季号。未知类型返回待核实。已经被旧流程误关联到 SeasonRecord 的待执行电影计划需失效并重新生成。

### 8.2 证据与批次

沿用剧集方案的快照、资源观察、来源归因、操作日志和批次机制，并增加电影的发行事件、收藏版本目标、媒体条目与文件验证结果。记录至少包括原订阅配置、继承规则快照、候选和排除原因、有效搜索站点范围、最近有效进展、预计动作及依据、执行前状态、回执、后验和恢复后的 ID。

同一实例同一订阅只允许一个执行者；同一电影不同订阅目标也要检查相交动作，避免重复退订或恢复。写前重新读版本要求、用户保留、活动和插件状态；变化则跳过重算。写请求超时、后台重启或数据库提交失败时，先读取 MP 实际状态，区分已取消、仍存在、恢复重建和未知。

批量入口、单项入口和自动调度共用资格校验。人工「仅退订」记录用户决定，自动退订必须满足配置的证据要求。业务回执失败不得统计成功，列表读取失败也不能解释为订阅已取消。

## 9. 调度、站点压力与插件协作

建议电影与剧集共用一个每日巡检入口，沿用建议时间 03:30，电影策略可单独启停。服务停机后恢复只合并补查一次。先读轻量列表和活动，再分批查库，最后对符合条件的候选做站点搜索，避免每天重搜全部 365 部电影。

等待发行默认每 7 天核查资料；有明确发行日期的项目在发行前 7 天及到日安排复查。资料长期未知的自动来源可以暂停并按 30 天低频核对，用户关注项可立即复查。暂停观察每 7 天核对一次，临近自动退订必须取得 7 天内有效证据。

建议电影与剧集共享每轮 20 条资源候选、最多 2 条订阅同时搜索的起始预算，并计入底层每站点的请求限制。新增、来源重复和持续等待按可见优先级排队，显示预计轮次；可调整预算，不能因队列积压跳过必要复查。站点认证或限流故障合并处理，避免同一问题产生数百条待办。

订阅助手现有电影暂停天数基于上映字段，未完整表达数字/实体发行阶段。MediaFlow 负责本方案的发行与资源决策，插件可作为状态执行或入口配合方；配置上明确同一订阅由谁处理长期停滞。用户或插件把 S 改回 R/P 时重评；反复改写聚合为策略冲突。

## 10. 验收场景

使用固定日期、模拟 MP/媒体库/站点及可重置测试订阅。每项同时检查页面原因、MP 实际状态、媒体与下载任务保留情况和审计记录。

| 编号 | 输入或操作 | 可观察的通过条件 |
|---|---|---|
| F01 | 当前 365 条电影记录，其中 351 条符合旧年份保护 | 旧标签不作为最终结论，当前年份已核实目标满足的影片也能进入退订 |
| F02 | P 状态老片没有可用入库证据，R 状态新片已有合格完整文件 | 前者继续核查，后者可完成；状态字母不代替事实 |
| F03 | 六条老片候选在本地索引未命中；远程季集接口返回空对象 | 不伪报真实媒体库为空，不增加资源未命中次数，不直接批量退订 |
| F04 | 电影与电视剧使用相同数字 TMDB ID，电影季号为空 | 查询、缓存、队列、预览、来源抑制均按类型隔离，电影不会关联或删除剧季文件 |
| F05 | 电影资源具有正确 ID 和年份，没有 S01 或集号字段 | 电影搜索可正确匹配；TV 搜索的既有调用仍工作 |
| F06 | 同名翻拍、外文片名、无豆瓣 ID、年份空 | 按稳定电影身份匹配，缺资料明确展示；名称和豆瓣缺失不独立触发退订 |
| F07 | 院线上映已过 100 天，数字发行未知；另一个数字日期在未来 | 分别显示等待发行/资料待核实，均不凭院线时长自动退订 |
| F08 | 用户要蓝光，只有数字版；用户要原声中文字幕，库中是其他版本 | 保留目标，列出属性差异；用户明确调整目标后重算 |
| F09 | 影片分两文件只入库一份、蓝光目录不完整、仅预告/NFO、STRM 目标不可用 | 目标未满足，详情定位缺项或可用性问题 |
| F10 | 完整文件和目标版本已核实，发行日期缺失，后台只有正常做种 | 可按完成事实退订；做种保留，发行日期缺失不会造成无限等待 |
| F11 | 全部 last_update 为空，但创建已超过 90 天 | 没有活动记录时从本轮观察；不把创建天数写成连续无进展证据 |
| F12 | 三次完整搜索跨 14 天无资源；对照组一站点失败或规则挡住候选 | 只有前者累计有效无资源证据；后两者分别进入故障或条件不满足 |
| F13 | 下载短时 0 速度、长期无进展、100% 待整理和整理报错 | 分别保留/诊断停滞/等待整理/进入修复，不误以下载状态直接完成 |
| F14 | 观察 30 天满足条件后自动退订；观察中发现新资源 | 前者退订并抑制重建，后者重评并按归属恢复；媒体文件保持可用 |
| F15 | 用户原本暂停，随后设置始终保留或开启洗版 | 旧自动计划失效，用户状态不被定时恢复覆盖 |
| F16 | 同片改名、换榜单再次导入，另一部续集或新版本也导入 | 原目标被稳定身份抑制，续集和新目标独立核查，不扩大封锁 |
| F17 | 用户确认批量计划后改单项规则，执行中断线、重启、重复点击 | 变化项跳过，回执丢失先对账，逐项结果可恢复，无重复操作 |
| F18 | 电影策略启用，剧集使用不同设置；来源用户同时创建电影和剧集 | 类型隔离有效，两个模块不会相互覆盖策略，原始媒体类型未知时待核实 |
| F19 | 需要明细的接口不支持、媒体服务器离线、暂停观察来不及复查 | 显示能力或健康缺口，退订延期；页面不会显示虚构完成数 |
| F20 | 用户批量仅退订或恢复已取消的订阅 | 原媒体、附件、下载及做种任务没有新增删除；恢复关联新 ID，并避免重复下载已满足目标 |

建议实施顺序为先完成电影类型隔离、资源查询和查库适配，再实现真实完成诊断及批量仅退订，随后增加发行阶段、观察与定时治理，最后接入来源准入、防重建和恢复。每阶段验证对应场景；现有把 P 当电影完成的测试需要随新证据规则修订，不能仅更新页面文案。

## 11. 核查范围与依据
