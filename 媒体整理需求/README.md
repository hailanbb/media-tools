# 媒体整理需求

文档版本：1.2 · 更新日期：2026-10-27 · 对象：tv-workflow-win

本套文档以**需求**为中心，固定剧集初检、补缺下载、复核清理、剧集归档的业务目标、规则、异常边界和验收依据。它是后续开发的参考基线，不表示当前程序已经实现这些能力。

本套文档整理自 tv-workflow-win 的需求研究。仓库发布的是文档基线；没有随文档发布运行配置、用户数据或本地实现源码。

发布适配说明与文件校验值见 [发布清单](发布清单.md)，文中本地源码链接统一指向 [源码定位索引](本地源码定位.md)。业务规则与本地 1.2 基线保持一致。

## 文档中的四种结论

- **继承**：在所审阅的上游需求中有明确依据；不等于已由 Windows 版实现。
- **修正**：根据代码、上游规则或可复现结果，纠正矛盾、遗漏或错误。需要修改源码时，仅列待办。
- **建议**：本次提出的实现或产品增强方向，尚未当作用户已确认的业务偏好。
- **待讨论**：缺少事实或存在业务取舍，先保留问题与选项，不编造结论。

功能需求使用 G、I、D、R、A 编号；验收使用 T 编号；实现差异使用 F 编号。修改某条规则时，应同时更新详细需求、对应测试与变更记录。

## 本次最重要的结论

1. 四阶段应共享身份、集号、版本、播出状态与操作记录的定义，否则上阶段的“齐全”会被下阶段误解。
2. 不能把“文件数够了”“请求成功”“目录存在”“没有发现视频”分别当作“集号完整”“操作闭环”“归档完整”“目录为空”。
3. Windows 版已经提供流程入口，但关键判断比上游简化，尤其是补缺身份校验、防重复、清理快照、归档核验与报告追溯。详见 07；这些是审阅发现，不是已修复成果。
4. 上游文档与源码本身也有日期边界等差异，不能机械照搬。文档将冲突显式保留，并给出待讨论事项。
5. 当前适配对象已确认是 MoviePilot v2.15.6；豆瓣经该实例访问。动漫主要使用 S01E01，先统一编号体系再与 TMDB 比较；自定义扫描根必须贯穿报告和下阶段。
