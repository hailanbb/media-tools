# 核心需求基线

版本：1.2 · 日期：2026-10-27

## 1. 目标与需求范围

目标是把源目录中的剧集，从“身份、集号和版本状态不清楚”，推进到“缺集有依据、补缺不重复、冗余可解释、归档可核验”的状态，并保留完整过程证据，便于恢复与二次开发。

四项核心功能：

1. **剧集初检**：确定当前有什么、缺什么、哪些集还没播、哪些信息未知。
2. **补缺下载**：只补已确认应补的内容；对已下载但整理受阻的内容，先形成定向修复方案。
3. **复核清理**：以真实文件为准证明存在应保留的完整版本，再形成最小删除清单。
4. **剧集归档**：在整剧范围满足条件后无覆盖地移动，并核验目标完整、原有资料未受损、源端已按计划清理。

外部系统分工：CloudDrive2 提供文件视图与文件操作；用户部署的 MoviePilot v2.15.6 提供资源搜索、下载管理、整理及豆瓣数据访问通道；TMDB 为默认剧与季集目依据。本地可信集号在统一编号体系后超出 TMDB 本季登记范围时，通过 MoviePilot 用豆瓣复核；不默认由本工具直接访问豆瓣。接口方案见 10。

初检范围扩展为电视剧与动漫，根目录支持自定义修改；动漫主要使用 S01E01。动漫详细命名、特殊篇、编号映射和四阶段差异集中在 [独立动漫专项文档](11-动漫整理专项需求与命名规范.md)，此处仅保留核心需求编号。动画电影可分类发现，但不自动套入逐季流程。

**完成本季，不等于全剧以后不再出新季。** 初检与补缺按季判断；整剧归档检查“本次源剧目录的全部实际内容”，不要求收藏世界上所有已发布或未来季。缺少整季是否纳入补缺，另见 Q-02。

## 2. 文档如何成为开发依据

本章的需求表是主索引，四阶段文档负责详细解释。需求的“必须”指该能力在交付时应满足的规则，不表示本次已批准执行真实下载、删除、移动或修改配置。

来源标记：

- **继承**：来源于上游四阶段需求及报告协议，见 09。
- **修正**：对本地实现缺陷、上游前后矛盾的明确纠正。
- **建议**：为后台运行补充的设计提议；业务偏好尚未确认时不能默认开启。
- **用户确认**：2026-10-27 明确选择的来源政策，以及明确保留待讨论的自动化边界；优先于与其不一致的上游默认规则。

优先级：

- **P0**：不满足时可能错下、误删、错误移动、重复执行，或错误宣布完成；相关写操作交付前必须解决。
- **P1**：核心能力完整性、常见异常与可维护性。
- **P2**：体验、性能及可选增强。

## 3. 必须统一的概念

| 概念 | 定义与边界 |
| --- | --- |
| 媒体身份 | 提供方 + 剧 ID + 媒体类型；没有可信 ID 时才使用完整标题、年份、别名证据形成待确认身份 |
| 季身份 | 媒体身份 + 分季体系 + 季号；Season 1 和 Season 01 是同一数字季 |
| 视频文件数 | 被识别为视频类的实际文件数量；不等于集数 |
| 已识别集号 | 确定属于本季的去重集号集合；未知、错季、合并集不能随意折算 |
| 来源登记集目 | 可信来源给出的本季集目集合及数量，不是本地文件数，也不是资源站最高集号 |
| 已播缺集 | 来源确认已播、当前未收录且没有身份/解析歧义的集目 |
| 尚未收齐 | 来源登记集合减去已确认持有集合；可能包含待播、播期未知 |
| 版本 | 能被文件证据区分的一套发布版本；多个版本集号并集完整不代表某一版本完整 |
| 下载已接受 | 远端明确接收且具备可追踪任务标识；不是下载完成或文件入库 |
| 文件已核验 | 在正确目录看到符合身份、集号及所需属性的实际文件；不自动代表可播放 |
| 来源状态未知 | 缺少足够证据；不能按“无缺集”“0 集”“已完结”处理 |
| 请求结果未知 | 写请求可能已生效，但尚无可靠结论；先对账，不自动再发 |
| 归档成功 | 全部计划对象核验通过、目标原有内容受保护、源端满足计划后置条件 |

## 9. 全流程验收指标

这里使用可检查的条件，不虚构成功率、吞吐或接口可用率承诺。

- 正确性：所有自动放行项都有可追溯证据；任何阻挡项都能指出具体原因。
- 操作边界：计划外写操作为 0；预览/审计中的业务写操作为 0。
- 防重复：同一操作未决时新增重复写请求为 0；真实失败重试必须能证明原请求未生效或已终止。
- 可恢复：故障注入到任意“记账前、记账后、请求后、核验前”位置，重启后均可解释当前状态。
- 数据保留：文件不凭数量推定；人工备注与必要历史不被静默覆盖；机器记录不截断。
- 可观测：每次执行有 runId，每项操作有 operationId，最终摘要能追溯到对象与错误。
- 性能：先测服务实际响应与限流再定并发预算；不得为速度减少核验或跳过目录。
- 兼容：用目标 CloudDrive2/MoviePilot 版本验证协议后再启用写能力；未确认版本保持只读可用、写入阻挡。

## 10. 已确认决策、待讨论事项与暂行处理

### 已确认：Q-01 来源政策（2026-10-27）

用户原话：“当集数超过TMDB的集数时，用豆瓣复核”。

按前述“集数不等于文件数”的定义落地为：默认用 TMDB；先证明本地与 TMDB 是同一季/编号体系，再判断本地已识别集号是否超出有效登记范围，触发后用豆瓣核对同一部剧、同一季/分部的登记集数。以有效连续编号 1～N 为例，出现 E(N+1) 即触发，即使中间缺集使去重集数不超过 N；不能因重复版本使视频文件数超过 N 就触发，也不能直接用动漫绝对集号与单季数量比较。

豆瓣结果须通过身份、年份、季号和数量校验。结果支持更大的本季数量时，保留两来源证据并按经核实的范围重算；结果不能解释超范围、查询失败或身份不明时，继续待核实，不把超出文件直接当多余文件删除。豆瓣只有集数不自动证明本季播完。

这项确认不扩大为“所有季都必须查豆瓣”，也不自动确定来源缺失/播完未知时的其他豆瓣触发条件。

后续已确认：豆瓣数据通过 MoviePilot 获取；部署为 v2.15.6；动漫主要使用 S01E01；自定义根和动漫初检纳入需求。接入方向不再待选，剩余为实例响应、绑定数据和映射的实际验证，详见 10、11。
