# 剧集初检：详细需求与业务规则

文档基线：1.3（2026-10-27）。本轮只更新需求；历史研究/实现核查保留原时点。

关联需求：G-01～G-14、I-01～I-18。需求主定义见 [核心需求基线](01-核心需求基线.md)；动漫专属规则集中见 [动漫专项](11-动漫整理专项需求与命名规范.md)，本章不复制其全文。

## 1. 使用场景与完成条件

用户选择全库、一个分类或一部剧，得到“每个收藏范围中的逻辑季一行、多个物理目录为明细”的结果，以及未能正常形成季记录的异常项。初检只读取云端与来源数据，写出本地报告/检查点；不提交下载，不创建云端目录，不改名、移动或删除。

本轮完成应表示：范围内每个对象均有“已核对、读取失败、身份待确认、结构不支持、已取消”等终态或明确待办。不能因异常被 catch 后跳过，就把其从分母中去掉。

输入至少包含：明确的服务与库标识、扫描根、选择范围、来源政策、核对日期/时区。输出包含季结果、剧级结构问题、来源证据、文件快照、汇总与本轮范围。

## 2. 目录识别与范围（I-01、I-02、I-06）

原项目常用结构为“源根 / 分类 / 剧集 / 季目录 / 文件”，不是 Emby 唯一合法结构。初检须允许自定义根、明确选择电视剧/动漫范围及目录布局；区分本轮路径与保存默认配置。实际路径必须保留原始字符，不以标题标准化结果或下次运行的新根重新拼接。

| 情况 | 判定与处理 |
| --- | --- |
| 明确指定单剧，包含 Season 目录 | 按剧检查，父路径记录分类；仍验证属于选定库 |
| 空的标准季目录 | 文件列表完整读取后记录视频数 0、识别数 0，继续查询来源 |
| 整剧无季目录 | 输出结构异常，不默认补一个 Season 1 |
| 视频直接位于剧根 | 明确 SxxExx 可形成逻辑季视图；当前适配未实现则报告布局不支持，不猜 S01、不自动重组 |
| 季内有子目录 | 列出嵌套问题；可只读清点，不能把未扫描部分当不存在 |
| 分类第一部剧为空或不可读 | 不用这个样本将整个分类误认作根目录；优先明确范围参数或多项证据 |
| Extras、花絮、字幕包及未知目录 | 已核实角色的列为受保护配套；证据不足列未知；都不能当可删除空目录 |
| 目录分页或流不完整 | 标记扫描未完成，不用于完整性和后续写操作 |
| 文件列表在扫描期间变化 | 重取稳定快照或暂缓，不能拼接成一个从未真实存在的清单 |

延续上游按云盘修改时间从旧到新处理的意图；时间缺失时明确提示并使用记录好的稳定次序，不伪称仍按修改时间。是否把缺失时间视为整轮阻挡可作为体验策略，不应影响单季完整性事实。

路径检查应识别段边界、点段、控制字符与服务返回的越界路径；“/电视剧2”不能因前缀相似被视为“/电视剧”的子目录。源路径、Windows 本地路径和 MoviePilot 容器路径属于不同命名空间。

## 3. 剧与季的身份（I-03、I-13）

优先使用目录中明确的 TMDB ID，但仍核对来源返回的 ID、媒体类型与季号。报告里的 TMDB ID 与目录里的 ID 不一致时保留冲突，不能任取一个。

无 ID 时可列出完整标题、年份与来源明确别名的候选。繁简、全半角、空白正规化只是比较辅助手段；不能因为标题含有某个子串、删除“特别篇”等后缀后相同，就自动认定同一剧。

Season 1、Season 01、S01 可归一到数字季 1；保留原始目录名称。多个目录归一到同季时，先核实身份、收藏与编号；逐目录保留明细并按季聚合，区分互补、重复与混版。不得仅因同季多目录拒绝统计，也不得仅因并集齐全直接放行物理操作。

Season 0 / Specials 可识别为特殊季，但“能解析出 0”不代表当前链路支持自动处理 0。绝对集号、分部、上下篇、地区拆季与来源分季不同，须保存明确映射版本；没有映射时交人工。用户动漫主要为 S01E01，该模式复用普通季集检查；特殊内容与编号差异的完整规则在独立动漫文档。

### 3.1 多语言名称与目录查找

日文/韩文优先通过可信来源 ID 对应中文标题、原名和别名；繁体转换为简体只用于显示和比较。中文名称的推荐顺序为用户已确认名称、来源简体标题、来源其他中文译名的简体显示；无可靠中文名时保留原名并标待确认，不把机器翻译写成官方名。

在已允许范围内查找同中文名/别名及同 ID 目录：同名不同 ID 分开，无 ID 多义候选待核实；唯一且有充分来源身份依据时可建立只读关联。原名称、语言、依据、ID、年份、季/分部和路径保留。初检不直接重命名。

### 3.2 同剧各季矩阵与归并可行性

列清每个目录有哪些季；同季的文件聚合、不同季分别核对。例如 A 有 S01E01–06 和 S02，B 有 S01E07–12 和 S03，S01 可形成 E01–12 的覆盖视图，S02/S03 各自判断；不要求 A/B 都补齐三季。

初检须回答：能否组成完整目标版本、是否仅混版并集齐全、哪些是重叠集、哪些真的缺失，以及仍缺哪些证据。别名目录读取失败、分页不完整或身份未决时，不按局部缺集自动补下。只选单路径时标局部结论，并提示已发现但未纳入的关联目录。

具体判定矩阵见 [12 专项](12-同剧多目录与分季归档专项需求.md)。归并可行并不代表已移动或已获准清理。

## 4. 文件与集号（I-04、I-05）

建议解析器输出结构而非单个数字：

    parseStatus: single | repeated-expression | multi-episode | wrong-season | conflicting | unknown
    season: number | null
    episodes: number[]
    evidence: 原文件名中的命中片段
    issues: 错季、重复表达、范围冲突等

| 示例文件名（当前季为 1） | 应有解释 |
| --- | --- |
| 示例 - S01E01 - 01.mkv | 同一集重复表达，属于第 1 集 |
| 示例 - S01E01 - 02.mkv | 数字冲突，不取第一个数字放行 |
| 示例.S02E03 - 03.mkv | 明确错季，不能降级用末尾 03 作为 S01E03 |
| 示例.S01E01E02.mkv | 合并集；保留集合证据，默认自动流程阻挡 |
| 示例.S01E01-E02.mkv | 多集范围，不截成 E01 |
| 第十二集.mkv | 明确中文单集；各阶段模板化必须采用同一规则 |
| EP05.mkv / 05.mkv | 在明确季上下文中识别；仍检查来源范围 |
| 示例.2024.1080p.mkv | 年份/分辨率不当作集号 |
| sample.mkv / trailer.mkv | 疑似样片/预告；报告不确定性，不擅自计入或删除 |
| 剧集.strm / 剧集.iso | 与实体单集视频不同；需专门能力声明，不能仅凭扩展名证明内容完整 |

保留文件大小、修改时间、服务文件 ID（可用时）、原始路径。0 字节实体视频是异常；缺少大小是未知，不能改写为 0 后混同。

“没有解析出来的文件”不应被丢弃。未知文件可能包含应补集，在身份/解析尚不确定时，不能拿已识别集合给出确定缺集并立即下载。

## 5. 集合计算（I-07、I-08）

设：

- E：通过校验的本季来源登记集合。
- P：同一收藏、逻辑季和编号体系下，已核实关联目录的有效集号并集；源库与已绑定归档库位置分别保留。目标版本另有自己的覆盖集合。
- B：来源确认已播集合。
- F：明确未来播出集合。
- U：日期未知或当日未确认集合。

在来源、文件解析及双方编号体系/映射均可信时：

    尚未收齐 = E - P
    已播缺集 = B - P
    本地超范围 = P - E
    待播缺口 = F - P
    未定播期缺口 = U - P

B、F、U 应按统一政策划分且互不冲突。来源仅有数量时，不应伪造逐集播期；数量可以保留，但可自动补缺范围可能仍未知。

若来源集号不连续、重复、数量与条目不一致，先标来源异常。默认连续季政策下不得使用数组长度构造 1..N；若未来支持非连续正式编号，必须显式变更集合规则并加测试。

## 6. 播出状态与来源补查（I-09、I-10）

**已播完**需要本季集目充分、登记集目播期均已满足政策，并存在可信结束或季终证据。取消不自动等于已经播齐：Canceled 状态仍需检查本季实际集目和未来日期冲突。

**连载中**需要本季已播与本季后续播出证据。全剧有下一季、来源状态为 Returning Series、资源站最高只有 E42，都不能单独证明本季仍连载。

**当日日期边界**存在上游不一致：初检需求使用“早于核对日”；上游 broadcast-audit 源码采用“不晚于当日”。本次不沿用两个定义。Q-03 未确定前，统一报告为当日待确认，不自动宣布完结。

用户已于 2026-10-27 确认来源政策：**默认使用 TMDB，本地可信集号超出 TMDB 本季登记范围时用豆瓣复核**。这替代机械照搬上游的较广触发条件。

以 TMDB 有效登记 1～16 为例：本地出现 E17 即触发，即使缺 E02 导致去重集数仍为 16；本地仅 E01～E16 但存在重复版本、文件总数 20，不因文件数超出就触发。错季、合并集或冲突解析不能作为可信 E17，须先核实解析。来源本身无效时不能伪造登记范围来判断“超出”。

TMDB 失效、身份/季目无效或播完未知仍需报告并保留阻挡，但是否也自动查询豆瓣尚未确认；不在本次政策中擅自追加。普通缺集、空季也不单独触发豆瓣。

来源处理必须保留：

1. 原来源数量、集目、URL、获取时间、返回身份与诊断。
2. 补查结果及匹配依据；不能把全剧总集数套给某季。
3. 冲突双方，不以“最新查询覆盖全部旧字段”隐藏冲突。豆瓣有效证据解释了更大本季范围时，据此重算；若仍解释不了本地超范围，保持待核实，不能自动删超出的文件。
4. 已知数量与未知完结状态可以同时存在。

豆瓣通道已由用户确定为 MoviePilot v2.15.6：用请求级 source=douban 搜索条目，再取 /douban/{doubanid} 详情。当前本地客户端尚未实现此链路。MP 可能从数量合成季集列表，必须记录证据类型，不能据此生成逐集日期或完结结论；失败保持待复核，不自动直连豆瓣。详细契约见 [MoviePilot 接入方案](10-MoviePilot接口研究与接入方案.md)。

## 7. 输出判定（I-11、I-12）

| 事实组合 | 结果 |
| --- | --- |
| 可信完整单版本、本季已播完、无阻挡 | 绿色，可进入归档预检 |
| 已确认连载，无下载/复核待办 | 蓝色；仍可补明确已播缺集 |
| 缺集且尚未提交下载 | 明确缺集状态；颜色按统一显示规则 |
| 多版本、重复、未知、来源冲突 | 待复核/待核实，不能绿色 |
| 已确认空季 | 空季事实 + 来源信息；不等价于无资源 |
| 读取失败 | 失败/未知，数量为空并附错误，不填 0 |

本地当前用红色表示空季，而上游红色主要表示无合格资源。建议固定语义：红色仅用于已经完成资源检查后的无合格资源；空季作为事实字段。状态字段比颜色更权威，兼容导入时保留旧色含义来源。

最低输出：recordId、scopeId、showId、season、真实 showPath/seasonPath、文件数、识别集合、重复/未知/超范围、来源集合、已播缺集/待播/未知日期、版本清单、完结依据、检查时间、扫描完整标志、issueCodes。

### 7.1 初检后的分流

| 核对结果 | 下一步 |
| --- | --- |
| 其他同剧目录已覆盖、或文件已下载待整理 | 不重复补下，转关联/复核或等待整理 |
| 本季已播真缺、没有已有任务覆盖 | 形成补缺需求，提交前再次检查 |
| 仅待播缺口，或当前已播齐但全季未播完 | 留源等待更新，不归档半季 |
| 已播完但缺集 | 留源，核对分散内容与任务后补真缺集 |
| 集号齐但重复/混版/身份/来源未决 | 复核或待核实，不提前绿色 |
| 本季完整已播完、目标版本与安全边界明确 | 可进入所选季归档预检，其他季继续留源 |

报告分别显示中文名/原名、候选及已关联目录、每季物理清单、覆盖、版本、播期、治理建议和阻挡原因；不把文件数、颜色或名称翻译作为唯一分流依据。

## 8. 边界及验收

不得将“当前文件名核对通过”写成“视频内容健康”。可选探测层可另外检查容器、时长、可播放性与哈希，必须记录检查等级。

对应验收：T-I01～T-I15、T-P01～T-P08、T-N01～T-N12，以及 T-X01～T-X48 中的初检/名称/范围场景。尤其要验证：重复导致数量够但集合缺、编号未映射而误触发豆瓣、自定义根后旧任务串路径、附加内容误算正片、来源转换证据不足。
