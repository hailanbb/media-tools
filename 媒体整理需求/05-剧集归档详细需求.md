# 剧集归档：详细需求与业务规则

关联需求：A-01～A-13、G-01～G-14。默认归档单位为整部源剧目录；同名目标存在时，操作可拆成季目录与根文件，但整剧资格要在第一项移动前确认。动漫专题集中见 11。

## 1. 业务目标

将已经符合归档条件的源剧集完整迁移到既定目标分类，保持目标原有资料，保证过程可核验、可恢复。不是只把文件搬过去，也不是看见目标有一个视频就完成。

本基线继承“源端已有全部实际季均可归档”的要求，不要求全剧永久完结。如果第一季完成而源目录中还有未完成第二季，则整剧暂缓；若源只有已完成第一季，可以归档第一季所在整剧，未来第二季再按增量季流程合入。

## 2. 整剧资格检查（A-01、A-02）

必须构建完整源清单：

- 全部实际季目录及其规范季号。
- 季内全部文件与子目录，含视频、配套和未知对象。
- 剧根全部文件与未知子目录。
- 每个对象的真实路径、类型、大小、修改时间与可用 ID。

每个实际季恰好对应一个有效报告行。检查两个方向：报告中的季都真实存在，真实季都在报告中有可用记录。绿色行缺少第二季不能导致整剧把第二季一起移动。

实际文件复查应证明来源集合、集号集合、版本、大小、临时文件和未决任务满足要求。手工改绿色可以表示用户意向，不能跳过物理与操作安全检查。

目录中出现未支持结构，整剧暂缓。为了输出报告可只读递归清点，但自动移动前必须对每一项有清楚归属。已核实的 extras/特殊篇应进入受保护清单，不能视为垃圾；若尚无迁移能力则暂缓。平铺文件形成的逻辑季须映射到物理移动单元，不要求伪造不存在的季目录。

## 3. 路径与身份（A-03）

源与目标须为不同、非包含关系的根；目标根和同名分类必须已存在。归档不隐式创建缺失分类。

目标同名定义：目录名必须精确匹配；可用 Unicode 正规化/大小写比较发现潜在冲突，但不能据此静默改名或合并。若 ID 有冲突即使同名也应阻挡。若 ID 相同但不同名，作为别名候选报告，待人工建立映射后重新规划。

真实操作必须使用文件 API 返回的原始路径，并绑定原报告的 profileId、sourceRoot 与 configRevision。用户改初检默认根不应改变旧报告的源路径；没有明确归档根/存储映射时只读检查并阻挡写入。不得把 Windows 路径规则盲目用于云盘路径；不得将 URL 的主机与当前服务不一致的 path 参数直接用于删除/移动。

跨云移动是否实际变成复制再删源，取决于服务实现，不能只根据方法名判断。本地适配是否允许跨云写操作必须单独验证；默认设计先约束在已验证的同一存储范围。

## 4. 归档模式与冲突矩阵（A-04～A-06）

| 源与目标情况 | 计划 |
| --- | --- |
| 目标分类没有同名剧 | 整剧目录移动，清单涵盖全部子内容 |
| 源仅 Season 2，目标同名剧仅 Season 1 | 全量预检后可把 Season 2 与缺失根资料合入 |
| 源 Season 1，目标 Season 01 | 同季冲突，整剧暂缓，不移动其他无冲突季 |
| 目标存在不同大小写/正规化同名目录 | 名称冲突，暂缓 |
| 目标为同名普通文件而非剧目录 | 类型冲突，暂缓 |
| 源与目标都有标准共用 poster.jpg | 保留目标版本；源副本列为有条件清理对象 |
| 源与目标都有 unknown.bin、README.txt、字幕或根视频 | 非白名单同名冲突，不能称为重复元数据后删除 |
| 源有目标缺少的普通根文件 | 明确列入迁移计划；若内容归属影响剧资格，先人工判断 |
| 源有未知子目录 | 整剧暂缓，不能迁移季后把未知目录随根删除 |
| 任一文件/季移动失败 | 保留源残留，停止清源并进入恢复流程 |

标准共用资料白名单必须可审阅且版本化，例如 tvshow.nfo、poster、fanart 等明确名称与扩展名组合。不能以“非目录”统一当作元数据；不能以“没有视频”判断可以删除。

## 5. 计划应包含什么（A-07）

ArchivePlan 至少包括：

1. 本剧身份、全部季行、源/目标根与分类。
2. 源完整清单、目标原有完整清单及稳定快照标识。
3. 模式：整剧移动 / 合入已有剧。
4. 每个移动操作的源对象、目标父路径、预计目标路径与递归子清单。
5. 必须保留的目标原有对象。
6. 可能删除的源端标准共用资料、删除理由、目标对应证据。
7. 最终源目录删除操作；明确先决条件。
8. 冲突、阻挡、计划版本、生成时间与批准依据。

确认时应能看到“移动多少季/文件、哪些目标已有资料保留、源端哪些副本将删除”。单独显示剧名与总数不足以审阅合入风险。

## 6. 执行顺序（A-07～A-10）

### 6.1 整剧移动

1. 锁定源剧与目标剧，检查没有在途整理/下载会继续写入。
2. 核对源清单与目标不存在事实，保存 pending。
3. 使用已验证的“冲突不覆盖”调用移动；不能依赖检查时不存在来防止提交瞬间新冲突。
4. 刷新源/目标及其父目录；对照清单逐项验证。
5. 可靠确认源路径消失且目标清单对应完整，保存 verified 后标紫。

### 6.2 合入已有剧

1. 第一项移动前对全部源与目标做冲突预检；有任一阻挡不开始。
2. 逐季/逐文件移动，每项提交前持久化，每项后核验。
3. 校验所有源迁移内容到位，目标原有对象未变。
4. 再次完整读取源端；仅允许为空或剩下计划中明确批准的标准共用资料。
5. 逐项清理列明的源副本，核验；再删除确认为空的源剧目录，核验源路径消失。
6. 保存最终清单与结果，全部通过才标紫。

这是对上游“源目录及列明资料清理”的更明确表达：任何未迁移文件、未知目录、字幕、失败元数据或新到达文件均阻止最后删除。不能递归删目录来掩盖之前移动失败。

## 7. 核验到底证明什么（A-08、A-10）

至少核对相对路径、类型、文件数量、字节大小和服务支持的稳定属性。修改时间若在移动时由服务改变，需要明确且经过验证的适配规则；不可无声忽略，也不可要求不可能保持的时间导致永远失败。

目标原有清单需保持；只有本计划新增内容可以出现。外部新增导致无法判断时标“计划后状态变化”，重新核验，不能为完成归档删除外部新文件。

核验层级：

- L1 路径/类型/集号：证明布局及集合。
- L2 大小/稳定标识/可比较时间：证明迁移对象基本一致；核心归档应达到可取得的这一层。
- L3 内容哈希/媒体探测：可选更强检查，取决于成本与 API 能力。

没有达到 L3 就不能宣传“字节级无损核验”。统计“目标有视频”只能证明非空，不能证明季数、集数和内容完整。

读取路径返回不存在与网络/鉴权失败分开处理。exists 应返回“存在/确定不存在/未知”或抛出异常，不能 catch 所有错误后返回 false。

## 8. 中断、部分成功与恢复（A-11）

| 观察到的状态 | 恢复处理 |
| --- | --- |
| 源在、目标无，且证明未提交 | 可重新制定/继续已批准且未变化的计划 |
| 源无、目标完整符合清单 | 核验并补记成功，不再次移动 |
| 源在、目标已有本次部分内容 | 对照 operationId 与清单识别已完成单元；剩余单元重新检查 |
| 源/目标均有同路径但内容冲突 | 人工处理；不能自动覆盖或删除任一方 |
| 源无、目标缺项 | 严重异常，停止其他写入并输出恢复所需证据 |
| 删除源目录请求超时 | 先只读核实，不能重复递归删除 |
| 进程重启只找到旧报告，无操作日志 | 不猜上次结果，重新清点并标人工核实 |

“整剧冲突时不开始”不意味着云端多操作具有数据库事务。中途可能部分成功；应靠持久操作日志恢复，不承诺自动回滚。反向移动也会遇到新冲突，须另行形成计划。

## 9. 归档后审计（A-12）

独立 verify/audit 的目标是输出事实和差异，默认没有删除副作用。

审计应检查：

1. 本轮每个归档对象是否逐项存在于目标，原目标对象是否保留。
2. 本轮应离开的源对象是否确实消失。
3. 本轮应留下的源对象是否仍在；范围外对象作为观察信息，不混入本轮预期数量。
4. 同 ID 异名残留是否存在，包含哪些文件、是否属于本轮计划。
5. 所有未知、失败、源残留、目标缺项是否进入最终摘要，不能只打印警告而返回成功。

同 ID、不同目录名、0 个可识别视频并不等于空目录：可能有字幕、NFO、压缩包或更深层视频。因此别名清理应生成独立计划，检查全树和归属；本次核心归档不顺带删除历史别名。

对账应比较集合及对象，而不只比“剩 5 部”。局部选剧时源分类当然可能还有其他剧，不能把它们全部当作对账失败。

对应验收：T-A01～T-A15、T-F01～T-F09，以及 T-I13～T-I15 的根范围、T-N 的动漫保护/电影隔离场景。动漫专属规则见 [独立动漫专项](11-动漫整理专项需求与命名规范.md)。
