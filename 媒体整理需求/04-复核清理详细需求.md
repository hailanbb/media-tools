# 复核清理：详细需求与业务规则

文档基线：1.4（2026-10-29）。Python 当前核查见 13；历史研究/其他实现核查保留原时点。

关联需求：R-01～R-13、G-02～G-07、G-10。该阶段的中心是证明“保留集完整且受到保护”，然后才讨论删除。动漫专属文件关系与配套保护集中见 11。

## 1. 输入、输出与完成条件

兼容流程默认读取黄色项，也支持未来按明确任务 ID 选择需要复核的季。颜色仅提供入口，实际阻挡状态始终生效。

输入：可信季身份、来源政策、历史操作记录、当前完整文件列表。输出分为：

1. 复核事实：来源、真实文件、集号与版本、异常。
2. 清理计划：逐文件保留/删除/保留配套/未知对象及理由。
3. 实际结果：每个请求与最终核验，成功、失败、未提交、待核实分开。

无须删除而已经符合全部要求的季，也可以复核通过；不能以“删除文件数大于零”定义阶段成功。

## 2. 来源与清理资格（R-01～R-03）

来源必须能证明本季应保留集合。用户已于 2026-10-27 确认：**默认使用 TMDB，本地可信集号超出 TMDB 本季登记范围时，用豆瓣复核**。不要求所有季一律先查豆瓣；这是相对于上游“豆瓣对应季为准”的明确调整。

例如 TMDB 登记 16 集、本地有 E17，先核对豆瓣同剧同季；不能先把 E17 当作多余文件删掉。豆瓣确认 18 集时，保存两来源证据并按核实范围重新计算版本完整性；豆瓣失败、身份不符或仍无法解释 E17 时，暂缓该季清理。文件数超过 16 但只是重复版本，不因此触发豆瓣。

豆瓣证据统一经用户 MoviePilot v2.15.6 获取，先解决编号/分部映射，再比较范围。若初检已产生有效的同季豆瓣复核证据，可校验并复用；实际清理前重新扫描发现新的超范围，必须重新检查证据是否仍适用。不能只读取报告里的一个数量或 MP 推导的默认季号就声称实现了该政策。

严禁使用“来源数量为空 → 视频文件数”兜底。否则缺 E03、目录只有 E01/E02 时会误认为本季就两集。

先检查：

- 目录路径、季号、剧 ID 与任务一致。
- 文件列表完整、稳定，读取失败不当空。
- 不存在未决下载/修复/删除/移动记录。
- 修复目标集已在正确位置出现，且符合目标版本与属性证据；光有同号其他版本不够。
- 没有临时下载文件或仍在写入的对象。
- 未知子目录、合并集、错季、超范围视频、未知文件名已经形成明确处理结论。

普通未知配套文件默认保留，不一定阻挡一切清理；但若它使归属、完整性或计划范围无法证明，应阻挡。不要将“保留未知文件”误解为“可以忽略影响核心判定的未知视频”。

## 3. 版本分组（R-04、R-05）

共享版本识别器至少应输出：versionId、可读标签、集号集合、文件集合、缺失/超范围、完整性、可信修改时间、身份置信依据。

推荐用统一集号解析器识别集号片段，再将片段替换为占位符建立模板；不能只对 SxxExx 做替换，而使 EP01、EP02、01、02 被分成不同版本。

文件扩展名、发布组及技术标记如何参与版本身份应明确且稳定。扩展名大小写应正规化；不同容器是否同版本不能仅凭后缀判断，证据不足分开并标待确认。

| 分组结果 | 允许行为 |
| --- | --- |
| 没有完整版本，整体仍缺集 | 不清理，输出各版本缺集 |
| 没有完整版本，但版本并集齐全 | 明确偏好允许混版且逐集保留可决定时生成计划；否则人工/同版本补缺 |
| 唯一完整版本，其他不完整版本 | 可继续制定保留该完整版本的计划 |
| 多个完整版本 | 按明确偏好及可信版本证据自动择版；未配置、并列或不能满足字幕/语言等要求时转人工 |
| 版本归属不足 | 不猜组，保留并说明证据缺口 |

完整性基于期望集号集合，而非文件数量或最大集号。多余的 E00/E99、样片等不能因某组覆盖 1..N 就被隐藏。

## 4. 同集文件与副本判定（R-06、X-10）

同集多文件可能是相同副本、不同画质/剪辑/音轨版本、上下段或正片与加更。先证明关系再确定保留；修改时间、文件大小、同名或文件名中的 CRC 字样都不能单独证明内容相同或质量优劣。

可靠内容校验一致且明确为同一副本时，可提出保留已确认主目录副本的计划，同时保护各副本旁独有字幕/附件。不同版本依据明确收藏策略决定，可自动形成择版计划；证据不足时保留待核实，不按“较新”自动淘汰。偏好允许混版时保留其混版标识，不能称为单一版本。

本版替代旧“同版本少量副本按修改时间选最新”规则。原始时间仍记录，用于追踪；任何保留对象不能确定，都不能执行依赖其完整性的本季删除计划。

跨目录复核使用全部已关联的本季文件。目录 A/B 或日/韩/中文名称差异本身不构成版本差异；并集齐全但版本不一致仍按混版处理。

### 4.1 可选目录归并

初检先给出可行性，复核形成具体治理计划。逐项列明原→目标、保留、移动、重复候选、配套与未知内容；目录归并和冗余删除分别确认。冲突不覆盖，无法确定保留对象时不执行依赖该决定的计划。

可选择保持分散布局、归并到源主目录，或在该季具备归档资格后直接按完整计划归入归档目标，避免无必要的二次搬运。详细规则见 [12 专项](12-同剧多目录与分季归档专项需求.md)。

## 5. 删除范围与配套文件（R-07）

| 对象 | 默认规则 |
| --- | --- |
| 已明确淘汰版本的视频 | 可列入计划，附版本与集号理由 |
| 已有可靠证据证明冗余的同内容副本 | 可列入计划，附保留对象、内容/身份依据及附件保护；不按时间单独决定 |
| 唯一属于拟删视频的 NFO / 缩略图 | 可随其列入计划；一对多或含糊归属不删 |
| tvshow.nfo、poster、fanart、season 共用图等 | 保留 |
| .srt / .ass / .ssa / .sub / .idx 等字幕与索引 | 仅经核实只属于淘汰视频、保留版需求已满足且配对完整时可列清理；共享/未知/仍需字幕保留 |
| 未识别文件、压缩包、未知图片 | 保留，必要时人工处理 |
| 目录、嵌套目录 | 不作为本阶段普通文件清理对象 |

关联规则必须解释：例如“文件主干精确等于某视频主干”，或“主干为该视频主干加 -thumb”。仅共享前缀不构成唯一归属。

若保留视频也可能使用该配套文件，即使拟删视频同名，也不能删除。用户已允许清理经核实仅属淘汰视频的字幕；是否独占与是否仍需要要分别核实，不能只凭同名、语言后缀剥离或“看似孤立”决定。

## 6. 计划、执行与并发变化（R-08～R-10）

计划包括 planId、taskId、规则版本、来源证据、完整目录快照、保留集合、删除集合、配套保留集合、阻挡项、生成时间与计划摘要。

提交前比较的不只是待删文件，还包括保留文件和目录其他对象。新文件到达、旧文件被替换、修改时间/大小改变、发现子目录，都可能使原计划失效。

建议执行步骤：

1. 读取共享未决记录并获取该季锁。
2. 重新列目录，对比原快照减去已验证删除对象。
3. 保存本批 pending 及逐文件属性；保存失败不发送。
4. 调用适配器删除计划中的确切对象。
5. 强制刷新并读取，必要时有界等待最终一致性。
6. 逐文件确认待删对象消失、保留对象存在且属性不变。
7. 保存逐文件结果，再决定能否进入下一批。

上游浏览器实现每批最多 50 个，不代表本地 CD2 API 已验证支持相同批次能力。Windows 适配可先顺序单文件；将来启用批量必须确认协议、限制与逐文件核验，不能把“批次返回成功”当成 50 个全部成功。

遇超时或部分成功：停后续批次，保存已确定结果，其余为待核实。恢复只读检查，不能重发整批。用户暂停后先处理已经发出的本批结果，再停发后续。

## 7. 删除后放行（R-11）

复核通过至少同时满足：

- 真实存在的保留集合覆盖完整期望集合且符合明确版本策略，且每个逻辑集的保留归属明确。普通单版本单集模式为每集一个对象；明确保留多版本时按各目标版本分别核对；合并集/分段不得套用这个数量条件，须使用经过验收的文件覆盖关系，否则暂缓。
- 所有计划删除的结果已核验；没有未决写操作。
- 保留视频、共用资料和其他受保护对象未被改动或丢失。
- 修复状态已通过文件核验闭环。
- 本季播完证据成立；来源冲突已解决。
- 无新的未知/超范围/错季/下载中问题。

若本季仍连载，只能报告“当前已播集合/拟保留版本的已播部分齐全”，不能标为可整季归档。是否允许连载中清理旧版本属于额外政策，不应仅因当前已播集齐全而自动开放；本基线的自动完整版本清理以可信完整季集合为前提。

### 分季归档的配套保护

清理/归并不能破坏仍留源的其他季。tvshow.nfo、根海报、公共字幕/字体以及跨季文件按归属记录；无法独立切分时阻挡受影响季，不能为归档一季删除整个源剧目录。

## 8. 审计与报告（R-12）

复核阶段报告记录检查尝试、来源、版本分析、计划，不随实际执行被改写成“已经删除”。实际清理报告记录 operationId、每个文件、原因、请求时间、核实时间、状态及错误。

必须按实际对象记成功。例如删 A 失败、删 B 成功，记录成功项必须是 B，不能用“成功计数=1”截取计划前一个 A。

汇总至少区分：检查季数、可清理季数、无需清理通过季数、人工判断季数、实际已删文件数、失败数、待核实数。不要把“完成循环”显示为“全部清理成功”。

对应验收：T-R01～T-R12、T-F01～T-F09，以及 T-N 的合并/分段、修订多版本、字幕字体和附加内容场景；细节见 [独立动漫专项](11-动漫整理专项需求与命名规范.md)。

## 9. 1.4 自动择版与字幕清理的边界

2026-10-29 用户明确允许按偏好自动择版，以及清理经核实仅属淘汰视频的字幕。偏好至少明确收藏模式、保留版本数量、画质/语言/字幕等优先条件及是否允许混版；默认优先完整单版本，混版需明确允许，未配置或并列不能硬选。分辨率、体积、名称和修改时间是线索，不单独证明文件优劣、字幕兼容或内容完整。

字幕删除计划必须逐文件证明：被淘汰视频身份明确；不为任何保留视频/其他季共享；保留版本满足需要的语言、强制字幕/特效等要求；idx/sub 等配对及相关依赖已核对。字体、章节、封面共用资料与未知附件不因本次字幕政策而扩大删除。字幕迁移/重新关联如需实施应单列计划，不能以将来可能重下字幕代替当前保留证明。

零字节、大小未知、写入中和损坏分别标记。执行前比对完整快照，执行后重新核对保留清单；按回执计数和刷新请求不足以证明删除及完整性。审计准确写出成功/失败/未知的对象，不能取计划前 N 项替代真实成功项。阶段后 JSON 日志不替代事前记录。对应 Y-05～Y-07、Y-11，当前实现差异见 [13 专项](13-Python版更新核查与需求补充.md) P-06～P-08。
