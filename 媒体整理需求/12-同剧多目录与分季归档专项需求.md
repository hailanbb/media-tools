# 多语言同剧目录、跨目录初检与分季归档专项需求

日期：2026-10-29 · 文档基线：1.4 · 范围：业务需求、方案与验收

用户要求在初检时统一识别多目录、多语言名称及各季覆盖，避免盲目补缺，并考虑已完成季先归档、未齐全或连载季留源。本次据此更新需求文档；不涉及程序修改或真实媒体操作。后台自动执行边界继续保留待讨论。

本稿以该目录在提交 `d3bd0cb89cfabc4c023c34b12094ae512776790d` 中的 14 份 Markdown 文档为核对基线；它们与此前已审阅的发布文档内容一致。本次在各分册同步修订规则。具体媒体身份、主目录选择与文件保留对象仍依据实际证据和具体计划决定。

## 1. 案例、已知事实与尚不能确定的事项

用户描述的源分类为：

    /115/Library_incs/nas/电视剧/综艺/

| 项目 | 目录 A | 目录 B |
| --- | --- | --- |
| 剧目录 | 奔跑吧！兄弟 (2014) [tmdbid=98031] | 奔跑吧兄弟 (2014) [tmdbid=98031] |
| 季目录 | Season 13 | Season 13 |
| 用户描述的集号 | E01–E10 | E10–E13 |

用户指出 TMDB 中文显示名为“奔跑吧 (2014)”。本次读取的 [TMDB 第 13 季页面](https://www.themoviedb.org/tv/98031/season/13?language=zh-CN)列出 E01–E13，E13 标有季终信息；但检索结果带有缓存时间，不能用它证明用户下一次执行时的数据仍相同。实际工作流需要保存届时的来源、语言、集目与查询时间。

在“文件确实对应这些正片集号、均能正常列出”的前提下：

| 指标 | 应得到的结果 |
| --- | --- |
| 作品身份候选 | 一部作品：TMDB 的 TV 条目 98031 |
| 物理剧目录 | 2 个 |
| 集号覆盖并集 | E01–E13，共 13 个不同集号 |
| 集号重叠 | E10，位于两个目录 |
| 若每集各为一个普通视频文件 | 合计 14 个视频文件；不等于 14 集 |
| 若本季有效应有集合确认为 E01–E13 | 普通补缺为空 |
| 文件内容、版本与质量 | 尚未检查，不能认定 E10 为可删除副本 |
| 建议状态 | 集号覆盖齐全；同剧分散存放；E10 重复候选待复核 |
| 当前能否直接归档 | 不能仅凭上述描述放行；还需版本、季终、路径、所选季跨目录清单与共享依赖及相关未决任务检查 |

“TMDB 名称变化导致 MoviePilot 创建不同目录”是合理的原因假设，尚不是已证实的根因。不同语言、缓存、历史识别结果、命名设置或人工改名也可能形成类似现象。需求应覆盖结果本身，不依赖先证明唯一原因。

**本例应避免的错误：**分别为 A 下载 E11–E13、为 B 下载 E01–E09；把 14 个文件当作超出 13 集；按目录名挑一个目录删除；把两个 E10 直接视为同内容；因为并集齐全就认为已有单一完整版本。

## 2. 核心目标与概念

### 2.1 核心目标

以可信作品身份关联分散内容，以经过核实的季集映射计算覆盖；名称作为展示与搜索信息，物理路径作为实际存放位置。四阶段共享同一份作品、收藏范围、目录关系与状态，避免某阶段重新按名称拆成不同任务。

### 2.2 必须分别记录的概念

| 概念 | 含义 | 本例 |
| --- | --- | --- |
| 作品身份 | 数据来源 + 媒体类型 + 来源 ID；名称和年份为辅助证据 | TMDB + TV + 98031 |
| 收藏范围 | 用户希望共同管理的一套收藏，限定媒体库、存储和收藏目的 | 该综艺分类中的这一套收藏 |
| 显示名称 | 来源当前名称，可随语言或元数据变化 | 奔跑吧 |
| 历史别名 | 曾用于识别、目录或资源搜索的名称及其出处 | 奔跑吧！兄弟、奔跑吧兄弟 |
| 物理目录实例 | 一个真实存在的目录；保留原始路径和可取得的稳定标识 | A、B 分别保留 |
| 主目录 | 用户确认的后续存放位置；属于特定收藏范围及源库/归档库角色 | 待确认；不是根据本次标题临时拼出的路径 |
| 逻辑季 | 同一作品、收藏范围和已确认编号体系下的一季 | 98031 的第 13 季 |
| 版本 | 发布版本、剪辑、音轨/字幕等足以影响保留选择的差异 | 尚未知，不能按目录 A/B 直接分版本 |

同一 ID 是关联同一作品的重要证据，但不自动证明目录标签正确，也不代表所有副本都应合并。例如，同一作品可以有 4K 收藏、1080p 收藏、不同语言版和备份库。

### 2.3 三个判断独立成立

1. **作品相同：**这些目录是否确实属于同一作品及对应季。
2. **覆盖齐全：**所需逻辑集是否在已核实的收藏范围内出现。
3. **可执行整理：**版本选择、目标目录、冲突、附件和外部任务是否都已明确。

“作品相同”不能直接推出“删除其中一个目录”；“覆盖齐全”也不能直接推出“版本完整”或“可以归档”。

## 3. 目录关联与处理范围

### 3.1 发现同剧目录

默认在本轮已选的根与分类内发现同 ID 目录，展示全部候选及理由。分别核对目录 ID、文件/元数据中可用的身份、季号和编号体系；出现明确矛盾时标身份冲突。

| 情况 | 需求规则 |
| --- | --- |
| 同根、同分类、同 ID，季与编号一致，无相反证据 | 形成同剧关联候选，并给出可解释的合并覆盖视图 |
| 同 ID，名称、标点或年份有差异 | 名称差异不拆作品；年份差异保留为待核实信息，不自动改名 |
| 同 ID，但目录属于明确不同收藏版本或备份用途 | 保持独立收藏；可提示重复，不互相抵扣目标版本缺集 |
| 同名、不同 ID | 保持不同作品，不能通过去标点或模糊匹配合并 |
| 名称相近、没有 ID | 只给候选，补充身份或人工绑定后再参与可信聚合 |
| 目录 ID、NFO、已识别媒体身份明显冲突 | 阻挡受影响对象；不任取其中一个 ID |
| 跨分类、跨根、跨存储或源库与归档库之间发现同 ID | 先提示关系；只有已确认属于同一收藏、路径可核验时才用于该收藏的覆盖判断 |
| 多个路径实际指向同一对象或根范围重叠 | 只计一个物理对象；别名入口保留，不制造虚假重复文件 |

一次查询失败、目录缺页或一个关联目录不可达，应标“覆盖核对不完整”，不能当作该目录没有文件。

### 3.2 只选单个目录时

“只检查 A 目录”和“检查作品 98031 的全部已关联目录”必须是两个清楚的范围选择。

- 只检查 A 时，可报告 A 内局部缺 E11–E13，但不能将它直接标成整套收藏缺集。
- 若既有索引提示 B，展示“另有同剧目录尚未纳入本次检查”。新增补缺前需完成相关覆盖核对。
- 用户明确限定一个路径时，不默默扫描或移动范围外目录。
- 只读关联范围、后续移动/删除范围分别列出；确认关联不等于批准物理归并。

### 3.3 多个实际目录归属一套收藏

首次发现多目录时，先给出带依据的聚合结果。同一已选根与分类、可信身份与编号一致、没有独立收藏标记或相反证据时，可作只读关联并据此避免重复补缺；关系有歧义时待确认，不让“尚未合并目录”变成重复下载理由。涉及物理归并、版本取舍或跨收藏范围时，须明确关系与具体计划；保存决定，下一次同一关系不必反复询问。

新增第三个同 ID 目录仍要列入异常与范围变更检查，不能因为旧绑定存在就自动扩大删除或移动对象。

### 3.4 多语言目录识别与中文名称

初检需要识别日文、韩文、简体和繁体中文目录；原始名称与真实路径必须保留。中文名称用于展示、候选查找和建议命名，初检不直接重命名。

1. 先提取并验证来源 ID、媒体类型及年份等身份信息。有可信 ID 时取得该作品中文标题、原名、已登记译名/别名，建立同一身份下的名称关系。
2. 中文显示优先使用用户已确认的中文名，其次可信来源的简体中文标题；没有时可使用该作品的其他中文译名并提供简体显示，记录原始地区/语言。
3. 繁简、全半角、空格与标点正规化只生成比较键；日文汉字不能直接当繁体中文转简体，日文/韩文转中文需要作品身份及译名对应，不能靠逐字翻译认定作品。
4. 无 ID 时用原名、可信中文名/别名、类型、年份及季/分部等生成候选；来源身份得到唯一、可解释的核实后可关联，多个候选或证据不足时明确待核实。
5. 中文显示名确定后，在已允许的扫描范围内查找同中文名/别名及同 ID 目录，保留所有候选。中文同名但 ID 冲突必须分开；没有 ID 的中文目录不能只凭同名并入。
6. 无可靠中文译名时保留原名，显示“中文名待确认”。机器翻译如作为候选建议须标明未经核实，不写成官方名称，不据此合并、补下或改名。
7. 改成中文物理目录名属于后续可选治理计划，必须显示原→目标路径并处理重名冲突；不自动把字幕、视频和元数据全部改名。

记录原名、简体显示名、可信别名、来源/语言、身份核实状态和匹配理由。[TMDB 译名说明](https://developer.themoviedb.org/reference/tv-series-translations)提供作品已登记译名的查询；[语言说明](https://developer.themoviedb.org/docs/languages)说明语言参数语义。这些能力不保证每部作品都有中文名。

### 3.5 多目录中的相同季与不同季

先建立“目录 × 逻辑季”清单，再在每个逻辑季内聚合。不能要求所有目录拥有相同季，也不能将不同季的集号合在一起抵扣。

| 物理目录 | 第 1 季 | 第 2 季 | 第 3 季 |
| --- | --- | --- | --- |
| A | E01–E06 | E01–E03 | 无 |
| B | E07–E12 | E03–E05 | E01–E02 |
| 聚合事实 | E01–E12 | E01–E05，E03 重复候选 | E01–E02 |

逐季取得各自应有集合与播期。第 1 季若本季应有 E01–E12 且版本相容，则可形成归并后完整方案；第 2/3 季仍需各自判断缺集、待播与版本。某目录没有第 3 季不意味着必须给这个目录下载第 3 季。

初检输出“可否归并成完整季”的依据与阻挡：同版本互补可计划归并；不同版本并集齐全只算集号覆盖；有重叠集先复核；确有已播缺集才补下；来源、身份或读取不完整则暂缓。跨季合并文件或公共附件无法分离时，关联季的移动计划需一并评估。

## 4. 名称变化与主目录政策

### 4.1 建议采用“显示名可更新，主目录保持稳定”

1. 最新名称、原名、历史别名分别保存，记录语言、出处与观察时间。
2. 已确认主目录继续使用。仅有标题、标点、译名或年份展示变化，不自动移动目录，也不重建收藏或下载任务。
3. 首次出现多个别名目录且尚无主目录时，提供已有目录与按当前可信名称生成的新目录建议，由用户选择；不静默创建第三个目录。
4. 如果用户选择统一为“奔跑吧 (2014) [tmdbid=98031]”，它是一次明确的目录治理决定。将来来源再改标题，也不自动再次迁移。
5. 既有归档库主目录优先复用。若源库与归档库的主目录不同，记录各自角色和映射，不强求两处显示名同步。
6. 更改主目录时，重新核对旧路径引用、待处理任务、配套文件及目标冲突。只改报告标题不能视为完成迁移。

不建议“每次扫描都改成 TMDB 最新名称”：这会让元数据变化持续变成物理路径变化。

### 4.2 元数据变化分级处理

| 变化 | 需求行为 |
| --- | --- |
| 标题、译名、标点或简介变化 | 更新展示/别名记录，主目录保持；不自动重下、不自动改号 |
| 年份修正 | 重新核对身份辅助证据，目录是否调整另列计划 |
| 本季登记新增集目 | 保存前后差异，重算已播/待播/未知与缺集；有条件才产生补缺 |
| 本季登记集目减少或集号重排 | 标来源结构变化；原有文件不自动变成“多余”，旧清理/归档计划重新核对 |
| TMDB 条目合并、删除或更换 ID | 保留旧身份与证据；核实新旧映射后显式迁移，不按同名自动替换 ID |
| 默认分季与剧集组发生变化 | 原编号证据保留；映射确认前阻挡依赖该编号的补缺、清理与归档 |

核对一批目录时使用同一份有效来源快照，避免 A 按旧 12 集、B 按新 13 集计算。执行前若发现集目或身份实质变化，重新生成相关计划；显示名变化不应自行改变既定文件目标。

## 5. 四阶段需求

### 5.1 阶段一：剧集初检

初检先列清物理对象，再产生逻辑作品与季的聚合结果。保留目录明细，不用汇总行替代证据。

普通季集模式下，按以下集合区分：

    已核实覆盖 = 已关联且检查完整的各目录有效正片集号并集
    已播缺集 = 来源中已确认已播的应有集号 − 已核实覆盖
    超出登记范围 = 同一编号体系下有效本地集号 − 来源有效登记集号

版本未知时只能给集号覆盖事实；同版本完整性另行判断。合并集、多段文件以及上下期不能直接套用“一文件一集”。

本例确认来源为 E01–E13 后，聚合报告应为：

| 展示项 | 示例结果 |
| --- | --- |
| 作品 | 奔跑吧 (2014)，TMDB 98031 |
| 季 | 第 13 季 |
| 关联目录 | 2 个，可展开 A/B 原路径 |
| 不同集号 | 13，E01–E13 |
| 视频文件数 | 依真实清单；普通单集假设下为 14 |
| 普通已播缺集 | 无 |
| 重复候选 | E10：A 一份、B 一份 |
| 版本完整性 | 待复核 |
| 目录治理状态 | 分散存放，主目录待确认 |
| 建议下一步 | 复核 E10 与版本归属，确认主目录或保留分散布局 |

不因目录分散而将全部文件判为缺集，也不因并集齐全提前标为无异常绿色。报告应分别显示覆盖、版本、目录、播期和下一步状态。

既有豆瓣政策保持：只有可信本地集号在同一编号体系下超出 TMDB 本季登记范围时，经 MoviePilot 复核豆瓣。本例 E10 有两份，不增加不同集号，不因此触发豆瓣。若实际出现 E14，而 TMDB 仅列 E01–E13，才进入已确定的复核流程；TMDB 页面单纯改名不新增豆瓣触发条件。

### 5.2 阶段二：补缺下载

普通补缺以收藏范围内的可信聚合结果为起点，不再为同一作品每个别名目录单独计算需求。

1. 搜索前核对关联目录、已归档内容、现有下载、待整理文件及结果未明的操作。
2. 只有属于同一收藏且位置、身份已核实的已归档内容，才可抵扣该收藏缺集；同时标清“位于归档库”，不伪装成源目录已有。
3. 下载管理中的名称变化不能生成新任务身份。匹配作品、季、覆盖集号、收藏目的与目标版本；旧标题只作为辅助。
4. E01–E13 已覆盖时，普通补缺为零。E10 重复候选转复核，不再次下载 E10。
5. 若并集齐全却由版本 A/B 拼成，普通覆盖齐全仍成立；只有用户选择保持单一版本且目标明确时，才产生“目标版本补缺”。报告必须解释为什么在已覆盖情况下还需要下载。
6. 已下载但整理至旧名称目录的文件，应先识别为现成内容或整理待治理，不按“新名称目录为空”重新下载。
7. 对已有下载/整理中的集号，记录待到位；任务覆盖不明或状态未决时暂缓重复提交。

搜索需求区分“找作品”和“找资源”。有可信 ID 时以作品身份约束结果；资源站使用的旧标题、原名、译名可能不同，允许在不足时按已验证别名补充查询并合并资源候选，但每个候选仍需核对作品、季号和编号体系。不得仅因名称相似或包含“奔跑吧”就接受。

这些是对 MoviePilot 联动结果的需求，不表示已经证明某个公开接口可以指定任意最终文件名或目录。

### 5.3 阶段三：复核清理及可选目录归并

保留四阶段结构。把“目录归并”作为本阶段独立展示、独立确认的治理子流程，明确区分三种结果：

- 仅复核并关联，暂时保持两个目录。
- 将同一收藏的互补文件归并到已确认主目录，暂不删除未定副本。
- 在完整保留集合已确定后，清理明确冗余文件。

归并计划与清理计划各自列明对象；用户可以只同意其中一种。一次不可分割的计划若有未决冲突，整份计划暂缓；如希望先处理无冲突内容，应另生成边界明确的部分计划并展示残留状态。

**E10 的处理规则：**

| 核查结果 | 处理 |
| --- | --- |
| 已验证可靠内容校验一致，确属同一视频副本 | 可提出保留主目录副本的建议；删除另一份仍须在清理计划中列明，先保护附件 |
| 一份经可信检查确认为损坏/未完成，另一份完整有效 | 展示证据，提出保留有效文件的计划；不能仅凭大小差异作此判断 |
| 画质、剪辑、发布组、音轨或字幕版本不同 | 按明确收藏偏好形成择版计划；未配置、并列或证据不足时保留待判断 |
| 属于“上/下”“正片/加更”等不同内容 | 不是重复副本；先核实内容角色与编号，不按 E10 删除其中一份 |
| 只有文件名、大小或修改时间可比较 | 证据不足，不自动选择和删除 |
| 同名同大小但内容未核实 | 仍是重复候选，不声称字节相同 |

本版修订原 R-06：“同版本少量重复按可信修改时间选最新”改为“先证明副本/版本关系，再决定保留；修改时间仅为辅助信息，不能单独确定优劣”。下载、复制和迁移都可能改变时间，新文件并不必然更好。这一规则变更已同步到核心基线、复核分册和验收表；它不预先选定本例 E10 的保留对象。

**归并计划至少展示：**主目录、所有参加目录、每个文件的原路径/目标路径、集号与版本、保留/移动/待决定项、关联字幕及附件、同名冲突、执行先决条件和完成后预期清单。

互补视频可以在已确认的计划中逐项归并；冲突文件不得覆盖。NFO、海报、字幕、字体、章节和未知文件分别处理；两个 tvshow.nfo 不能因名称相同就认定内容相同。只改目录名不自动要求批量改视频名。

### 5.4 阶段四：按已完成季增量归档

默认需求支持按已完成季归档；保留“整剧归档”作为显式选择。每次计划都写明模式和季范围，旧报告或上次任务不能静默改变本次模式。只有在全部源内容均符合条件且计划明确包含整剧时，才可整体移动剧根。

**A 有齐全的 S01 和未齐全/连载中的 S02：S01 通过复核即可单独归档，S02 留源。**不要求等 S02 完成，也不要求所有已登记但从未收藏的季都出现。S02 若只是当前已播集齐、仍有待播集，也不能当作已完成季。

| 季状态 | 处理 |
| --- | --- |
| 本季已播完、应有集齐全、目标版本明确、无相关冲突或未决任务 | 可列入本轮归档 |
| 已播完但缺集 | 留源；先核对别名目录、已有下载/待整理，确有已播缺口再补缺 |
| 连载中且当前已播齐全 | 留源等待后续，不重复下载、不提前标季完成 |
| 连载中且已播有缺集 | 留源补已播缺集，未来集继续等待 |
| 来源/播期未知、身份冲突、读取不完整 | 留源待核实，不盲目补缺 |
| 集号齐全但混版、重复或附件关系未决 | 留源复核；普通缺集与版本治理分别记录 |
| 同季文件分散但可归并成完整目标版本 | 先形成治理/归档计划；可直接按完整计划合入归档目标，无须为了归档先重复搬到源主目录 |

检查同收藏全部已知关联目录，以发现目标季的其他文件、附件和任务；归档写入只限选定季。其他季独立的缺集或连载状态不阻挡已完成季；作品身份冲突、跨季物理文件、无法隔离的共同任务或共享附件冲突会影响关联季，应明确阻挡范围。

季内文件归并与归档遵循以下规则：

1. 同一逻辑季可以有多个物理季目录；一行季汇总对应多条目录/文件明细，不按重复行直接拒绝。
2. 目标以可信作品/收藏绑定与主目录查找；异名同 ID 先核对。源目标同季只有逐文件互补与冲突检查通过，才可在具体计划中合入，绝不直接覆盖整个 Season 目录。
3. 明确归属所选季的字幕、海报等配套一并列清。剧根 tvshow.nfo、海报及跨季共用资料在仍有留源季时保留；归档目标需要副本时单独列出“不覆盖复制”的范围。归属不明时保留，必要时阻挡相关操作。
4. 留源季的文件、目录及必要资料不变；不因 S01 成功而删除整个剧根。源季目录仅在计划内对象全部核验且确为空时才可收尾移除。
5. 本轮结果区分“所选 S01 归档完成”“S02 留源待处理”“本收藏仍有未归档季”。紫色只作用于已核验季，不把整剧标完成；预期保留项不算错误残留。
6. 后续 S02 完成时增量归入同一已绑定归档主目录。已归档 S01 新到达旧目录的文件作为待核对新增内容，不凭旧紫色忽略，也不自动重下或删除。
7. 最后一个可归档季离开后，剧根是否清理仍单独核对所有残留；有字幕、NFO、未知文件不等于空目录。归档审计保持只读。

### 5.5 初检到补缺/归档的分流

    发现目录与季 → 核实身份/中文名/别名 → 同收藏逐季汇总
      → 读取或身份不完整：待核实
      → 其他目录已有：归并/复核，不重复补下
      → 已播真缺：先核对在途和待整理，再补缺
      → 仅待播缺口：留源等待
      → 集号齐但版本/重复未决：复核
      → 本季已播完且完整、可安全分离：按季归档

每个分流必须在报告中解释理由；不能按颜色或一个缺集数量直接触发下一动作。

## 6. 防止后续再次分散

目录治理的结果不仅是合并一次，还应让后续下载与整理继续落到已确认位置。

- 后续工作流使用稳定作品/季身份和已确认主目录，不能按最新显示名重新决定路径。
- MoviePilot 任务保留自身任务标识、原识别名与原始历史；另记当前关联目录及实际结果。不把历史标题改成新标题来假装历史没有分歧。
- 整理前能够核对目标时，应检查目标与主目录映射一致；无法确定最终目标时明确标“路径待核实”。
- 整理后再次检查实际落点；若又出现新别名目录，提示“同剧新增目录”，关联核对后更新报告，不自动重复下载。
- 外部 MoviePilot 订阅、其他脚本或人工操作可能独立写入。工作流只能对其管理范围内的任务作出保证，不能宣称已控制全部外部写入。
- 实际目录迁移期间要协调相关下载/整理任务。无法保证同剧没有在途写入时，只形成计划或等待；不能通过连续几次目录无变化就宣称已永久排除外部写入。
- Emby 可能仍引用旧路径。需求中应记录旧→新路径、媒体识别结果与必要复查项，不承诺移动后播放记录必然保持，也不隐式修改 Emby 数据库。

普通补缺继续沿用既有 MoviePilot 下载位置；云盘路径与 MoviePilot 容器路径分别记录，经确认映射使用。统一主目录并不意味着把 `/115/...` 直接填入下载器。

## 7. 举一反三：适用场景与处理边界

| 场景 | 应采用的需求规则 |
| --- | --- |
| 标点、繁简、空格、全半角不同 | 可辅助发现别名；同一可信身份不会因此拆任务，原路径保留 |
| 中文名、英文名、日文名及旧译名并存 | 维护有出处的别名；搜索可补充名称，资源仍验证身份 |
| 来源标题改动但 ID 不变 | 更新显示和别名，主目录保持，不自动重下 |
| 同名翻拍剧、电影和电视剧 ID 数值恰好相同 | 来源与媒体类型共同限定身份，不按裸数字或同名合并 |
| 一个目录含 E01–E10，另一个含 E11–E13 | 聚合覆盖后无需普通补缺；明确版本后可计划归并 |
| 两目录有多个重叠集 | 按每个物理文件核对；一个集号的决定不能替代整季版本检查 |
| 两目录分别是 4K/1080p，用户有意保留 | 两套收藏或版本目标分别核对，不互删、不用另一套抵扣目标版本缺集 |

| 备份库里有 E13、主收藏库没有 | 默认只是备份提示；未经收藏范围确认不能直接当作主库完整 |
| A/B 季目录分别叫 Season 13、Season 013 | 核实为同一逻辑季后聚合；原路径均保留 |

| 正片、加更、会员版、上下期共用日期或 E10 | 内容角色、版本与集覆盖先核实，不按同号当冗余 |
| 动漫 Part 2、绝对集号、不同剧集组 | 遵循独立动漫专题；先映射季集，再聚合和比较范围 |
| 一个视频覆盖 E09–E10，另一文件是 E10 | 不能因 E10 重叠而删除合并视频，避免丢 E09 |
| 初检只扫到 A，B 无权限或分页不完整 | 覆盖未知/不完整；不据局部缺集自动下载 |
| 下载完成后尚未整理，或整理历史标题仍旧 | 关联现成文件与在途任务，先等待/核对，避免重复提交 |
| 刚归并完成，订阅又写入旧目录 | 报新增分散目录与外部写入；先核对，不默默清空 |
| 只有字幕、海报或未知文件留在旧目录 | 保留并列明，不当空目录递归删除 |
| 来源撤回 E13 或把 E13 改为特别篇 | 暂停依赖旧范围的清理与归档，核实映射；不自动删除文件 |

## 8. 报告与长期记录需求

### 8.1 用户看到的内容

主表每个“收藏范围 + 作品 + 编号体系 + 逻辑季”一行，物理目录和文件作为可追踪明细。不同收藏不能因同 ID 被折叠成一行。

最低展示内容：作品 ID、当前名、历史名、收藏范围、季与编号体系、目录数量及原路径、主目录、不同集号数、物理文件数、缺集、重复候选、未知内容、版本完整性、播期状态、治理状态和下一步。

颜色只是辅助。至少区分“覆盖齐全”“单一目标版本完整”“目录分散”“重复待决定”“路径未确认”“来源变化待复核”“归档已核验”。

### 8.2 必须可追溯的记录

- 作品身份及身份冲突证据；当前标题与别名的来源、语言和观察时间。
- 收藏范围与目录成员；谁确认关联、何时确认、哪些对象仍未纳入。
- 原始物理路径、源库/归档库角色、主目录及变更记录。
- 逻辑季与分季/剧集组映射；文件覆盖的集号、分段与内容角色。
- 当前来源快照与前后变化；本地扫描完整性和各路径核对时间。
- 下载/整理任务关联、版本目标、未决状态；名称变化后仍能续接。
- 归并、清理、归档各自的具体计划及逐项结果。

旧报告只有一个目录路径时，不能靠新显示名推导出多个目录；需重新扫描或由用户确认绑定。报告标题可读化与实际路径保存分开，不能因换标题导致下游操作指向新位置。

## 9. 异常、中断与恢复需求

- 全部关联目录完成可核对的读取前，聚合完整性不可冒充已确认。
- 冲突不覆盖；目标多候选时不按接口返回顺序挑第一个。
- 迁移过程中到达的新文件使相关计划重新核对，不能顺手纳入删除。
- 请求结果不明时保留“待核实”，不能直接重复移动或重新下载。
- 中断恢复展示哪些文件已到位、哪些仍在原路径、哪些结果不明；不盲目全量重做或自动反向搬回。
- 主目录绑定变化、集合范围变化、编号映射变化或文件清单实质变化，要重新评估旧计划。
- 对暂时离线的收藏可以只查看旧快照，但必须标过期/未复查，不据此作出当前可删除或可归档结论。

## 13. 本版采用的政策与仍待实际确认的事项

| 政策 | 本版要求 |
| --- | --- |
| 多语言名称 | 用可信身份和译名形成中文显示/候选；初检保留原目录，不直接重命名 |
| 同剧聚合 | 同收藏逐季核对全部关联目录，先识别已有/在途/待整理，再判断真缺集 |
| 主目录 | 显示名可更新，已确认存放位置保持稳定；具体主目录由实际计划确认 |
| 重复选择 | 不按修改时间单独淘汰；本例 E10 的保留对象尚未决定 |
| 目录治理 | 复核、归并、清理分别有具体对象和结果；冲突不覆盖 |
| 归档 | 默认支持完成季先归档、未齐全或连载季留源；整剧模式显式选择 |
| 留源保护 | 保护未归档季及其共享资料；本轮完成不冒充整部收藏完成 |

用户此次授权的是完善并发布需求文档。实际媒体操作、后台长期自动写入、S00 收藏范围、无法核实的译名/身份及具体版本偏好继续按各自证据与权限边界处理，不因文档发布自动开放。
