# MediaFlow 综艺分段识别与订阅清理改进方案

2026-11-10 · 基于 v2.5.8、本机当前“综艺”任务及 MoviePilot 只读查询。本文件是待实施设计。查询期间没有退订、下载、移动或删除文件。

## 1. 先改正用户看到的判断

| 当前表现 | 核查结果 | 建议呈现和操作 |
|---|---|---|
| “归档核对”像一个新的待办清单 | 上次为解决源季只剩附件、归档已有正片却提示清理而新增。实际还接收别名目录、仅花絮、无法识别的视频和读取失败。本次 16 条中，13 条为未找到对应归档季，3 条通过别名找到归档季。 | 改名“文件核对”。每条先说是否要处理，再列源端实物、归档覆盖、匹配依据。归档齐全和附件留存列为“无需操作”，目录读取失败显示“重新检查”，媒体身份或分段有疑问显示具体待核对文件。 |
| “连载留源”有可点击的“留源”按钮 | 前端把动作设为 `skip`，单项处理函数没有对应分支。点击不会保存决定、安排复查或改动网盘；批量按钮也没有实际处理逻辑。 | 用静态状态“连载中，文件已留在源目录”替代单项按钮，移除这一区的全选和批量按钮。若要更新状态，入口明确叫“重新初检”。 |
| 暂停 385 天即建议退订 | 订阅诊断根据日期、暂停状态和进度生成候选，清理预览没有先查询资源。 | 改为“订阅已暂停，上次更新于……；资源待核查”，提供“核查缺集资源”。有搜索证据后再决定是否进入退订清单。 |

例如，“Love is Blind：Polska”应写成“无需补集。归档目录已覆盖 11/11 集，源端另有 5 个视频；两个目录名称不同，TMDB ID 相同。”只有 NFO 的“歌手2025”应写成“源季目录只有 2 个 NFO 文件。当前归档分类未找到对应季。可保留附件。”两者的下一步不同。

另外，“Hot Ones：Extra Heat”当前把正片文件名中作品标题自带的 Extra 当成了花絮。对已知片名和别名先遮蔽标题部分，再识别发行文件名中的独立“花絮、加更、Clip”等标记。独立衍生作品本身含“纯享”的情形也应纳入测试。

## 2. 《一年一度喜剧大赛》按期号和分段核对

| 季 | TMDB 逐条标题 | 源目录证据 | 应给出的结果 |
|---|---|---|---|
| S01 | 第 1–12 期，每期上、下各一条，共 24 条 | E01–E12 均有 PartA 和 PartB，另有同号未标分段的文件；E03 还有 Plus 文件 | 按文件名已覆盖 12 期的全部 24 段。退出“真缺集待补”。同号无分段文件作为另一版待核实。 |
| S02 | 第 1–10 期各两段，第 11 期一段，第 12 期两段，共 23 条 | 上述拆分各期均有 Part01、Part02，第 11 期有无分段文件，另有 E13 | 按文件名已覆盖官方正片分段。退出“真缺集待补”。E13 单独显示“资料未列此期，待核对内容”。第 11 期的两个文件再做版本比较。 |

本次核对的是目录清单、文件命名和 TMDB 分集标题。未播放视频，尚不能判断未标分段文件的实际时长、剪辑内容或 E13 的性质。

**实现规则**

1. 从逐集标题建立“资料条目号 → 节目期号、分段”的对应表。第二季第 21 条对应第 11 期，第 22、23 条对应第 12 期上、下。仅在标题能支持完整对应关系时采用，避免用固定除二公式套所有季。
2. 本地解析保留四个字段：季、期、分段、版本。支持 PartA/B、Part01/02、上/下和上/中/下。文件名中同一标记重复出现只计一次。仅有普通线性集号的剧保留既有识别方式。
3. 同期上下段分别计入覆盖；同一段的两种编码列为版本候选。未标分段的同号文件先列为“可能的整期版”。仅凭文件数、大小或编码不得判定整期等价于上下两段。
4. 初检、归档侧核对、重复清理预览、实际清理、删除后重新诊断、补缺提交共用此对应表。每次生成或执行删除计划前，检查保留文件仍覆盖每一个已知分段。旧记录缺少分段信息时先重新生成清单。
5. 缺少 B 段时显示“第 N 期缺下段”，搜索时转换为该资料来源的具体条目号。映射歧义、疑似整期版或额外 E13 均先进入只读核对，不自动推送整季，也不因此取得删除资格。

## 3. MoviePilot 订阅候选的实际情况

本次读取 1,041 条订阅，旧规则将 122 条列为清理候选：78 条“短剧停滞”、35 条“中途停滞”、6 条“长期无源”、3 条“已完成”。前 119 条的入选条件均不能证明缺集搜不到。额外从有 TMDB ID 的电视订阅中取各规则首尾样本，共查 5 条，本次按作品 ID 搜索均返回 0 条。样本不是随机抽取，单次查询的站点成功范围也未得到证明，因此无法估算整份清单中确有资源的比例。

**“她从棺中醒来”的建议展示**：订阅已暂停，MoviePilot 记录 65/99，缺 34。按同作品、第一季查到 1 条资源，返回做种数 13，标题为 S01；资源元数据标注总数 65，未提供具体集号清单。TMDB 当前只列第一季 1 条；MoviePilot 有 64 条同作品整理历史。三种数字分别描述不同对象。当前应显示“找到同季资源，待核实是否覆盖缺集”，允许查看资源或继续保留。不能据此把第 66–99 集全部列为真实缺集，也不能据此认定已齐。

**两阶段清理预览**

- 列表快速筛选只给出事实：暂停、最后更新、订阅配置总数、已完成、是否有保护标记。删除“逾多少天无做种”等未经搜索验证的措辞。旧的“深度清理”预览也要使用新条件，不能继续按旧置信度直接退订。
- 用户选择单条或批量“核查缺集资源”后，先核对本季正片范围、源库、归档库、活动下载和正在整理的集号。整理历史用于定位文件，实际是否仍在库以当前清单为准。
- 搜索优先用作品 ID、季号，未命中再用片名、别名和季号。结果按作品、季、明确集号、分段或种子文件清单匹配。缓存键包括作品、季、待补集号、站点范围和过滤条件；限并发并展示核查时间。记录站点成功、失败、超时和未配置情况。现有客户端会把部分未知响应转为空列表，核查接口必须保留失败原因。
- **有缺集资源**：显示可覆盖哪些集，供保留订阅、恢复追更或预览补缺。**有同季资源但覆盖未知**：打开资源详情。**本次搜索未命中**：显示检索时间、查询条件和成功站点数。**部分站点失败或队列状态未知**：显示核查未完成，支持重试。**多次完整查询均无匹配且无在途任务**：列为“可考虑退订”，由用户选择。永久无资源无法通过几次检索证明。
- 退订执行前重新读取订阅及保护状态。对有资源、资源未知和保护项不作默认勾选；对矛盾的“已完成”数据另做入库核验。提供“仅退订”和“退订并清理源端”两种明确动作。

## 4. 退订并清理已下载的源文件

适用于用户决定放弃追更且源端仍留有部分集数的订阅。订阅级操作以**选中季度和当前已确认的源文件**为范围。当前 MediaFlow 的“删除源端”会删除整部剧目录，多季剧不能直接复用这个删除范围。

| 阶段 | 必须做到 |
|---|---|
| 预览 | 展示订阅 ID、作品、季、退订原因、搜索结果、源目录、将删集号、具体路径、文件数和大小。源文件匹配需要作品身份与季号，并验证当前路径严格位于配置源根下。拒绝源根本身、归档或媒体库、下载临时目录、共享目录中身份不明文件。没有源文件时只提供退订。 |
| 确认 | 用户可以选择保留文件。选择联合操作时明确展示“退订后删除以下 N 个源文件”。若源文件是唯一副本也要标明，允许用户清楚选择放弃这些已下载集数。其他季、独有字幕和公共刮削资产应逐项列明归属，仅处理确认的项目。 |
| 执行 | 先持久化操作 ID、订阅快照及文件清单，复核当前下载/整理队列与文件身份、大小和修改时间，再退订。退订成功后逐项执行已确认清单并记录回执。目录出现新文件或文件身份变化，停止有差异的部分。仅在实时确认目录为空后清理对应空季目录。 |
| 中断恢复 | 退订失败则保留全部文件。退订成功但删除部分失败，显示“已退订，尚余 N 项”，从已保存清单重试。响应超时先查询实际状态；重复点击使用同一操作 ID，避免重复退订或误删同路径的新文件。 |

**前置依赖。** 已有项目核查发现，CD2 客户端会把某些非协议的 HTTP 200 响应解释为空清单或删除成功。联合操作启用前需修复协议校验、确认移动和删除的业务回执，并在专用样例目录演练回收站恢复。无法确认删除结果时保留“待核对”状态。

## 5. 建议实施顺序与验收

1. 先更新只读文案和列表默认行为，移除无动作的“留源”按钮，停止将时间规则命中的订阅默认列作可退订。现有任务刷新后也应获得清楚的解释。
2. 实现分段识别并保护所有清理与补缺入口；用本次两季的匿名文件夹样例回归。去掉一个下段应只报缺该段；保留完整 A/B 应不报缺；E13 不参与自动清理；普通剧同一集的 H.264/H.265 两版仍应提示重复。
3. 接入订阅资源核查，先在预览模式验证基础情形：65/99 且找到无集号清单的季包、能匹配真实缺集、仅匹配已有集、搜索服务超时、所有已配置站点正常但无匹配、已有下载在途。
4. 最后上线联合执行，在模拟网盘及专用测试目录验证多季隔离、唯一副本提示、确认后目录变化、退订失败、删除部分失败、超时恢复和重复点击。验收同时核对页面结果、订阅实际状态和网盘剩余文件。
