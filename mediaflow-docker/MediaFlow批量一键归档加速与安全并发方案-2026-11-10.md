# MediaFlow 批量一键归档加速与安全并发方案

2026-11-11 修订。评审范围为本地工作区的一键归档入口 `POST /api/archive/execute`，包括普通就绪季和保留全部版本归档的分段综艺。原方案提出的“跨剧并行、同剧串行”方向可以保留。建议调整上线顺序：先让串行归档能够确认文件去了哪里，再减少重复读取，最后开放跨剧并发。

## 一、先修正归档完成的判断

以下为当前源码行为，主要定位在 `app/api/archive.py` 的 `execute_archive`、`_safe_cleanup_source_show_dir` 和 `app/clients/clouddrive2.py` 的 `move_file`。

| 优先级 | 已核实的行为 | 建议改动及成功条件 |
|---|---|---|
| P0 | 增量合并先把剩余文件设为空列表。若已有文件移动成功，但随后读取源季失败，异常只写警告，后续可能仍将该季登记为已归档。 | 显式区分“读取成功且为空”和“读取失败”。失败时记为待核实，保存已处理文件，保留源季；恢复后重新比对两端。 |
| P0 | 季内合并先按名称跳过已有非视频文件，随后可能仅凭同名删除源端副本。剧根目录的公共资产迁移则遍历所有非目录项，移动默认允许覆盖。 | 同名字幕、NFO、海报可能内容不同。默认保留两端并列出冲突。仅在可验证为同一内容且原操作授权覆盖该项时清理副本。未知附件留源；公共资产迁移也使用遇冲突跳过的写入策略。 |
| P0 | 普通整季和逐文件移动依赖事前列目录，实际写入仍默认允许覆盖。若检查后另一进程创建了同名文件，先前的清单已经过时。 | 对归档写入统一使用 CD2 的跳过同名策略；跳过后重新核实两端。目标季匹配多个候选时停止，展示候选路径。保留当前对所有同名视频的拦截，同大小也不能单凭大小认定内容一致。 |
| P1 | 普通整季移动主要依据调用回执登记成功；保留版本分支额外检查源季是否消失。部分合并会进入 review_needed，页面虽提示支持重试，但执行入口仅接受两种就绪状态。 | 整季完成须确认目标路径及计划内容到位；部分成功提供明确的恢复入口，按剩余清单执行。媒体已到位但空壳清理失败应单列提示，避免用户再次搬移整季。 |

写入前规范化源、目标及父路径，确认分别位于配置的源库和归档库内，拒绝相同或互相包含的路径。对平铺单季（源季目录就是剧目录）单独核对目的层级与父目录清理范围。缓存、并发和重试均须复用这组检查。

## 二、按三类操作减少开销

1. **目标季尚不存在，普通整季搬移。** 保留一次目录级移动。使用源清单记录预期文件名、类型、大小和可用的稳定标识，移动后核实目标季确实包含这些内容、源端已按预期移出。核验通过后才写入归档状态。
2. **目标季已存在，增量合并。** 在同一执行计划中复用刚读出的源季清单，逐项识别待移动、需保留和冲突文件。同集异名也要区分版本和上下段。首版按季内串行移动。核验时分别读取源季与目标季，对照计划检查到位和残留；只在变化、读失败或结果未知时补读。单次源端强刷无法证明目标内容完整。仅当源季实物确认为空时才尝试回收，发现子目录或新文件就保留。
3. **分段齐全，保留全部版本。** 当前执行前以整部剧为入口复查，可利用初检已有的 only_season_path 限定本季，保留作品、分段完整性和目标身份核验。只整季移动，若目标季已出现则停止。验证所有版本仍在，不触发剧根清理。

同一剧连续处理多季时，后端可在持有该剧互斥锁期间复用已确认的父目录和季名列表，减少重复建目录与查询。每次成功写入更新快照；超时、冲突、外部变动或释放锁后重新获取。缓存仅用于规划，不能授权覆盖或删除。普通季的剧根空壳检查可合并到该剧所选季完成后做一次，仍逐项核实其他季度、Extras、字幕和公共资产。

## 三、并发、中止和恢复

当前 `frontend/index.html` 的 `confirmArchiveDone` 逐季请求，沿用默认并发 1，并已将 abortSignal 传给接口。前端工作池只约束一个页面，无法协调另一标签页、其他任务或 MoviePilot 入库。实施建议如下。

- **互斥放在后端。** 同时认领规范化的源剧根路径和实际目标剧根路径，按固定顺序获取，覆盖别名剧目归入同一目标的情况。与本服务的清理、删除源端等操作检查父子路径冲突。多进程部署采用共享执行队列或持久化认领。外部程序不受该锁约束，仍需冲突跳过和实物复核。
- **从两部剧同时处理、全服务一个移动槽开始试验。** 允许读取与另一剧的移动重叠。先看限流、等待和核验结果，再测试两个移动槽。跨剧三个槽乘季内三个槽，单批最多可同时发出九个移动，多个批次还会叠加。读取、移动、删除及退避都应纳入同一挂载的调用统计。
- **中止后停止领新项。** 浏览器断开不能证明网盘已停止搬移。后端在每个新移动发出前检查批次状态，对已发出的操作完成对账。界面分别显示“未开始已取消”“已归档”“部分归档”“结果待核实”和“归档完成、源端仍有附件”。允许关闭进度窗并重新查看批次。
- **按季保存结果。** 在短事务里保存操作标识、计划、源目标路径以及逐项结果。云端写入与 SQLite 提交之间可能中断，重启时先核对两端再续跑。当前 CD2 客户端仅对指定读取操作自动重试，建议保留写请求超时后先对账的策略。对账无法区分同名替换时转人工，避免重复移动或删除。

## 四、压测与上线门槛

沿用原方案的 30 部剧、60 季样本，其中 50 季整移、10 季增量合并。每轮还原同一文件清单、目录结构和冲突条件，分别测试现有串行、串行去重读取、两剧并行。记录端到端耗时、各分支 P50/P95、每季移动文件数、CD2 请求数、最大在途写数、限流、部分完成和待核实次数。多季剧占比决定缓存收益，归档目录中原有的文件不可计作本轮新增。

| 故障或边界场景 | 验收依据 |
|---|---|
| 同剧两季、两个别名写同一目标、两个页面同时点击 | 同一源或目标互斥；只执行一次已认领的操作；未选季度完整。 |
| 列完目录后出现同名视频或字幕 | 目标原件未覆盖，源端文件仍可定位，清单显示冲突。 |
| 第 N 个文件移动失败、移动已成功但回执超时、源端或目标端末次读取失败 | 逐项结果与模拟网盘一致；未知结果不得标为成功；重试仅处理未完成项。 |
| 媒体到位后数据库提交失败、点击中止后立即重新打开 | 能凭批次标识恢复或对账；已完成文件不会再次搬移，页面区分未知和已取消。 |
| 源端仅剩同名异内容字幕、新增文件、Extras，或父目录删除失败 | 保留对应实物；媒体归档与清理结果分别报告。 |
| 保留版本综艺与平铺单季 | 全部版本到达正确层级；不误并季、不回收无关目录。 |

建议先在可重置测试目录完成故障注入，再用少量已获授权的正常归档观察真实延迟。原方案的 60～90 秒保留为待验证目标。本次仅审阅代码与方案，未在真实网盘执行搬移或删除。若出现目标覆盖、源文件去向不明或误报成功，应立即停止派发，核对在途操作；回退并发度只能影响后续任务。
