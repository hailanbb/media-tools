# MediaFlow 版本管理

当前应用版本为 v2.5.23，发布日期为 2026-11-14。

v2.5.23 重点落实初检提速与停止状态一致性保护（基于《MediaFlow初检提速与结果一致性优化方案-v2.5.22-2026-11-14.md》）：
1. **停止状态一致性与旧结果保护（P0 级修复，`task_service.py` + `tasks.py` + `inspection.py`）**：
   - 停止请求引入 `stopping` 优雅过渡态，后端保存与落库完成前不提前标记终态；
   - 零产出中止保护：当任务在中途或目录发现阶段被停止导致本轮产出为 0 时，严禁清空数据库中已有的历史季记录与目录组，完整保留上轮已发布的季明细与汇总快照；
   - 部分完成安全合并：任务部分完成中止时，仅更新已扫描剧目范围，未扫描范围的已有历史季记录完好留存；
   - 异常事务安全回滚：发生异常时先回滚当前事务，再用独立事务记录 failed，防止脏写；
2. **初检性能提速四项组合拳（`inspector.py` + `identity_resolver.py`）**：
   - 按需拉取分集详情：底层查询仅对当前所需季（`needed_seasons`）请求 `get_tmdb_episodes` / `fetch_season_detail`，其余季仅保留摘要，长寿多季剧分析大幅提速；
   - 目录发现结果复用：`_discover_shows` 列出的目录项在剧目发现时挂载至 `entries` 并在 `_inspect_single_show` 中直接消费并释放，消除 350+ 次重复的 `list_files` 调用；
   - 任务内共享 TMDB ID 媒体服务器（Emby）核查结果：将 `task_ms_cache` 提升至任务级，同一任务同 ID 别名目录仅核查一次 Emby；
   - 跨任务元数据缓存复用与 TTL：完结季设置 7 天 TTL，连载季设置 1 小时 TTL，过期自动重算，有效时直接命中缓存；
3. **前端去伪存真与平滑交互（`frontend/index.html`）**：
   - `selectTask` 只要任务存在已发布结果（`completed` / `stopped` / 总数 > 0）均正常加载明细与目录组，杜绝“stopped 有数字无列表”假象；
   - 细化无记录空态显示，明确区分“本轮尚无已分析剧季”、“该分类无条目”、“明细加载失败，可重试”；
   - `triggerStopTask` 平滑等待后台轮询完成，状态提示支持 `stopping`（显示保存中进度条与文案）。

v2.5.22 重点落实异常剧集自动核查与多目录逐季覆盖安全清理：
1. **初检主链路自动打通 Emby 媒体服务器分集核查（`moviepilot` + `inspector`）**：彻底取代卡面手动点击。对带 TMDB ID 且正片为 0（如仅剩 NFO 的空壳目录）或正片有缺失的目录，初检时自动远程核查 Emby。若 Emby 全无直接转入「真缺集待补」；若 Emby 部分收录则精准扣减已收录集仅补差集（如 1–8 集已在 Emby 中则仅补 9–12 集）；若各端并集已齐全则从待补清单移出并明确标注文案，无需人工反复探测；
2. **多目录组展开渲染逐季覆盖对照表与安全门禁矩阵（`directory_governance` + `tasks` + `frontend`）**：在展开已确认目录组时，按季度直观展示源端物理路径、归档目标路径、正片覆盖范围、缺号情况及可清理判定（如 `可删除（已完全覆盖）` / `不可删除（归档目标自身缺失）`）；
3. **单季安全覆盖清理严密门禁（`tasks.py`）**：提供 `POST /api/tasks/{task_id}/directory-groups/{group_id}/clean-source-season` 接口，执行严格物理安全校验：必须已指定归档目标、选定归档目标自身必须单独全季齐全（1..total）、归档目标必须完全覆盖源端现有集数，且源端独有的外挂字幕自动安全迁移至归档目标后，才允许物理删除源端单季目录，防止任何误删；
4. **前端交互降噪与去伪存真（`frontend/index.html`）**：清洗历史数据中无意义的引导文案（如“想保留这些内容可直接标记已手动处理”）；移除异常卡片上的冗余主按钮（“查 Emby 转待补”与“处理说明”）；将卡面外层“人工映射”收纳进“详情”弹窗，界面保持极简紧凑；
5. **修复目录组重算 500 与异步 Session 属性懒加载隐患（`directory_governance.py`）**：解决 SQLAlchemy 异步刷新下读取 ORM 属性可能抛出的 `MissingGreenlet` 异常，保证批量重算与目录组序列化高可靠性。

v2.5.21 重点治理同作品多目录组重复展示，将处理入口统一收口于「待复核清理」：
1. **多目录确认入口唯一收口于「待复核清理」（`frontend/index.html`）**：彻底解决跨分类切换时共用面板全量平铺霸屏问题；在「待复核清理」内提供可折叠的「待确认归档目标」独立专区，与逐季重复清理彻底分开计数（如 `0 处需清理 · 33组待确认`），且目录组卡片不参与“全选清理冗余”批量勾选；
2. **「真缺集待补」等其他分类隐藏大容器并支持季卡跨页精准定位（`frontend/index.html`）**：在真缺集、连载留源等分类中彻底隐藏整批目录组面板，使无待补季的作品不再错误出现；对确实关联待确认组的季卡展示「归档目标待确认 · 查看目录」徽章，点击无缝切换至待复核清理并平滑滚动高亮展开对应卡片，顶部提供「返回原清单」便捷按钮；
3. **支持待处理/已处理分栏查看与折叠收起**：默认紧凑展示待处理组，支持一键切换查看已确认或有意共存的已处理历史，并可在单组卡片内展开查看多路径明细与覆盖季集信息。

v2.5.20 重点打通 0 视频 NFO 空壳的 Emby 媒体服务器联动核查与直转真缺集待补：
1. **0 视频 `[tmdbid=...]` 空壳目录 Emby 联动核查与自动分流（`moviepilot` + `inspector`）**：当源季目录 0 个视频文件（无子目录、如仅剩 `.nfo` 等附件）、目录带有明确 `[tmdbid=...]`、已取得正式完结季集数且归档库未找到对应正片时，自动调用 MoviePilot 实时接口 `/api/v1/mediaserver/exists_remote` 探测 Emby 入库状态；若确认 Emby 同样 0 集，直接归入「真缺集待补 (`download_needed`)」，若 Emby 已有剧集或接口不可达则安全保留在 `archive_check` 并注明原因；
2. **历史异常卡片一键「查 Emby 转待补」与详情核查展示（`frontend/index.html`）**：为历史已扫 0 视频带 TMDB ID 的异常卡片增加一键 `查 Emby 转待补` 按钮，实时核查后原位转入「真缺集待补」或展示 Emby 已存集数，并在详情弹窗显示媒体服务器核查回执。

v2.5.19 重点优化多目录确认交互体验与无冲突详情降噪：
1. **同一 TMDB 多目录确认改为单选勾选并关联 TMDB 页面默认推荐（`directory_governance` + `tasks` + `frontend`）**：废除繁琐的纯手工文本框输入，改为展示归档库现有目录 / 按源端目录映射生成的目标候选单选列表（保留可选自定义路径单选开关），并自动查询 `MetadataCache` 与 `matched_work` 在顶部高亮提示「TMDB 官网页面 (tmdbid=...) 当前显示名称」，默认勾选与 TMDB 页面当前正名一致的目标目录（兼顾新初检任务与历史已保存任务）；
2. **无归属冲突详情弹窗降噪（`frontend/index.html`）**：当季诊断仅存在重复版本/常规别名证据且不存在真实身份冲突拦截（`conflict.blocking`、冲突原因及集标题冲突均为空）时，不再误显示红色「识别证据与冲突拦截」警告框，改为中性参考卡「作品识别与别名参考（无归属冲突）」。

v2.5.18 重点消除外文发行名误报并建立同一 TMDB 多目录组级确认与安全门禁：
1. 外文发行名/双语前缀防误报与真错配保留（`identity_resolver` + `inspector` + `tmdb`）：严格落实判决优先级，当目录带有明确且有效 TMDB ID 且当前季已收录时，不因中韩日英译名、标点差异或同季多字幕组双语前缀触发 `identity_review` / `mixed_works`；接入并缓存 TMDB 英文译名与多语言别名展示证据（译名接口失败或缺失时安全降级不误报）；保留文件内显式冲突 `[tmdbid=...]`、未收录季真实错配（如 `Gravesend S08`）与短词重名（如 `Kingdom S06`）拦截；修复撤销单季映射时不按最新规则重估而盲目恢复旧误报的问题，并在任务详情页提供只读「重新评估本任务归属提示」与核算前后对比；
2. 同一 TMDB ID 多目录索引与组级确认门禁（`directory_governance` + `DirectoryGroup` + `archive`/`subscription_service`）：按同分类+已核实 TMDB ID 构建物理剧集目录索引（不因大小写/全半角/标点或未创建的计算目标路径误报，也不跨 TMDB ID 混淆）；同侧出现 ≥2 个物理目录（如 `307478`）或双库同 ID 异名目录合并生成 1 张组级复核确认卡（不按季刷屏），未确认目标或有意共存前统一暂停自动归档、冗余清理、「删除源端（本季）」、整剧删除及退订联动清理；确认本身绝不自动移动/删除文件，并在目录新增第 3 目录、目标消失或 ID 变更时实时自动失效并重新提示（可通过 `MF_ENABLE_MULTI_DIR_GOVERNANCE` 开关控制）。

v2.5.17 重点落地作品身份/季号错配核对与批量补缺持久化闭环：
1. 作品身份冲突与跨条目季号核对（`identity_resolver` + `season_mappings.json`）：区分发布组线索触发的 `identity_review` 冲突与脱壳目录 `not_listed`/`unknown`（拒绝豆瓣错配小季）；短标题重名（如《王国》）严格阻断清理/归档/补缺且绝不自动改绑，仅允许单季可逆人工映射并保持其余季口径完全独立；内置与人工可扩展跨条目拆条映射（如《极地恶灵 S03》`75191/S03 <-> douban:36768839 <-> tmdb:323903/S01`），打通双库别称取证与映射后补缺过滤错剧；显式区分 `fetch_failed` / `no_candidate` / `episodes_tba` / `not_listed` 元数据失败态并复用 `MetadataCache` 已核实快照；同目录混部作品拦截为 `mixed_works`，新增只读 `/recalculate`（完整保留 `manually_handled`）；
2. 批量补缺完成刷新与真实待补清单持久化（`gap_fill_episodes` + `gap_fill_season_runs`）：推种前先落盘 `intent_submitting` 并立即持久化脱敏回执（严禁存储 `passkey/authkey/token`）；按真实未受理集逐集部分扣减，支持默认“真缺集待补”与同页“已推送待入库”视图切换；覆盖 `submitted_unverified` 超时锁与 `aborted_unstarted` 中止标定，支持一键“核对入库”（联合 MP 队列/整理队列/下载与转移历史 + CD2 双库实物核对，已入库收口、已删种无文件退回待补），重检保留同一身份推种记忆并隔离改绑身份，“完成并刷新”直接读取后端持久态而不重推或串任务。

v2.5.16 重点重构 MoviePilot 补缺选种、默认站点扩展与整季安全回退机制：
1. 做种同档内省容量优先：以本轮最高做种数 H 计算同档边界 `H - seeders <= max(1, floor(H * 10%))`，同档内严格按实际需下载总字节升序选种，大小为零或空值视为未知排在已知大小之后；支持跨站同种去重（保留可用站点来源），多集补缺采用 Pareto 剪枝与有界搜索优先最大化覆盖再比总字节（连集包容量仅计一次）；
2. 将“天空”“观众”自动纳入补缺默认搜索范围：动态从 MP 读取默认索引配置 `IndexerSites` 与站点状态（禁止写死 ID），仅将已启用有效站点合并并一致传入 TMDB 精确搜索、标题回退与整季补搜；当 MP 默认为空代表全部站点时保留全部范围，读取失败不缩窄范围并标明原因；
3. 散集补不全时安全回退整季包并保护已有集：合格散集能补齐时优先散集；存在未覆盖缺号且无同季活跃下载重叠时，经文件清单、完整分集表或显式全集说明严格核验 `1..total_episodes`（拒收仅标 `S03`、缺段综艺或未含全集资源）后触发最多一次整季补搜与整季提交；提交前仅清理真实缺号的明确冲突整理记录，绝不传 `episodes=None` 清空已有集历史，提交超时先核查 MP 下载队列防止重复推整包。

v2.5.15 重点落实批量一键归档加速、完成判断修正与安全并发机制：
1. 增量合并完成条件修正（P0）：显式区分“读取成功且为空”与“读取失败”。当读取源端失败时，记为待核实，保存已处理文件并安全保留源季，坚决杜绝误标已归档或误删源目录；
2. 杜绝盲目删除非视频资产（P0）：严禁仅凭同名盲删源端字幕/海报/NFO，默认两端保留并列出冲突，未知附件严格留源；
3. 归档写入统一启用跳过同名策略（P0）：整季移动、单文件增量移动及公共资产迁移统一使用 `skip_existing=True`，杜绝同名覆盖；
4. 目标多候选安全熔断（P0）：当目标库匹配到多个候选季目录时安全停止，展示候选路径转入人工复核；
5. 路径规范化红线（P0）：写入前规范化源、目标及父路径，拒绝相同或互相包含的路径，严密保护平铺单季；
6. 剧级后端互斥与父目录快照复用（P1）：引入剧目级规范化路径互斥锁，同剧多季串行化并复用父目录与季名列表快照，剧根空壳检查合并在该剧全部所选季处理完毕后安全执行一次。

v2.5.14 重点落地批量冗余清理加速与 MoviePilot 补缺优雅中止机制：
1. 批量冗余清理剪除重复网络强读，改为单次实物重读做双向核验，遵循主视频优先、伴生文件严格从属的安全删除顺序；
2. 批量流水线引入独立批次会话隔离（Session Isolation）与 AbortController 网络层熔断，中止时瞬间中断在途请求，消除永久转圈伪死锁并实时解禁弹窗；
3. 严格保障各类季数与总选定季数的数学不变量（成功+暂缓+取消+失败≡总季数），单季多种子按 1 季成功结算；
4. 后端引入 MoviePilot 活跃下载队列 30 秒短时 TTL 快照复用，并建立本地已受理待确认清单（`_recently_submitted_tasks`），彻底杜绝并发推送时的重复提交。

v2.5.13 按实际缺号精准检索补缺，支持非分段标记容错与批量补缺状态分类。

当前联合清理以已初检、能唯一关联到订阅作品及季的独立源季目录为依据。共享目录、无法定位或含子目录的情形保留手工核对入口。字幕及元数据保留，源季目录不自动删除。MoviePilot 搜索接口没有返回完整站点健康信息时，搜索未命中会标注“站点完整性未知”。


- 应用版本以 app/config.py 的 VERSION 为准，首页静态版本标记同时更新，运行时从健康接口读取版本。
- 每次发布先更新 README 版本历史，再提交源码、文档和测试，并创建对应的附注标签。

- 本机开发仓库位于 E:/GoogleAI/emby/mediaflow，GitHub 完整仓库克隆位于 E:/GoogleAI/emby/media-tools。开发仓库的发布标签与 GitHub 标签使用同一版本号，两者提交哈希因目录结构不同而各自独立。
