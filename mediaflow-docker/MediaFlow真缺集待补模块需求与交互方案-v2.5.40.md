# MediaFlow「真缺集待补」模块需求与交互方案 (v2.5.40)

当前方案版本为 v2.5.40，与本地源码版本一致，适用范围为所有初检目录。原方案基线为 v2.5.38，原文记录的 D01–D09 落地情况作为历史记录保留。2026-11-18 根据用户需求新增「读取 MoviePilot 站点管理、动漫／非动漫独立勾选及排序」方案，详见 6.1–6.8 节及 S01–S16 验收项。新增需求尚待实现，本轮仅修改文档，未修改 MP 配置、提交下载或运行功能测试。验收以“这一季应该补哪些内容、使用哪套站点规则、实际提交了哪些、还有哪些需要用户处理”为准。

## 一、用户打开这个模块，应该看到什么

默认清单只展示**已经确认有缺口，而且仍有至少一个缺号可以搜索或重试**的作品季。每季一张卡。用户可以直接按系统推荐推送，无需自己逐个查 Emby、核对上下段或在站点之间比较种子。

点击「完成并刷新」后，四种结果应一眼能分清：

| 本次结果 | 默认待补清单如何变化 |
|---|---|
| 全部缺号已由 MoviePilot（MP）明确受理 | 整季移出默认清单，进入同模块「等待入库」。收到文件后再按实物分流 |
| 仅部分受理 | 保留一张卡，仅对剩余缺号提供推送；已受理的集号在同卡标明 |
| 没有合格资源 | 原卡保留，显示缺号、搜索时间和具体原因，例如“E09 找到 3 个候选，最高 1 人做种，本次要求至少 2 人” |
| 请求已发出但未收到可靠回执 | 对受影响的缺号暂停重推，显示“提交结果待确认”。系统先核对队列与历史；不能把超时算作成功或普通失败 |

## 二、v2.5.33 基线与核心演进

本地初检与真缺集补缺在实际运行中经历了从 v2.5.27 到 v2.5.33 的深度迭代。系统已全面实现「待补／已推送待入库」双视图、逐集台账、补缺站点扩展、相近做种数下的容量比较和整季包回退。

在 v2.5.33 中，重点针对用户日常补缺和源盘清理的真实体验进行了两项核心升级：

1. **缺集 > 3 集优先整季包下载**：当单季缺失集数较多（大于 3 集）时，散集拼包往往意味着多次下载任务开销及做种碎片化，因此优先选择整季包（Season Pack）下载；整季包不可用或缺集 $\le 3$ 集时，平滑回退至省容量散集拼包逻辑。
2. **放弃补缺删源时空壳剧集清理与初检目录强制刷新**：在单季删除源端时，系统自动检查当前任务或数据库中该剧目是否已无其他有效剧季记录。若已无其他季，直接删除剧集根目录（清理所有海报、nfo等刮削伴生文件），并在该任务的初检目录（`task.source_path`）中执行 CloudDrive2 强制刷新，防止源目录残留空文件夹。

## 三、准入、排除和分流

**准入同时满足**：作品与季的身份可信；已确认本季播毕；至少一个应有正片集、期或段有可验证的季级依据；已核查与这些缺号有关的源端、归档及可用的可信 Emby 分集资料；这些缺号在所有可成立的编号解释下确实缺失。写明查询范围和证据时间。旧记录中的“已完结”、文件总数或者一个空数组本身不构成完整证据。

| 情形 | 应放在哪里 |
|---|---|
| 源端 6/10，归档补足其中 2 集，另 2 集确认无覆盖 | 真缺集待补，只列最后 2 集；展示两端各自覆盖及去重后的覆盖 |
| 已播毕，全季均无正片 | 身份、应有集合以及相关位置均核实后，可按全季待补；接口超时或看不到子目录时不能把全季判成零 |
| 同号多个版本，同时有真缺号 | 仅进真缺集待补；版本差异与重复不产生第二张清理卡 |
| 分段歧义仅涉及少数期 | 已确认的缺号仍可补；未定期在同卡详情说明。唯一缺口也无法确认时进入异常剧集的系统跟踪 |
| 同 ID 多目录未定、错季、作品归属冲突可能改变缺口 | 异常剧集；列出各路径证据。解除冲突后自动重算，待补列表不复制目录组 |
| 确认连载或已公布集数尚未播出 | 确认连载走连载留源；播出状态或节目表无法确认时系统跟踪。预告、花絮、S00 和未播正片分别识别 |
| 已有全部正片，或缺号全部入库 | 移出补缺模块。符合条件的整季进入齐全可归档或待复核清理；归档已齐且有源端冗余时走异常剧集的清源判断 |

**覆盖口径。** 先建立同一季的正片内容单元。普通电视剧以正式季集号为单位，综艺允许“第 8 期下”等细分单元。源端、归档以及可信 Emby 明细按同一身份映射后取并集，重复集只计一次。Emby 的整季数量、空响应或不同版本的同名剧均不能直接抵扣缺号。已整理历史只提供核验线索。无法读取但可能含有目标集的位置，需保留不确定性。

## 六、MoviePilot 怎样选资源、怎样解释结果

1. **取最新目标。** 本轮目标＝用户确认的缺号 ∩ 最新确认缺号，再扣除有效在途和回执待查内容。匹配同一作品、同季、同一编号口径及用户已配置的质量要求，再剔除不达实际做种门槛的候选。相同种子跨站去重。
2. **站点范围与顺序可核对。** 新方案以本季适用的动漫／非动漫规则为唯一允许站点范围，按 6.1–6.8 节执行。替代原「MP 默认站点＋天空、观众」自动扩展逻辑；旧规则仅用于首次迁移草稿。按 ID 搜索、标题／别名回退、整季补搜采用相同已选站点范围，未勾选站点不得参与候选或下载。分别记录请求范围、返回来源和错误，不能由“没返回候选”推断某站搜索成功。
3. **同站同档优先省容量。** 沿用默认门槛 2 人做种、同档容差 max(1，最高做种数的 10% 向下取整)，以本次设置为准。在相同策略阶段、相同站点等级与可覆盖目标内比较做种档位和容量，不让低优先站仅因更小或更多做种越过合格的高优先站。相同覆盖和匹配条件下，同站 10 人做种的 2 GiB 与 9 人做种的 600 MiB 同档，选 600 MiB。多集比较方案实际下载总量，包按完整体积计一次，组合以其中最低做种衡量可用性。未知大小排在同档已知大小之后，详情列出入选与次选差异。
4. **缺集规模与整季包策略（v2.5.32 重点优化）。**
   - **缺集数量 > 3 集（`len(missing) > 3`）**：**优先选择整季包（Season Pack）下载**。若首轮候选无整季包，系统主动触发一次别名/原名+季号整季补搜；只要检索到合格整季包且与在途队列无重叠冲突，直接选用整季包；若整季包不可用或存在在途队列重叠，平滑回退至省容量散集拼包；
   - **缺集数量 $\le 3$ 集**：**优先采用省容量散集拼包**，避免为少量缺号拉取大容量整包；散集补不全时才回退至合格整季包。
   - 整季包必须严格核实同作品、唯一目标季、实际包含目标缺号、满足做种门槛，排除假全集、跨季包和与已提交任务重叠的整包。
5. **准确解释没有下载的原因。** 0 命中、做种不足、作品／季不匹配、编号映射不明、整季包覆盖无法验证、站点故障、队列占用与 MP 明确拒绝分别编码。能定位到具体缺号的理由逐号保存；站点范围不完整时只写“已响应范围内无匹配资源”。一季 0 个合格资源属于“未找到可推资源”，不计为程序故障。

### 6.1 站点来源与两套独立配置（新增，待实现）

站点目录首先来自用户所连接 MoviePilot 的「站点管理」。MediaFlow 只读取目录和可用状态，在自身保存补缺专用规则；勾选、排序不修改 MP 全局站点启用状态、默认搜索顺序、订阅规则或其他模块配置，也不创建 MP 订阅。

| 配置 | 适用对象 | 独立保存内容 |
| --- | --- | --- |
| 动漫补缺站点 | 已确认属于动画类的剧集，包括国漫、日漫及其他地区动画剧集 | 勾选站点 ID、有序优先级、规则版本、更新时间 |
| 非动漫补缺站点 | 已确认非动画类的电视剧、综艺等当前可准入的作品季 | 独立勾选集合与顺序，不随动漫配置联动 |

两套规则可选不同站点，也可选相同站点但采用不同顺序。动画电影不因分类进入本模块。动漫指作品类型，不按语言、地区或种子标题中含有「Anime」判断。

站点关联键采用「MP 实例标识＋站点 ID」；名称只用于显示。改名不丢失勾选和顺序，同名不同 ID 独立显示；删除后重建的新 ID 不按名称自动继承。切换 MP 实例后重新读取并配置，不能复用另一实例的数字 ID。

### 6.2 设置面板与首次配置

从「真缺集待补」工具栏进入「补缺站点设置」。面板顶部显示 MP 实例名称、站点目录读取时间与「刷新站点」；下方为「动漫」「非动漫」两个页签。每页按优先级展示已选站点，再列出未选站点，支持名称筛选。

| 控件／信息 | 行为 |
| --- | --- |
| 站点行 | 勾选框、名称、ID、无敏感参数的域名、MP 可用状态、本规则优先序号 |
| 勾选／取消 | 勾选后追加到当前规则末尾；取消后立即从该规则移除，其他规则不受影响 |
| 拖动排序／上移下移 | 只调整已选站点，序号从 1 连续生成；明确提示「数字越小越优先」 |
| 复制另一套规则 | 用户主动点击后复制为当前页草稿，可继续调整，保存后两套仍独立 |
| 保存规则 | 原子保存两页草稿并生成新版本，不搜索、不下载；有未保存修改时关闭面板提示保存或放弃 |
| 刷新站点 | 只刷新站点目录，不重置草稿、勾选或顺序；新增站点默认不勾选，失效站点保留原位及原因 |

首次打开先读取 MP 站点清单，可把旧版解析得到的默认站点及「天空、观众」填入两套**待确认草稿**。旧配置无业务优先顺序时，展示确定的初始排列并标注「请确认顺序」，不把 ID 大小说成 MP 推荐优先级。用户保存后才启用新规则。首次读取失败则显示错误，可查看旧快照但不能伪造空站点目录或自动采用全部站点。

允许保存某一套空规则，含义为「暂停该类别补缺」。推送时该类别明确显示「未启用站点」并跳过；不得把空数组、全部失效或未初始化解释为全部站点。未初始化与用户主动停用是不同状态。

### 6.3 每季如何选择动漫或非动漫规则

本模块需要作品级分类，不仅是扫描任务级分类。按以下顺序判断并保留依据：

1. 用户对该作品明确保存的「补缺类型」优先，按 MP 实例、媒体类型、作品 ID 关联，跨初检复用；允许修改或清除。不改变作品 ID、季集映射和播毕结论。
2. 没有人工设置时采用原作品可信元数据中的动画类型及已有明确分类。只有可信类型资料完整且明确非动画时，才自动使用非动漫规则；类型字段缺失不等于非动漫。
3. 元数据不足时，可采用用户明确指定的纯动漫目录／任务类型作为范围依据；`auto`、笼统 `tv` 和目录名文字猜测不能独立证明非动漫。目录设置与作品元数据冲突时列为类型待确认，不能静默覆盖。
4. 无法确定或有冲突的作品标记「补缺类型待确认」，在当前推送弹窗内直接选择动漫或非动漫，可批量设置。未确定项不自动搜索，其他已确定季可继续；这不是第三套站点规则，也不要求重跑初检。

卡片标示「动漫规则／非动漫规则」及来源，详情提供「修改补缺类型」。混合目录或混合批次逐季路由，不能把第一季的规则套到整个批次。人工修正只影响尚未开始的新执行计划，已受理和回执待查下载继续按原台账对账，不撤单重下。

### 6.4 搜索范围与优先级的准确含义

**优先级由 MediaFlow 选种器执行，不依赖 MP 返回顺序或请求中站点 ID 的顺序。** 在本轮所有允许站点中搜索并汇总结果，可受控并发；同一策略阶段按用户顺序选资源。不是最快响应的站点先下载，也不是只查第一个站点。

有效站点范围＝该类别勾选集合 ∩ 当前 MP 实例中已存在且未停用、具备搜索能力的站点。站点管理中的状态及搜索资格字段需按实际接入版本验证；缺失字段不能直接宣称健康。MP 的默认搜索集合仅用于首次导入参考，不在用户保存规则后重新扩展或替代名单。

- 按作品 ID、中文标题、别名、原名和季号搜索，以及整季包回退，全部携带显式有效站点 ID；任何分支都不能省略站点范围以回退到 MP 默认或全站。
- 返回候选再次按允许 ID 校验。未知站点、未选站点和已停用站点的资源不可提交；无法从结果可靠确定来源时，不靠相似站名猜测。
- 每个搜索阶段等待参与请求完成或到达有界超时，再进行该阶段选择；不以低优先站先返回抢占高优先站。
- 同一批次共享只读站点目录和两套规则快照，搜索缓存按实例、规则版本、有效站点集合、作品季和查询条件隔离；排序用独立的有序规则快照，不能复用错误类别的选种结果。

### 6.5 站点优先级与现有选种策略的顺序

统一顺序为：**身份／编号／质量／最低做种／在途去重等硬条件 → 整季包或散集策略阶段 → 站点优先级 → 同站做种档位 → 同档容量 → 稳定键破同分。** 高优先级不能让错季、低于做种门槛或未知覆盖的资源合格；低优先站更多做种、更小容量也不能在同一阶段抢占高优先站的合格资源。

| 缺口规模 | 阶段与站点应用方式 |
| --- | --- |
| 缺号大于 3 | 先在所有已选有效站点中找合格整季包（必要时完成同范围别名补搜），选有合格包的最高优先站，再在该站按做种档位和容量选包；所有已选站点均无可用整包才转散集 |
| 缺号不超过 3 | 先进行散集方案，按站点顺序填充缺口；散集组合覆盖不全时才评估合格整季包回退，避免为少量缺号直接下载整包 |

散集阶段按站点逐层形成**尚未提交的计划**：第一站在满足硬条件的候选中最大化覆盖目标缺号，再按同站做种和容量选择；后续站只填前面未覆盖的缺号。跨站组合不重复提交同一集或同一种子，多集文件存在不可拆分重叠时重新规划，不能简单按单集贪心重复下载。

若散集补不全，先评估整包能否合法替代暂定散集计划，再提交最终计划；不能先把散集全部提交、再下载覆盖相同集的整包。整包不合法或与既有在途记录冲突时，可提交不冲突的散集部分，其余仍待补。重规划时优先保持更高站点已可覆盖的目标；必须替换高站资源才能增加覆盖时，按整包回退阶段处理并记录原因。

跨站相同种子去重须保留每个来源的站点 ID、独立下载凭据和有效候选。不能先按最高做种选出低优先站、丢掉高优先来源；也不能把一个站的做种数、链接或 Tracker 套到另一个站。选定下载来源按规则排名决定，某来源不合格才使用下一合格来源。

示例（A、B 仅为占位站点）：

- 动漫设置 A → B。A 的 E03 有 3 人做种、1 GiB；B 有 20 人做种、600 MiB。两者均符合要求且最低为 2 时选 A。若 A 只有 1 人做种，选 B 并注明 A 未达门槛。
- 缺 E03、E04：A 有合格 E03，B 有 E03 和 E04，形成 A:E03＋B:E04，不重复下载 B:E03。
- 缺 4 集：A 仅有散集、B 有合格整季包，按照现有「大于 3 集优先整包」选择 B，解释为「整季包策略优先」，不是站点排序失效。
- 非动漫设置 B → A，同样的候选应按 B 优先评估；两套规则互不影响。

### 6.6 站点异常、规则变更与提交恢复

| 情况 | 预期处理 |
| --- | --- |
| 部分已选站点删除／停用 | 保留失效配置并具名提示，只在剩余已选有效站点中补缺；不自动启用新站、未选站或另一类别站点 |
| 全部已选站点失效 | 本季不搜索、不提交，显示「没有可用的已选站点」，保留缺号 |
| 站点目录读取失败或响应结构异常 | 旧快照仅供展示，不能把错误解析为空列表；本批暂停新搜索／提交，已有下载继续对账，提供重试读取 |
| 高优先站搜索超时或失败 | 记录该站异常，在其有界超时结束后可使用已响应的低优先站；明确「高优先站未完成，已降级」，不能写高优先站无资源 |
| 搜索无候选但缺少逐站回执 | 只称「已返回结果中无合格资源／部分站点结果未确认」，不推断所有站点搜索成功 |
| 提交被 MP 明确拒绝且确定未受理 | 可在本次授权的规则快照内选择下一合格候选，重新检查在途与覆盖，有限次回退并记录原因 |
| 提交超时或结果不确定 | 暂停同一缺号和相同包的跨站重投，先核对台账、下载队列及历史，不以换站规避幂等保护 |
| 用户修改或取消站点勾选 | 新批次使用新规则；运行批次固定使用确认时的旧规则，保存面板和进度页明确说明。需要立即应用时先「停止后续推送」，剩余缺号新建批次；不取消已受理下载 |
| 运行中 MP 停用／删除站点 | 提交前更新站点可用状态并剔除失效来源；只收缩旧计划范围，不因 MP 新增站点扩大范围，读取失败则暂停未提交部分 |

保存规则采用版本校验，另一窗口已修改时提示冲突，不能静默覆盖。目录刷新不自动恢复已停用规则；失效站点恢复后可按原勾选参与下一批，面板明确显示恢复状态。重试与批次恢复必须保留原执行快照，使用最新规则需重新生成用户可见的计划。

### 6.7 执行前展示与结果解释

推送确认框增加「本次使用的站点规则」，按动漫／非动漫分组显示季数、规则版本、站点有序名称、失效跳过项和未确定类型项。用户可以打开站点设置再返回确认；快照从最终点击「开始评估并推送」时固定，配置版本发生变化时刷新确认内容，不提交过期预览。

逐季结果记录分类与依据、规则版本、请求站点、实际响应情况、候选来源、最终站点及排名、策略阶段、降级原因。无资源结果应写「本次所选站点内无合格资源」，不能声称全网无资源。记录详情示例：

> 使用动漫规则 v3：A → B → C。E03 选用 B（优先级 2）；A 候选最高 1 人做种，低于本次门槛 2。E04 的 A 请求超时，B 无匹配结果，C 资源合格，使用 C 并标注本次搜索范围未完整响应。

更改站点规则不清空无资源历史、已受理回执、待查状态或实物覆盖，不把已受理集号重新变成可推。用户主动「重新搜索」时，对仍可补的缺号应用新规则。

## 七、用户主动放弃补缺并删除源端（v2.5.32 重点优化）

这项操作可能删除用户仅有的正片。建议提供**「删除源端（本季）」单季入口**，与「归档已齐，可清理冗余」区分清楚。前者允许用户明确放弃不完整藏品，后者要求归档有可替代副本。不能把“站点没搜到”自动解释为用户放弃。

- **空壳剧集目录级联清理（v2.5.32 核心演进）。**
  - 用户点击「删除源端（本季）」时，系统检查当前任务或数据库中该剧目是否已无其他有效剧季记录（过滤 `status != 'source_absent'`）。
  - **若已无其他有效季**：说明源端仅剩本季。系统直接删除该剧集目录（`show_path`），连同 `poster.jpg`、`tvshow.nfo`、`fanart.jpg` 等刮削伴生文件一并彻底清理，避免源端目录遗留空壳文件夹。
  - **若仍有其他有效季**：仅安全删除该季目录（`season_path`），严格保留剧集根目录及其他有效季的正片与伴生文件。
- **初检目录强制刷新（v2.5.32 核心演进）。**
  - 删除操作完成后，系统必须定位到当前任务的初检目录（`task.source_path`，如 `/115/Library_incs/nas/电视剧/香港剧集`）。
  - 在任务初检目录中执行 CloudDrive2 的强制刷新操作（`force_refresh=True`），确保网盘目录树与前端即时同步，彻底消除“删除后仍能在上层目录看到该剧”的缓存不同步问题。
- **安全路径防御。**
  - 删除 `show_path` 或 `season_path` 均强制执行根目录与安全边界拦截：必须在受控源目录下、严禁为根目录、严禁为任务初检目录本身、严禁触碰归档库根目录及其子目录、路径层级深度 $\ge 2$。
  - 严禁删除被多个季度平铺共享的未分季目录。
- **预览与确认。**
  - 弹窗中动态标明是否将级联删除整剧根目录及伴生文件，清晰展示拟删路径、包含的正片分集、非视频文件数量与总容量。
  - 若 MoviePilot 尚有该剧活跃下载或整理任务，安全禁用删除按钮，防止误删在途资产。
- **结案与日志。**
  - 源季或整剧删除后，对应记录状态更新为 `source_absent`，相关补缺记录结案，记录完整的 `OperationLog`，并重新计算任务汇总信息。

## 八、按缺号记账，保证刷新与下次初检一致

| 缺号状态 | 可以推送吗 | 如何离开 |
|---|---|---|
| 已确认缺失，未搜索／无合格资源／明确未提交 | 可以 | 发现实物后抵扣；提交前先写意向 |
| 提交中、提交超时、回执不确定 | 暂停重推 | 查同一下载标识、种子标识、队列和历史。只有明确未受理，或经过可配置观察期、多次完整查无匹配且实物仍缺时，才释放回待补 |
| MP 已受理／下载中／待整理 | 暂停重推 | 有可信实物则标入库；确认取消／失败且仍缺才退回 |
| 已入库 | 移出补缺 | 其余集照常处理；全季齐全时走统一分流 |
| 身份或期段映射变化 | 暂停引用旧判断 | 旧账保留审计，按新身份重新核查；防止旧回执污染新作品，也防止跳过实际仍在运行的同一下载 |

台账以作品身份、季、有效映射及缺号为基础。按期综艺需能表达“第 8 期下”，旧版只保存整数集号的记录需按原口径读取，不能自动扩成上下段均已受理。任务 ID 用于展示来源，跨次初检需核对仍有效的在途记录。同一下载包涉及多个缺号时记录一份下载意向，多条缺号引用同一回执。入队前作并发互斥与持久化；服务重启从意向核验，不盲目重发。季数、缺号数、下载任务数分别统计，避免“1 个整季包覆盖 3 个缺号”显示成提交了 3 个下载。

| S05 | 各搜索分支一致 | ID、中文名、别名、原名、整季补搜及重试均只使用对应已选集合；额外返回的未选站候选不可提交，天空／观众不再被强制追加 |
| S06 | 优先级真实参与选种 | 同一阶段高优先站资源合格时，即使低优先站更多做种、更小容量、返回更早，仍选高优先站；站点 ID 数值排序不影响业务顺序 |
| S07 | 硬条件优先 | 高优先站错季、做种不足、质量不符或覆盖不明时跳过，并具名解释使用低优先站的原因 |
| S08 | 跨站散集组合 | A 覆盖 E03、B 覆盖 E03–E04，最终 A:E03＋B:E04；多集重叠重规划，缺号与包不重复提交 |
| S09 | 整包与散集策略 | 缺 4 集时低优先站合格整包可优先于高优先站散集；缺 1–3 集先散集，整包回退在散集提交前决定，且不覆盖已有在途内容 |
| S10 | 跨站去重与来源 | 同种子多个来源保留独立凭据及排名；不以低站高做种提前丢弃高站来源，不混用站点链接、做种和 Tracker |
| S11 | 站点目录变化 | 改名保留 ID 关联，新增默认未选，删除／停用具名标记；同名不同 ID 不替换，切换实例不继承旧 ID；全部失效不搜索 |
| S12 | 站点错误及读取异常 | 目录读取失败不变空列表、不使用未验证旧快照提交；单站超时有界降级并记录未完成，不能伪装该站无资源或全网无资源 |
| S13 | 保存与执行并发 | 多窗口版本冲突不覆盖；预览版本过期重新展示；执行批次按旧快照，新批次用新规则，MP 停用站点可收缩计划但新增站不扩展 |
| S14 | 提交回退与恢复 | 明确未受理可有限次换候选；超时不跨站重投，先对账；重启恢复沿用原快照，修改规则不抹掉已受理和待查台账 |
| S15 | 缓存隔离及解释 | 相同作品在不同类别、实例或规则版本下不串用选种结果；详情显示请求范围、来源站点、策略阶段、排名与具体降级原因 |
| S16 | 权限范围与回归 | 规则仅影响真缺集待补；不改变播毕准入、质量和最低做种门槛、不自动创建订阅或改动文件；前端及日志不暴露站点密钥，原逐集台账、等待入库、停止后续推送行为保持正确 |
