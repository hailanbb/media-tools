## 一、模块职责、准入边界与互斥分流规范

本模块专职处理**已核实完结缺口的作品季选源推送、逐集在途防重追踪、异步入库对账与补缺后实物复核，以及用户显式放弃补缺时的受控本季删源**。同集重复版本清理、同 ID 多目录归并与归档已齐清源统一由「待复核清理」先行收敛，处理后携带既有下载台账自动回流本模块。

### 1.1 准入条件与跨模块分流矩阵

**准入必须同时满足**：① 作品与季身份可信（含有效人工确认或跨条目季映射）；② 已确认本季播毕（结合 TMDB 与豆瓣多通道核验，含 `S02+` 跨年开播 `±1` 年容差校准）；③ 至少一个应有正片集／期／段具有可验证的季级依据；④ 源端、归档端及可用可信 Emby 分集明细按同一映射合并去重后，仍存在明确缺失集号。

| 初检或运行期实物情形 | 归属模块与处理规则 |
| :--- | :--- |
| 源端 `6/10`，归档库补足其中 `2` 集，另 `2` 集两端与可信 Emby 均无覆盖 | 进入 **缺集待补**，仅列剩余 `2` 个真实缺号；详情同时展示两端各自集号与并集覆盖 |
| 已核实播毕，源端与归档完整枚举确认 `0` 视频（或仅含 NFO／海报等纯附件） | 进入 **缺集待补** 按全季待补处理；目录读取失败、未识别视频、有效 `.strm` 绝不按零媒体误判全季缺失 |
| 同作品多目录归并清理纯空壳旧目录后残留 `0` 集旧记录（v2.5.83） | 自动收敛为 `source_absent` 结案退出，绝不残留虚假全季缺集卡片 |
| 已播毕且缺集，同时存在同内容可替代技术副本或同 ID 多目录待归并 | 先进入 **待复核清理** 清理冗余副本或全季归并，完成后携带准确缺号自动转入 **缺集待补** |
| 分段歧义仅涉及少数期；其余缺号映射一致且明确 | 一致缺号正常开放补缺，未定期在详情标注原因；若唯一缺口亦无法确认且自动补取映射失败，转 **异常剧集** |
| 确认连载中、待首播或已公布集数尚未播出 | 进入 **连载留源** 继续留源保护；预告、花絮、`S00`/先导片与未播正片严格区分识别 |
| 完结且主集数齐全（含附随少量相邻扩展集或 `E00` 特辑，无未决副本冲突） | 进入 **齐全可归档**（`v2.5.84` 统一认可权威分类 `work_cat == "archive"`，不误判缺集或卡单） |
| 归档端已独立完整覆盖本季正片，源端仅剩残留目录 | 进入 **待复核清理** 执行附件保全与「清理已归档源端」，不占用补缺待办 |

### 1.2 覆盖计算与无重叠计数铁律

1. **统一内容单元并集**：普通剧集按正式集号计算，按期综艺支持 `第 8 期下` 等细分期段单元；源端、归档端及可信 Emby 明细统一换算至同一本地口径取并集。Emby 仅有整季总数、空响应或异版同名剧不能抵扣缺号；衍生特辑（`Vlog / 加更 / 纯享 / 先导片 / E00 / SP`）与会员版不抵扣正片缺号。
2. **一作品季一主卡**：满足全局不变量 `review + anomaly + download + airing + archive + held == total_work_seasons`。同一作品季跨多个源目录时聚合为单张主卡，不重复生成多张待补卡片。
3. **四类数量严格分计**：**作品季数**、**目录组数**、**逐集缺号台账数**与**实际提交的下载种子任务数**独立统计（例如 `1` 个整季包覆盖 `4` 个缺号，计为 `1` 季、`4` 集在途、`1` 个下载任务，严禁混称为“提交了 4 个下载”）。

## 二、三页签工作台布局、工具栏与卡片交互体系

### 2.1 顶栏主卡与模块内三页签互斥划分（v2.5.56 ~ v2.5.62）

顶部五模块导航中的「缺集待补」主卡采用“大号主数字 + 小号分项摘要”布局（防止字号继承撑高卡片抖动），展示 **`N 季待补 · M 季待回执`**。进入模块后，内部划分为**三个互斥页签**：

| 页签名称（键值） | 准入条件 | 子筛选与批量能力 |
| :--- | :--- | :--- |
| **缺集待补**（`todo`） | 仍有至少 `1` 个缺号可搜索或重试，且不满足「无合格资源」整季条件（含未搜索、部分分集已推剩余待补、搜索/提交接口异常、中止未开始项） | 提供 **全部 / 未搜索 / 部分已推 / 接口失败** 四个子筛选胶囊；支持全选本页可推项并执行 **「批量一键推送 MP 补缺 (已选 N 季)」** |
| **无合格资源**（`no_resource`） | 当前季路径已有持久化搜索结论、覆盖当前全部可补缺号、结果属于 `zero_hits / low_seeders / no_qualified_candidate / wrong_identity`，且本季及同作品季关联目录**无任何在途阻塞集** | 支持勾选重新执行 **「批量一键推送 MP 补缺」**（应用最新站点规则重搜），并独享 **「批量删除源端（本季）· 已选 N 季」** 与 **「查看最近删源回执」** |
| **等待入库／回执**（`pushed_pending`） | 当前全部缺号均处于有效在途或待核实状态（`intent_submitting / queued / transfer_pending / submitted_unverified`），或处于 **「补缺后待复核」** 门禁状态（若仅含提交超时待核实项，页签文案动态显示为 `提交待确认 (M)`） | 复选框禁用防重复提交；顶部重点引导点击 **「核对入库」**，不展示批量推送与删源按钮 |

> **多目录保守归类原则**：若同一作品季关联多个活动源目录，只要任一目录尚未满足「无合格资源」条件，整季保留在 `缺集待补` 或 `等待入库／回执`，绝不提前归入 `无合格资源` 误导批量删源。

### 2.2 工具栏按钮布局顺序与职责（v2.5.62 校准）

工具栏在页签切换组右侧按高频工作流排列：

1. **「核对入库」**（`#reconcileGapFillBtn`，位于「补缺站点设置」**左侧**，当处于 `等待入库／回执` 页签或任务存在在途项时显示）：异步启动队列、历史与双库实物对账，下方实时展开 `#gapFillReconcileProgress` 进度条。
2. **「补缺站点设置」**（附 `#gapFillSitesToolbarBadge` 实时状态徽章，如 `2套规则生效中`、`动漫已暂停` 或 `待初始化`）：打开双页签站点优先级配置弹窗。
3. **「批量一键推送 MP 补缺 (已选 N 季)」**（`todo` 与 `no_resource` 页签可见，零勾选禁用）：打开批量推送确认与站点规则快照弹窗。
4. **「批量删除源端（本季）· 已选 N 季」** + **「查看最近删源回执」**（仅 `no_resource` 页签可见）：对勾选的无资源季（单批上限 `100` 季）生成删源预览或回看本会话最近一次批次回执。

### 2.3 季条目卡片展示与操作按钮全集

- **卡片信息结构**：
  - 标题行：作品名、季号与缺集状态胶囊（如 `S01 (缺 3 集)`，实物未入库前绝不因已推送而虚增本地覆盖数）、映射标识与 `TMDB ID`（卡片表面已移除“动漫/非动漫”标签降噪，改在详情抽屉查看与切换）。
  - 路径与摘要行：明确标注 **源端路径** 与 **归档目标路径**（目标路径仅表指向，不代表已归档）、缺号明细、最近搜索结论（区分未命中、做种不足与最高做种数、身份不符、接口报错）及蓝色在途提示条（`在途下载: E07, E08 已提交下载，等待入库`）。
- **卡片右侧操作按钮**：
  1. **「详情」**：打开本季诊断抽屉，展示身份与播毕依据、三端集数覆盖、**补缺适用站点规则与路由卡片**（支持一键切换本作品动漫／非动漫偏好）、逐集台账状态与选种／降级回执；同时在人工核对无误场景下提供 **「已复核无误 · 强制归档」** 预检入口（`v2.5.84`，受物理防覆盖硬红线保护）。
  2. **「推送补缺」**（`todo` 与 `no_resource` 页签可补项）：打开单季推送确认弹窗，可查看／微调本轮目标缺号并开始评估推送。
  3. **「确认源已移删」**（`v2.5.62` 由原易误解的「核对源目录」正式更名）：仅用于用户已在 CloudDrive2 外部手动删除或移走源目录后的只读对账结案；在 `等待入库／回执` 页签点击时强制弹出防误触二次确认框，明确提示若需检查下载到货请点击顶部「核对入库」。
  4. **「删除源端（本季）」**（仅 `todo` 与 `no_resource` 页签非连载卡显示，`pushed_pending` 严格隐藏）：打开单季主动放弃补缺预览弹窗。

## 三、补缺站点管理与动漫／非动漫独立规则体系

### 3.1 MoviePilot 站点脱敏读取与多实例隔离（S01, S11, S16）

1. **只读目录与白名单脱敏**：通过 `GET /api/moviepilot/gap-fill/sites/catalog` 读取 MoviePilot `/api/v1/site/` 站点清单，经 `sanitize_site_data` 严格执行白名单过滤（仅保留 `id / name / domain / 清洗后 url / is_active / public / pri / comment`），**100% 剥离 Cookie、Passkey、Token、API Key 及含私钥查询串**；修改补缺规则绝不回写或改动 MP 全局站点启用状态、默认索引配置或订阅规则。
2. **实例强绑定键**：规则与作品偏好均以 `instance_key`（由 MP 实例地址生成的规范标识）+ `site_id` 为唯一主键（持久化于独立表 `gap_fill_site_rules` 与 `gap_fill_work_preferences`）。站点在 MP 侧改名不丢失勾选与顺序；同名不同 ID 独立识别；切换 MP 实例后自动隔离，绝不跨实例串用数字站点 ID。

### 3.2 双套独立规则、交互面板与乐观锁并发控制（S02, S04, S13）

| 规则类别 | 适用范围 | 状态枚举与行为约束 |
| :--- | :--- | :--- |
| **动漫规则**（`anime`） | 国漫、日漫、欧美动画剧集及剧场衍生番剧季 | 各自独立保存有序 `selected_site_ids`、`status` 与递增 `version`；互不联动 |
| **非动漫规则**（`non_anime`） | 真人电视剧、综艺、纪录片等非动画作品季 | 支持独立勾选不同站点，或勾选相同站点但配置完全不同的优先顺序 |

- **设置面板能力**（`<dialog id="gapFillSitesModal">`）：支持动漫／非动漫双页签切换、按名称搜索筛选、勾选追加至末尾、拖拽或上下按钮微调优先级（明确标注 **序号越小优先级越高**）、一键复制另一套规则为当前草稿、按页签细粒度追踪未保存修改（`_gapFillDraftDirty`），点击「保存生效规则」协同持久化双页签已改动项并立即刷新工具栏状态徽章（`v2.5.50`）。
- **乐观锁防覆盖**：`POST /api/moviepilot/gap-fill/sites/rules` 强校验 `expected_version`，多窗口并发修改触发 `HTTP 409` 冲突提示，拒绝静默覆盖。
- **空规则与未初始化硬拦截**：
  - 允许将某套规则保存为空列表并标记 `paused`（含义为**暂停该类别补缺**）；尚未保存过的初始草稿标记为 `uninitialized`；
  - `MoviePilotClient.search_resources` 与 `resolve_category_gap_fill_sites` 设有显式空集合熔断：**空规则、暂停状态或全部已选站点停用时直接拦截返回空结果，严禁省略 `sites` 参数退化为全站搜索**，也不再强制追加旧版默认附加站点（「天空」「观众」仅作首次未初始化草稿迁移参考）。

### 3.3 免确认自动分类路由与人工偏好覆盖（S03, S17）

取消主卡与推送前弹窗中的强制“⚠️ 类型待确认”阻塞框，由 `resolve_record_gap_category` 按以下优先级全自动判定并记录依据：

1. **用户既有人工指定偏好（`manual`）**：查询 `GapFillWorkPreference`（按 `tmdb_id` 或清洗剧名匹配），一经保存跨任务、跨重检永久复用，用户可随时在详情抽屉自愿切换。
2. **已核实作品级元数据／可信 NFO 动画类型（`metadata`）**：检测 TMDB `Genre 16 (Animation)` 或可信 NFO 类型标签。即使动画作品被误放在 `电视剧/综艺` 目录下，也会自动纠偏采用**动漫规则**。
3. **初检目录及路径层级分类继承（`directory`）**：从 `season_path → show_path → task.source_path` 自下而上查找最近明确分类目录（如 `动漫 / 动画 / 国漫 / 日漫 / Anime` → 动漫规则；`综艺 / 真人秀 / 脱口秀 / 国产剧 / 港剧 / 美剧` → 非动漫规则），兼容简繁体与大小写，不被外层宽泛目录名“电视剧”覆盖子目录“动漫”，也不因片名偶然含某字误判。
4. **目录与文件名显式类型标记及安全诊断回退**：宽泛目录无分类词时综合目录／文件名明确标记与任务 `media_type` 判定；全程透明写入 `gap_category_source` 与 `gap_category_reason`。

## 四、选种决策引擎、统一身份防线与推送后整理记录清理

### 4.1 六级选种决策链与整包／散集策略（S05 ~ S10）

候选评估在单季允许的有效站点集合（`已选站点 ∩ 当前 MP 已启用站点`）内等待本阶段全部请求返回或到达有界超时后统一裁决，严格遵循以下六级顺序（**绝不因低优先站响应更快、做种更多或体积更小而抢占同阶段已达标的高优先站资源**）：

$$\text{① 硬条件门禁} \succ \text{② 策略阶段（整包 vs 散集）} \succ \text{③ 站点优先级} \succ \text{④ 同站做种档位} \succ \text{⑤ 同档省容量} \succ \text{⑥ 稳定键破同分}$$

1. **硬条件门禁**：站点在本次有效允许列表内、做种数 $\ge \text{min\_seeders}$（默认 `2`）、画质与中文字幕／配音过滤达标、免费／HR 策略达标、非在途下载／做种重叠项，且通过作品身份与季集覆盖核验。
2. **缺集规模驱动的策略阶段**：
   - **缺集数量 $> 3$ 集**：**整季包（Season Pack）优先**。先在全部有效站点候选中筛选合格整季包（若首轮无整包，自动携带相同允许站点列表触发一次原名／别名＋季号补搜），选出存在合格整包的最高优先站点，再在该站内按做种档位与容量择优；仅当所有已选有效站点均无可用整季包（或整包与在途队列冲突）时，平滑回退至散集拼包。
   - **缺集数量 $\le 3$ 集**：**散集拼包优先，不全则自动回退整季包**。先按站点优先级瀑布式组合散集（第 1 优先站最大化覆盖目标缺号，后续低优先站仅填补剩余未覆盖缺号，多集包重叠时重规划防重复下载）；若所有站点的散集合计仍无法补齐当前缺口（哪怕仅缺 `1` 集散集断种），在**尚未提交任何散集前**自动评估同范围合格整季包回退，合格则直接改推整季包并在日志写明 *“为补 Exx，下载整季 N 集（其中 K 集已有）”*。
3. **同站做种档位与省容量比较**：同档做种容差为 $\max(1, \lfloor \text{最高做种数} \times 10\% \rfloor)$；同一站点、同一做种档位内优先选择总下载体积更小的方案（未知体积排在已知体积之后）。
4. **跨站同种去重**：相同 InfoHash 或规范化同名同大小种子跨多站出现时，`_dedup_evaluations` 严格保留 **`site_priority` 排名最高** 的合格站点来源及其独立下载凭据，绝不先按最高做种保留低优先站而丢弃高优先站，也绝不混拼不同站点的下载链接或 Tracker。
5. **整季包真实性核验**：优先核验种子文件清单／分集范围；无明细且无已知上下段拆分冲突时，可采纳同季且集数一致的明确 `全 N 集／期` 或 `Complete` 声明；对跨季合集（`S01-S02`）、连载残卷（`更新至 / 前N集 / 暂缺`）、已知分段冲突或总集数矛盾候选一律拦截。

### 4.2 跨模块统一媒体身份核验与 MP 提交前置守卫（v2.5.81 ~ v2.5.82）

`app/services/download_service.py` 作为全系统（五模块缺集待补 ＋ 电视剧／电影订阅治理补缺）的**单一选种与身份核验底座**：

1. **防同名异片与跨条目映射核验（`verify_candidate_media_identity`）**：
   - **TMDB 精确检索分支**：强校验候选 `media_info.tmdb_id` 与目标检索 ID 一致，且单季季号精确匹配；
   - **关键词／别名回退分支**（当 `/api/v1/search/media/tmdb:{id}` 无结果回退标题搜索，MP 返回未识别 `media_info={}` 时）：强制先调用 `fetch_mp_media_context` 获取官方片名、原名、别名集合与首播年份，要求候选必须同时通过 **`candidate_title_matches_aliases` 精确片名边界匹配**（剥离技术后缀，杜绝弱子串误撞同名异作）与 **年代防翻拍校验**（拦截早于首播年 `>1` 年的旧版翻拍及 `S01` 跨时代异片，同时兼容 `S02+` 跨年续季）；
   - **跨条目映射分支**（如分季独立 TMDB 条目或特辑映射）：支持检索口径与源口径双向季号／强别名校验，严防误中母条目早期季。
2. **`MediaInfo` 自动回填与前置非空守卫（`ensure_candidate_media_info` + `is_valid_download_payload`）**：
   - 提交下载前自动用 MP 官方媒体上下文回填补齐缺失的 `media_info`；
   - `MoviePilotClient.submit_download` 前置校验 `has_valid_media_info` 与 `has_valid_torrent_info`，从根源杜绝空 `media_info={}` 触发 MoviePilot `/api/v1/download/` `500 Internal Server Error`，并通过 `_raise_for_status_with_detail` 精准提取 MP 返回的真实业务失败原因（4 小时种子缓存 TTL 过期或提交被拒时支持有限次换种／重搜）。

### 4.3 推送受理后立即清理 MoviePilot「媒体整理」转移记录（v2.5.62 ~ v2.5.71）

- **问题根因**：MoviePilot「媒体整理（转移历史）」中若残留该剧集此前的整季包记录（`E01-E24`）、空集号记录、失败记录或已有集记录，下载完成后 MP 常因命中历史记录而跳过整理新下载的补缺分集；且单一检索词在遇到中英文剧名差异时会漏查历史。
- **现行机制**：在 `mp.submit_download` **明确受理成功（`is_ok`）或超时入队／转入待核实（`is_unverified`）后立即执行**（每季每批仅执行 1 次；提交明确失败未入列时不误删历史）：
  1. 调用 `mp.clear_transfer_history_for_episodes(title=primary_query_title, season=search_season, episodes=None, explicit_only=False, tmdb_id=..., title_aliases=[primary_query_title, clean_name, media_title])`；
  2. **多别名合并 + TMDB ID 防误删**：遍历全部非空剧名别名拉取历史并按记录 `id` 去重；若历史条目携带 `tmdbid` 且与当前作品不一致则严格跳过，同时保护其他无关季（如补 `S02` 绝不删 `S01` 历史）；
  3. **绝对物理安全红线**：底层 `delete_transfer_history` 强制固定参数 `deletesrc=False, deletedest=False`（对应 MP **「仅删除转移记录」**），**只清理 MP 数据库中的整理日志行，100% 绝不删除任何源端做种文件或归档库媒体文件**。

## 五、逐集持久化台账、异步「核对入库」加速与补缺后完整复核

### 5.1 稳定季键逐集台账与提交幂等防重

台账存储于 `gap_fill_episodes` 与 `gap_fill_season_runs`，以稳定复合键 `(task_id, season_path, identity_key)` 锚定（重检重建 `SeasonRecord.id` 自动继承；人工改绑作品或修改映射口径后旧记录自动归档为 `superseded` 审计隔离）。

| 逐集状态（`state`） | 是否允许推送 | 状态流转与释放条件 |
| :--- | :---: | :--- |
| 未记录 / `no_resource` / `search_error` / `rejected` / `aborted_unstarted` / `cancelled_or_failed` | **允许** | 实物核对已存在则直接抵扣；发起提交前先原子落盘 `intent_submitting` |
| `intent_submitting` / `submitted_unverified`（提交中或超时未确认） | **禁止重推** | 保留 `300 秒` 提交观察窗口；观察期内或单次队列未命中保持锁定防跨站重投；超时后队列命中自动转 `queued`，明确失败或过观察期且连续 $\ge 2$ 次完整对账未命中且双库无实物才释放为 `cancelled_or_failed` |
| `queued` / `transfer_pending`（MP 下载中或待整理／整理队列中） | **禁止重推** | 核对发现源端或归档库已有合格实文件则转 `in_library`；MP 下载历史明确标记 `fail / cancel / delete / error / abort` 且双库无文件则退回待补 |
| `in_library`（已核实入库） | **移出补缺** | 本集补缺收口；当季触发补缺后完整实物复核，复核通过后按最新全季覆盖自动分流 |

### 5.2 异步「核对入库」实时进度与三级并发提速（v2.5.62）

为消除多季对账时的无反馈阻塞与串行等待，「核对入库」升级为后台异步作业 + 三级并发流水线：

1. **异步作业与实时进度条**：
   - 前端点击 `#reconcileGapFillBtn` 调用 `POST /api/tasks/{task_id}/reconcile-gap-fill-start`（同任务单实例防重入，使用 `app.database.async_session` 独立后台会话），每 `500ms` 轮询 `GET /api/tasks/{task_id}/reconcile-gap-fill-status/{job_id}`（同步接口 `POST /reconcile-gap-fill` 继续保留兼容）；
   - `#gapFillReconcileProgress` 实时展示当前阶段文案、百分比进度条与 `已核对/总季数`（如 `正在并发强读网盘源库与归档库 (3/8): 剧名`）。
2. **三级性能优化（`reconcile_gap_fill_records`）**：
   - **MP 四路并发拉取**：通过 `asyncio.gather` 并发请求 `get_active_downloads`、`get_transfer_queue`、`get_download_history` 与 `get_transfer_history`；
   - **DB 批量预筛消除 $N+1$**：单次批量查询当前任务的在途／已入库 `GapFillEpisode` 与历史 `download_gap_fill` 日志，直接跳过无在途且无待复核标记的无关剧季；
   - **`Semaphore(5)` 并发预读双库目录**：对候选待核对剧季，使用 `asyncio.Semaphore(5)` 并发调用 `cd2_client.list_files(..., force_refresh=True)` 强读源季目录与归档季目录（兼容无事件循环同步测试步进器自动降级顺序执行）。

### 5.3 补缺到位后的完整实物复核门禁（v2.5.58）

缺号文件到达网盘**绝不等于可以直接归档**（例如整季包下载可能引入大量同集重复副本、衍生特辑或未识别视频）。当「核对入库」检测到新文件到位（或存在历史未复核标记）且确认对应种子已非正在写入／整理中（做种状态 `seeding / completed` 不视为写入阻塞）时，自动调用 `review_after_download` 执行本季完整实物重核：

| 到位复核后的真实实物结果 | 系统自动分流与门禁动作 |
| :--- | :--- |
| 正片全季唯一补齐（允许不同集之间存在正常分辨率／编码差异，无同集重复） | 清除 `post_download_review` 阻塞，自动转入 **齐全可归档** |
| 整季包或补缺引入同集技术副本 | 下载台账正常收口为 `in_library`，同时重新生成副本清理计划并转入 **待复核清理**（绝不沿用下载前的旧副本列表直接归档） |
| 含已确认独有剪辑／配音版本、明确 `S00`/花絮，或纯附件子目录 | 复用独立资产保护规则原样保留，不误判为缺集或异常，归档预检时一并明确去向 |
| 出现正片超号、错季、无法识别视频或身份冲突 | 有效到位集结案不重推，争议文件转入 **异常剧集** 人工复核 |
| 源端／归档读取失败、文件指纹跳变、MP 队列查询失败或仍在下载／整理写入 | 保持 `post_download_review` 待复核状态留在 **等待入库／回执** 页，明确展示阻塞原因，统一暂停归档、删源与重复推送（归档目录仅明确 `NotFound` 视为零覆盖，超时／权限错误绝不误放行） |

## 六、主动放弃补缺删源与「确认源已移删」外部对账

### 6.1 主动放弃补缺：单季／批量删源与无他季连删剧根（v2.5.52 ~ v2.5.86）

与「待复核清理」中的“归档已齐安全清源”完全隔离，采用独立路由（`app/api/source_discard.py`）：

1. **开放范围**：
   - **单季入口**：`缺集待补` 与 `无合格资源` 页签卡片均提供「删除源端（本季）」（`/api/archive/discard-source-season/preview` 与 `/discard-source-season`）；
   - **批量入口**：**仅在「无合格资源」页签**开放勾选后的「批量删除源端（本季）」（`/api/archive/discard-source-season/batch-preview` 与 `/batch`，单批 `1~100` 季），若同作品季存在其他未达无资源条件的目录则拒绝纳入。
2. **七重安全门禁（缺一不可）**：
   - 必须先生成预览（递归盘点季目录至多 8 层、20,000 项，展示确切删除路径、视频／字幕／其他文件数与总容量，有效期 `30 分钟`），且执行时必须携带有效 `preview_token` 并勾选 `confirm_abandon=True`；
   - 初检任务未结束、`post_download_review` 待复核、存在在途 `GapFillEpisode` 台账、MP 活跃下载队列命中相关作品季（或 MP 已配置但队列状态读取失败）时，一律 `HTTP 409` 硬拦截；
   - **严格目录边界与无他季自动连删剧根（v2.5.86）**：目标必须位于受控 `source_root` 内（严禁触碰 `archive_root` 或任务根目录），季目录名必须严格匹配 `Season N / SN` 且未被其他季引用；当数据库无其他有效剧季记录，且物理网盘剧集目录下除待删季外**零子目录、零视频／STRM 文件**（仅剩刮削海报／NFO／字幕或隐藏临时垃圾）时，预览自动标记 `will_delete_show_dir=True` 并在执行删季后（含多季批量全删的最后一季）一并删除该剧集目录；若同剧仍有其他季目录或视频文件则严格仅删本季目录、保留剧集根目录；
   - **执行前指纹复核与外部已删兼容**：执行前重读比对目录 ID 与全量文件快照，发现新增或变化立即拦截要求重预览；若预览时或执行前源目录已在外部消失，安全降级为零删除对账结案（但若预览时不存在、执行前目录又重新出现，则拒绝套用旧请求删除）；
   - 删除后经短退避强读父目录确认消失，并对剧集父目录及任务初检目录同步执行 `force_refresh=True` 强制刷新 CloudDrive2 缓存，持久化批次回执（支持同令牌幂等重查与「查看最近删源回执」），状态记为 `source_absent`（注明主动放弃，不计入归档完成，不自动取消外部下载）。

### 6.2 「确认源已移删」按需外部对账与防误触机制（v2.5.61 ~ v2.5.62）

针对用户在 CloudDrive2 / 115 外部手动删除或移走了源季目录（或 MP 采用「移动」模式整理移空了原季目录）导致条目留在列表的场景，卡片提供 **「确认源已移删」**（`POST /api/tasks/{task_id}/seasons/{record_id}/reconcile-source`）：

1. **全程零媒体写入**：仅按需调用 `source_entry` 强读父目录核实存在性，**绝不执行任何网盘删除／移动操作，也绝不取消 MP 下载任务**（普通切页与 `GET` 请求不自动扫盘）。
2. **严格区分“确认不存在”与“仍存在／读取异常”**：
   - 若目录仍存在（**哪怕是空目录**）→ 返回 *“源目录仍存在；未改变记录或文件”*，卡片原样保留；
   - 若遭遇超时、权限错误、清单格式异常或源根不可用 → 返回 `HTTP 409` 保留待办，绝不把网络故障吞成“目录已删”；
   - 仅当明确 `NotFound` 确认源季目录已物理消失（且无未完成的剧根附件保全回执）→ `record_source_absent` 将记录标记为 `source_absent` 移出当前待办列表并刷新任务汇总，写入独立 `reconcile_source_absence` 审计日志。
3. **名称去歧义与等待页二次确认（v2.5.62）**：将原易被误认为“普通只读刷新”的「核对源目录」统一更名为 **「确认源已移删」**；在「等待入库／回执」页签点击时弹出确认提示，明确告知该操作会在源目录不存在时将条目移出待办，若仅想核查下载分集是否入库应点击顶部的「核对入库」。

## 七、核心验收标准（D01–D12、S01–S17）与源码测试映射索引

### 7.1 缺集补缺、对账复核与安全删源验收矩阵（D01–D12）

### 7.2 补缺站点规则与自动分类验收矩阵（S01–S17）

| 编号 | 验收场景 | 通过标准 |
| :---: | :--- | :--- |
| **S01** | 站点脱敏读取与首次草稿 | 只读获取 MP 站点目录并 100% 剥离 Cookie／Passkey／Token；未初始化时生成待确认草稿，不自动发起搜索或下载 |
| **S02** | 动漫与非动漫两套独立持久化 | 两套规则独立保存勾选集合、优先级顺序与版本号，刷新或重启后完整回显（`v2.5.50`），互不串改且不修改 MP 全局设置 |
| **S03** | 免确认自动分类与人工偏好覆盖 | 按 `人工偏好 → 作品动画元数据/NFO → 最近明确分类目录 → 显式标签` 自动路由，取消强制类型选择框；人工切换后跨任务复用 |
| **S04** | 空规则与暂停状态硬拦截 | 空规则／`paused`／`uninitialized` 明确提示并阻断该类搜索，严禁省略 `sites` 参数退化为全站搜索 |
| **S05** | 全搜索分支站点范围一致 | TMDB 精确搜索、中英文别名回退、整季包补搜及失败换种重搜统一携带相同有效站点列表，剔除未授权站点候选 |
| **S06** | 站点优先级绝对生效 | 同一策略阶段内高优先站候选达标时，即使低优先站做种更多、体积更小或返回更早，仍严格选用高优先站 |
| **S07** | 硬条件先于站点优先级 | 高优先站候选若错季、做种低于门槛、身份不符或覆盖不明则跳过，并在回执中具名记录降级至低优先站的原因 |
| **S08** | 跨站瀑布式散集组合 | 高优先站最大化覆盖缺号，低优先站仅补剩余缺号（如 `A:E03 + B:E04`），多集包重叠时重规划不重复提交 |
| **S09** | 整包与散集阶段衔接 | 缺 $>3$ 集时低优先站合格整包优先于高优先站散集；缺 $\le 3$ 集散集不全时在提交散集前切换合格整包回退 |
| **S10** | 跨站同种去重保高优来源 | 同 Hash／同名同体积种子跨站出现时保留最高优先站点来源及其独立凭据，绝不混用不同站点的链接与做种数 |
| **S11** | 站点改名、新增、停用与实例隔离 | 改名保 ID 顺序，新增站默认未选，停用／删除站具名标记并自动收缩有效范围，切换 MP 实例隔离旧 ID |
| **S12** | 目录异常与单站超时有界降级 | 站点目录读取失败不伪造空列表；单站超时在有界等待后允许降级使用已响应站点并如实标注未完整响应 |
| **S13** | 乐观锁保存与批次规则快照 | 保存校验 `expected_version` 拦截多窗口冲突（`HTTP 409`）；运行批次冻结确认时的规则快照，新规则作用于新批次 |
| **S14** | 提交拒绝回退与超时幂等 | MP 明确拒绝可在快照内有限次换次优活种；请求超时锁定观察期先对账，严禁立即换站重投 |
| **S15** | 缓存隔离与可解释诊断 | 搜索与审计缓存按实例、类别、规则版本与站点集合隔离，4 小时 TTL 防短效直链过期（`v2.5.72`）；详情完整展示路由与选种依据 |
| **S16** | 权限边界与脱敏审计 | 规则仅作用于补缺选源，前端与日志零密钥泄露；保留优雅停止、逐集台账与受控放弃删源边界 |
| **S17** | 嵌套分类路径与错放目录纠偏 | `动漫/日本/作品/Season 1` 自动用动漫规则，`电视剧/综艺/作品/Season 4` 自动用非动漫规则；综艺目录内误放动画作品凭元数据自动纠偏为动漫规则 |
