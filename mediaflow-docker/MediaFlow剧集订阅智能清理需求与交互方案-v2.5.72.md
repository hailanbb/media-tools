## 0. v2.5.63 ~ v2.5.72 修订落地与现行生效规范（最高优先级）

> **零回归隔离红线**：本模块所有新增与优化严格收口在订阅治理域（`subscription_cleaner.py`、`subscription_cd2_index.py`、`subscription_governance_service.py`、`app/api/moviepilot.py` 订阅路由及 `frontend/index.html` 订阅视图），**不改动**初检引擎、五模块归档与清源、补缺核心及任何数据库表结构（快照与缓存统一持久化至既有 `metadata_cache` 表）。

### 0.1 2026-11-22 实盘数据复查结论（1,072 条订阅）

- **总量分布**：MoviePilot 共 1,072 条订阅（电视剧 682 条、电影 390 条）。
- **来源噪音确认**：**99.7%（1,069 / 1,072）** 的 `username` 均为 `豆瓣榜单`，仅 3 条为 `admin` 手动订阅；因此移除卡片上刷屏的「豆瓣榜单」徽标，改为**反向高亮**极少数的 `👤 手动订阅`（后端仍保留 `is_douban_sync` 保护权重）。
- **异常词条分布**：实测无封面图 44 条、无中文译名 35 条、小语种标题 3 条、纯繁体字标题 40 条（启用 GB2312 一级常用简体字防误报护栏后，对《食神·百厨大战》《深夜食堂》等全库简体标题 **0 误报**）。

### 0.2 数据真相源：全面以 CD2 实盘为准

- **废弃纯 MP 计数口径**：剧集卡片显示的集数统计与「全季完结」判定，一律改为以 **CloudDrive2 受控源根（`source_root`）∪ 归档根（`archive_root`）** 下的 `电视剧 / 动漫` 实盘目录为准。
- **双端合并去重**：按目录名 `[tmdbid=XXX]` 主键匹配（无 ID 时回退规范化剧名），钻取目标季号 `Season X` 合并 `源目录 ∪ 归档目录` 去重集号集合，卡片清晰标注 `CD2 实存 X / Y 集 [源A·归档B] (MP记Z)`；同步复用既有巡检的 `SeasonRecord` 数据与本地 `MetadataCache`（`tmdb_tv:{id}`）。
- **单目录容错护栏**：仅当剧集大类完整扫描无超时/报错（`tv_scanned_ok = True`）时，才对未命中项标注 `cd2_verified = True`（0 集），防止因单目录超时误判为未入库。
- **全季完结标签定位**：`🟢 全季完结` 专门承接“CD2 实盘已收齐整季且播完，但 MP 订阅记录尚未移除”的安全退订队列，避免历史完结订阅持续消耗 MP 轮询与搜索资源。

### 0.3 多维「虚标短剧」识别（借鉴开源社区最佳实践，严防误杀）

参考 GitHub `MoviePilot-Plugins`（`PlayletCategory`）与 TMDB 社区规范，废除旧版按 `season > 5` 或单看 60/99 集的粗暴规则，改为 **「强白名单防误杀 + 四层分层识别」**：

1. **强白名单排除**：
   - TMDB 类型命中动画（`16`）、纪录片（`99`）、儿童（`10762`）、新闻（`10763`）、真人秀/综艺（`10764`）、脱口秀（`10767`）；
   - CD2 路径包含 `/动漫/` 或 `/儿童/`；
   - 标题含综艺/晚会/特辑后缀（`纯享版`、`大神版`、`加更版`、`晚会`、`纪录片` 等）；
   - `Season >= 2` 的多季长剧（除非显式标记短剧）。
2. **四层分层判定**：
   - **P1 显式声明**：标题或简介明确含 `短剧 / 微短剧 / 竖屏 / 小程序剧 / playlet`。
   - **P2 TMDB 单集时长金标准**：复用本地 `MetadataCache` 已有缓存（零额外 TMDB 请求），华语/中文区 `episode_run_time <= 15` 分钟直接判定。
   - **P3 S01 高集数 + 微短剧高频题材词**：`Season 1` 且总集数为 `99` 占位或 `>= 40` 集，联合命中高置信微短剧题材词（如重生、穿越、闪婚、霸总、炮灰、收废品、棺中醒来等）。
   - **P4 CD2 实盘体积佐证**：CD2 实存 ≥ 10 集且非 `.strm` 正片单集均体积 `< 65 MB`。

### 0.4 「断更停滞」精细分桶 + 联动补缺选种引擎

- **彻底拆分为两类**：
  - `🟡 部分已下·断更`（`stalled` / `partial_stalled`）：曾下载过部分集数但长期断更，优先联动补缺引擎筛查可补资源。
  - `⚫ 零进度死种`（`zombie` / `never_downloaded`）：自订阅起至今 CD2 实存 0 集，长期无资源入库，适合直接批量取消订阅。
- **只读复用补缺核心（零修改 `download_service.py`）**：
  - 复用 `resolve_category_gap_fill_sites`（动漫 / 非动漫独立站点路由）、`_evaluate_raw_candidates`、`_dedup_evaluations`、`_plan_standalone_downloads`、`_pick_best_season_pack` 与同档省容量算法。
  - 在统一查询阶段 3 中，以 `Semaphore(3)` 受控并发为所有 `🟡 部分已下·断更` 剧集按 CD2 真实缺集号搜寻 PT 站点资源，结果持久化至 `metadata_cache`（`sub_resource_audit_cache_v1`），卡片直接展示命中站点、做种数、体积、整季包/散集方案与覆盖集号。

### 0.5 低质 / 异常特征识别（`⚠️ 异常特征`）

在剧集与电影双轨同步新增 5 类异常特征检测（`detect_low_quality_signals`）：
1. **无封面图**（`poster` 与 `backdrop` 均为空）；
2. **垃圾/占位词条**（`重复词条`、`test`、`tbd` 等）；
3. **小语种标题**（日文假名、韩文谚文、俄/阿/泰/印地/希伯来/希腊等脚本）；
4. **纯繁体字标题**（`PURE_TRADITIONAL_CHARS` 叠加 **GB2312 一级常用简体字自动剔除护栏**，确保全库简体中文零误报）；
5. **无中文译名**（仅含拉丁字母且无任何汉字）。

保护边界：已有 CD2 实盘资源、手动订阅或受保护关键词条目仅展示 `⚠️` 提示标签，**绝不自动划入退订清单**。

- **批量补缺下载规则对齐与诚实进度条（v2.5.71）**：
  - **去掉虚高进度偏置**：所有订阅治理批量动作（批量补缺推送、批量取消订阅/删源、批量变更状态）统一从 `0%` 起算，严格按真实完成数 `int(100 * processed / total)` 更新，文案统一为 `正在推送第 X/N 部（已完成 Y 部）`，消除百分比与进度提示错位；
  - **自动清理 MP 转移记录**：电视剧批量补缺推送成功后，与独立补缺模块保持一致，立即调用 `mp.clear_transfer_history_for_episodes(..., episodes=None)` 清理 MoviePilot「媒体整理」中该剧该季的旧转移记录（**严格仅删记录，绝不删实体文件**），防止下载完成后被 MP 跳过自动整理，并在回执中汇报清理条数；
  - **电视剧活跃下载队列双重防重**：新增 `_is_tv_season_in_active_downloads()`（按 TMDB ID+季号或标题+季号精确匹配，忽略已完成/纯做种任务），在资源筛查与推送前双重拦截已在 MP 下载队列中的剧季，防止重复下种。
- **种子缓存 4 小时 TTL、推送失败自动实时重搜换种与报错透出（v2.5.72）**：
  - 为 `downloadable` 种子缓存新增 **4 小时有效期（`RESOURCE_DOWNLOADABLE_CACHE_TTL_SECONDS = 14400`）**，防止如天空（`hdsky.me`）等 PT 站点的短时效签名直链隔天失效后继续被复用；
  - 批量推送中若某作品的缓存种子全部提交失败，系统自动触发一次实时重搜（`_audit_single_subscription_item`），剔除已失败链接并自动切换至其他站点有效活种重试（重试成功后同步执行 MP 转移记录清理）；若重搜确认无可用资源则自动刷新缓存状态为 `no_resource`；
  - 后端日志与前端结果弹窗（`_formatGapFillPushAlert`）完整透出每部失败作品的站点标签与具体报错原因，不再仅提示汇总失败数。

### 1.1 当前实例的只读快照

## 2. 用户最终得到的处理方式

推荐提供一次配置、持续执行的「自动治理」模式。启用时显示具体策略与作用范围，之后符合规则的项目自动处理，每轮只输出一份结果摘要。首次进入先给出只读诊断和实际候选，用户可一键启用推荐配置。历史数据没有足够观察证据的项目，从本轮开始积累。

| 类型 | 系统默认建议动作 | 用户日常需要做什么 |
|---|---|---|
| 全季已播毕、目标范围与版本已核实入库，订阅仍挂着 | 自动仅退订，保存设置快照和完成依据 | 查看汇总，需要时查看详情或恢复 |
| 从未取得内容，达到长期无有效资源条件 | 自动暂停并进入观察；观察满 30 天且复查仍符合时自动退订 | 默认无需逐条点选，可为想长期收藏的项目设置「始终保留」 |
| 中途收集停滞，后续资源多轮核查均不可用 | 同样暂停观察，再按策略退订；已收到的部分内容保留 | 可选择继续等，或手动仅退订 |
| 能找到资源但规则、权限、磁盘或整理流程阻碍获取 | 进入「需要修复」，相同原因集中成一项 | 一次修正站点或规则问题，再批量复查受影响订阅 |
| 待播、正常连载、仍在产生有效下载进展、洗版中或显式保留 | 保留订阅；必要时依据可信排期暂缓搜索 | 查看状态即可 |
| 身份、播期、总数或查库范围无法确定 | 本轮待核实并保存原因；证据变化后再检查 | 只处理需要用户决定的身份或收藏意图，临时故障自动重试 |

**清理的作用对象是订阅记录。** 自动治理执行暂停或取消订阅，源视频、媒体库、下载任务和做种任务各自保留。现有「退订并清理源视频」继续作为独立的手动操作，显示具体文件和已有确认流程，不参与自动规则。取消一条订阅也不代表整部作品永久停止收藏。

## 3. 每条订阅先建立一份可解释的证据

以 MoviePilot 实例、订阅 ID 识别具体操作对象；以媒体来源及 ID、季、剧集组/编号映射、起始集与目标范围、版本和语言要求判断是否重复或完成。季号为空保持未知，季号 0 单独解释。相同 TMDB 的 S01 与 S02、正片与特别篇、国语版与原声版分别核验。

| 证据 | 读取与解释要求 |
|---|---|
| 身份与名称 | 保留原始标题，同时补充可信中文名、原名、发行别名和年份。优先按 ID 关联，再用别名搜索；名称翻译只改善显示与检索，不授权更换作品身份 |
| 目标范围 | 读取 season、start_episode、total_episode、episode_group、用户定制范围和版本规则。按范围判断完成，例如仅追 E09–E12 时，界面写“订阅范围 4 集已满足”，不宣称全季已齐 |
| 本季播出 | 复用连载留源模块的季级证据，区分已播、待播和日期未知。总数 99/100、整剧 Ended、已播部分齐全、长时间未更新都不足以独立证明季终 |
| 入库 | 以 CD2 实盘源+归档合并去重集号为准，辅以媒体服务器分集明细及多集映射。多份 E05 计一次，E05–E06 合集按可靠映射计两集，特辑不抵正片；STRM 文件须有可用的目标证据 |
| 下载与整理 | 关联下载器、下载哈希、MP 历史、作品 ID、季与集号。区分下载有进度、排队、停止、错误、已完成待整理、做种和整理失败。仅做种不持续阻挡完成退订 |
| 搜索与站点 | 保存每次使用的站点范围、名称/ID/别名、季集范围、候选、过滤理由、做种情况、成功/失败站点及时间。0 命中、请求失败、被规则过滤分别记录 |
| 时间与变化 | 分别保存最后新增已入库内容、最后有效下载进展、最后成功核查、最后有效搜索未命中时间。MP last_update 只作为线索，观察期以可验证事件为准 |
| 来源与用户意图 | 优先绑定插件历史/导入事件和来源 RSS；只有 username 时标“来源推定”。显式保留、手动暂停、洗版与用户指定品质均参与决策 |

任何必要接口失败，字段以未知记录；缺数据不能补零。未知 ID 的下载任务若可证明属于另一作品，不阻塞所有订阅；若无法排除与本季有关，只阻塞受影响对象。读取分页结果时保存是否读全，防止被截断的列表误报订阅已消失或没有在途任务。

## 4. 自动退订已完成项目

同时满足以下条件，才进入「已入库，可退订」。

1. 身份、季与目标集范围明确，当前来源资料支持该范围已经播出完毕。一般订阅需要本季播毕；有明确用户范围的订阅按其范围判断。
2. 所需正片或期段均有可核实的 CD2 实盘入库文件。电影式合集、跨季、动漫绝对集号与综艺分段必须先转换到本季对应关系。
3. 入库版本满足订阅意图。洗版、特定语言或版本保留默认保持；另行启用“版本目标已满足也退订”时才进入专项核验。
4. 同一目标范围没有尚需结算的下载、整理或修复任务。已完成并处于正常做种的任务可继续存在。
5. 本轮执行前再次读取订阅及相关证据，用户没有刚修改范围、开启洗版或设置保留；P 状态的待定理由已解除。插件仍明确否决完成时保留并说明原因。

推荐每天核查一次完成候选；收到可信入库事件时可提前重评。对所有剧集可分批进行低成本入库比对，避免只检查 MP 自报完成的四条，从而漏掉“MP 尚报缺集，但库中早已齐全”的订阅。

通过后显示“已核实 E01–E12 入库，取消 S01 订阅”。执行结果记录订阅实际已不存在、核查依据和本轮计数。取消操作使用订阅 ID 定位，不按片名整批删除同名项目。人工删除 API 与 MP 自身“自然完成”历史的效果要分别适配，MediaFlow 保存自己的完成审计，不伪造下载历史。

## 5. 从未有资源与中途断更如何自动处理

### 5.1 候选阈值与暂停观察

下列为建议初始参数，用户可在「自动治理设置」统一调整。天数只负责进入候选，执行还需有效搜索、播期及活动证据。

| 情况 | 进入长期停滞候选的建议条件 | 后续动作 |
|---|---|---|
| 从未收到目标正片（零进度死种） | 订阅创建至少 60 天；至少已确认有目标正片播出；连续 45 天无有效进展 | 满足下述资源条件后自动暂停或批量取消订阅 |
| 已收到部分内容后停滞（部分已下·断更） | 存在已播待补内容；连续 60 天无新增入库或有效下载进展；正常停播间隔已排除 | 优先联动补缺引擎搜寻站点可补缺资源，有源一键补缺、无源取消订阅 |
| 等待尚未播出的内容 | 下集/季终尚未来到，或有可信的正常休播公告 | 留在正常追更或待播，排期可用于减少搜索 |
| 资料未知、占位总数或编号冲突 | 无法形成可信目标缺口 | 资料核对；不计算“剩下多少集永久无资源” |
| 已由 MediaFlow 暂停的观察项 | 观察至少 30 天，最近 7 天内完成一次有效复查，仍符合无有效资源及无进展条件 | 自动仅退订，并进入退订记录与自动来源抑制 |

资源条件为至少 3 次成功的有效搜索，跨至少 14 天，最近一次在 7 天以内，均未找到能覆盖目标缺口且满足订阅要求的可用资源。历史订阅很老但没有可信搜索记录时，先从本轮积累；用户仍可对明确不想继续收藏的项目批量仅退订。搜索历史满足条件时直接进入暂停，避免再次重复等待。

有效搜索须覆盖该订阅配置的有效站点范围。某站点失败则这一轮不计入“全范围无匹配”；其余成功站点的结果仍保存复用。长期失效站点可由用户在一处调整参与范围，系统据新范围重新观察。发现同一站点影响大量项目时，汇总一个修复事项。

### 5.2 为什么没资源，要分清原因

| 搜索或下载事实 | 本轮结论与操作 |
|---|---|
| ID 与可信别名均无同作品同季候选，搜索范围完整且站点健康 | 记录一次有效未命中，满足周期条件后暂停观察或供批量退订 |
| 有同季资源，但只有已经收齐的集号 | 对剩余缺口仍记未命中，注明搜到了哪些已拥有内容 |
| 有整季包，但缺少可核实的内容清单 | 列为范围待核对，不能用“整季”字样抵缺口 |
| 有符合身份和缺口的资源，但被指定分辨率、语言、免费条件或过滤规则挡住 | 「有资源，规则未满足」。展示具体差异，用户可一次应用规则调整到选择范围；不静默降低收藏标准 |
| 有正确候选但长期零做种、反复下载无进展 | 标“资源不可用／下载停滞”，结合连续下载观测及替代资源检查决定暂停。短时 0 速度不成立 |
| 站点登录失败、超时、限流、下载器空间不足、整理报错 | 「运行故障」。修复后再判断资源。无效搜索次数不累计 |
| 标题纯日文、韩文、繁体或其他小语种 | 纳入「异常特征」提示标签，无实盘且非手动收藏项支持一键批量清理；已有实盘或手动收藏项保留 |
| 豆瓣未收录或查不到 | 记录该来源不可用，使用 TMDB 或已验证映射继续核验。豆瓣存在与否不作为自动清理门槛 |

暂停时写入 S 状态并记录“由 MediaFlow 因长期停滞暂停”，从活跃清单转到观察清单。仍在下载的无进展任务单列给用户处理，订阅暂停不直接删种。观察期发现合格新资源或新入库进展时，系统重评并可自动恢复原追更状态；只恢复由本模块暂停且没有后续人工更改的项目，用户原本暂停的项目保留其意图。

## 6. 从入口减少积压，退订后防止反复回来

### 6.1 当前就能使用的控制点

本机“订阅助手”表单已提供按新增订阅用户自动暂停的能力，可以把「豆瓣榜单」的新导入先置为暂停。该字段按用户匹配，本轮读到的表单没有剧集专属限定，直接启用可能同时影响电影。剧集首版应由适配层增加媒体类型条件；具备类型隔离并验证与其他暂停策略的联动后，再决定是否复用该开关。MediaFlow 对新增剧集先判身份、季、已在库、已有订阅及资源，再恢复合格的追更项。无法在入库前拦截的插件使用这一流程，并标明“导入后筛选”的生效时机。

DoubanRank 可减少榜单/RSS、提高评分要求。现有评分门槛为 0，公开 2.1.0 支持选择评分来源，但本机配置未显式保存该字段；实施界面应读回实际默认并解释。评分、国家和内容语言属于收藏偏好，推荐以来源的实际产出决定是否收紧，不把缺评分或非中文标题直接判为无资源。

来源面板逐个列出两个内置榜单与 13 个自定义 RSS 的标识、最近导入、7/30 天新增、已核实入库、长期停滞、被拦截和退订后重建数量。历史无法追溯到具体 RSS 时先合并显示“豆瓣榜单，具体源未知”；从新事件建立精确归因，避免把推测展示成精确报表。

### 6.2 新增订阅的拟议准入

手动收藏且选择「始终保留」的项目遵循用户意图。自动来源先检查稳定身份、季和编号范围，确认尚未满足收藏目标，再按以下规则处理。

| 新导入情况 | 处理 |
|---|---|
| 同身份、季、范围与版本的订阅已存在 | 关联已有订阅并记录来源，抑制重复 |
| 相同目标已核实在库 | 跳过自动创建，或对刚创建的项按完成流程退订 |
| 已播且有合格资源 | 纳入追更；恢复订阅后的实际下载由 MP 原有规则执行 |
| 已播但首次有效搜索无匹配 | 进入待筛选观察，按预算重查，不因一次未命中永久排除 |
| 尚未首播且排期可信 | 进入待播，建议首播前 7 天恢复资源检查 |
| 身份冲突、多个版本范围或资料未定 | 进入待核实。具备可信 ID 的小语种标题可正常通过 |

### 6.3 抑制与恢复

退订后按“实例、作品身份、季、剧集组/范围、版本目标、自动来源”保存抑制记录，不能只记已删除的订阅 ID。已完成项以入库目标仍满足为条件持续抑制；长期无资源项建议抑制 90 天。用户选择「永久不再自动订阅」时持续抑制，手动「重新收藏」可解除。新一季、新版本目标或用户明确手动新增要重新判断。

DoubanRank 的公开实现通过标题加豆瓣 ID 组成同步历史键，因此保留现有导入历史有助于减少重复。MediaFlow 的稳定身份抑制用于应对改名、换 RSS、插件历史清空和其他来源再次创建。仅写 MediaFlow 的抑制表无法阻止所有 MP 插件，需由来源插件适配、统一准入插件或创建后暂停机制真正执行。重复创建被识别后记录来源并处理，不产生无穷的创建—删除循环；无法控制的来源集中提示一次。

恢复暂停通常可以沿用原订阅 ID。恢复已退订项要按保存的配置重新创建，生成新 ID，再从实际媒体库与在途情况计算缺口；MP 当前公共写入接口会裁剪部分运行字段，因此恢复不承诺原样写回内部状态或历史。

## 8. 自动运行、限流和冲突处理

建议默认每日本地时间 03:30 进行轻量巡检，资源搜索按候选轮转；用户可改时段或选择仅手动运行。MediaFlow 服务未运行时，该轮标为未执行，恢复后合并执行一次，避免补发多轮请求。此定时任务属于本模块的显式自动治理配置，初检页面继续按原有使用方式工作。

对当前规模，先批量读取订阅、配置和队列，按作品/季复用元数据，再核对完成候选和疑似卡住项。站点资源搜寻采用 `Semaphore(3)` 受控并发与缓存复用（`sub_resource_audit_cache_v1`），并支持中途优雅停止保留已查结果，避免触发 PT 站点限流。

只在本季身份、范围、规则、来源或实际内容发生变化时失效相关证据。健康状态变化会影响“无资源”结论。暂停到自动退订前，必须取得仍在有效期内的复查；队列来不及复查的项目延期，不凭旧结论执行。

每个实例及订阅 ID 的写入只能有一个执行者，批次同时记录本次策略版本和订阅快照。执行前重读最新设置及活动，有变化则跳过并重算。与订阅助手、缺失集数插件、人工修改保持单一动作责任。持续出现自动改回 P/R/S 的项目转为“策略冲突”，暂停自动写入并指明已观察到的变化。

## 10. 验收场景与上线顺序

| 编号 | 输入或场景 | 必须观察到的结果 |
|---|---|---|
| T01 | 复现本轮 671+ 条剧集记录，豆瓣 ID 全为空 | 身份判断能使用已有 TMDB ID，不把剧集批量标为无效（已通过） |
| T02 | CD2 实盘集数与 MP 计数不一致 | 卡片与诊断一律以 CD2 源+归档合并去重集数为准，明确展示 `[源A·归档B] (MP记Z)`（已通过） |
| T03 | MP 计数仍缺集，但 CD2 实盘本季已收齐播毕 | 被 CD2 对账发现并归入 `🟢 全季完结`，支持「批量一键取消订阅」（已通过） |
| T04 | 长篇国漫（《仙逆》）、多季综艺（《密室大逃脱 大神版》）、纪录片（《中国玉》） vs 真微短剧（《她从棺中醒来》） | 强白名单 0 误杀国漫/综艺/纪录片，精准识别真微短剧（已通过） |
| T05 | 简体标题（《食神·百厨大战》《深夜食堂》） vs 繁体/小语种/无封面标题 | 简体中文 0 误报，精准归入 `⚠️ 异常特征` 并支持批量取消订阅（已通过） |
| T06 | 进入「订阅清理」页签 vs 点击「查询最新订阅数据」 | 进入仅秒读快照不触发外部请求；点击查询后三阶段进度条逐项推进，阶段 2 完成即渲染分类数据（已通过） |
| T07 | `🟡 部分已下·断更` 搜寻到合格种子与无源条目混杂 | 卡片直接展示命中站点种子详情；「批量补缺下载」零二次搜寻直接推送；「批量取消订阅」默认仅选无源项；执行期间实时显示逐项进度条（已通过） |
| T08 | 首播未到、连载当前已播齐、正常季中休播 | 归入 `🔵 活跃连载` 自动锁定保护，不提供批量取消订阅按钮（已通过） |
| T09 | 下载 0 速度一小时、连续多轮无进展、完成做种、整理失败 | 短时停滞保留；做种不阻止完成退订；整理失败进入修复 |
| T10 | 自动暂停、自动退订、恢复订阅 | 全流程媒体文件与下载/做种任务无新增删除 |
