# MediaFlow 批量补缺完成刷新与待补清单优化方案

2026-11-12 · 适用入口为“真缺集待补 → 批量一键推送 MP 补缺 → 完成并刷新”。本文为设计方案。

## 用户点击后应看到什么

建议把“真缺集待补”作为需要继续找资源或处理问题的工作清单。若本季所有实际缺号均已获 MoviePilot 受理或已在队列中可靠匹配，点击“完成并刷新”后，该季从默认待补清单移出，仍可在同页“已推送待入库”筛选中查询。文件入库后再按初检规则流转。部分推送只扣除已覆盖的待办号，保留同一张剧季卡片；完全无资源则原卡保留并给出原因。无需新增独立模块。

例如《24小时主厨生死门》S03 原缺 E02、E03、E09。若三个集号均获受理，默认待补清单减少一季；若只受理 E02、E03，清单季数不变，卡片显示“待补 E09 · E02、E03 已推送待入库”。再次点击只尝试 E09。若只找到一个高做种种子但 MP 拒收，三个缺号仍需保留。

## 当前实现为何会继续显示

本地 download_service.py 已区分整包物理覆盖、实际补缺覆盖和 MP 受理，并写入操作日志。成功后主要更新 status_detail，原季状态仍为 download_needed 或 period_missing；多次提交还可能覆盖上一条说明。暂无候选、做种不足等信息主要随本次响应或弹窗日志返回。前端 confirmDownloadDone 收尾重新加载清单，前端分类、任务查询和任务汇总仍按原季状态取数。因此刷新可以再次显示已推送季，失败原因也可能随弹窗关闭而消失。进程内的近期提交缓存适合防短时间重复，跨刷新、重启与重检还需要持久依据。

## 按缺号计算待办

保存两种事实：初检认定源端与归档仍缺哪些正片；MP 已经受理哪些缺号、处在哪一步。以最近可信的两库核验为基准，默认可重搜号 = 实物缺号减去有有效受理或队列证据的覆盖号，再排除提交结果待核对的号。后者留在默认清单提示“核对提交结果”，暂停重复推送。期号和分段集号分别计算；整季包只抵扣它能证明覆盖的本次缺号。

| 最近结果 | 刷新后的清单和原因 | 下一次动作 |
|---|---|---|
| 所有缺号均受理，或同作品、同季、同编号队列已覆盖 | 默认移出；同页显示“已推送待入库”及覆盖号 | 核实下载与入库 |
| 部分受理、部分暂缺或失败 | 保留一张卡，列出剩余号及各自原因 | 仅重试剩余可补号 |
| 搜索正常完成，返回零条 | 保留，显示“本次搜索未返回资源”、请求站点和时间 | 下次可重新搜索 |
| 有候选但未满足条件 | 保留，写出具体条件，例如“E09 有 2 个匹配候选，最高 1 人做种，最低要求 2 人” | 有新候选或做种恢复后重试 |
| 有资源但错季、整包覆盖未知或分段不匹配 | 保留，给出身份或覆盖差异 | 核对编号或换资源 |
| 部分站点超时、认证失败、接口不可用 | 保留，并区分“查询未完成”和“已查询站点未命中” | 重试查询，必要时检查站点 |
| MP 明确拒绝提交 | 对应缺号保留，显示可读的拒绝原因 | 修复后重推 |
| 已发出请求但回执丢失 | 保留为“提交待核实”；核对下载标识或种子及覆盖号 | 明确未受理后才开放重推 |
| 用户中止批次 | 未开始的条目标“本次未执行”；已受理的照常计算，已发出的先对账 | 继续未执行部分 |
| 下载已完成但未见入库、任务从队列消失 | 先核对下载历史、整理结果和两库；显示“待整理”或“待核实” | 确认取消、失败或缺失且没有有效任务后，自动回到待补并说明原因 |

## 后端和页面如何保持一致

1. 逐候选保存实际覆盖号、受理结果和 MP 下载标识（若返回），再按季合并；为无候选、覆盖不足和未执行也保存最近一次逐季结果。沿用操作日志中的已核实字段，为待覆盖、在途、待核实、已入库和失败原因提供可查询的数据。未知大小、缺少站点回执等情况按实际信息显示。日志不保存站点凭据或种子私密链接。
2. 每次提交前记录意图，收到回执后独立落库。用任务、稳定源季路径、作品身份、季号和编号口径关联记录；同时以作品身份、覆盖范围及资源标识检查跨任务重复提交。现有重检会重建季记录，不能仅用旧记录 ID 关联。作品纠偏或编号口径改变后重新匹配，不能继承旧作品的受理结果。
3. “完成并刷新”读取本批及所属任务的后端结果，只触发显示更新；受理证据及时落库，即使关窗或断线也保留。重复点击刷新不提交下载。已切换到其他任务时，旧批次只更新原任务。任务卡数字、分页、全选与批量操作统一使用后端的待办计算，避免页面隐藏后仍被全选推送。
4. 在刷新、重检和后续补缺前按需对账，支持主动“核对入库”。队列消失或缓存到期不能单独认定失败。优先用下载标识及种子标识核对，最终以源端和归档实际覆盖流转到已有模块；已齐但有版本冲突的仍交给既有复核规则。
5. 历史日志若有可靠覆盖号且身份仍一致，可结合当前队列和实物还原。只有“已推送”文字或证据已失效的旧记录留待核实。保留最近检查时间和每个剩余缺号的原因，新的结果替换过期说明。默认卡片显示一行理由，点击详情再看站点、候选数、做种门槛和回执。

## 验收

用同一任务准备三季：A 全部受理，B 部分受理，C 搜索无结果。点击“完成并刷新”后，默认清单从 3 季降至 2 季，B 显示剩余缺号，C 显示保留原因，A 在同页待入库筛选中可查。关闭页面、重启服务后应得到相同结果。再次全选只处理 B、C 当前可重试的号。

另测整包与散集重复覆盖、同季多个候选一成一败、提交超时后队列延迟出现、中止时仍有请求在途、重检生成新记录 ID，以及 MP 取消下载后确实仍未入库。逐项核对默认清单数量、各集号状态、实际提交次数及恢复原因。先以模拟回执验证，再对本地历史任务做只读回放，确认差异后实施。
