# MediaFlow「订阅清理」电影智能治理需求与交互方案

现行落地稿 · 2026-11-24 · MediaFlow **`v2.5.72`**（沿用并全面升级自 v2.5.40 评审稿）· 已连接 MoviePilot v2.15.6 与 CloudDrive2。

本文对应「MoviePilot 运维 → 订阅清理（剧集 / 电影）→ 电影」。与《[剧集订阅智能清理需求与交互方案](MediaFlow剧集订阅智能清理需求与交互方案-v2.5.72.md)》共用独立分轨三阶段采集引擎、CD2 实盘核验索引、诚实批量进度状态机、CD2 实盘路径一键复制与高性能页面交互框架，并独立定义电影专属的 CD2 入库核验、老片死种补缺、发行阶段保护与异常特征清理规则。**第 0 节为 v2.5.63 ~ v2.5.72 现行最高优先级生效规范**；第 1 ~ 11 节保留 v2.5.40 原始实盘调研基线与长期自动治理远景作为参考。

## 0. v2.5.63 ~ v2.5.72 修订落地与现行生效规范（最高优先级）

> **零回归隔离红线**：本模块改动严格收口在订阅治理域（`subscription_cleaner.py`、`subscription_cd2_index.py`、`subscription_governance_service.py`、`app/api/moviepilot.py` 订阅路由及 `frontend/index.html` 订阅视图），**不改动**初检、五模块归档与清源、补缺核心及数据库表结构。

### 0.1 已入库完成判定：全面以 CD2 实盘为准（3.1）

- **废弃 MP 索引与 `state == 'P'` 误判**：电影「已入库完成」判定不再依赖 MoviePilot 媒体库索引或 `state == 'P'`，全面改为扫描 **CloudDrive2 受控源根（`source_root`）∪ 归档根（`archive_root`）** 下的 `/电影/` 全部二级分类目录。
- **有效正片核验**：按 `[tmdbid=XXX]` 主键匹配（无 ID 时回退标准化片名 + 年份），进入匹配电影目录核实存在有效正片视频文件（排除极小样片/预告/非视频附件，兼容 `.strm`），核实存在才判定 `🟢 CD2 已入库`；若 CD2 全盘扫通确认无文件，即使 MP 状态为 `P`，也**绝不误判为已入库**。
- **单目录超时防误判护栏**：仅当电影大类全部子目录完整扫描无超时/错误（`movie_scanned_ok = True`）时，才对未命中影片标注 `cd2_verified = True`（`⚪ CD2 未入库`），避免如 `/华语电影` 冷缓存超时造成误判。

### 0.2 往年老片死种：同构联动补缺选种引擎（3.2）

- **电影专属搜索隔离**：在「查询最新订阅数据」阶段 3 中，自动为 `🟠 往年老片死种`（往年公映且 CD2 未入库、长期无进展的电影）调用 MoviePilot 检索接口，严格按 `media_type="movie"` 检索、**绝不拼接 `S01`**。
- **只读复用补缺选种算法**：复用 `download_service.py` 的站点优先级、最低做种门槛、做种同档与同档省容量排序算法（`_select_best_movie_candidate`），推送前执行 MP 活跃下载队列防重检查。
- **直接呈现与双出口处置**：搜寻结果持久化至 `metadata_cache`（`sub_resource_audit_cache_v1`），电影卡片直接展示命中的站点名、做种数、文件体积与种子标题，支持一键 **「📥 批量补缺下载」**（零二次搜寻）或 **「🗑️ 批量取消订阅」**（默认仅勾选无合格源影片，防止误退订有源老片）。

### 0.3 移除冗余「豆瓣推选」标签 + 异常特征治理（1 & 3.3）

- **移除冗余页签与徽标**：2026-11-22 实测 390 条电影订阅中 **99.5% 以上** 来自 `豆瓣榜单`，正式移除电影视图中无区分度的 `🔵 豆瓣推选`（`btn-mov-douban`）筛选页签与满屏「豆瓣榜单」徽标，改为反向高亮极少数的 `👤 手动订阅`（后端继续保留 `is_douban_sync` 保护逻辑，避免误清理手动收藏）。
- **新增 `⚠️ 异常特征` 维度**：同步覆盖 5 类高概率无效订阅特征——无封面图、垃圾/占位词条（如 `重复词条`）、小语种标题（日/韩/俄/阿/泰等）、叠加 **GB2312 一级常用简体字自动剔除护栏**的纯繁体字标题（如《紅火的荒原》《稍後觀看》《調整中，非常抱歉，請稍候片刻！》等，简体标题零误报）、无中文译名。已有 CD2 实盘或手动保护的电影仅展示提示标签，不自动划入清理队列。

### 0.4 电影独立分开查询、安全退订隔离与高性能交互（v2.5.64 ~ v2.5.72）

- **进入页面零自动扫描**：进入「订阅清理 (剧集 / 电影)」仅秒读持久化快照（`GET /api/moviepilot/subscriptions?cached_only=true`，`< 50ms`），不自动执行远程查询。
- **电影独立分开查询（v2.5.68）**：切换到电影 Tab 时，主按钮自动切换为 **「查询最新电影订阅」**，仅传 `media_type="movie"` 扫描 CD2 `/电影/` 目录并检索往年老片死种站点资源，跳过剧集目录扫描与剧集 TMDB 纠偏（实测数秒完成），同时完整保留电视剧侧既有快照与站点缓存。
- **严格 CD2 核验与防跨年重名误判（v2.5.67）**：
  - 启用 `strict_cd2_only` 且增加 `movie_year >= now.year` 保护，彻底杜绝如当年新片（如《潜伏6》`state == 'P'`）在 CD2 未入库时被误判为「已入库完成」；
  - 仅在目录无 `[tmdbid=...]` 时才建立片名+年份兜底索引，杜绝 2024 vs 2026 同名异片跨年误匹配；
  - **电影严格仅退订不删源红线**：所有电影分类的批量取消订阅与单条退订（文字按钮「取消订阅」）均强制 `cleanup_source=false`，绝不删除本地电影文件或归档正片。
- **电影分类页签与专属功能按钮矩阵**：

| 分类页签 | 展示的核心数据 | 分类专属功能按钮 |
| :--- | :--- | :--- |
| **`🟢 已入库完成(CD2)`** | CD2 源目录或归档目录已核实存在有效电影正片文件的条目 | **`批量一键取消订阅`**（仅退订不删文件） |
| **`🟠 往年老片死种`** | 卡片直接展示已通过 MP 搜寻出的站点种子详情（`🎯 站点有源可补缺` / `⚪ 暂无合格资源`），附快速子筛选 `[全部 / 有源可补缺 / 无合格资源]` 与单卡 `📥 补缺下载` | **`📥 批量补缺下载`**（直接对已搜出的合格站点资源一键推送，零二次搜寻）<br/>**`批量取消订阅`**（仅退订不删文件，默认勾选无源项） |
| **`⚠️ 异常特征`** | 无封面图 / 繁体字 / 小语种 / 无中文译名 / 占位词条 | **`批量取消订阅`**（仅退订不删文件） |
| **`🔵 待映预订保护`** | 未上映、院线热映中或新片窗口期保护中的电影 | 🔒 只读自动保护（不提供批量取消订阅按钮） |

- **全流程实时进度、路径直出、缓存防过期与切换性能优化（v2.5.65 ~ v2.5.72）**：
  - 批量操作统一接入 `400ms` 诚实进度条（`0%` 起算，按真实完成数 `int(100 * processed / total)` 推进，消除虚高偏移）与单次拉取映射（消除 $N+1$）；退订完成后原地更新本地快照；
  - 已入库电影卡片与确认弹窗同步支持 CD2 实盘命中路径直出（自动标注 `源目录` / `归档库`）与点击一键复制；批量补缺推送前二次校验 MP 活跃下载队列防重；
  - 为 `downloadable` 种子缓存启用 4 小时有效期（TTL），推送失败时自动触发实时重搜换有效活种重试，且前后端显式透出失败作品的站点与具体报错明细；
  - 共享前端分批渲染（首屏 24 条 + 滚动自动追加）、语义 CSS 卡片、视口外 `content-visibility: auto`、`w185` 懒加载封面、O(1) 预索引与弹窗原位勾选，确保电影/剧集切换全程无卡顿。

## 1. 用户希望得到的结果

用户配置一次自动治理范围后，已满足收藏目标的电影自动退订，发行后长期无有效资源的订阅自动暂停观察，观察结束仍无进展的自动来源项目按政策退订。等待首映、数字版、蓝光或指定版本的项目有清楚的保留理由。网络、下载和整理故障按根因集中提示，避免用户逐部片判断。

自动治理以订阅记录为动作对象，已有电影文件、下载任务和做种任务各自保留。用户可随时将关注影片设为「始终保留」，或主动批量仅退订。影片没有豆瓣 ID、年代久远只作为查询上下文，不能单独决定清理；对于无封面、纯繁体、小语种或垃圾占位词条，在确认无实盘且非手动收藏前提下归入「异常特征」供用户核验后批量清理。

## 3. 电影的有效目标是什么

先识别“用户想收藏哪一部电影、哪一种版本”，再判定完成。执行对象以实例和订阅 ID 定位；身份至少包含媒体类型 movie、媒体来源和作品 ID。版本目标记录剪辑版、画质、音轨/字幕要求、介质及保存范围。TMDB 的电影 ID 与电视剧 ID 属于不同命名空间，相同数字也必须隔离。

| 场景 | 判断要求 |
|---|---|
| 普通电影订阅，继承默认规则 | 读取当前生效规则，核对 CD2 实盘入库文件是否满足硬性条件。策略启用时保存解释，后续规则变化使旧计划失效 |
| 想收藏 4K 国语版，库内只有 1080p 原声版 | 显示“已有版本，目标版本仍待满足”。片名和 ID 一致不能直接退订 |
| 洗版订阅 | 默认保留。用户单独启用“最高目标已满足可退订”时，才核对 MP 优先级与实际文件的对应关系 |
| 导演剪辑版、加长版、修复版、IMAX 或 3D 版 | 按用户已表达的目标区分，不能只以同一电影 ID 当成等效完成 |
| 电影分上下文件、CD1/CD2、蓝光目录或 ISO | 验证整部影片所需组成齐备。单文件交付只是常见情况，不能成为强制假设 |
| 片名相同的不同年份电影、翻拍版、电视电影 | 优先按类型和来源 ID 绑定，年份与别名辅助核对。未知类型进入核实，不能默认归成电视剧 |
| 系列电影、合集包 | 每部电影按独立 ID 和版本目标核验。第一部入库不结束续集订阅，合集标题也不代表已包含所有目标作品 |
| 明确手动长期收藏或稀有版本 | 「始终保留」优先于停滞天数，正常查询和完成提示仍可展示 |

关键词命中“收藏、原盘、keep”等只作为旧数据意图线索，需要显示命中字段。标题自然含这些词时，提供一次解除误判的入口；显式保留标记是后续自动化的稳定依据。

## 4. 上映与资源发行怎样判断

电影至少区分未定档、已定档待映、院线阶段、目标家庭发行待到、目标发行已到，以及资料待核实。TMDB 的发行日期按地区和类型提供，类型 1 为首映、2 为有限院线、3 为院线、4 为数字发行、5 为实体发行、6 为电视播出。系统需保存来源、地区、日期和发行类型，不能把年份或电影节首映时间直接当作可下载资源的出现时间。[发行日期接口](https://developer.themoviedb.org/reference/movie-release-dates) · [地区规则](https://developer.themoviedb.org/docs/region-support)

| 可验证情况 | 默认处理 |
|---|---|
| 已定档且首映尚未来到 | 自动来源进入 `🔵 待映预订保护`，临近目标发行日再复查 |
| 已院线上映，只有首映/院线日期 | 显示「等待家庭发行」。没有数字或实体发行依据时，不计长期无有效资源 |
| 用户要 WEB 版本，数字发行日期已确认 | 该日期用于安排资源检查；实际是否有符合要求的站点资源仍需核查 |
| 用户要蓝光/REMUX，已有数字版但实体版未发售 | 显示「等待目标介质发行」，数字版不自动满足原盘目标 |
| 只在某地区发行，或发行语言与目标不匹配 | 记录地区差异。按用户目标选择适用发行事件，不自动以全球最早日期启动清理倒计时 |
| 改档、撤档、发行取消或日期前后矛盾 | 失效旧计划，保留待核实并降低搜索频率。取消发行本身不能证明永远没有收藏价值 |
| 旧电影缺少数字发行日期，但有可靠的发行记录或曾匹配目标版本资源 | 可记录“目标版本已可获取”的替代依据，再按资源观察判断；年代只作线索 |
| 没有发行日期，但 CD2 实盘已经存在可验证的合格完整入库文件 | 可按入库目标满足判定完成；缺失发行资料不额外阻挡已核实的完成事实 |

日期只精确到天时，保留来源日期精度，避免通过服务器时区换算把日期提前。年份为空写“年份待核实”。资料只给出院线日期时不自动估算“上映 30/90 天必有数字版”。外国标题与豆瓣未收录不影响可信发行资料的使用。

## 5. 自动治理规则与动作

### 5.1 已满足收藏目标后自动退订

同时具备稳定身份、CD2 实盘完整电影正片文件（或可验证 STRM 目标）、满足订阅硬性版本要求，且没有待结算的相关下载/整理/修复任务，才能进入完成退订。下载历史成功、MP 索引存在、电影封面或 NFO、文件名命中、下载进度 100% 都只能提供线索。

当前年新片、上一年电影和老片都使用同一完成检查。正常做种任务可继续存在；有第二个目标版本正在下载或整理时，应先核实其意图。P 状态先解释待定原因，不能直接当已完成；R 状态也必须检查是否早已满足目标。

### 5.2 已发行但长期无有效资源（往年老片死种）

推荐自动来源使用下列初始参数。手动添加的电影默认保留收藏意图。

| 阶段 | 建议条件与动作 |
|---|---|
| 进入候选 | 订阅创建至少 60 天；与目标匹配的发行/可获取依据已达到至少 90 天；CD2 实盘确认未入库 |
| 站点补缺筛查（v2.5.64+ 已落地） | 在「查询最新订阅数据」阶段 3 自动按补缺站点与省容量规则检索电影资源：有合格源直接支持「批量补缺下载」，无合格源归入待退订清单 |
| 暂停观察（远景自动模式） | 条件满足后自动置为 S，记录原因和暂停前状态；观察 30 天，继续低频检查 |
| 观察期恢复 | 发现合格资源、有效下载进展或新的目标入库内容，重新诊断。符合追更条件时恢复本系统暂停的订阅 |
| 观察后退订 | 30 天届满，最近 7 天完成复查且条件仍满足，自动仅退订并写来源抑制记录 |
| 证据不完整 | 暂缓退订，标具体缺口。用户可按意愿批量「仅退订」，人工决定单独审计 |

MP last_update 为空时不代填“无进展 60 天”。可用下载/整理历史及连续快照建立活动时间；历史不能覆盖观察区间时从本轮开始积累。先前成功核查可复用，避免每轮重新等待完整周期。

### 5.3 不能直接归为长期无资源的情况

| 证据 | 推荐动作 |
|---|---|
| 有匹配电影，但被分辨率、音轨、字幕、价格/促销条件或过滤规则排除 | 「有资源，条件未满足」。显示阻挡规则，用户可一次调整所选范围；自动处理保留原有硬性目标 |
| 只有预告、花絮、样片、枪版或身份不符候选 | 不计目标可用资源，记录排除理由。合格搜索可累计目标未命中 |
| 有正确资源，持续零做种或下载无进展 | 查看多轮下载变化与替代资源。短时零速度不判失效，持续停滞达条件可暂停订阅，已有下载单列状态 |
| 下载已完成，整理失败、媒体库未刷新或目录不可访问 | 「需要修复」。不因订阅沉寂自动退订 |
| 站点认证失败、限流、下载器空间不足、媒体服务器离线 | 聚合故障并退避重试，不累计无资源次数 |
| 正版/家庭发行资料缺失，自动来源长期占位 | 可低频等待或暂停为「资料待定」，以减少活跃请求；资料待定天数不直接转自动退订 |
| 高品质或稀有剪辑版尚无可靠发行依据 | 明确“目标版本待发行/待核实”，按收藏政策保留 |

暂时停止活跃搜索与最终取消订阅各有明确理由。用户手动暂停、随后开启洗版或改了版本目标时，系统暂停前的恢复计划失效。仅恢复由 MediaFlow 暂停且未被用户改动的项目。

## 6. 来源控制、防重复与恢复

本轮 363 条电影标记来自豆瓣榜单。建议将新导入的电影先按“已在库、身份明确、目标发行已到、是否有有效资源”筛选，合格项恢复追更；待发行项进入等待，未知项留在待筛选。

现有订阅助手有按新增用户自动暂停的功能，但该字段按用户匹配，会同时涉及同一用户的剧集。电影策略须增加媒体类型隔离，或通过共享准入组件分别执行剧集与电影配置。两个模块由一个调度和执行机制管理，避免对「豆瓣榜单」反复改设置。

来源界面可复用剧集方案，按 RSS/榜单显示新增量、成功入库、停滞、退订和重复创建。历史只有 username 时标“具体来源未知”。调整榜单、评分或语言偏好前显示影响范围与样例。评分无数据时保留未知，不能当作 0 分；配置为空时说明采用哪个默认。

退订后的抑制键包含实例、媒体类型、稳定作品身份、版本目标与自动来源。已完成项目在目标仍被满足时持续抑制；长期无资源的自动来源项目建议抑制 90 天，届满重新诊断后再决定准入。不同续集、不同用户认可版本或用户主动重新收藏分别处理。

每次取消保存可恢复配置。恢复时先核现有订阅、媒体库和在途，再使用 MP 新建接口恢复，记录新订阅 ID；旧运行计数、历史、状态等字段不能承诺全部原样回写。用户可选择恢复为暂停状态先查看，也可明确恢复追更。

## 7. 界面与交互

> 现行已落地的电影分类页签、顶部唯一入口「查询最新订阅数据」、各分类专属功能按钮与全流程实时进度条详见 **第 0.4 节**。

电影页默认仅秒读缓存快照，不自动发起耗时远程请求；点击「查询最新订阅数据」后在顶部展开三阶段全宽进度条，阶段 2 扫描 CD2 实盘完成即呈现全部分类，阶段 3 实时将老片站点搜寻结果回写至 `🟠 往年老片死种` 卡片。

电影卡片展示片名、年份、`电影` 徽标（手动订阅额外高亮 `👤 手动订阅`）、`🟢 CD2 已入库` / `⚪ CD2 未入库` 状态、`⚠️` 异常特征标签、决策依据，以及已搜出的 PT 站点补缺资源详情（支持单卡一键 `📥 补缺下载`）。电影页绝不显示剧集专用的「退订并清理源视频」入口，防止跨类型误删。

## 8. 接口、数据与执行要求

### 8.1 电影适配与现行接口

| 接口或模块 | 现行实现 |
|---|---|
| `GET /api/moviepilot/subscriptions?cached_only=true` | 进入电影治理页秒读持久化快照（`sub_unified_snapshot_v1`），绝不触发外部请求 |
| `POST /api/moviepilot/subscriptions/unified-query` | 统一触发三阶段采集（MP 订阅 ➔ CD2 `/电影/` 与 `/电视剧/` 全盘实盘扫描 ➔ 老片/断更站点资源搜寻） |
| `GET /api/moviepilot/subscriptions/unified-query/status` | 轮询三阶段采集进度、阶段标签、实盘核验进度与快照版本号 |
| `GET /api/moviepilot/subscriptions/batch-action/status` | 轮询批量取消订阅、批量补缺下载、批量变更状态的逐项实时进度 |
| `POST /api/moviepilot/subscriptions/batch-gap-fill-push` | 支持 `audit_id="unified"` 直接从持久化资源缓存一键推送已搜出的电影种子至 MP |
| `MoviePilotClient.search_resources` | 电影严格按 `media_type="movie"` 检索，绝不拼接 `S01`，不要求季集字段 |
| `TMDBClient.get_movie_release_dates` | 读取电影多地区发行类型（首映/院线/数字/实体）辅助待映保护判定 |
| `POST /api/moviepilot/subscriptions/batch-delete` | 单次拉取 MP 订阅映射消除 $N+1$ 瓶颈，逐项汇报进度并原地同步更新本地快照 |

### 8.2 证据与批次

沿用剧集方案的快照、资源观察缓存、操作日志（`OperationLog`）与统一进度机制。同一实例同一订阅只允许一个执行者；所有退订与补缺推送均写入审计日志，绝不删除本地已入库正片文件或做种任务。

## 9. 调度、站点压力与插件协作

建议电影与剧集共用一个每日巡检入口，沿用建议时间 03:30，电影策略可单独启停。服务停机后恢复只合并补查一次。站点资源搜寻采用 `Semaphore(3)` 受控并发 + 持久化站点结果缓存复用（`sub_resource_audit_cache_v1`），并支持运行中随时点击「停止搜寻 (保留已获数据)」，兼顾响应速度与 PT 站点防风控。
