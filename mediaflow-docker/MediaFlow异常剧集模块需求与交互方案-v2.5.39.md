修订日期：2026-11-18。当前源码基线为本地 v2.5.39，适用于所有初检目录。本轮按用户确认的使用习惯全面落地：**初检完成后立即处理问题，初检负责检查，异常模块负责让用户作出决定，确认后利用已有初检结果继续分流。**完整实现候选资料误报修正规则、人工确认弹窗与实时结果预告、独立确认记忆与实质矛盾熔断、任务级本次保留清单、跨轮指纹差分智能以及条件式重试与刷新流程。

**v2.5.39 已完成本文全部核心需求的代码实现与自动化验收（见 `tests/test_v2539_anomaly_module.py` 与 `tests/test_frontend_logic.js`）。**此前源码修正与测试见 [异常误报与连载条目操作修正](MediaFlow异常误报与连载条目操作修正-v2.5.37.md)；涉及本轮交互调整时以本文为准。

**核心定位与使用方式**：

- **离散快照与一次性操作**：系统是按需发起的“离散快照分析器（On-demand Snapshot Inspector）”。系统上的所有操作均是一次性的，不存在需在后台维持长周期的跟踪态。两轮初检之间系统完全静默，不常驻轮询网盘，杜绝高频请求引发的 API 封禁。
- **当场分流与证据待决**：用户每次使用时发起一轮初检，能判定的当场分流（或由用户一次性决策）；证据不足的标为**「证据待决 · 安全保留」**（原“系统跟踪”），源端文件安全保留原样，用户无需操作即可直接结束本轮。
- **人工确认直接推动处理**：用户已经核实的信息可通过「人工确认」保存为明确的判断依据，提交后自动更新分类和计数，不要求再跑完整初检，也不以接口暂时取不到资料否定有效的人工确认。
- **跨轮指纹差分智能（Delta Intelligence）**：下一次重新初检时，系统通过比对物理文件指纹与外部元数据版本，对无变化的已知搁置项**自动静默折叠**，仅对发生实质变化（如网盘新增文件、官方公布总集数）的条目**智能唤醒**，消除用户的重复认知负担。

## 一、用户打开模块要能回答的三个问题

1. **哪几季需要我决定？** 例如同一作品有两个可信归档目标，系统能列出各自缺哪几集，但需要用户指定本次归档使用哪个目录；或作品身份冲突需用户裁定。
2. **哪几季归档已齐，可以清掉源端？** 例如源端只有 5 集，单一归档目标已有全 11 集。系统确认这 5 集及同目录的其他内容都得到保留，给出安全的「删除源端（本季）」。
3. **哪几季本轮可以先放下（安全保留）？** 例如源端能读到 1–10 期的文件，但官方还没有资料证明每个文件是一整期。本轮明确显示缺少哪项依据，源端文件已安全保留，无需用户逐个打开样片或人工标记，可直接结束本轮。

同一作品季只占一张主卡。一个季有多项疑点时，卡面只展示当前最先要解决的问题，其余疑点和受限操作放在详情中。用户只需对确实需要选择的事项作决定。

### 全面优化收紧与架构修复

- **彻底废除“系统跟踪”伪概念**：将旧版具有常驻暗示的“系统跟踪”重塑为客观的时点结论——「证据待决 · 安全保留」。不挂载任何误导性操作按钮，消除人工干预焦虑。
- **待确认归档目标矩阵修复**：修复 `build_group_coverage_matrix` 跨剧季度污染严重 Bug（严禁把全任务所有季号混入当前组），并对齐前后端行列契约，使“查看目录”能够准确展示当前作品涉及季度的逐路径覆盖、缺号与删除状态。
- **异常卡移除整剧删除入口**：从异常卡移除整剧级删除入口，并在服务端严格限制只能发起单季级受控清理，杜绝意外越权删除父目录。
- **集数校准与完结状态解耦**：人工校准集数不再联动把季判定为播毕，避免用户补齐总数后被系统错误推定为“真缺集”。
- **确认、保留与结案分离**：「人工确认」补充判断依据并推动分类；「本次保留，不再提示」仅暂时移出本轮待办；「已手动处理」仅表达确已在外部完成处置。三者不能共用一个含混的完成标记，连载保护也不因隐藏卡片而解除。
- **候选资料与文件归属分离**：其他作品的搜索命中、集数相同或名称年份相同，仅能作为参考。目录已有明确 ID 时，不自动改绑、不借用候选集数与完结状态，不将候选数据写入该 ID 的已核实缓存。
- **主分类与连载保护分离**：异常主分类决定卡片所在模块，连载保护决定可执行动作。`main_category=anomaly` 不能覆盖底层或关联记录的连载保护。
- **按问题提供有效操作**：资料不完整提供「人工确认」，多目录问题提供「确认目录」，真实归属冲突提供「核对归属」。只有初检请求失败才显示「重试失败项」；用户在外部修改后可使用「刷新修改结果」。普通卡不再常驻「重新核查」。

## 三、准入、三分类与退出机制

**准入条件**：初检已经取得该季可发布的结果，并命中以下至少一种情况：作品或季归属有实质疑点、应有集数或正片覆盖无法可靠判断、多个真实目录需要决定去向、已齐的归档对应仍有待处置的源端。

### 异常卡片唯一三分类（互斥）

按「需你决定 → 归档已齐，可清源 → 证据待决 · 安全保留」评估适用条件，当前最优先阻塞原因决定唯一子分类。未通过清源准入的季不能落入可清源类别；多个疑点保留在详情中。

| 子分类 | 准入特征 | 前台行为与退出条件 |
|---|---|---|
| **需你决定** | 同一 TMDB ID 在源端或归档存在多个真实目录；或文件身份、季号存在需要人工裁定的实质冲突 | 显示「确认目录」或「核对归属」。用户选择后用已有初检结果重算受影响季；仍有其他阻塞则留在异常，无其他阻塞且在播则回到连载留源 |
| **归档已齐，可清源** | 本季已确认播毕，归档单端已独立覆盖全季正片，源端视频均有等价副本，独有字幕支持自动迁移；无连载保护或其他阻塞 | 经实时双端核验通过后，展示「删除源端（本季）」。执行完成后源端消失、归档保留，结案退出 |
| **证据待决 · 安全保留** | 外部集数未公布、只有尚未核实对应关系的候选资料、期与分段缺少映射、目录读取异常或仅含附件无视频 | 明确缺少什么依据。可人工补充的资料提供「人工确认」；实际请求失败才提供「重试失败项」。**无需操作即可结束本轮**；也可选择「本次保留，不再提示」移出本轮待办 |

### 主分类与播出状态并行表达

- 正常连载或待首播季归「连载留源」；出现待确认目录组等优先阻塞时，只在「异常剧集」保留一张作品季主卡，不在两个模块重复计数。
- 异常卡仍展示「连载中／待首播」及最近取证时间。确定属于同一作品季的关联目录，按正片集号去重合并覆盖；真实身份冲突尚未解决的覆盖不能当作已确认齐全的依据。
- 任一参与记录需要连载保护时，主卡及关联记录均不得出现归档、删源、清理冗余、补缺推送或手动结案入口；接口须再次核验，不能只依赖前端隐藏。
- 确认目录不是确认播毕。只有本季播出、集数、覆盖与身份等条件均满足后，才按正常规则转入其他模块。
- 人工确认也不直接触发媒体写入。只确认作品归属不能顺带确认总集数或播毕；明确确认本季资料后，系统先更新相应判断，再评估其他门禁，不以历史保护标记永久阻塞有效的新确认。

## 四、主卡片、清单与跨轮差分智能

| 位置 | 交互与视觉呈现 |
|---|---|
| **首页主卡** | 标题“异常剧集”，主数“99 季”。副行显示“需你决定 N 季 · 待决 M 季 · 可清源 K 季”（三项相加恒等于主数）。待确认目录组单独标注“涉及 G 组待办”，不计入季数加总 |
| **二级视图筛选** | 提供四项标签：`全部 (99)`、`需你决定 (N)`（默认优先）、`归档已齐可清源 (K)`、`证据待决 · 安全保留 (M)`。同一任务内切换即时重绘，记住用户偏好 |
| **待确认归档目标区块** | 顶部独立可折叠面板。条目显示作品名、TMDB ID 页面官方原名、待确认状态。点击「查看目录 (N)」平滑展开逐季逐路径正片覆盖表格；点击「确认归档目标」弹出并排对比模态框 |
| **本次保留清单** | 单独显示「本次保留 H 季」入口，可查看原问题与保留时间、恢复处理。这些记录不进入五个模块的当前待办计数，不计为归档成功或人工处置完成；任务已扫描作品季总量不因暂存而减少 |
| **跨轮资产指纹差分（规划要求）** | 任务持久化每个季的资产指纹 `Fingerprint = Hash(文件明细, 元数据版本)`。新任务启动时，指纹未变的历史搁置项默认折叠；指纹有实质变化时标记「有新进展」并重算分流。折叠不等于删除记录或手动结案，也不豁免升级后对旧候选污染记录的重新评估 |

## 五、每季卡片与详情信息规范

**卡面四行信息**：

1. **作品与季度**：剧名、首播年份、Sxx、可点击跳转的 TMDB ID 页面链接。
2. **核心阻塞原因**：一句话说明疑点（如“期号与分段对应关系待决”、“存在 2 个不同的真实源端目录”）。
3. **两端覆盖与差异**：源端识别集数、归档已存集数及关键差异（如“源端 5 集，归档已收录全 11 集”）。
4. **动作与安全状态**：
   - 需决定的条目：多目录问题展示【确认目录】；身份冲突展示【核对归属】，进入证据与确认界面；
   - 可清源的条目：展示紫色的【删除源端（本季）】；
   - 证据待决的条目：展示【证据待决 · 安全保留】或【作品资料不完整】徽章；能够人工补充的资料以【人工确认】为主入口，不强迫用户确认未知事实；
   - 详情入口：右侧常驻【查看详情】；更多菜单按资格提供【本次保留，不再提示】或【已手动处理】，含义和回执明确区分。

### 按问题生成操作按钮

| 当前情形 | 主入口 | 补充入口 | 不提供的误导操作 |
| --- | --- | --- | --- |
| 连载且多目录待确认 | 确认目录 | 查看详情 | 已手动处理、即时归档、删源、清理、补缺推送 |
| 原 ID 资料未取得，仅有搜索候选 | 人工确认 | 查看详情；更多菜单「本次保留，不再提示」 | 按候选一键改 ID、自动把现有集数当总集数、强迫重新查询 |
| 明确文件归属冲突 | 核对归属 | 查看详情、确认正确归属或修正单季映射 | 未确认就自动改绑；以搜索得分断言文件属于另一作品 |
| 播期或期段证据不足 | 能补充播期时提供人工确认；否则呈现安全保留说明 | 查看详情、本次保留 | 强制手动处理、仅凭已收数量推定播毕、以总集数输入代替分段核实 |
| 初检接口超时或目录读取失败 | 重试失败项 | 查看失败原因；适用时保留本轮待办 | 无差别重跑成功项目、将失败说成资料不存在 |
| 用户已在外部修改文件、目录或 ID | 刷新修改结果 | 查看修改范围与结果 | 要求再次扫描整个任务、未更新就沿用已失效覆盖 |
| 已播毕且归档独立全齐，通过清源门禁 | 删除源端（本季）预览 | 查看详情 | 整剧删除；未核对独有内容就执行清源 |

每卡只突出当前最优先问题的一个主操作。普通卡没有常驻「重新核查」按钮。正常连载主卡在「连载留源」模块提供「查看详情」，不要求用户再检查或人为结案；「刷新修改结果」在外部修改后的处理流程或更多菜单中按需使用。

**详情抽屉按原因展开**：

- **资料证据**：目录 ID、本次查询结果、收录来源、取证时间、总集数依据；搜索候选另列 ID、名称、季号、参考集数与对应关系是否已确认。匹配得分不得展示为片源已验证的证明；
- **三端覆盖明细**：源端真实物理路径、实存归档路径、Emby 库内识别分集（明确区分物理实物与播放记录）；
- **文件证据与排除项**：明确列出产生疑点的样本文件、版本标识、受保护的非正片视频或独有附件。
- **连载与目录组明细**：已播、今日排播、待播、源端／归档端／Emby 覆盖及关联路径；同作品多目录合并后重新计算已播未见集，不能把另一关联目录已有的 E01/E02 重复列为缺集。
- **用户核对记录**：分别显示人工确认的归属、总集数、播出状态、适用范围及时间，与系统资料查询结论分开；提供「修改确认／撤销确认」。没有新的实质矛盾时，不以同一搜索候选或查询无结果反复质疑已确认内容。

## 六、关键操作与安全约束

### 6.1 人工确认：补充依据并立即更新结果

适用于作品资料不完整、总集数或本季播出状态可以由用户核实的条目。主按钮为「人工确认」，弹窗默认展示当前作品、ID、季号和本轮已识别集号，不要求用户为了认可原 ID 而填写一套改绑映射。

| 字段 | 交互与校验 |
| --- | --- |
| **作品归属** | 显示当前名称、TMDB ID 与季号；用户可明确选择「当前作品与季号正确」。发现错误时再展开修正选项。保持原归属不改目录名，不产生无意义的跨作品改绑 |
| **本季总集数** | 可填写正整数，也可选择「尚不清楚」。本地识别 4 集或候选收录 4 集只能作为参考，不能自动作为用户已确认的总数 |
| **本季播出状态** | 选择「已播毕／仍在连载／尚不确定」。首次人工确认不默认勾选已播毕，不能从用户填写总集数推导播毕 |
| **备注** | 选填，例如「已核对片头与发行页面」。不强制上传截图或填写长篇理由 |
| **作用范围与结果预告** | 展示当前作品、当前季及已确认关联目录；根据已填写信息和初检结果预告目标模块或仍缺少的依据 |

主要提交按钮统一为 **「保存确认并更新结果」**。用户可以只提交自己已核实的事实，未确认字段保持未知；首次提交需至少有一项明确确认或修正，不能把全未选择视为同意。提交后防重复保存，成功回执说明记录了什么、转入哪个模块或还有哪个阻塞。

保存人工事实后，系统自动利用本轮初检覆盖、已有有效资料和目录规则重新计算，不要求用户再点击「重新核算」或重跑初检。人工确认不移动、重命名、删除媒体，也不提交下载；修正归属时明确展示将保存的单季映射及作用范围，文件改名不作为隐藏副作用执行。

### 6.2 人工确认后的分流与闭环

| 用户确认与当前证据 | 预告与保存后的结果 |
| --- | --- |
| 原 ID、季号正确，共 4 集且已播毕；本地 E01–E04 齐全，无重复与其他阻塞 | 转入「齐全可归档」，由用户继续点击归档；不在保存确认时自动搬移 |
| 原 ID、季号正确，共 6 集且已播毕；合并源端、归档端及其他可信覆盖后仍缺 E05–E06 | 转入「真缺集待补」，显示实缺集号；不自动推送下载 |
| 当前作品正确，仍在连载，无其他阻塞 | 转入「连载留源」，文件原位保留 |
| 已播毕、正片齐全，但存在需要处理的重复版本 | 转入「待复核清理」，不能跳过版本核对直接归档 |
| 只确认作品正确，总集数或播毕状态仍不清楚 | 解除原来的归属疑点，显示「总集数待补充」或「播毕状态待确认」，保留文件；不再重复原来的 ID 质疑 |
| 另有目录目标冲突、混放作品、未核实分段等问题 | 保留异常卡，将主提示和操作切换为尚未解决的具体问题；不因总集数已填而掩盖其他阻塞 |

以上服从模块原有准入。例如已确认归档单端独立全齐而源端仍有残留时，按可清源规则判断，不机械地再发起归档；总集数小于已识别最高正片集号时，明确提示矛盾，不能自动舍弃超号文件。总集数输入不代替混放、分段或实际覆盖核验。

《性爱治疗师》示例：若用户确认「315775 正确，S01 共 4 集且已播毕」，系统采用该人工依据，结合本轮 E01–E04 与其他检查结果分流。只要没有其他阻塞，就进入齐全可归档；接口继续无资料或再次返回候选 315653，不得将它退回同一归属疑点。

### 6.3 人工确认的记忆、修改与失效

- **独立保存来源**：确认记录保存作品标识、季号、适用目录范围、逐项确认事实、确认时间和可选备注，来源标注「人工确认」。不把用户填写的数据写成 TMDB 官方返回值，不覆盖原始查询证据。
- **按范围复用**：后续离线核算及下一轮初检继续采用作用范围仍匹配的有效人工确认，不自动扩散到其他作品、其他季或尚未确认归属的新目录。
- **相同弱证据不推翻确认**：接口无资料、接口失败、同一个搜索候选再次命中，不构成撤销人工确认的理由。新增同集的其他版本也不能仅凭文件指纹变化抹掉作品身份确认。
- **新实质矛盾才重新提示**：例如已确认总集数 4，之后发现正片 E05，或文件新增明确的异作品 ID。列出原确认和新证据，暂停依赖冲突字段的自动准入，保留其他仍有效的确认；不得静默覆盖原决定。
- **修改与撤销**：详情提供「修改确认／撤销确认」。修改后按新事实重算；撤销后回到当前可用证据进行判断，不删除文件，不简单恢复可能已经过时的旧状态。
- **避免误继承**：目录 ID、季号或作用范围变化时检查确认适用性。不能将旧确认无条件套用到已改绑的新作品，也不能仅因无关文件变化让同一个疑点反复出现。

### 6.4 本次保留，不再提示

该操作作为资料不完整或证据待决条目的次级入口，放在更多菜单中，表示用户决定本轮不继续处理这些文件；不是声明已核实正确或已经在外部完成处置。

1. 保存任务级「本次保留」记录，保留原问题、原诊断、作用范围与时间；从本轮五模块的待办清单和待办计数移出。
2. 单独展示「本次保留」清单，允许查看与「恢复处理」。恢复后根据当前证据重新分流，不创建重复主卡。
3. 不标记为已齐、已播毕、已归档或手动处置完成，不修改文件、作品归属、下载队列或有效人工确认；隐藏卡片不解除后端写入限制。
4. 刷新页面、离线核算不能重新弹出本轮已保留事项；下一轮初检仍正常评估，不继承永久忽略。若规划中的历史指纹折叠生效，只影响展示，不跳过新一轮分析。
5. 「不操作直接结束本轮」仍然成立；此操作仅供希望主动清空本轮待办的人使用，不强迫逐条点击。

### 6.5 确认目录：使用已有结果解决去向

展示源端各目录与归档候补目录在各季的覆盖对比矩阵。用户选择唯一归档目标或明确选择「有意共存」，保存相应目录规则，并用本轮结果自动重算受影响季；不要求再扫描整个任务，不直接搬移、合并或删除文件。

《BOSS的甜蜜诱惑》应直接显示两个目录各含 E01／E02、合计已收 2 集、仍在连载。确认后没有其他阻塞就回到「连载留源」，保留文件原位；若还有其他阻塞，卡片切换到该问题。确定后续目标不等于确认本季播毕。

### 6.6 只在必要时重试或刷新

| 操作 | 出现条件 | 范围与回执 |
| --- | --- | --- |
| **重试失败项** | 初检接口超时、读取目录失败等明确请求失败 | 只补查失败项及依赖它的受影响结果，不无差别重跑成功范围；返回成功、仍失败的具体项 |
| **刷新修改结果** | 用户已在外部修改文件、目录或 ID，并主动选择刷新修改范围 | 更新受影响目录、作品季及必要的关联覆盖；目录或 ID 已变化时不能只请求失效的旧路径，不默认扫描整个任务 |
| **自动执行前检查** | 用户真正发起归档、删除等文件操作 | 系统自动检查路径、文件与计划是否变化；发现变化则中止并解释，不要求用户先手动点一次通用核查 |

普通卡不显示常驻「重新核查」。资料未收录、总集数待公布不等同于请求失败，不能因此不断建议重试。正常确认保存后的重新分类属于本地计算，不算新的远程检查。

重试或刷新进行中禁用对应按钮，结束或失败后恢复；初检运行、暂停或正在停止时，服务端拒绝并发覆盖结果。部分读取失败时保留仍有效的历史证据及原取证时间，明确哪些范围未完成、哪些受变更影响已不能确认；不以历史快照冒充新核实结果，不把单个目录成功当成整卡完成。这些操作均为一次性动作，不建立后台轮询。

### 6.7 单季清源与已有手动结案

**单季删除源端**继续满足以下条件：本季已确认播毕；归档单端独立覆盖全部正片且源端视频有等价副本；已确认唯一实际归档目标；两端为独立季目录；无身份、覆盖或连载保护阻塞。源端独有字幕列入预览迁移计划并完成保护，不能直接丢弃；严禁删除整剧父目录。执行须幂等，并在自动实物重读发现变化时中止。

**已手动处理**仅用于用户确已在外部完成处置、且允许结案的异常季，在更多菜单中提供；按作品季记录任务级结案，连载及受保护的关联记录不得借此结案。它不再承担「我认为资料正确」或「我本轮不想处理」的含义。已有历史结案标记、有效映射和已受理回执继续保留，不在升级时擅自改成新确认或本次保留记录。

### 6.8 离线核算与旧任务兼容

使用上次初检资料、有效缓存、人工确认及映射重新判断，不访问网盘。用户保存人工确认或目录规则后由系统自动完成，不要求额外点击。

识别旧版把其他候选资料当作当前作品依据的记录，解除「文件来自另一作品」的断言，显示「作品资料不完整」；保留原 ID、实存集号与既有人工决策。没有新的可靠依据时，不能借用污染缓存的集数或完结状态转成可归档；有效的人工资料确认、可靠原作品资料或用户确认的映射可以补充所缺依据，再按全部准入条件分流。

### 候选资料与文件身份的判断约束

| 证据 | 允许得出的结论 | 不允许得出的结论 |
| --- | --- | --- |
| 原 ID 查询没有取得季资料 | 本次资料未核实；根据实际响应区分请求失败、未收录或待公布 | 原 ID 必然错误；源文件必然是另一作品 |
| 搜索名称、年份相同，候选收录 4 集 | 找到可供核对的候选与参考集数 | 当前目录官方总集数就是 4；本地 4 集属于候选作品 |
| 文件显式 ID 与目录不同，或存在可靠混放、分集身份矛盾 | 有文件层面的归属冲突，列出样本供核对 | 无需用户核对即可自动改绑、改名或删除 |
| 用户确认有效的单季映射 | 对该映射作用范围重新计算集数及播期 | 整剧其他季自动继承改绑；确认集数等同于确认播毕 |
| 用户仅确认当前作品与季号正确 | 保留原 ID，记录人工归属确认，解除相应身份疑点 | 将总集数或播毕状态也视为已确认 |
| 用户明确确认本季总集数和播出状态 | 标注人工来源，结合已有实物覆盖继续分流 | 冒充官方资料；不检查其他阻塞就直接移动或删除文件 |

参考提示：

> 已识别 E01–E04，共 4 集。当前目录 TMDB 315775 的第 1 季资料未取得，暂不确定全季总集数。搜索候选 315653 仅供参考，不能据此判断目录 ID 错误。若你已核实，可点击「人工确认」补充结果。

统一标签为「作品资料不完整」，不追加「非文件错配」这种超出已有证据的断言。工程上可沿用 `metadata_unverified` 表达资料对应关系未核实；主分类 `main_category` 与连载保护 `airing_protected` 分开传递。人工确认记录、任务级本次保留、实际处置结案需独立表达；具体字段与接口在实现阶段确定，不能直接复用一个「已完成」状态。按钮同时结合问题原因、可用证据和操作资格生成。

## 七、实施与验收标准

| 验收用例 | 预期行为与标准 |
|---|---|
| **待确认归档目标点开“查看目录”** | 展开详细的逐路径、逐季正片覆盖与缺号对照表。**严禁出现跨剧无关季度，严禁出现空白路径或 undefined** |
| **《乘风》真实样本（33 组待办之一）** | 仅精确呈现真实的 S06、S07 两个季度行；列明源端《乘风》、源端《乘风破浪的姐姐》与归档现有目录的正片覆盖对比 |
| **未判定条目心智与文案** | 彻底消除“系统跟踪”字眼；卡片呈现「证据待决 · 安全保留」，批量复选框置灰，不给用户带来需要处理的认知焦虑 |
| **二级分类筛选** | 点击“需你决定”、“归档已齐可清源”、“证据待决”能够瞬间无感完成列表过滤与重绘，无控制台报错 |
| **离散运行与安全防击穿** | 初检停止后保留快照结果；两轮初检之间绝不向网盘发起轮询；重新初检时尊重历史映射白名单 |
| **《性爱治疗师》候选误报回放** | 315775 未取得季资料、315653 搜索命中 4 集、本地 E01–E04 时，保留 315775；总集数保持未知，不虚构文件错配或已播毕，不自动改绑 |
| **候选资料缓存隔离** | 其他候选的总集数、完结状态不进入原 ID 已核实缓存；旧缓存带候选来源时不得当成本作品资料恢复 |
| **旧任务重复重新核算** | 无新增可靠依据或有效人工确认时，连续两次离线重算均保持资料不完整与原集号，不重新出现「文件来自另一作品」，不升级为可归档 |
| **取得可靠资料后的恢复** | 远程核实原 ID 的本季资料后，清除旧待核实提示，按新的播期与覆盖正常分流；ID 不被搜索候选替换 |
| **真实归属冲突不被吞掉** | 文件显式携带不同 ID 或可靠混放证据时仍显示冲突与样本；候选误报修复不解除真实拦截 |
| **《BOSS的甜蜜诱惑》异常连载卡** | `main_category=anomaly`、底层 `airing` 且目录组待确认时，显示「确认目录」「查看详情」，无常驻「重新核查」，不出现「已手动处理」及媒体写入入口 |
| **关联目录合并进度** | `Boss…` 的 E01 与 `BOSS…` 的 E02 合计覆盖 2 集；不互报对方已存在的集为缺集；季数只计 1 季，目录组另计 |
| **关联记录直接请求结案** | 对主卡或任一关联记录调用手动处理接口均被连载保护拒绝；不能以另一物理记录状态不同绕过 |
| **确认目录后仍在连载** | 保存规则后用已有初检结果自动重算，无需再次扫描。文件保持原位，无其他阻塞则回到连载留源；有其他阻塞则继续异常，不误转归档或清源 |
| **重试范围与按钮恢复** | 初检仅一项请求失败时，只补查失败项和必要依赖；进行中防连点，成功后更新分类，失败后按钮可重试 |
| **外部修改后的刷新** | 用户主动指定变更范围后，更新相关路径、作品季和关联覆盖；ID 或路径已改变时处理新旧对应关系，不沿用失效旧路径，不默认重跑整任务 |
| **扫描期间并发拦截** | 初检运行、暂停、停止保存过程中禁用会覆盖结果的操作；直接调用相关接口同样拒绝，不覆盖扫描中的结果 |
| **读取失败与时间可信性** | 保留仍有效的历史证据和原取证时间，明确未完成及因变更失效的范围；不宣称已取得最新资料，不移动文件或提交下载 |
| **正常连载及资料待决无结案压力** | 普通卡无常驻通用核查按钮；连载卡不提供手动结案；资料待决允许不操作结束本轮，也可主动本次保留 |
| **历史人工决策保护** | 升级、核算、必要刷新尊重已有结案标记、有效单季映射和已受理回执；其他季不受当前单季映射影响 |
| **人工确认弹窗默认值** | 保持原 ID 正确无需填写改绑映射；识别到 4 集或候选 4 集不自动成为已确认总数；首次确认不默认已播毕；全未选择不能作为有效确认提交 |
| **人工确认结果预告** | 保存前展示作用范围、预计目标模块或剩余阻塞；保存后自动刷新卡片与计数，不要求另点重新核算，不发起完整重检 |
| **《性爱治疗师》人工确认闭环** | 明确确认 315775、S01、总数 4、已播毕，结合初检 E01–E04 且无其他阻塞后进入齐全可归档；保存动作不搬移文件，不因接口仍无资料退回相同疑点 |
| **只确认身份** | 解除 ID 质疑；总数和播毕仍未知时分别显示缺失信息，不凭现有集数生成全季齐全结论 |
| **其他分流与门禁** | 确认总数 6 且播毕、各端仍缺 E05–E06 则入待补；确认连载则留源；齐全但重复则待清理；目录、混放或分段阻塞仍保留异常 |
| **人工确认跨轮复用** | 同作品季、适用范围未变时，刷新、离线核算和下一轮初检采用有效确认；再次搜到同一候选或接口无资料不推翻确认 |
| **新矛盾与字段范围** | 已确认全 4 集后发现 E05，显示原确认与新证据，暂停依赖总数的准入；不静默改总数，不自动丢弃 E05，也不抹掉仍有效的身份确认 |
| **修改与撤销确认** | 详情可修改、撤销；重新按当前有效证据分流；不继承到其他季或已改绑作品，不删除文件、不恢复过时状态 |
| **本次保留计数与恢复** | 移出本轮五模块待办，单列本次保留数量；已扫描总量不变，归档成功数不增加；可查看原问题和恢复，恢复后无重复卡 |
| **本次保留的有效期** | 页面刷新和本轮核算不重新弹出；下一轮初检正常评估，不继承永久忽略；文件与后端写入保护保持不变 |
| **人工来源与结案隔离** | 人工确认标明来源与时间，不伪装成官方缓存；人工确认、本次保留、外部处置完成三种记录与回执互不混用 |
| **执行前自动检查** | 用户真正发起归档或删除时自动检查实物及路径变化；发现变动则中止并解释，不要求先点通用重新核查 |
