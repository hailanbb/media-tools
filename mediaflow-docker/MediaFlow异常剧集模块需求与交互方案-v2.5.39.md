修订日期：2026-11-18。当前源码基线为本地 v2.5.39，适用于所有初检目录。沿用用户确认的使用习惯：**初检完成后立即处理问题，初检负责检查，异常模块负责让用户作出决定，确认后利用已有初检结果继续分流。**既有方案涵盖候选资料误报修正、人工确认弹窗与结果预告、确认记忆与实质矛盾处理、任务级本次保留、跨轮指纹差分以及条件式重试与刷新；本轮补充实际目录合并的交互及执行约束。

**本轮已全面完成「确认目录后实际合并、文件名前缀统一、旧目录清理与自动刷新」方案（第 6.5 节与 M01–M14 验收项）的代码落地与全矩阵自动化测试验证。**版本号保持 v2.5.39。功能实现见 `app/core/directory_merge.py`、`app/clients/clouddrive2.py`、`app/api/tasks.py`、`frontend/index.html`，验收测试见 `tests/test_v2539_directory_merge.py`、`tests/test_v2539_anomaly_module.py` 与 `tests/test_frontend_logic.js`。

**核心定位与使用方式**：

- **离散快照与一次性操作**：系统是按需发起的“离散快照分析器（On-demand Snapshot Inspector）”。系统上的所有操作均是一次性的，不存在需在后台维持长周期的跟踪态。两轮初检之间系统完全静默，不常驻轮询网盘，杜绝高频请求引发的 API 封禁。
- **当场分流与证据待决**：用户每次使用时发起一轮初检，能判定的当场分流（或由用户一次性决策）；证据不足的标为**「证据待决 · 安全保留」**（原“系统跟踪”），源端文件安全保留原样，用户无需操作即可直接结束本轮。
- **人工确认直接推动处理**：用户已经核实的信息可通过「人工确认」保存为明确的判断依据，提交后自动更新分类和计数，不要求再跑完整初检，也不以接口暂时取不到资料否定有效的人工确认。
- **跨轮指纹差分智能（Delta Intelligence）**：下一次重新初检时，系统通过比对物理文件指纹与外部元数据版本，对无变化的已知搁置项**自动静默折叠**，仅对发生实质变化（如网盘新增文件、官方公布总集数）的条目**智能唤醒**，消除用户的重复认知负担。

## 一、用户打开模块要能回答的三个问题

1. **哪几季需要我决定？** 例如同一作品有两个可信归档目标，系统能列出各自缺哪几集，但需要用户指定本次归档使用哪个目录；或作品身份冲突需用户裁定。
2. **哪几季归档已齐，可以清掉源端？** 例如源端只有 5 集，单一归档目标已有全 11 集。系统确认这 5 集及同目录的其他内容都得到保留，给出安全的「删除源端（本季）」。
3. **哪几季本轮可以先放下（安全保留）？** 例如源端能读到 1–10 期的文件，但官方还没有资料证明每个文件是一整期。本轮明确显示缺少哪项依据，源端文件已安全保留，无需用户逐个打开样片或人工标记，可直接结束本轮。

同一作品季只占一张主卡。一个季有多项疑点时，卡面只展示当前最先要解决的问题，其余疑点和受限操作放在详情中。用户只需对确实需要选择的事项作决定。

### 全面优化收紧与架构修复

- **彻底废除“系统跟踪”伪概念**：将旧版具有常驻暗示的“系统跟踪”重塑为客观的时点结论——「证据待决 · 安全保留」。不挂载任何误导性操作按钮，消除人工干预焦虑。
- **待确认归档目标矩阵修复**：修复 `build_group_coverage_matrix` 跨剧季度污染严重 Bug（严禁把全任务所有季号混入当前组），并对齐前后端行列契约，使“查看目录”能够准确展示当前作品涉及季度的逐路径覆盖、缺号与删除状态。
- **异常卡移除任意整剧删除入口**：常规清源仍限于单季；本轮新增目录合并允许在全部内容核验迁入后回收指定旧剧根空壳，条件见 6.5 节，不开放任意整剧递归删除。
- **集数校准与完结状态解耦**：人工校准集数不再联动把季判定为播毕，避免用户补齐总数后被系统错误推定为“真缺集”。
- **确认、保留与结案分离**：「人工确认」补充判断依据并推动分类；「本次保留，不再提示」仅暂时移出本轮待办；「已手动处理」仅表达确已在外部完成处置。三者不能共用一个含混的完成标记，连载保护也不因隐藏卡片而解除。
- **候选资料与文件归属分离**：其他作品的搜索命中、集数相同或名称年份相同，仅能作为参考。目录已有明确 ID 时，不自动改绑、不借用候选集数与完结状态，不将候选数据写入该 ID 的已核实缓存。
- **主分类与连载保护分离**：异常主分类决定卡片所在模块，连载保护决定可执行动作。`main_category=anomaly` 不能覆盖底层或关联记录的连载保护。
- **按问题提供有效操作**：资料不完整提供「人工确认」，多目录问题提供「确认目录」，真实归属冲突提供「核对归属」。只有初检请求失败才显示「重试失败项」；用户在外部修改后可使用「刷新修改结果」。普通卡不再常驻「重新核查」。

## 三、准入、三分类与退出机制

**准入条件**：初检已经取得该季可发布的结果，并命中以下至少一种情况：作品或季归属有实质疑点、应有集数或正片覆盖无法可靠判断、多个真实目录需要决定去向、已齐的归档对应仍有待处置的源端。

### 异常卡片唯一三分类（互斥）

按「需你决定 → 归档已齐，可清源 → 证据待决 · 安全保留」评估适用条件，当前最优先阻塞原因决定唯一子分类。未通过清源准入的季不能落入可清源类别；多个疑点保留在详情中。

| 子分类 | 准入特征 | 前台行为与退出条件 |
|---|---|---|
| **需你决定** | 同一 TMDB ID 在源端或归档存在多个真实目录；或文件身份、季号存在需要人工裁定的实质冲突 | 显示「确认目录」或「核对归属」。仅保存规则时按已有结果重算，执行合并时按核验后的实物结果重算；仍有其他阻塞则留在异常，无其他阻塞且在播则回到连载留源 |
| **归档已齐，可清源** | 本季已确认播毕，归档单端已独立覆盖全季正片，源端视频均有等价副本，独有字幕支持自动迁移；无连载保护或其他阻塞 | 经实时双端核验通过后，展示「删除源端（本季）」。执行完成后源端消失、归档保留，结案退出 |
| **证据待决 · 安全保留** | 外部集数未公布、只有尚未核实对应关系的候选资料、期与分段缺少映射、目录读取异常或仅含附件无视频 | 明确缺少什么依据。可人工补充的资料提供「人工确认」；实际请求失败才提供「重试失败项」。**无需操作即可结束本轮**；也可选择「本次保留，不再提示」移出本轮待办 |

### 主分类与播出状态并行表达

- 正常连载或待首播季归「连载留源」；出现待确认目录组等优先阻塞时，只在「异常剧集」保留一张作品季主卡，不在两个模块重复计数。
- 异常卡仍展示「连载中／待首播」及最近取证时间。确定属于同一作品季的关联目录，按正片集号去重合并覆盖；真实身份冲突尚未解决的覆盖不能当作已确认齐全的依据。
- 任一参与记录需要连载保护时，仍禁止跨入完结归档库、丢弃媒体、清理冗余、补缺推送和手动结案。新增例外仅为用户确认的同作品源端目录归并：允许保全内容的源端移动、限定前缀重命名，以及成功后的旧空壳回收；须经过 6.5 节独立门禁，不能普遍放开连载写操作。
- 确认目录不是确认播毕。只有本季播出、集数、覆盖与身份等条件均满足后，才按正常规则转入其他模块。
- 人工确认也不直接触发媒体写入。只确认作品归属不能顺带确认总集数或播毕；明确确认本季资料后，系统先更新相应判断，再评估其他门禁，不以历史保护标记永久阻塞有效的新确认。

## 四、主卡片、清单与跨轮差分智能

| 位置 | 交互与视觉呈现 |
|---|---|
| **首页主卡** | 标题“异常剧集”，主数“99 季”。副行显示“需你决定 N 季 · 待决 M 季 · 可清源 K 季”（三项相加恒等于主数）。待确认目录组单独标注“涉及 G 组待办”，不计入季数加总 |
| **二级视图筛选** | 提供四项标签：`全部 (99)`、`需你决定 (N)`（默认优先）、`归档已齐可清源 (K)`、`证据待决 · 安全保留 (M)`。同一任务内切换即时重绘，记住用户偏好 |
| **待确认归档目标区块** | 顶部独立可折叠面板显示逐季逐路径覆盖。确认弹窗区分本次源端合并位置与未来归档位置；选择目标后自动展示移动、改名及旧目录清理预览，主按钮「确认并合并目录」直接执行该预览计划，详见 6.5 节 |
| **本次保留清单** | 单独显示「本次保留 H 季」入口，可查看原问题与保留时间、恢复处理。这些记录不进入五个模块的当前待办计数，不计为归档成功或人工处置完成；任务已扫描作品季总量不因暂存而减少 |
| **跨轮资产指纹差分（规划要求）** | 任务持久化每个季的资产指纹 `Fingerprint = Hash(文件明细, 元数据版本)`。新任务启动时，指纹未变的历史搁置项默认折叠；指纹有实质变化时标记「有新进展」并重算分流。折叠不等于删除记录或手动结案，也不豁免升级后对旧候选污染记录的重新评估 |

## 五、每季卡片与详情信息规范

**卡面四行信息**：

1. **作品与季度**：剧名、首播年份、Sxx、可点击跳转的 TMDB ID 页面链接。
2. **核心阻塞原因**：一句话说明疑点（如“期号与分段对应关系待决”、“存在 2 个不同的真实源端目录”）。
3. **两端覆盖与差异**：源端识别集数、归档已存集数及关键差异（如“源端 5 集，归档已收录全 11 集”）。
4. **动作与安全状态**：
   - 需决定的条目：多目录问题展示【确认目录】；身份冲突展示【核对归属】，进入证据与确认界面；
   - 可清源的条目：展示紫色的【删除源端（本季）】；
   - 证据待决的条目：展示【证据待决 · 安全保留】或【作品资料不完整】徽章；能够人工补充的资料以【人工确认】为主入口，不强迫用户确认未知事实；
   - 详情入口：右侧常驻【查看详情】；更多菜单按资格提供【本次保留，不再提示】或【已手动处理】，含义和回执明确区分。

### 按问题生成操作按钮

| 当前情形 | 主入口 | 补充入口 | 不提供的误导操作 |
| --- | --- | --- | --- |
| 连载且多目录待确认 | 确认目录，弹窗内「确认并合并目录」 | 查看详情；仅保存目标、有意共存 | 已手动处理、移入完结归档库、删除未保全媒体、清理重复、补缺推送 |
| 原 ID 资料未取得，仅有搜索候选 | 人工确认 | 查看详情；更多菜单「本次保留，不再提示」 | 按候选一键改 ID、自动把现有集数当总集数、强迫重新查询 |
| 明确文件归属冲突 | 核对归属 | 查看详情、确认正确归属或修正单季映射 | 未确认就自动改绑；以搜索得分断言文件属于另一作品 |
| 播期或期段证据不足 | 能补充播期时提供人工确认；否则呈现安全保留说明 | 查看详情、本次保留 | 强制手动处理、仅凭已收数量推定播毕、以总集数输入代替分段核实 |
| 初检接口超时或目录读取失败 | 重试失败项 | 查看失败原因；适用时保留本轮待办 | 无差别重跑成功项目、将失败说成资料不存在 |
| 用户已在外部修改文件、目录或 ID | 刷新修改结果 | 查看修改范围与结果 | 要求再次扫描整个任务、未更新就沿用已失效覆盖 |
| 已播毕且归档独立全齐，通过清源门禁 | 删除源端（本季）预览 | 查看详情 | 整剧删除；未核对独有内容就执行清源 |

每卡只突出当前最优先问题的一个主操作。普通卡没有常驻「重新核查」按钮。正常连载主卡在「连载留源」模块提供「查看详情」，不要求用户再检查或人为结案；「刷新修改结果」在外部修改后的处理流程或更多菜单中按需使用。

**详情抽屉按原因展开**：

- **资料证据**：目录 ID、本次查询结果、收录来源、取证时间、总集数依据；搜索候选另列 ID、名称、季号、参考集数与对应关系是否已确认。匹配得分不得展示为片源已验证的证明；
- **三端覆盖明细**：源端真实物理路径、实存归档路径、Emby 库内识别分集（明确区分物理实物与播放记录）；
- **文件证据与排除项**：明确列出产生疑点的样本文件、版本标识、受保护的非正片视频或独有附件。
- **连载与目录组明细**：已播、今日排播、待播、源端／归档端／Emby 覆盖及关联路径；同作品多目录合并后重新计算已播未见集，不能把另一关联目录已有的 E01/E02 重复列为缺集。
- **用户核对记录**：分别显示人工确认的归属、总集数、播出状态、适用范围及时间，与系统资料查询结论分开；提供「修改确认／撤销确认」。没有新的实质矛盾时，不以同一搜索候选或查询无结果反复质疑已确认内容。

## 六、关键操作与安全约束

### 6.1 人工确认：补充依据并立即更新结果

适用于作品资料不完整、总集数或本季播出状态可以由用户核实的条目。主按钮为「人工确认」，弹窗默认展示当前作品、ID、季号和本轮已识别集号，不要求用户为了认可原 ID 而填写一套改绑映射。

| 字段 | 交互与校验 |
| --- | --- |
| **作品归属** | 显示当前名称、TMDB ID 与季号；用户可明确选择「当前作品与季号正确」。发现错误时再展开修正选项。保持原归属不改目录名，不产生无意义的跨作品改绑 |
| **本季总集数** | 可填写正整数，也可选择「尚不清楚」。本地识别 4 集或候选收录 4 集只能作为参考，不能自动作为用户已确认的总数 |
| **本季播出状态** | 选择「已播毕／仍在连载／尚不确定」。首次人工确认不默认勾选已播毕，不能从用户填写总集数推导播毕 |
| **备注** | 选填，例如「已核对片头与发行页面」。不强制上传截图或填写长篇理由 |
| **作用范围与结果预告** | 展示当前作品、当前季及已确认关联目录；根据已填写信息和初检结果预告目标模块或仍缺少的依据 |

主要提交按钮统一为 **「保存确认并更新结果」**。用户可以只提交自己已核实的事实，未确认字段保持未知；首次提交需至少有一项明确确认或修正，不能把全未选择视为同意。提交后防重复保存，成功回执说明记录了什么、转入哪个模块或还有哪个阻塞。

保存人工事实后，系统自动利用本轮初检覆盖、已有有效资料和目录规则重新计算，不要求用户再点击「重新核算」或重跑初检。人工确认不移动、重命名、删除媒体，也不提交下载；修正归属时明确展示将保存的单季映射及作用范围，文件改名不作为隐藏副作用执行。

### 6.2 人工确认后的分流与闭环

| 用户确认与当前证据 | 预告与保存后的结果 |
| --- | --- |
| 原 ID、季号正确，共 4 集且已播毕；本地 E01–E04 齐全，无重复与其他阻塞 | 转入「齐全可归档」，由用户继续点击归档；不在保存确认时自动搬移 |
| 原 ID、季号正确，共 6 集且已播毕；合并源端、归档端及其他可信覆盖后仍缺 E05–E06 | 转入「真缺集待补」，显示实缺集号；不自动推送下载 |
| 当前作品正确，仍在连载，无其他阻塞 | 转入「连载留源」，文件原位保留 |
| 已播毕、正片齐全，但存在需要处理的重复版本 | 转入「待复核清理」，不能跳过版本核对直接归档 |
| 只确认作品正确，总集数或播毕状态仍不清楚 | 解除原来的归属疑点，显示「总集数待补充」或「播毕状态待确认」，保留文件；不再重复原来的 ID 质疑 |
| 另有目录目标冲突、混放作品、未核实分段等问题 | 保留异常卡，将主提示和操作切换为尚未解决的具体问题；不因总集数已填而掩盖其他阻塞 |

以上服从模块原有准入。例如已确认归档单端独立全齐而源端仍有残留时，按可清源规则判断，不机械地再发起归档；总集数小于已识别最高正片集号时，明确提示矛盾，不能自动舍弃超号文件。总集数输入不代替混放、分段或实际覆盖核验。

《性爱治疗师》示例：若用户确认「315775 正确，S01 共 4 集且已播毕」，系统采用该人工依据，结合本轮 E01–E04 与其他检查结果分流。只要没有其他阻塞，就进入齐全可归档；接口继续无资料或再次返回候选 315653，不得将它退回同一归属疑点。

### 6.3 人工确认的记忆、修改与失效

- **独立保存来源**：确认记录保存作品标识、季号、适用目录范围、逐项确认事实、确认时间和可选备注，来源标注「人工确认」。不把用户填写的数据写成 TMDB 官方返回值，不覆盖原始查询证据。
- **按范围复用**：后续离线核算及下一轮初检继续采用作用范围仍匹配的有效人工确认，不自动扩散到其他作品、其他季或尚未确认归属的新目录。
- **相同弱证据不推翻确认**：接口无资料、接口失败、同一个搜索候选再次命中，不构成撤销人工确认的理由。新增同集的其他版本也不能仅凭文件指纹变化抹掉作品身份确认。
- **新实质矛盾才重新提示**：例如已确认总集数 4，之后发现正片 E05，或文件新增明确的异作品 ID。列出原确认和新证据，暂停依赖冲突字段的自动准入，保留其他仍有效的确认；不得静默覆盖原决定。
- **修改与撤销**：详情提供「修改确认／撤销确认」。修改后按新事实重算；撤销后回到当前可用证据进行判断，不删除文件，不简单恢复可能已经过时的旧状态。
- **避免误继承**：目录 ID、季号或作用范围变化时检查确认适用性。不能将旧确认无条件套用到已改绑的新作品，也不能仅因无关文件变化让同一个疑点反复出现。

### 6.4 本次保留，不再提示

该操作作为资料不完整或证据待决条目的次级入口，放在更多菜单中，表示用户决定本轮不继续处理这些文件；不是声明已核实正确或已经在外部完成处置。

1. 保存任务级「本次保留」记录，保留原问题、原诊断、作用范围与时间；从本轮五模块的待办清单和待办计数移出。
2. 单独展示「本次保留」清单，允许查看与「恢复处理」。恢复后根据当前证据重新分流，不创建重复主卡。
3. 不标记为已齐、已播毕、已归档或手动处置完成，不修改文件、作品归属、下载队列或有效人工确认；隐藏卡片不解除后端写入限制。
4. 刷新页面、离线核算不能重新弹出本轮已保留事项；下一轮初检仍正常评估，不继承永久忽略。若规划中的历史指纹折叠生效，只影响展示，不跳过新一轮分析。
5. 「不操作直接结束本轮」仍然成立；此操作仅供希望主动清空本轮待办的人使用，不强迫逐条点击。

### 6.5 确认目录：实际归并、统一前缀、清理旧目录并刷新（本轮新增）

#### 6.5.1 用户目标、现状与实际路径

用户希望选择「谎言 (2026) [tmdbid=307478]」后，系统把「完美的谎言」内的剧集文件移入所选剧集目录，按目标既有文件统一季集标记之前的名称，成功后删除旧文件夹并刷新；不能只显示「目标已保存」就结束。

本次本地记录显示：《完美的谎言》S01 为 E01–E02，《谎言》S01 为 E03–E05，均在源端、状态为 `airing`；用户提供的卡片为「已播 6 集／已收 5 集（全季 12 集）」。目前 `/directory-groups/{group_id}/confirm` 仅保存规则，页面默认候选却是 `nas.finish` 下的未来归档路径，尚无真实合并流程。

**本方案将本例定义为「源端同作品目录合并」**：文件仍保留在源库 `nas`，本次不移入完结库 `nas.finish`。这是对用户所说「归档成功」在本连载案例中的具体执行定义，界面必须明确显示，不能用相同剧名掩盖实际路径差异。如果用户要迁入完结库，应走满足播毕等条件的正常归档流程，不借此按钮绕过。

| 路径角色 | 本例路径与行为 |
| --- | --- |
| 待并入的旧源目录 | `/115/Library_incs/nas/电视剧/韩国剧集/完美的谎言 (2026) [tmdbid=307478]` |
| 本次保留的源端主目录 | `/115/Library_incs/nas/电视剧/韩国剧集/谎言 (2026) [tmdbid=307478]` |
| 本次季文件移动 | 旧源目录的 `Season 1` → 主目录的 `Season 1`；E01–E02 与已有 E03–E05 合并 |
| 未来归档目标（本次只保存） | `/115/Library_incs/nas.finish/电视剧/韩国剧集/谎言 (2026) [tmdbid=307478]` |
| 本次刷新父目录 | `/115/Library_incs/nas/电视剧/韩国剧集` |

源端主目录应通过目录组中同 ID 的 `source_show_paths` 等实物关联确定，不能盲目把 `nas.finish` 字符串替换为 `nas`。关联不唯一时要求在当前弹窗中选定；目标源目录不存在时，预览明确列出创建位置。目标路径不得等于旧路径、位于旧路径内部、包含旧路径，或指向任务允许范围之外。自定义路径仍需相同校验，不得隐式重定向。

#### 6.5.2 一次确认完成实际操作

沿用「确认目录」入口，弹窗升级为「选择主目录并合并」：

1. 展示同作品各源目录的季集覆盖，默认选择推荐的「谎言」名称。
2. 分别显示「本次实际合并到」和「未来归档到」完整路径；连载情况下明确写出「合并后继续留源，不表示全季已归档」。
3. 选择目标后自动生成只读执行预览：参与目录与季、待移动视频和附件、命名前缀样本、逐文件旧名→新名、冲突、旧目录清理条件。用户不需要先点“重新核查”。自动读取本次涉及目录属于写入前预检，不重跑全任务或重复查播期。
4. 主按钮改为 **「确认并合并目录」**，不能继续用只表达保存规则的「确认目标归档目录」悄悄执行文件写入。按钮旁明确说明「将移动列出的文件并统一前缀，全部核验成功后清理旧目录」。
5. 用户在同一弹窗确认一次后，系统连续执行合并、核验、清理、刷新；无需依次点移动、改名、删除、刷新。存在未解决冲突时按钮禁用，并指明原因。
6. 次级操作保留「仅保存目标，不移动」与「有意共存」，两者只保存规则，不执行合并、重命名或清理。旧的仅保存接口不能在升级后无提示变成会移动文件的接口。

从单季卡进入默认只处理本季；从目录组进入须明确列出将处理的季，未列入计划的季不动。只有旧剧根所有内容均已按计划保全、无其他季或剩余内容时，才能删除旧剧根。本例若确实仅含已列出的 S01 及已保全附件，成功后应删除整个「完美的谎言」目录；不能因为入口在 S01 就忽略旧目录还有 S02。

#### 6.5.3 文件名前缀统一规则

用户要求的边界是**代表本季的有效季集标记中的 S**，不是字符串第一次出现的字母 S。复用季集解析器识别边界，如 `S01E01`、合法连集 `S01E01-E02`，验证它与本次处理季相符。标题中 `Some.Show` 的 S、发行名内重复出现的标记均不能误选；无法唯一确定边界或季号不符时列为待确认，不盲改。

将文件名拆为 `前缀 P + 季集标记及后缀 R`，新文件名为 `目标命名前缀 P_target + 原文件后缀 R`：

- `P_target` 优先取目标同季已有正片文件在有效 S 标记之前的完整前缀，包括空格、短横线或点号分隔符。不是直接把整个目标目录名称当作文件前缀。
- 目标存在多种不一致前缀时，在本弹窗列出真实样本供选择；不能任取文件系统返回的第一个文件。目标无可用样本时，提出基于所选剧名的前缀建议，由用户在预览中确认，不擅自添加年份或 TMDB 标签。
- 只改移入文件的前缀。既有目标文件默认不改名；从有效 S 开始的原始文本全部保留，包括季号、集号、集标题、发行信息、画质、音轨、字幕组及扩展名；后缀中再次出现旧剧名也不全局替换。
- 字幕、分集 NFO、缩略图等明确同名伴生文件随对应视频使用相同的新基名，保留语言、字幕属性与扩展名，避免移动后外挂字幕失配。
- E00、特别篇、非标准季集名文件单独列示，保持既有非正片识别结果，不为凑齐集数擅改编号；需要用户解决的命名歧义在执行前收口。

以下仅为命名规则示例，不声称是当前网盘实际文件名：

| 项目 | 示例 |
| --- | --- |
| 目标已有样本 | `谎言 - S01E03 - Episode.03.1080p.WEB-DL.mkv` |
| 待移入视频 | `完美的谎言 - S01E01 - Episode.01.1080p.WEB-DL.mkv` |
| 合并后视频 | `谎言 - S01E01 - Episode.01.1080p.WEB-DL.mkv` |
| 待移入外挂字幕 | `完美的谎言 - S01E01 - Episode.01.1080p.WEB-DL.zh-Hans.srt` |
| 合并后外挂字幕 | `谎言 - S01E01 - Episode.01.1080p.WEB-DL.zh-Hans.srt` |

如果真实目标文件使用 `谎言.S01E03...`，则采用前缀 `谎言.`；如真实目标样本包含年份或 ID，则照样保留。最终以预览中选定的真实样本和逐文件结果为准。

#### 6.5.4 文件冲突、附件与其他内容

| 情况 | 处理规则 |
| --- | --- |
| 合并文件最终全名与目标文件重名 | 执行前阻止冲突计划，不覆盖、不静默跳过后删除旧目录；相同大小或相同集号不等于内容相同 |
| 两个待移入文件改名后同名 | 同样前置拦截；必须先明确各文件的保留方案，不能靠覆盖完成归并 |
| 同集存在不同版本，但最终文件名不同 | 可以完整保留并合并，重复版本标识保留；连载时不自动择优淘汰，也不因此增加已收集数 |
| 剧根 `tvshow.nfo`、海报或其他公共资产 | 目标缺失则迁入；目标已有同名时不覆盖，源版本可保全到预览列明的目标附件子目录，如 `合并保留/完美的谎言/`，避免重复 NFO 干扰主目录刮削 |
| 未识别附件或子目录 | 必须清点并列入保全计划；能原样迁入的明确目的地，无法判断用途、关联或冲突的保留原处并阻止旧剧根删除，不能当垃圾清掉 |
| 旧目录其他季未纳入计划 | 保持原位，允许本季合并完成但旧剧根保留，回执说明剩余季；不得声称旧目录已全部删除 |
| 正在写入、下载或做种依赖旧路径的文件 | 核对已有下载与做种信息及文件稳定性，有路径依赖或无法确认是否可安全移动时阻止受影响计划；不擅自暂停、删除或修改下载器任务 |

普通视频碰撞不通过自动添加数字后缀来掩盖，因为这会改变本次承诺保留的 S 后文本。根级公共附件的保全位置在同一预览中说明；未保全内容存在时，宁可显示「旧目录待清理」，不能为满足删目录而丢文件。

#### 6.5.5 执行、核验、删除与刷新顺序

1. **生成计划**：记录目标源目录、未来归档目录、选定季、各文件稳定标识／路径／大小／修改时间（可用时）、前缀和最终路径、附件保全位置、允许清理的旧目录。只读预检通过后生成计划标识与快照。
2. **认领并复核**：按作品与实际路径加锁，阻止与初检、归档、清源或其他合并并发；核对计划快照及命名冲突，无漂移才开始写入。路径和文件检查限制在本计划范围。
3. **移动与改名**：逐文件执行禁止覆盖的操作，记录每一步的实际路径和回执。优先使用提供方支持的原子移动改名；不支持时采用可恢复的分步改名、移动计划，中间名称同样预检。不能只改数据库路径而不执行实际文件操作。
4. **双端后验**：强制读取实际结果，逐文件确认目标最终名称、大小与可用的稳定标识或校验依据，确认原文件已离开旧位置；跨端标识变化时不能仅凭名称认定内容一致。被跳过、超时未知、漏文件、读失败均不得算成功。
5. **清理空壳**：先确认旧季目录为空，再重新完整列出旧剧根；确认其他季、字幕、公共资产、未知附件都已保全且根目录为空，才回收旧剧根。删除操作必须绑定计划中的确切旧路径，不得指向主目录、分类根或祖先目录；能使用非递归空目录删除则优先使用。只能递归回收的提供方必须在同一路径锁下最终核验为空，有新文件或活动写入则中止清理。
6. **落库和局部重算**：更新新物理路径、季覆盖、目录组成员与命名依据；保留原始路径及逐文件审计，不把旧物理记录消失等同于作品季归档完成。人工确认、映射与已推送回执按可验证的旧新身份对应迁移，不能丢失或套到其他季。
7. **刷新并呈现**：强制刷新新旧季目录、旧剧根所在父目录和目标父目录，去重请求；至少刷新本例韩国剧集分类目录。核实旧目录已消失和目标文件可见，再更新页面目录组、主卡、三端覆盖、模块计数及进度回执，无需用户另点刷新。

本例合并成功时：主目录实存 E01–E05，已收仍是 5 集、全季仍是 12 集；本轮已播 6 集的证据未更新时仍保留该值，不把合并说成补齐 E06。无其他异常则回到「连载留源」。成功提示为「已合并到谎言目录，已统一 N 个文件名，旧目录已清理，目录已刷新」，不用「全季归档成功」。

#### 6.5.6 部分失败、恢复与旧版兼容

- 文件移动成功但重命名、附件保全或核验未完成：显示「合并未完成」，保留未迁内容和旧目录；列明每个文件当前路径。不得批量盲目回滚，也不得用重试重新移动已完成文件。
- 文件全部就位但旧空壳回收失败：显示「合并完成，旧目录待清理」，提供仅重试收尾；不重搬媒体，不掩盖清理异常。
- 删除已成功而缓存刷新失败：显示「文件合并及清理完成，目录刷新待完成」，提供仅重试刷新，不把缓存中旧影子当作需要再次删除的实物。
- 重复点击、关闭弹窗、服务重启：执行计划与逐步回执持久化，按同一计划幂等查询／恢复；超时先对账双端现状，确认结果后只处理剩余步骤。用户再次打开目录组能看到未完成计划。
- 旧版已保存的 `use_archive_target` 只代表目录规则已确认，不能据此自动补跑媒体移动。需要在升级后的弹窗中看到预览并主动执行新的合并操作。
- 只保存规则与合并计划状态独立记录。合并中或失败不能提前抹掉待办；全部文件就位但收尾未完成时仍呈现可追溯收尾项，不能仅因组被标为 confirmed 而隐藏问题。

#### 6.5.7 实现落点与能力缺口

保留现有 `confirm_task_directory_group`／`confirm_directory_group` 的只保存语义，新增独立的预览、执行、进度与对账恢复能力，具体接口命名在实现时确定；前端 `openDirectoryGroupDialog`／`submitDirectoryGroupConfirm` 分别提交明确操作模式。计划必须同时携带本次源端目标和未来归档目标，不能复用一个含混的 `target_path`。

当前 CD2 客户端可见 `move_file`、`mkdir`、`delete_file` 与强制目录读取能力，未见重命名封装；落地前须补齐并验证提供方支持的重命名、禁止覆盖和部分失败回执语义，不假定现有 `MoveFile` 能同时改名。`skip_existing` 返回跳过不能被当作文件已迁入。还需新增精确到参与路径和季的连载目录合并门禁、文件计划持久化及旧新路径关联更新，不能只按相同 TMDB ID 改写全任务所有目录记录。

《BOSS的甜蜜诱惑》这类同作品连载双目录同样适用；单纯「仅保存目标」及「有意共存」仍保持不移动文件。所有本节行为属于待实现方案，本轮未执行任何网盘操作。

### 6.6 只在必要时重试或刷新

| 操作 | 出现条件 | 范围与回执 |
| --- | --- | --- |
| **重试失败项** | 初检接口超时、读取目录失败等明确请求失败 | 只补查失败项及依赖它的受影响结果，不无差别重跑成功范围；返回成功、仍失败的具体项 |
| **刷新修改结果** | 用户已在外部修改文件、目录或 ID，并主动选择刷新修改范围 | 更新受影响目录、作品季及必要的关联覆盖；目录或 ID 已变化时不能只请求失效的旧路径，不默认扫描整个任务 |
| **自动执行前检查** | 用户真正发起归档、删除等文件操作 | 系统自动检查路径、文件与计划是否变化；发现变化则中止并解释，不要求用户先手动点一次通用核查 |

普通卡不显示常驻「重新核查」。资料未收录、总集数待公布不等同于请求失败，不能因此不断建议重试。人工确认和仅保存目录规则后的重新分类属于本地计算，不算新的远程检查；第 6.5 节实际合并所需的局部预检、后验和刷新由系统自动完成，不增加用户手动核查步骤。

重试或刷新进行中禁用对应按钮，结束或失败后恢复；初检运行、暂停或正在停止时，服务端拒绝并发覆盖结果。部分读取失败时保留仍有效的历史证据及原取证时间，明确哪些范围未完成、哪些受变更影响已不能确认；不以历史快照冒充新核实结果，不把单个目录成功当成整卡完成。这些操作均为一次性动作，不建立后台轮询。

### 6.7 单季清源与已有手动结案

**单季删除源端**继续满足以下条件：本季已确认播毕；归档单端独立覆盖全部正片且源端视频有等价副本；已确认唯一实际归档目标；两端为独立季目录；无身份、覆盖或连载保护阻塞。源端独有字幕列入预览迁移计划并完成保护，不能直接丢弃；此操作严禁删除整剧父目录。第 6.5 节另行授权并核验的合并后空壳回收属于独立流程，不能借用单季清源入口执行。执行须幂等，并在自动实物重读发现变化时中止。

**已手动处理**仅用于用户确已在外部完成处置、且允许结案的异常季，在更多菜单中提供；按作品季记录任务级结案，连载及受保护的关联记录不得借此结案。它不再承担「我认为资料正确」或「我本轮不想处理」的含义。已有历史结案标记、有效映射和已受理回执继续保留，不在升级时擅自改成新确认或本次保留记录。

### 6.8 离线核算与旧任务兼容

离线核算使用上次初检资料、有效缓存、人工确认及映射重新判断，不访问网盘。用户保存人工确认或仅保存目录规则后由系统自动完成，不要求额外点击。实际目录合并不属于离线核算，须先完成第 6.5 节实物操作及局部核验，再用核验结果更新路径、覆盖和分类。

识别旧版把其他候选资料当作当前作品依据的记录，解除「文件来自另一作品」的断言，显示「作品资料不完整」；保留原 ID、实存集号与既有人工决策。没有新的可靠依据时，不能借用污染缓存的集数或完结状态转成可归档；有效的人工资料确认、可靠原作品资料或用户确认的映射可以补充所缺依据，再按全部准入条件分流。
