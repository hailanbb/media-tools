# MediaFlow「异常剧集」模块需求与交互方案 v2.5.61

修订日期：2026-11-21。本轮按实际源码 v2.5.61 同步本会话修复与跨模块约束，适用于所有初检目录。需求规则、已实现改动与验证边界分别说明；文档版本不表示所有设计目标已验收。

全局导航顺序为 **待复核清理 → 异常剧集 → 缺集待补 → 齐全可归档 → 连载留源**。有副本、规范化归并或归档已齐清源动作时先处理清理，再处理具体异常，之后按播期和内容覆盖分流。播期判断在下载资格之前，已确认连载的季继续留源。

各模块共用作品身份、期／集／段、内容类别、剪辑版本和技术副本的识别结果。旧状态仅供兼容，独立决定数、作品季数、目录组数和文件数分别统计。一次处理后自动核验、刷新及分流，无需另点重新初检。

设计依据为[五模块处理流程重构与智能清理方案 v2.5.44](MediaFlow五模块处理流程重构与智能清理方案-v2.5.44.md)，其中已包含按初检目录名称与完整路径确定动漫默认规则的修订。

## v2.5.61 手动复核与外部删除对账（2026-11-21）

本地源码 **v2.5.61**，清理规则仍 **v2.5.54**。本节优先于下文历史描述；下文各版本的验收记录不表示本版已部署。

- 异常剧集统一主入口为「手动复核」。面板包含「重新核对资料与文件」「核对源目录」、作品／季号／总集数／播期事实表单，以及折叠的「暂时无法判断，稍后再处理」。
- 「本次保留」改称「暂不处理」：只移入本任务的暂不处理清单，保留问题和文件，可恢复；不是复核通过、文件版本保留规则或下载取消。主卡不再并列展示三个含义难辨的操作。
- 五模块提供源目录对账入口；异常页收进手动复核，其余卡片显示「核对源目录」。用户明确触发后强读原路径，确认不存在才移出对应物理路径待办。原路径可能被外部删除或移动，不猜测操作人，也不伪称本应用删除或归档完成。普通 GET／切页不自动操作云盘。
- 原目录仍存在（即使为空）不能标记不存在。网络、权限、清单格式错误和源根不可用均保留待办。外部改名由「重新核对资料与文件」沿原有范围发现；只核对源目录不会自动迁移身份或扫描整库。
- 清源时，源剧根与本季均消失且没有保全事务时只对账结束；仅本季消失则跳过再次删除，继续核验归档覆盖及外层附件。已存在的附件保全回执仍须后验，不以源消失掩盖未完成迁移。
- 目录组仅源目录减少且归档范围不变时，清源不再一律撤销确认。旧版已失效记录须有同组、同归档目标的既有人工确认依据，并重新强读检查；仅为本季清源采用该依据，不自动重新批准整个目录组。新增源目录、归档减少／增加、共存选择及无确认记录继续阻断媒体操作。
- 单季与批量放弃补缺预览允许返回「源目录已不存在」的零删除计划，确认执行时再次核对并更新待办。预览后目录消失可对账；不存在预览后目录重新出现必须重新预览，不能套用旧请求删除。对账不取消或伪造下载台账。
- 切换复核动作前保护未保存草稿，执行中禁止重复提交；操作回执与列表刷新失败分开显示。保存事实的文件改动预览、明确同意和指纹门禁继续保留。

**本模块衔接：** 资料修正、重新核对、外部删源对账和暂不处理集中在手动复核；目录归并仍保留独立入口。

**验证与部署：** 新增 21 项后端专项，相关后端共 167 项通过；6 份前端脚本通过。使用模拟云盘、即时协程与内存数据库，不代表完整异步或真实 CD2 验收。未重启、未执行媒体操作、未提交或推送；《我不是大师》最新已知操作仍被旧目录组门禁拦截，本版加载与实际收尾待验收。详见 [v2.5.61 交接](MediaFlow会话交接摘要-v2.5.61-2026-11-21.md)。

## v2.5.60 剧集外层收尾与真实回执（2026-11-20）

当前本地源码 **v2.5.60**，清理规则仍为 **v2.5.54**；本节优先于历史修订；文件名与文档标题已同步为 v2.5.60。

**本次差异。** 季内附件保全已运行，但剧集外层仍可能另有「合并保留」目录。v2.5.59 只补齐季内路径，外层遇到子目录仍直接保留；前端成功日志又写死「残留目录已清除」，导致实际留存与提示不一致。

**收尾流程。** 本季删除并确认消失后，持久化本季完成标记，再检查剧集外层。只有已知公共资产和读取确认的纯附件保留目录时，将整个资料外壳保全至归档剧根的独立「合并保留／清源标识／原剧名」位置，保留全部原文件和层次，不覆盖已有同名海报或 NFO；核验目标清单、大小及源外层消失后完成。外层为空时删除仍需成功回执和消失核验。其他季、视频和未核实内容不随本季清源删除。

**结果与恢复。** 回执区分「本季已清理，外层已移除」「本季已清理，外层因其他内容保留」「本季已清理，外层待处理」。附件保全／核验失败保留待办，前端显示真实后端结果而非固定成功文案。再次执行只收尾并复核归档覆盖；若本季目录重新出现，停止并要求核对，不按旧回执重复删除。保全意图在移动前持久化，回执中断后继续验证既有去向。

**本模块衔接。** 纯附件剧根不因「合并保留」名称一律阻断。隐藏视频、未知附件、读取失败或迁移后验失败保留待处理理由，不能被笼统成功提示掩盖。

**验证边界。** 新增 14 项外层收尾隔离回归及 1 份前端回执脚本，连同相关旧用例共 146 项后端测试、4 份前端脚本通过。实际条目数据库只读复制到内存后，确认可恢复 1 项外层待办且原记录未改写。日志与实际回执证实上一轮季内保全已执行，但本轮没有操作真实媒体或重启服务；v2.5.60 运行加载、外层保全及消失仍待验收。详见 [本次交接](MediaFlow会话交接摘要-v2.5.60-2026-11-20.md)。

## v2.5.59 清源附件目录处理（2026-11-20）

当前应用源码 **v2.5.59**，清理规则仍为 **v2.5.54**。本节优先于下文历史版本；当时保留 v2.5.56 文件名，现已统一更名为 v2.5.60。

**用户操作。** 归档已齐的本季出现「合并保留」子目录时，继续按原「删除源端（本季）」／批量清源操作处理。系统先核实并保全附件，再核验归档覆盖和源端变化，最后回收源季；不要求用户先手工删除附件或重新执行整季归档。

**执行规则。** 强读展开「合并保留」目录，当前支持 nfo、jpg、jpeg、png、webp、txt 纯附件，最多 3 层子目录、500 项；空附件目录也可处理。视频、未知类型、清单异常或超出核验范围仍保留源端并提示具体原因。仅识别为纯附件不等于取得删除资格，原身份、路径隔离、目录组及归档覆盖门禁仍须通过。

**保全与恢复。** 整个附件目录先迁入归档端；归档已有同名目录时使用其中独立的「清源-唯一标识／合并保留」位置，不覆盖既有附件。移动前持久化源路径、目标路径及附件清单，移动后核对相对路径、类型、大小和源目录消失。中断或失败后再次清源沿用回执复核，不能因源附件已移走而跳过后验；重复执行不再次移动已确认到达的目录。

**完成口径。** 删除前复查归档正片未变化、附件全部到达且源季没有新增内容。只有删除回执成功并复查源季已消失，才更新已清理状态、成功季数和操作回执；失败／未确认均不记成功。保全目录和附件数写入本季清源记录。

**本模块衔接。** 已验证的纯附件目录本身不是新增身份异常。目录内实际有视频、未知文件或无法读取时仍需核对，不能按目录名称豁免内容核验。

**验证边界。** 20 项新增隔离回归，连同附件归并、推荐处理、既有闭环及补缺复核共 98 项通过；覆盖同名保全、视频／未知内容、读写失败、文件变化、缺失附件、中断重试及删除回执。使用模拟云盘和内存数据库，没有真实媒体操作；运行服务加载、真实 CD2 目录移动和当前条目清源仍待验证。详见 [v2.5.59 交接](MediaFlow会话交接摘要-v2.5.59-2026-11-20.md)。

## v2.5.58 补缺到位后的完整复核（2026-11-20）

当前应用源码 **v2.5.58**，清理规则仍为 **v2.5.54**。本节修订时保留原 v2.5.56 文件名（现已更名为 v2.5.60），本节优先于下文历史版本和运行快照。

**流程与触发。** 用户点击「核对入库」后，系统在对账链路中自动复核受影响的本季，复用初检的身份、集号／期段、内容版本与副本分析，不要求再跑整任务初检。当前没有接入 MP 完成回调或常驻定时轮询；仅切页、刷新列表不会启动扫描、下载或删除。

**到位与归档分别判定。** 不再使用旧重复集列表判断补缺后的归档资格。源端及相关归档端强读，更新已识别集、缺口、重复版本、内容冲突和证据。同一下载的有效到位回执保留，后续清理不会重新提交已经补到的集。

| 最新实物情况 | 分流及操作 |
|---|---|
| 每集一份，只有分辨率／编码不同，内容与覆盖正确 | 不为统一规格重新下载；其他条件均通过后可归档 |
| 整季包造成同集技术副本 | 重新生成待复核清理计划，执行仍需确认 |
| 已明确是独有剪辑、内容或配音版本 | 复用独立保留规则，不因同集号删除；归档计划保全独有内容及配套 |
| 明确的特别篇／花絮 | 不补正片缺号，保留并在归档预检明确去向 |
| 正片超号、错季、无法识别的视频或归属冲突 | 进入异常，列出文件；不自动改编号或当作额外赠送内容 |
| 子目录只含已读取确认的附件 | 保留且不误拦正片；不因此取得删除资格 |
| 子目录含视频或尚未展开的更深层目录 | 进入异常核对其范围，当前不自动归类所有嵌套媒体 |
| 读取失败、列表格式异常、文件指纹变化、MP 队列未核实或仍在下载／整理 | 保持补缺后待复核，显示原因，暂停归档、删源和重新推送 |

**等待与重试。** 「等待入库／回执」页增加“补缺后待复核”原因。来源目录读取失败不当作零文件；归档目录仅明确不存在（FileNotFound／gRPC NOT_FOUND）可作为零覆盖，超时和权限错误不能据此释放重推。已做种／明确完成的下载不当作仍在写入。下次核对可继续仅复核受影响的季；旧版已记入库但没有完整复核记录的活动条目，在核对时补做一次。已归档、源端不存在及手工处理等终态不重新操作。

**归档与版本门禁。** 单季、同作品季多目录汇总、批量推送、单季／批量删源及归档入口使用一致的复核状态；待复核不能被旧 archive_ready 或互补目录覆盖绕过。清理规则与副本等价标准未放宽，未知内容不自动删除，核对本身只有媒体读取。

**本模块衔接。** 承接补缺后新增的作品归属、错季、未识别视频、正片超号及含视频的未知子目录问题。清楚展示具体文件与原因，保留已有人工确认中仍有效的字段；不能仅因缺号清零消除真实冲突。

**验证边界。** 新增隔离测试覆盖新副本、正常规格混合、独有剪辑、超号与未知视频、源／归档读取失败、明确不存在、变化中的目录、在途下载、做种、旧回执补复核、同季多目录和直接接口门禁。其中实际初检引擎联调用例使用模拟云盘、模拟资料与顺序协程调度，不等于真实异步集成验收。真实 CD2／MP、当前运行版本、存量条目结果及实际耗时尚待运行核实；没有操作真实媒体、重新推送下载或重启服务。

## v2.5.56 当前规则与实现边界（2026-11-20）

当前源码为 **v2.5.56**，清理规则仍为 **v2.5.54**；本节优先于下文历史修订。五个主模块顺序保持不变，实际分流继续先核验播期。新增功能仅涉及缺集待补内部视图及用户明确放弃补缺的操作，不扩大推荐清理资格。

- 缺集待补分为「待搜索／可重试」「无合格资源」「等待入库／回执」三个互斥页签。无合格资源必须有当前季路径的搜索结果，覆盖当前全部可补缺号，且没有阻塞中的在途集；零命中、做种不足、候选不合格或候选身份不符分别保留原因。搜索异常、提交异常、未搜索和中止未执行留在可重试页；局部在途仍留在可重试页，只推剩余缺号，全部在途进入回执页。
- 同一作品季多个活动目录，任一目录未满足无资源条件时，不整体归入无合格资源。旧任务摘要没有新计数时先显示分类加载中，加载后按同一分类结果更新。作品季数、目录组数、逐集台账和实际下载任务数不得混算。

| 同作品多个译名／发行前缀 | 核对别名和发行证据，可确认一致则自动解除，不只按不同标题判为混放 |
| 明确异作品 ID、季号或片源冲突 | 展示具体文件和冲突，核对归属 |
| 整期、上下段或总数来源差异 | 自动核对同季条目、NFO、发行序列及必要文件属性，展示具体口径问题 |
| 作品资料缺字段 | 定向补取缺失事实，必要时提供人工确认或粘贴季条目链接 |
| 接口或目录读取失败 | 重试失败项，仅处理失败范围和依赖它的结果 |
| 实物修正或归档中断，媒体去向未核实 | 查看执行计划、对账并继续剩余步骤；媒体已到位而仅空壳／刷新收尾失败的项目交待复核清理 |
| 用户在外部修改了目录或文件 | 刷新修改结果，按新旧路径关联重算 |

取消“证据待决 · 安全保留”和“系统跟踪”的主标签及按钮。界面不展示 period_review、archive_check 等原始代码。正常条目无需再点通用重新核查，用户可结束本轮。

## 二、自动补证与多源事实

每个作品季分别保存身份、总期数、正片集合、期段映射、播期及实物覆盖。资料融合按字段采用有效证据，TMDB 的一个日期缺失不能抹掉已证实的内容或其他来源的季终依据。

自动处理顺序为精确 ID 与有效人工记录 → 已绑定同季豆瓣／发行资料 → 按季名与季年份寻找独立条目 → 可信 NFO、原发行名及必要文件属性。补证在初检或当前处理批次内有界执行，复用缓存和稳定文件结果，运行结束不保留常驻回查任务。

| 证据 | 采用规则 |
| --- | --- |
| 原 ID 未取得季资料 | 保留原身份，记录请求失败、未收录或字段缺失的具体原因 |
| 同名同年候选提供集数 | 仅作参考，未确认对应关系时不替换原 ID 或写入原 ID 的已核实缓存 |
| 文件显式异 ID、可靠季映射冲突 | 按文件和季限定问题，禁止只凭相似名称自动改绑 |
| 豆瓣独立季条目 | 核对作品、季及季年份，不能因剧根首播年不同拒绝后续季 |
| 总期数与 TMDB 分段条数不同 | 建立实际期段映射，1.5倍或2倍比例仅作为核对线索 |
| 来源提供合成 1…N 列表 | 只作为数量依据，不能当成真实分集标题表 |
| 季终公告、终期发行及完整排期 | 用于对应季的播毕判断，整剧续订状态不阻止已结束旧季归档 |
| NFO、海报和截图 | 提供身份和内容线索，不计入实存正片 |
| 目录读取失败 | 保留失败范围及历史时间，不能记录为零视频或全季缺失 |

同 ID 的标题别名差异、仅超出资料最大集号、某个衍生文件没有日期，都需先定位具体内容，不能直接要求用户重新确认整部作品。

系统自动补证仍无法得出关键事实时，列出一个具体问题和最小输入。可选择本次保留，操作记录保存原问题。下一轮初检正常评估，有新事实才重新提示适用的疑点。

## 四、主卡、清单与按钮

主卡显示当前需要解决的作品季数，具体问题作为筛选维度。可同时存在多个问题，但卡上只突出当前最先影响处理的一个。目录组任务数不混入季数，同一作品季只出现一个主模块。

| 元素／操作 | 交互要求 |
| --- | --- |
| 季条目 | 剧名、年份、季、ID、具体问题、系统已查到的事实、推荐动作及预计去向 |
| 详情 | 源／归档／可信媒体库覆盖、资料来源与时间、冲突文件、内容版本、人工确认、操作回执 |
| 执行推荐处理 | 集中预览系统可完成的补证／修正及实际文件变化，一次执行后核验刷新，逐季结算 |
| 人工确认 | 在同一弹窗补充已核实事实或展开单季修正，展示作用范围和实物变化 |
| 重试失败项 | 只补取失败项，保留仍有效结果；失败可再试，不重跑成功范围 |
| 刷新修改结果 | 用户外部变更后定向读回目录／身份和依赖覆盖，不仅访问失效旧路径 |
| 本次保留，不再提示 | 允许批量跳过当前问题，单列本次保留清单，提供恢复处理 |
| 查看／继续未完成操作 | 回到持久化计划，对账后只恢复剩余步骤 |
| 外部处理后更新 | 使用“刷新修改结果”或“重新取证并更新”核验，不以“已手动处理”直接隐藏问题 |

有界自动补证用尽且用户选择结束时可批量保留，无需逐季点击。查看详情、切换页面和重新加载只读取结果。页面刷新不派发下载、移动或删除。

## 五、人工确认与实际修正

### 5.1 字段与结果预告

| 字段 | 行为 |
| --- | --- |
| 当前作品与季号正确 | 用户明确选择即保存身份确认，不要求再填写改绑表 |
| 本季总集数／总期数 | 可确认正整数或保持未知，本地文件数和候选数不自动变成人工确认 |
| 播出状态 | 已播毕／仍在连载／尚不确定，首次不默认播毕，总数与播期独立 |
| 单季修正选项 | 正确 TMDB ID、豆瓣季条目、季号及必要集／期／段映射 |
| 备注 | 可选，记录人工来源与说明 |
| 作用范围及预览 | 展示参与目录和季、逐文件旧新名、目标位置、字段修改及预计模块 |

主按钮为「保存确认并更新结果」。首次必须有至少一项明确事实或修正。在同一弹窗显示实际改名、迁移和 NFO 更新范围后一次提交完成，不额外要求用户逐步点击。

### 5.2 执行变化

仅补充现有身份、总数或播期时保存事实并重算。填写名称、ID、季号或编号修正时，按预览执行实际文件操作。

- 名称或 ID 修正时创建／复用正确剧目录，迁入本季，按目标规范名统一文件名前缀及字幕基名。
- 季号修正时更新目标 Season N 和文件中明确指代本季的 S 标记；集号修正仅按已确认映射改变相应编号。
- 普通归并只改有效 SxxE… 前的前缀。明确的季／集修正是修改相关标记的例外，必须逐文件展示；其余发行文本和版本信息保留。
- 旧剧根还有其他季时只移动当前季。剧根共享 tvshow.nfo 不得被单季改绑污染，分集 NFO 结构化更新对应字段并保留备注及其他字段。
- 同名碰撞按内容核验或保全处理，禁止覆盖；附件、下载路径依赖和未知文件列入计划。

保存事实与媒体事务分别记录状态。计划先持久化，依次完成移动、改名、附件、双端核验、空壳收尾、父目录刷新和重新分流。失败显示实际路径及剩余步骤，不能只改数据库就宣称修正完成。

### 5.3 记忆、修改与旧数据

人工确认独立保存作品季、适用目录、确认字段、时间与来源，跨核算和下一次初检复用。相同弱候选、接口无资料或无关文件变化不推翻确认。明确新异 ID 或新增超出确认总数的正片时，展示原确认与新事实，仅暂停依赖冲突字段的动作。

人工改绑后的离线重算必须先处理身份、季号、目录范围仍有效的人工确认，再执行无确认的映射回退，不能因映射提前返回遗留旧“资料未核实”标签。保存回执和列表均以统一最终分类为准，不单凭 `archive_ready` 状态字段宣称已进入归档。人工确认不等于远程资料已核实，混放、显式异作品 ID、集号矛盾等真实拦截继续保留。此项本地修复新增 8 项回归，连同既有相关套件共 46 项隔离测试通过；服务加载及存量条目定向重算尚未验收。

修改或撤销确认后按当前证据重算，撤销不会自动回滚已完成实物移动。新作品／新季不无条件继承旧确认。目录组、季映射、有效人工记录和补缺台账按可验证的新旧身份迁移，保留原下载请求和回执，避免重复推送。

旧版保存确认或目录规则的行为按原授权解释。升级不能自动补跑新媒体修改，需要在新预览中发起实际修正。

## 六、处理后的分流与本次保留

| 结果 | 去向 |
| --- | --- |
| 身份和口径修正后发现副本、同 ID 归并或已齐清源动作 | 待复核清理，复用本轮已完成证据 |
| 在播或待播依据明确 | 连载留源 |
| 已播毕，有确认缺口 | 缺集待补，继承有效在途与待查回执 |
| 已播毕且正片齐全，前置动作完成 | 齐全可归档 |
| 已清源且归档保全，或已核实归档完成 | 完成记录 |
| 尚有具体事实或操作未完成 | 保留对应问题和恢复入口，不能为了转模块伪造结果 |

纯数量冲突先解释期段和衍生内容，仅在确认口径后计算缺号。只有附件且无正片时，完整读取和其他端覆盖核验通过后可以进入全季补缺，不由 archive_check 永久阻塞。

本次保留记录原问题、范围、时间，从当前人工待办移出但单独可查。原已扫描作品季总量保持可核对，成功归档数不增加。恢复处理按当前证据去重分流，本轮刷新不反复弹回，下一轮初检正常分析。未变化的已解释文件保留判定，避免异常与清理来回循环。

## 七、失败恢复与实施

同作品季和相交物理路径使用统一执行认领。计划固定规则版本、稳定文件身份和允许操作范围；预览后发生影响内容或新增删除范围的变化时重算相关计划。超时先对账，关窗、刷新、服务重启均能查看和恢复原批次。

删除已完成但刷新失败只重试刷新，文件迁移成功但本地提交失败先恢复记录。未知回执范围限制重复操作，其他独立季继续。并发扫描运行、暂停或停止保存阶段不能覆盖其尚未发布结果。

初检、人工确认预告、实际修正后的核验、缓存核算与摘要共用分流器。旧候选污染缓存重新标记参考来源；旧 status、hold、映射和操作记录保留审计。普通确认可用已有证据重算，实际文件修改必须局部实物后验。

实施涉及[初检引擎](app/core/inspector.py)、[期段判断](app/core/segments.py)、[身份解析](app/core/identity_resolver.py)、[人工确认](app/core/manual_confirmation.py)、[目录归并](app/core/directory_merge.py)、[任务接口](app/api/tasks.py)、[统一分流](app/core/season_classifier.py)及[页面](frontend/index.html)。
