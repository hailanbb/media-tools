# 报告与操作追溯

[项目首页](README.md) · [通用安装](INSTALL.md)

## 主表与颜色

报告一季一行；仅“剧集目录”单元格决定阶段选取。人工维护时请修改这个单元格，保留目录超链接、季号和原表头，避免合并或复制出重复季行。报告路径必须属于脚本配置的源目录。

| 状态 | 底色 / 字色 | 含义 |
| --- | --- | --- |
| 绿色 | C6EFCE / 006100 | 已确认播完且齐全、无待处理异常，或人工确认；可交归档检查 |
| 蓝色 | BDD7EE / 1F4E78 | 仍在播出，不等于齐全；第二脚本可补报告中确认缺失的已播集 |
| 黄色 | FFFF00 / 000000 | 已提交下载、已有任务或等待复核；第三脚本选取这些项 |
| 红色 | FFC7CE / 9C0006 | 没有合格资源或做种数不足2 |
| 紫色 | E4DFEC / 7030A0 | 已验证归档成功 |

未填色通常表示缺集、待播、来源未知或待核实。颜色是流程状态，原因请结合处理结果和说明查看。第二脚本跳过绿色和紫色；第三脚本读取黄色；第四脚本检查同剧所有季是否都为绿色。

“视频文件数”可能大于“已识别集数”，例如重复版本、无法解析的文件。确认空季时两者为0；读取失败用未知，不能当成0。“来源登记集数”未知时不伪造0；豆瓣补查成功后需重新导出，旧文件不会自动改变。

## 三类操作明细

每次更新报告保留原表的备注、公式、链接和历史明细，追加本轮明细工作表；同一内存报告重复导出不重复追加。再次导入后生成的新轮次保留先前明细。机器记录分片写入，勿手工删除内部记录。

| 明细 | 记录内容 |
| --- | --- |
| 下载明细 | 剧集/季号、站点、资源标题、单季整包/单集/零散多集、对应集号、查询时做种数及说明、容量、中文标记、选择依据、任务ID、提交响应时间、结果与错误 |
| 清理明细 | 每个文件的原路径、大小、云盘修改时间、视频/刮削类型、关联视频、保留或删除理由、计划/尝试记录、请求及核实结果 |
| 归档明细 | 每个视频/刮削文件的原路径和目标路径、文件属性、所属整剧/季移动操作、同季/同名文件冲突、整剧暂缓项、提交和验证状态；另列“删除源空目录”的计划、提交、错误及验证时间 |

“已提交”不代表下载完成；“已有任务”不代表本轮新增下载。已有任务的做种数只有与本轮搜索标题、站点唯一匹配时才补充，并注明来源；无法确认显示未知。没有选定资源显示“未选定资源”，不能填0。

删除或移动的“计划”“未提交”“待核实”“已验证成功”“跳过”含义不同，不能把计划当作实际操作。发生中断时优先查看逐项明细，再在面板核实上次结果。标注 UTC 的时间按 UTC 记录；选版本的“最新”使用云盘显示的文件修改时间。

## 保存和追溯

每个阶段导出一个新文件，建议保留阶段顺序与日期，不覆盖唯一原件。报告包含目录、资源及操作信息，按个人资料保管。脚本不把登录凭据写入报告。

浏览器本地操作记录用于中断恢复，Excel 用于离线查询；两者不能互相替代。报告不验证视频内容或画质，也不是云盘完整备份。

第三脚本另提供独立的“复核阶段报告”，用于查看复核过程与拟清理计划，不替代阶段衔接用的原表更新报告。见[第三脚本使用说明](docs/03-review/usage.md)。

第二脚本 v1.4.0 增加资源覆盖与播出复核六列。确认连载且没有已提交/已有下载时标蓝；有下载任务时黄色优先，播出状态独立记录。仅最高集号不足不构成蓝色依据。


## 整理修复记录

②新增“整理修复状态、整理修复集号、整理修复时间、整理修复说明、整理修复记录”及必要续列；长记录分片保留。额外的“整理修复明细”逐文件记录旧历史快照、仅删除历史/复制整理的时间、结果和错误。不同于下载日志，删除历史成功不代表整理成功，整理返回成功不代表云盘补齐。③追加真实文件核查时间并确认集号，④据此阻止未完成修复的归档。


第四脚本 v1.4.0 将“删除源目录及已列多余资料”逐项展开，目标同名共用资料保持原样。源资料删除不是移动，不会被记作移动成功。
