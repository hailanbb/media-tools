## 功能与范围

手动选择分类，按云盘显示的目录修改时间从旧到新，逐剧、逐季核对集号。目录中的 TMDB ID 优先；来源不可用、异常或本季播完状态不明确时使用豆瓣。不移动、删除、重命名文件，不创建云端目录，不读取归档目标目录。

支持 `Season 1`、`Season 01` 等明确季目录，按集号集合判断完整性，不用视频文件数量代替集数。`麻辣教师 - S01E01 - 01.mkv` 中相同集号的重复表达可以识别。未知集号、重复集号、冲突数字、季内子目录和特别篇进入人工核实；不会猜测它们属于哪一集。

## 按钮与操作

| 按钮 | 作用 |
| --- | --- |
| 读取分类 | 读取 SOURCE 根目录下的分类。 |
| 开始检查 | 新建一轮分类检查；完成后停止。新一轮会替换保存的上一轮进度。 |
| 检查当前剧集 | 在手动打开的剧集/Season 路径基础上新建单剧检查；先导出旧结果。 |
| 暂停 / 继续本轮 | 保留已完成项目，当前中断剧集继续时重新核对。 |
| 恢复上次进度 | 刷新后从本机恢复已保存结果，恢复本身不启动查询。 |
| 仅补查豆瓣待处理项 | 手动开始补查待处理季，并重新读取该季文件；普通限速可排队等待。 |
| 绑定豆瓣链接 | 保存明确的详情页作为候选，不立即查询；仍需核对剧名、年份和季号。 |
| 强制重查此季豆瓣 | 跳过结果缓存及单条失败记录，仍遵守额度和风控冷却。 |
| 导出 Excel（绿 / 蓝标记） | 导出本轮全部结果，适合手工维护及交给第二脚本。 |
| 导出 CSV / 导出完整 JSON | CSV 不含颜色；JSON 包含待补查状态和诊断信息。 |

第一脚本自动保存本机进度；刷新后先“恢复上次进度”，再手动继续。恢复前需重新确认豆瓣可访问。面板仅显示最近 100 项，导出文件包含本轮全部项目。

## 来源集数、完结与缺集

- TMDB 按 ID 查询具体季，检查季号、登记集目和数量。登记集目均早于核对日，且具有已结束状态或季终依据，才支持“本季已播完”判断。当日、未来及日期未知集目不直接当作已播。
- TMDB 已确认本季播完且数量可用时，不因本地缺集/空目录额外查豆瓣。超出登记范围、来源异常、连载/状态不明或请求失败才触发备用/复核。
- 豆瓣匹配支持简繁中文、日文、韩文及英文的完整标题/明确别名，并校验年份、具体季及唯一候选。它不是自动翻译，也不按名称前缀猜剧。
- 豆瓣查询失败时，保留已经取得的 TMDB 集数与来源；查询失败不等于零集。不同来源数量或播出状态冲突时保留待核实，不直接标绿。
- 第一季已播完且齐全，即使电视剧还有续季，也可标绿。只有集数数字而没有播完依据时不能自动标绿。
- 空季确认成功后记录视频数/已识别数 `0/0`，仍查询来源。整个剧目录为空且没有季号时不猜第一季。读取失败保留未知数量，不当作空目录。

## 豆瓣补查与限速

初次扫描遇到限速时记录“豆瓣待补查”，继续其他剧集，**不会到时间后自行开始补查**。扫描结束后勾选“豆瓣已可访问”，点击“仅补查豆瓣待处理项”。补查后更新原记录，再导出新的 Excel；以前导出的文件不会自动改变。

| 控制 | 默认值 |
| --- | --- |
| 页面间隔 | 搜索和详情各计一页，至少间隔 45 秒 |
| 批次休息 | 每 20 页休息 10 分钟 |
| 滚动额度 | 近 1 小时 40 页；近 24 小时 200 页 |
| 结果缓存 | 已播完 30 天；连载/待播 6 小时；状态未确认 24 小时 |
| 单条失败 | 无匹配、详情不符、解析失败后，24 小时内不重复自动查 |
| 风控暂停 | 验证码、限流、拒绝访问至少冷却 30 分钟；页面要求更久时遵从 |

“打开豆瓣／登录准备”也计入页面额度。缓存按电视剧身份、年份和季号区分，缓存命中仍重新检查本地文件；报告注明缓存及原查询时间。过期缓存不用于直接标绿。普通明确网络错误最多延迟重试一次。

出现风控时，在已有豆瓣标签页手动完成登录/验证。冷却结束后勾选可访问，点击“人工确认豆瓣已恢复”，再点击补查。到期不会自动恢复，强制重查也不能绕过限制。

这些参数是脚本的保守默认值，不是豆瓣保证的安全额度；不能统计手动浏览、其他插件或其他脚本的请求。避免多个工具同时批量查豆瓣，不通过清空脚本存储规避额度。

## Excel 列与人工维护

### 绿色、蓝色和无填色分别表示什么

颜色只标在对应季的 **“剧集目录”单元格**，不是整行。第一脚本自动输出绿色或蓝色，其余情况保留无填色。

| 标记 | 判定含义 | 是否还可能缺集 |
| --- | --- | --- |
| 浅绿底 `C6EFCE`、深绿字 `006100` | 本季已确认播完，集号齐全且无待处理异常。 | 自动标绿时不缺集；第二脚本跳过。 |
| **浅蓝底 `BDD7EE`、深蓝字 `1F4E78`** | **有本季仍在播出的证据，播出状态为“连载中”。** | **可能缺已播集，也可能已播部分齐全。蓝色本身不代表齐全。** |
| 无填色 | 已播完但缺集、待播、状态未确认、来源信息不足或其他待核实情况。 | 阅读“缺失集号”“处理结果”和“核对说明”，不能只看颜色。 |

“尚未确认播完”不一定标蓝：只有明确判为“连载中”才标蓝；待播或播出状态未知不自动标蓝。蓝色行即使另有重复文件、待补查等问题，也应结合说明列判断。

对于蓝色行，请重点查看 **“已播集数核对”“缺失集号”“待播集号”“播期未知集号”**。例如本季登记12集、已播到第8集，本地缺第7、8集，第9—12集标为待播：该行可为蓝色，缺失集号是7、8，待播集号是9—12。

第二脚本**不会仅因蓝色而跳过**，它会根据报告检查已确认的缺集，排除待播和播期未知集目；提交下载成功后会按第二阶段规则标黄。第二脚本不实时重查播出进度，因此持续更新的剧集应先重新初检、导出最新报告，再补缺下载。

### 主要字段

| 字段组 | 用途 |
| --- | --- |
| 视频文件数 / 已识别集数 | 文件数量与去重后的已识别集号数量，二者可能不同。 |
| 来源登记集数 / 数据来源 / 来源链接 / 来源查询时间 | 查看数量来自哪里、何时查询。 |
| 缺失集号 | 排除已知待播及播期未知集目的缺集；“无”是已核对范围内不缺，“未确认”是不足以计算。 |
| 尚未收齐集号（含待播） / 待播集号 / 播期未知集号 | 分开看未收齐与尚未播出的集目。 |
| 已识别集号 / 重复集号 / 无法识别集号的文件 | 解释文件数量与集数为何不同。 |
| 集数核对 / 已播集数核对 / 播出状态 / 播出判定依据 | 完整性和是否播完分别记录。 |
| 处理结果 / 核对说明 | 查看待补查、错误、来源冲突及下次可尝试时间。 |
| 分类 / 剧集目录 / 季数 / 源链接 / 路径 / TMDB ID / 记录ID / 报告版本 | 用于后续脚本定位；不要随意改写。 |

可维护个人备注，并将人工确认完整且播完的季的“剧集目录”格改为普通实心绿。不要用条件格式、合并目录格或给身份字段写公式，第二脚本遇到无法可靠定位的行会拒绝处理。不要删掉报告中的机器记录列。

## 常见问题

**“超出来源登记集数：17”是什么？**

发现被识别为第 17 集的文件超出当前来源登记范围，不是多出 17 集。查看该文件名，核实特别篇、季号及来源集数；必要时补查豆瓣。

**目录手动能打开，为何“路径输入框未出现”？**

这是脚本切换路径时没能打开网页路径输入框，不等于目录不存在。v1.1.2 每次重新寻找可见可用控件，最多尝试三次；仍失败则暂停在当前剧集。关闭云盘弹窗、确认页面可操作，再点击“继续本轮”。旧版已跳过的失败记录可先导出旧报告，再手动进入该剧用“检查当前剧集”重查。

**同一部剧停留四秒是否卡住？**

非空列表需要连续稳定约 1.8 秒；剧目录和季目录两次读取约 3.6 秒，另有刷新、网络查询时间。短暂停留不等于卡死。长时间无变化时记录面板提示和完整错误，不要把未知数量手动填成零。

**豆瓣待补查在哪里看？**

面板待补查计数、对应季卡片，以及重新导出的 Excel“处理结果／核对说明／来源登记集数”等列。超过 100 项时以导出文件查看全量。

**没有 TMDB ID 或查不到集数？**

确认目录 ID 是电视剧 ID，季号对应正确。TMDB 无可用信息时尝试豆瓣；豆瓣也不可用则保持未知并说明原因。可绑定正确豆瓣详情后手动补查；绑定并不取消身份校验。

本脚本不读取视频内容、不测试播放质量；文件名、页面列表和来源信息是判断依据。界面结构、站点访问限制或来源缺数据可能导致待核实。

This product uses the TMDB API but is not endorsed or certified by TMDB.

## 面板拖动与收起

按住面板标题栏可拖动，展开和收起状态均可移动。点击“收起”时自动停靠页面右下角；点击“展开”恢复收起前的展开位置。收起后可再次拖走，但下次点击收起仍会重新停靠。各脚本分别记住位置和收起状态，窗口缩放时避免面板超出可视区域。收起只隐藏界面内容，不暂停、启动或取消任务；点击按钮不会触发拖动。

## 同版本补缺（初检 v1.2.0 / 下载 v1.3.0）

1. 用新版第一脚本重新初检并导出 Excel，报告会附带分片保存的“版本文件清单”（文件名、路径、大小及云盘修改时间）。也可以导入第三脚本最新导出的复核报告，优先使用其版本记录。
2. 第二脚本按第三阶段同一文件名模板分组，分别计算每个版本的缺集，不把不同版本拼起来当作齐全。
3. 已有一个完整版本时不再下载，标黄交第三脚本清理；多个完整版本交人工判断。
4. 均不完整时，优先选择搜索资源能补齐的版本；同一优先级按云盘显示的最新文件修改时间选择。仅能部分补齐时保持该版本，时间相同则交人工。
5. 资源站资源须与拟保留版本的发布组及已识别的分辨率、来源、编码、音频和 HDR 等标记一致。缺少唯一标识或无同版本资源时不自动换组；已存在的视频集不会为整季包重新下载。
6. 混版目录若已有本季下载任务或提交记录，先完成下载并交第三脚本重新复核，再计算新的版本缺集，避免不同版本记录抵扣集号。普通非混版的按集防重复不变。

拟保留版本、其缺集、云盘修改时间和选择依据写入“下载说明”及下载明细的“选择依据”。第二脚本不删除云盘混版文件，清理仍由第三脚本确认执行。

版本判断依据报告快照，不是 MoviePilot 中实时读取云盘。文件有变化时先重新检查导出报告。旧报告没有文件清单时无法可靠识别混版；已发现重复/混版迹象则提示重检，其他旧报告保持原普通缺集流程。文件已被重命名、发布组/技术标记丢失时不能猜测来源版本。CSV 不携带这一版的分片清单，阶段衔接请使用 Excel。
