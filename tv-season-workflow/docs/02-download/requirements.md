# 第二脚本需求：MoviePilot 补缺下载

需求整理日期：2026-10-21。对应发布版本：**v1.2.3**。

[工具首页](../../README.md) · [安装教程](../../INSTALL.md) · [操作说明](../02-download/usage.md) · [第一脚本需求](../01-inspect/requirements.md)

本文记录已经确认的下载需求、当前优先级及验收标准；不新增自动订阅、云盘写操作或额外资源筛选条件。

## 1. 目标与分工

读取第一脚本导出或人工维护的Excel，对非绿色、非已归档的电视剧季记录逐项检索MoviePilot，选择可确认的补缺资源，提交下载并导出更新报告。

第二脚本负责补缺下载及确认后的定向整理修复，不将下载提交视为入库，不删除多版本文件、不移动云盘剧集、不创建订阅。普通下载沿用现有配置；修复限定为单集复制整理。

## 2. 输入、启动与任务范围

| 编号 | 需求 |
| --- | --- |
| D-01 | 安装或刷新后默认不运行；导入Excel只生成队列，点击“开始补缺下载”或“继续本轮”才执行。 |
| D-02 | 跳过普通实心绿色目录格，以及紫色或文字明确已归档的记录；蓝色、红色、无填色及旧黄色项可检查，但不绕过防重复规则。 |
| D-03 | 校验分类、剧名、季号、路径与源链接一致。云盘地址和源根目录必须与第一脚本配置对应。 |
| D-04 | 来源登记集数必须有效。无已确认缺集的记录不下载；重复版本、播出状态不明不等于需要下载。 |
| D-05 | 排除来源明确的待播及播期未知集目。缺集范围不明确时只允许有完整证据的整季包，不猜零散集号。 |
| D-06 | 支持暂停、继续和导出。暂停后先记录已发请求结果，再停止后续提交。原Excel不直接覆盖。 |

当前接收不超过30MB的xlsx。CSV不保存阶段颜色，因此不作为下载输入。条件格式、合并目录格、关键身份字段公式、路径冲突或重复关键表头等无法可靠解释的内容须提示并拒绝自动处理；无关备注与公式保留。

## 3. 资源身份与基本资格

| 编号 | 需求 |
| --- | --- |
| D-07 | 优先按报告中的TMDB ID匹配；其次豆瓣ID；均无时才使用完整标题/原名和年份。 |
| D-08 | 支持简繁、全半角、不可见字符等文本标准化，但不凭模糊标题、任意译名或前缀相似下载。明确冲突ID不能被同名结果覆盖。 |
| D-09 | 同名同年结果对应多个媒体ID、身份不足或查询不完整时暂缓，不自动选做种数最高的不同剧集。 |
| D-10 | 资源须为当前电视剧的明确单季，覆盖集号可确认。错误季、混季、集号证据冲突及超出来源范围不得自动选择。 |
| D-11 | 资源须有可用下载入口、可确认的做种数，且做种人数至少2个。做种数未知不能视为满足要求。 |
| D-12 | 整季包必须覆盖来源登记的本季全部集号，或有与来源一致的“全N集”等明确证据；只有S01字样不足以证明完整。 |

## 4. 下载优先级

以下规则按顺序执行，不能把“小容量优先”放到媒体身份、季号和最低做种数之前。

### 4.1 先区分整季和零散集

| 编号 | 需求 |
| --- | --- |
| D-13 | 合格整季包优先。没有合格整季包时，允许单集或零散多集资源补缺。 |
| D-14 | 只选择能补上剩余缺集的资源；无关集不影响排序。已有成功提交的集目时，不重新选择整季包覆盖整季。 |
| D-15 | 每选择一个零散资源后重新计算剩余缺集，避免同一轮重复选择已经覆盖的集目。多集包可能附带已有文件，报告应如实显示覆盖范围。 |

### 4.2 同类优先明确中文标记

| 编号 | 需求 |
| --- | --- |
| D-16 | 同类候选中，优先有中文标签、中文字幕或中文配音明确标记的资源，例如中文、中字、简中、繁体字幕、国语、国配、CHS/CHT。 |
| D-17 | 标题/副标题中的明确字幕或配音说明可作为线索；仅剧名含汉字不算中文字幕证据。无中文、无字幕等否定或冲突标记不提升中文优先级。 |
| D-18 | 没有明确中文资源时，允许选择其他合格资源；“优先中文”不等于“仅允许中文”。 |

中文标记优先于同类资源的容量和做种排序，但不能绕过最低2个做种要求。当前按站点提供的标签及文本判断，不验证下载文件中字幕实际存在，也不推定所有双语或多语言资源都包含中文。

### 4.3 做种与容量的关系

| 编号 | 需求 |
| --- | --- |
| D-19 | 在同等中文条件下，先考虑做种不少于5个的候选。当前“5个以上”按**≥5，含5**实现。 |
| D-20 | 这一组候选容量均可确认时，优先容量较小者；相同容量再优先做种数多者。 |
| D-21 | 没有≥5候选时，在2—4个做种的合格候选中按做种数降序选择。 |
| D-22 | 高做种组存在未知容量时，整组退回做种数降序；未知容量不能视为零或最小值。 |
| D-23 | 整季包比较总容量；零散单集/多集包按“资源总容量÷本次能补上的缺失集数”估算单位成本，每次选择后重算。 |
| D-24 | 同分时采用稳定排序，避免仅因接口返回顺序改变而产生不同选择。 |

容量估算包含包内附带已有集的空间成本，不代表每集的实际大小，不承诺所有组合的全局最小下载量。不额外引入分辨率、编码、发布组或文件修改时间优先级；这些不属于本次第二脚本的已确认选择规则。

## 5. 提交、状态与防重复

| 编号 | 需求 |
| --- | --- |
| D-25 | 沿用MoviePilot默认下载器和自动保存目录，不修改下载器设置，也不把Excel源路径强行当作下载目录。 |
| D-26 | 每次提交前先持久保存准备记录。保存失败不提交；明确成功且有下载任务ID时才记录为已接受。 |
| D-27 | 开始前检查本地/报告记录及MoviePilot已有任务。已覆盖的集目不重复提交，已有本季任务但覆盖范围不明时也不能盲目追加。 |
| D-28 | 超时、响应缺少任务ID、刷新发生在提交期间等结果不明情况，保留记录并停止自动重试。 |
| D-29 | 人工确认任务确实失败或取消后，才能解除本地防重复记录；解除动作不取消真实下载，之后仍需手动开始。 |
| D-30 | 不读取、导出或另存登录令牌、Cookie及私密种子下载链接；使用页面已提供的API与认证环境。 |

## 6. 报告与追溯

| 编号 | 需求 |
| --- | --- |
| D-31 | 仅更新必要处理列及对应“剧集目录”格颜色；保留原备注、无关公式、超链接、其他工作表和已有明细。另存新报告。 |
| D-32 | 任务已接受或确认已有下载时标黄色，含义是等待下载与复核，不表示文件已齐全。部分成功应保留尚未覆盖集号。 |
| D-33 | 未找到合格匹配资源或匹配资源做种不足2时标红；登录、网络、信息不明或提交失败不冒充“无资源”。 |
| D-34 | 每个资源的下载明细记录剧名、季号、站点、查询时做种数、资源标题、覆盖集号及资源类型，明确区分“单季整包／单集／零散多集”。 |
| D-35 | 同时记录下载任务ID、执行状态、请求/发现时间、响应时间、容量、中文标记、选择依据和说明，供后续分析。 |
| D-36 | 未选定资源时，做种数显示“未选定资源”并说明原因；旧记录缺失则标为未记录，不填0。 |
| D-37 | 已有下载任务只在标题与站点唯一对应时引用本轮搜索做种数，并说明这不是原任务创建时的数量；无法确认时保留未知。 |
| D-38 | 机器记录过长时分列保存，不静默截断；新一轮导出新增明细快照，原明细保留，同一页面重复导出不反复叠加本轮页。 |

请求/响应时间按UTC标注，容量按字节记录。跨明细快照统计需结合任务ID、资源标识和时间去重，不能把多轮快照直接相加当作新增下载数。旧Excel不会自动回填。

## 7. 界面、兼容性与边界

- 深色网站中按钮及说明须清晰可读；v1.2.2保持面板自带浅色配色，明确普通、禁用按钮和键盘焦点样式。
- 依赖当前MoviePilot前端提供的MoviePilotAPI；缺少接口时提示兼容性问题，不以粘贴凭据绕过。
- 整轮Excel会话保存在页面内存，刷新前需导出；下载防重复记录跨刷新保留。更换浏览器或清除脚本存储可能失去记录。
- 资源范围取决于已配置且当时可用的站点。提交成功、资源标签和文件名都不能保证实际下载完成、字幕存在或视频质量。

## 8. 关键验收场景

| 场景 | 应有结果 |
| --- | --- |
| 安装、刷新、导入Excel | 不自动发起搜索或下载；等用户点击开始。 |
| 一季绿色或明确已归档 | 跳过。 |
| 只有普通S01标题，没有整季集号证据 | 不当作完整包。 |
| 无合格整季包，有合格单集 | 允许逐集补缺。 |
| 同样有中文字幕：50做种/30GB与5做种/10GB | 优先5做种/10GB。 |
| 同样有中文字幕：50做种/30GB与4做种/10GB | 优先50做种/30GB。 |
| 同类2做种中文资源与100做种无中文标记资源 | 中文资源优先；中文资源只有1做种时不合格。 |
| 高做种候选中有未知容量 | 按做种数比较，不把未知当作0。 |
| 1.2GB包补两集，两个单集各0.8GB，中文及做种条件相同且满足容量比较 | 优先1.2GB双集包，记录每个待补集估算0.6GB。 |
| 提交请求超时或缺少任务ID | 保留结果待核实，不自动重试。 |
| 无需下载或来源未确认，未选定资源 | 不提交；做种数显示未选定资源并说明原因。 |
| 原报告有人工备注、公式和旧明细页 | 导出后保留，必要处理结果单独更新。 |
| 网站启用深色模式 | 普通/禁用按钮文字均可读，操作逻辑不变。 |

当前验证包括模拟接口、页面控件及XLSX读写；不将本地测试通过等同于所有部署都已完成真实下载验证。

## 面板交互补充需求

按住面板标题栏可拖动，展开和收起状态均可移动。点击“收起”时自动停靠页面右下角；点击“展开”恢复收起前的展开位置。收起后可再次拖走，但下次点击收起仍会重新停靠。各脚本分别记住位置和收起状态，窗口缩放时避免面板超出可视区域。收起只隐藏界面内容，不暂停、启动或取消任务；点击按钮不会触发拖动。

验收：任意位置收起后停靠右下角；展开恢复原位置；缩放窗口仍可见；刷新恢复布局但不自动启动任务；拖动标题栏不触发下载或云盘操作。

## v1.2.3：下载管理优先核查

搜索资源前先读取下载管理；每个资源提交前再次读取，防止搜索期间出现的新任务被重复提交。同剧同季任务有明确集号时扣除覆盖范围，只补剩余集，且不选择与已有任务重叠的资源；范围不明确则本季不追加。其他剧或其他季不阻止本季补缺。下载管理读取失败时不提交。

例如缺第2、4集，而第2集已在下载：只选择第4集，不再下第2集或含第2集的整季/多集包。已有任务及本轮新提交在下载明细中分别记录，已有任务的低做种数不会导致防重复检查失效。下载失败或取消后，仍需人工核实再解除本季防重复记录。

## 同版本补缺（初检 v1.2.0 / 下载 v1.3.0）

1. 用新版第一脚本重新初检并导出 Excel，报告会附带分片保存的“版本文件清单”（文件名、路径、大小及云盘修改时间）。也可以导入第三脚本最新导出的复核报告，优先使用其版本记录。
2. 第二脚本按第三阶段同一文件名模板分组，分别计算每个版本的缺集，不把不同版本拼起来当作齐全。
3. 已有一个完整版本时不再下载，标黄交第三脚本清理；多个完整版本交人工判断。
4. 均不完整时，优先选择搜索资源能补齐的版本；同一优先级按云盘显示的最新文件修改时间选择。仅能部分补齐时保持该版本，时间相同则交人工。
5. 资源站资源须与拟保留版本的发布组及已识别的分辨率、来源、编码、音频和 HDR 等标记一致。缺少唯一标识或无同版本资源时不自动换组；已存在的视频集不会为整季包重新下载。
6. 混版目录若已有本季下载任务或提交记录，先完成下载并交第三脚本重新复核，再计算新的版本缺集，避免不同版本记录抵扣集号。普通非混版的按集防重复不变。

拟保留版本、其缺集、云盘修改时间和选择依据写入“下载说明”及下载明细的“选择依据”。第二脚本不删除云盘混版文件，清理仍由第三脚本确认执行。

版本判断依据报告快照，不是 MoviePilot 中实时读取云盘。文件有变化时先重新检查导出报告。旧报告没有文件清单时无法可靠识别混版；已发现重复/混版迹象则提示重检，其他旧报告保持原普通缺集流程。文件已被重命名、发布组/技术标记丢失时不能猜测来源版本。CSV 不携带这一版的分片清单，阶段衔接请使用 Excel。

## v1.4.0：资源覆盖差异与播出状态复核

当本轮搜索到的同剧同季资源最高集号低于报告登记总集数时，第二脚本通过 MoviePilot 的只读媒体详情与指定季集目接口复核 TMDB 播出信息，沿用当前页面认证，无需另填密钥，也不直接批量请求豆瓣。

- “最高42、登记100”仅代表资源覆盖差异，不能证明1～42全部有资源，也不能单独证明连载。
- 本季已有已播集，并有明确未来集目或同季下一集播期：确认连载；没有成功/已有下载任务时目录格为浅蓝底 BDD7EE、深蓝字 1F4E78。
- 已提交或已有下载任务仍以黄色为准，保持第三脚本的复核入口；本次有明确连载依据时原“播出状态”同步为“连载中”。
- 来源确认已完结，视为资源不全；来源不足、其他季续订或状态冲突不自动改蓝。来源查询失败时可沿用原报告明确结论，但注明本轮没有刷新来源。
- 来源复核确认的未来集、播期未知集不参与本轮自动补缺；不能仅凭资源存在推断已经播出。

导出增加：资源站最高集号、资源站覆盖集号、资源站查询时间、播出状态复核、播出复核依据、播出复核来源。此处来源登记总数仍保留原报告（例如豆瓣100集），不会用资源站42覆盖它。未执行新搜索的已有任务不伪造新查询时间，保留原有审计字段。

下载管理已覆盖缺集、报告没有缺集等无需搜索的情况，仍直接跳过，不额外为颜色发起搜索。缺少TMDB ID或接口不可用时，不能自动取得新播出证据，应由第一脚本补查来源。

接口依据：[MoviePilot媒体详情](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/media.py)、[指定季集目](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/tmdb.py)。


## v1.5.0：旧整理历史阻挡修复

- 检查、执行、只读核实三个入口分离；导入默认停止，写操作必须确认具体清单及下载完成。
- v2.15.6 版本检查，严格 TMDB/季/集、历史 ID、源存储/路径和预览目标匹配；分页完整才使用历史。
- 删除前保存白名单历史快照，只调用历史删除且 deletesrc=false、deletedest=false。禁止文件删除、全局重整、logid 重整或 reorganize。
- 写请求只提交一次，结果不明持久保存并禁止重复；下载取消确认不能解除整理修复状态。
- 报告记录源、目标、历史 ID、每个操作时间及结果；第三脚本确认实际文件后才能解除归档阻挡。
