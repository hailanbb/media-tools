## 点哪里，什么时候真正下载

1. 登录 MoviePilot，确认站点、默认下载器及自动保存目录已经正常配置。
2. 点击“导入 Excel”，选择第一脚本导出或人工维护的 `.xlsx`，最大 30 MB。导入只排队；看到“尚未执行”是正常的。
3. 查看非绿色项数量、跳过项及错误信息。修正源链接、季号或来源数量不明的行后再重新导入。
4. 点击 **“开始补缺下载”**。此时才开始查找资源、检查现有任务并提交下载，不会再逐资源弹窗确认。
5. 需要停下时点“暂停”，当前已发出的请求会先记录结果。点“继续本轮”才继续。
6. 完成或暂停后点击“导出更新报告”，另存为 `_下载补充.xlsx`。刷新前先导出；原文件不会被覆盖。

下载使用 MoviePilot 的默认下载器与自动目录，不创建订阅、不修改下载器设置，也不直接写云盘文件。脚本所需的 `MoviePilotAPI` 由页面提供，身份认证沿用页面，不需要在脚本里填写登录令牌。

## 哪些行会进入任务

- 跳过“剧集目录”格为绿色、归档紫色或文字标明已归档的行。蓝色、红色、无填色和旧黄色行会检查；有下载记录时仍防重复。
- 必须有有效来源登记集数；没有已确认缺集时不下载。重复版本或状态待核实，不等于需要重新下载。
- 路径、分类、剧名、季号和源链接必须相互对应。第二脚本的 CLOUD 与 SOURCE 必须和第一脚本一致。
- 待播及播期未知的集目不下载。缺集范围未知时，只允许明确完整包，不猜零散集号。
- 条件格式、合并目录格、身份/来源字段公式或重复关键表头会拒绝处理，保留并提示原因。

## 如何选资源

先确认媒体身份：报告中的 TMDB ID 优先，其次豆瓣 ID，均无时才用完整标题/原名与年份。名称统一简繁、全半角和不可见字符，不把任意译名或前缀相似认成同剧。明确冲突 ID 不会被同名结果覆盖；同名同年多个媒体 ID 时暂缓。

每个资源还需确认电视剧类型、**当前单季**、明确覆盖集号、有效下载入口及至少 2 个做种。混季、错误季、集号冲突、做种未知不自动选择。只有 `S01` 不代表整季；需明确集号覆盖，或“全 N 集”与来源数量一致。

### 优先级从上到下

1. **完整季包优先**。没有合格整季包时才使用零散单集或多集资源。已有成功提交的集目时不再改下整季包。
2. **同类优先中文标记**。支持中文、中文字幕、中字、简中、繁体字幕、国语、国配、CHS/CHT 等明确标签，也读标题/副标题中的明确字幕或配音说明。中文片名不代表有字幕；“无中文字幕”“No Chinese subtitles”等否定或冲突标记不提升优先级。标记来自站点声明，不是实际媒体验证。
3. **同等中文条件下优先≥5个做种的候选**。5 个算达到阈值；2—4 个做种的资源不会仅因更小抢占这一组。
4. **这一组容量全部已知时优先小容量**。整季比较总容量；零散多集比较 `总容量 ÷ 本次能补上的缺失集数`。选完一个资源后，重新计算剩余缺集与成本；容量相同再看做种数。
5. **没有≥5候选，或高做种组存在未知容量时，按做种数从多到少**。未知大小不是零。仍同分时采用稳定排序，避免仅因接口返回顺序变化而改变结果。

例如，同样带中字标签的两个整季包：A 为 50 做种 / 30 GB，B 为 5 做种 / 10 GB，优先 B。若 B 只有 4 做种，优先 A。同类中有 2 做种的明确中文资源、另一资源无中文标记且 100 做种时，中文资源优先；没有中文资源时仍可选择其他合格资源。

零散集的容量是成本估算：1.2 GB 的双集包补两集，估算每集 0.6 GB，优于各 0.8 GB 的两个单集包。包内附带已有集的空间也计入成本。它不是每一集的真实大小，也不保证所有资源组合的全局最小容量。

## 报告与颜色

| 状态 | “剧集目录”格 | 应怎么理解 |
| --- | --- | --- |
| 已接受下载且返回任务 ID | 黄底黑字 | 请求已被 MoviePilot 接受，仍需等实际下载并复核。 |
| 本季已有任务 | 黄底黑字 | 本轮没有重复提交，等待现有任务完成。 |
| 只覆盖部分缺集 | 黄底黑字 | 查看“下载未覆盖集号”，剩余集目仍未补上。 |
| 无匹配资源 / 做种不足2 | 浅红底深红字 | 当前可用站点未找到合格资源，不代表互联网都没有。 |
| 网络、登录、身份不明、拒绝提交、结果未知 | 保留原色 | 阅读说明，不能冒充“无资源”或“下载成功”。 |

原表追加：下载处理、下载资源、下载任务ID、下载覆盖集号、下载未覆盖集号、下载时间、下载说明、下载记录及必要续列。人工备注、无关公式、原链接和其他工作表保留。

每轮另加可筛选的 **“下载明细_N”** 工作表：报告位置、剧名、季号、单季整包/单集/零散多集、集号、站点、做种数、资源标题、任务 ID、请求/发现时间、响应时间、说明、资源容量、每个待补集估算容量、中文标记、选择依据、做种数说明。

时间标为 UTC，中国时间需加 8 小时。容量单位为字节，除以 `1024³` 可换算 GiB。整季资源按总容量比较，不填单集估算。做种数是查询时快照，不是当前实时值。

### 为什么做种数为空或“未选定资源”

旧版对“无需下载／待核实”且未选定资源的行留空；v1.2.2 改为“未选定资源”，旁边写明原因。已选定资源的旧记录缺失字段时显示“未记录”，不能当作 0。已有下载任务只有在资源标题和站点唯一匹配时才引用本轮搜索做种数，不将它冒充原任务创建时的数量。旧 Excel 不会自动回填。

明细是本轮快照，重新导入后保留旧页，再增一页；同一页面重复导出不会重复叠加本轮页。跨快照统计时按任务 ID、资源标识和请求时间去重，不要直接把所有页行数相加当作下载次数。机器记录续列必须完整保留，不能截断。

## 防重复与失败恢复

提交前先保存本地记录，随后才发送请求；只有成功响应及任务 ID 才认定接受。开始前也会检查 MoviePilot 已有下载任务。暂停、重新导入旧报告不会跳过这些保护。

超时、刷新发生在提交途中、响应没有任务 ID 等情况，可能已经下载成功；脚本会停止重复提交。先在 MoviePilot/下载器核实，不能靠清空浏览器存储重试。

确认原任务都失败或取消后，使用对应行的“核实任务已取消，解除本季防重复”。该按钮仅解除本地记录，不会取消真实下载；之后需要再手动开始/继续。若旧 Excel 仍包含原下载记录，先按核实结果维护报告，避免又导入旧记录。

第二脚本的整轮 Excel 只在当前页面内存中，刷新前应导出；下载防重复记录跨刷新保留。换浏览器、卸载或清除脚本数据可能失去本地记录，应保留报告并核实下载器现状。

## 常见问题

**找不到 MoviePilotAPI**：当前前端未提供所需页面接口，检查部署兼容性。不要通过写入登录 Cookie/令牌绕过。

**源链接不一致**：核对两脚本 CLOUD_ORIGIN/CLOUD、SOURCE，以及报告是否来自同一云盘；不要随意改动报告路径或季号。

**来源登记集数未确认**：回第一脚本补查并导出新报告；不能按视频文件数猜总集数。

**有资源却未下载**：检查媒体 ID、季号、集号、待播状态、做种数、已有任务及说明。中英文片名相似不能取代身份校验。

**已下载却还是黄色**：黄色表示已提交/已有任务，不代表实际入库；可用下方整理修复功能检查历史阻挡，最终交第三脚本复核。

## 接口与验证范围

使用 MoviePilot 页面 API；参考 [前端插件接口](https://github.com/jxxghp/MoviePilot-Frontend/blob/v2/src/api/index.ts)、[搜索接口](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/search.py)、[下载接口](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/download.py)。页面及接口升级可能需要适配。

本地测试使用模拟搜索、下载接口和 XLSX 文件，验证过程中没有向真实下载器提交任务。用户部署环境与默认下载/整理目录需自行确认；脚本不保证下载到的文件质量或字幕实际存在。

## 面板拖动与收起

按住面板标题栏可拖动，展开和收起状态均可移动。点击“收起”时自动停靠页面右下角；点击“展开”恢复收起前的展开位置。收起后可再次拖走，但下次点击收起仍会重新停靠。各脚本分别记住位置和收起状态，窗口缩放时避免面板超出可视区域。收起只隐藏界面内容，不暂停、启动或取消任务；点击按钮不会触发拖动。

## v1.2.3：下载管理优先核查

搜索资源前先读取下载管理；每个资源提交前再次读取，防止搜索期间出现的新任务被重复提交。同剧同季任务有明确集号时扣除覆盖范围，只补剩余集，且不选择与已有任务重叠的资源；范围不明确则本季不追加。其他剧或其他季不阻止本季补缺。下载管理读取失败时不提交。

例如缺第2、4集，而第2集已在下载：只选择第4集，不再下第2集或含第2集的整季/多集包。已有任务及本轮新提交在下载明细中分别记录，已有任务的低做种数不会导致防重复检查失效。下载失败或取消后，仍需人工核实再解除本季防重复记录。

## 同版本补缺（初检 v1.2.0 / 下载 v1.3.0）

1. 用新版第一脚本重新初检并导出 Excel，报告会附带分片保存的“版本文件清单”（文件名、路径、大小及云盘修改时间）。也可以导入第三脚本最新导出的复核报告，优先使用其版本记录。
2. 第二脚本按第三阶段同一文件名模板分组，分别计算每个版本的缺集，不把不同版本拼起来当作齐全。
3. 已有一个完整版本时不再下载，标黄交第三脚本清理；多个完整版本交人工判断。
4. 均不完整时，优先选择搜索资源能补齐的版本；同一优先级按云盘显示的最新文件修改时间选择。仅能部分补齐时保持该版本，时间相同则交人工。
5. 资源站资源须与拟保留版本的发布组及已识别的分辨率、来源、编码、音频和 HDR 等标记一致。缺少唯一标识或无同版本资源时不自动换组；已存在的视频集不会为整季包重新下载。
6. 混版目录若已有本季下载任务或提交记录，先完成下载并交第三脚本重新复核，再计算新的版本缺集，避免不同版本记录抵扣集号。普通非混版的按集防重复不变。

拟保留版本、其缺集、云盘修改时间和选择依据写入“下载说明”及下载明细的“选择依据”。第二脚本不删除云盘混版文件，清理仍由第三脚本确认执行。

版本判断依据报告快照，不是 MoviePilot 中实时读取云盘。文件有变化时先重新检查导出报告。旧报告没有文件清单时无法可靠识别混版；已发现重复/混版迹象则提示重检，其他旧报告保持原普通缺集流程。文件已被重命名、发布组/技术标记丢失时不能猜测来源版本。CSV 不携带这一版的分片清单，阶段衔接请使用 Excel。

## v1.4.0：资源覆盖差异与播出状态复核

当本轮搜索到的同剧同季资源最高集号低于报告登记总集数时，第二脚本通过 MoviePilot 的只读媒体详情与指定季集目接口复核 TMDB 播出信息，沿用当前页面认证，无需另填密钥，也不直接批量请求豆瓣。

- “最高42、登记100”仅代表资源覆盖差异，不能证明1～42全部有资源，也不能单独证明连载。
- 本季已有已播集，并有明确未来集目或同季下一集播期：确认连载；没有成功/已有下载任务时目录格为浅蓝底 BDD7EE、深蓝字 1F4E78。
- 已提交或已有下载任务仍以黄色为准，保持第三脚本的复核入口；本次有明确连载依据时原“播出状态”同步为“连载中”。
- 来源确认已完结，视为资源不全；来源不足、其他季续订或状态冲突不自动改蓝。来源查询失败时可沿用原报告明确结论，但注明本轮没有刷新来源。
- 来源复核确认的未来集、播期未知集不参与本轮自动补缺；不能仅凭资源存在推断已经播出。

导出增加：资源站最高集号、资源站覆盖集号、资源站查询时间、播出状态复核、播出复核依据、播出复核来源。此处来源登记总数仍保留原报告（例如豆瓣100集），不会用资源站42覆盖它。未执行新搜索的已有任务不伪造新查询时间，保留原有审计字段。

下载管理已覆盖缺集、报告没有缺集等无需搜索的情况，仍直接跳过，不额外为颜色发起搜索。缺少TMDB ID或接口不可用时，不能自动取得新播出证据，应由第一脚本补查来源。

接口依据：[MoviePilot媒体详情](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/media.py)、[指定季集目](https://github.com/jxxghp/MoviePilot/blob/v2/app/api/endpoints/tmdb.py)。


## 下载好了但网盘仍缺集：整理修复

适用于 MoviePilot **v2.15.6** 中“同一下载文件已有整理历史，自动整理跳过”的情况。此功能不诊断上传链路，也不批量清空历史。

1. 先用第一或第三脚本获取 **24 小时内**的文件检查报告，确认具体缺失集号。已有的“扫描时间”可直接使用，第一脚本无需升级。
2. 导入第二脚本，点击 **检查整理问题**。此时只查询和预览，不删除记录、不重新整理。
3. 展开每部剧的“整理修复清单与记录”，核对缺哪集、下载源文件、目标文件及历史记录 ID。
4. 在下载器确认清单中的资源已下载完成，再点 **修复整理** 并确认清单。下载管理接口只显示正在下载的任务，任务消失不能证明完成，因此保留这一人工确认。
5. 脚本重新核对后，保存旧记录快照，只删除对应整理历史，随后从当前下载文件发起单集复制整理。源文件和旧目标文件不删除，不使用旧历史的“重新整理”入口。
6. 点击 **导出更新报告**，交第三脚本复核。整理请求成功仍是黄色；实际集号到位、整季完整及版本等原有条件通过后才转绿。

如提示“结果待核实”，点击 **核实修复结果**。该按钮只查新的成功历史、整理队列和目标文件，不重发请求。没有充分证据时仍保留待核实，需要在 MoviePilot 人工检查，不能用“解除下载防重复”按钮清除修复状态。暂停后可重新点击“检查整理问题”；已提交项不会重复整理。

### 安装时的两个额外目录

第二脚本源码顶部的 REPAIR_CONFIG 使用 **MoviePilot 文件管理中的路径**，不填网页链接或 CloudDrive2 路径。示例：

```javascript
const REPAIR_CONFIG={source:'/video/downloads/电视剧',target:'/video/link/电视剧'};
```

source 是下载源根目录；target 是整理后的电视剧根目录。目标下面必须已有对应分类；预览路径必须与报告的分类、剧名、季号一致。目录名不一致时交人工核实，不猜测合并。

### 会暂缓的情况

- 缺少 TMDB ID、缺集不明确、报告过期，或源文件不存在。
- 同集存在多条候选历史、跨集视频、自定义剧集组、非 local 存储。
- 报告存在混版或已有完整版本：先交第三脚本明确版本，不通过旧历史盲目补入另一版本。普通补缺下载仍保留原有的版本选择规则。
- 本季仍在下载或整理，文件大小/时间变化，预览识别不一致。
- 目标已有同集/同名视频或无法确认集号的文件；先交第三脚本复核。
- 历史查询不完整、权限不足、版本不符，或删除/整理请求结果不明。

本次自动整理只复制缺失的单集视频，不同步附加文件、不启用刮削或旧目标重整，以免影响已有图片、NFO 和字幕。需要补刮削时单独在 MoviePilot 处理。所有检查、旧历史快照和操作状态均写入“整理修复明细”及主表的修复记录列，原下载日志保留。
