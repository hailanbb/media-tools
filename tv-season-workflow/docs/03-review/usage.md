# ③ 复核清理 · 使用

[项目首页](../../README.md) · [需求](requirements.md) · [安装](install.md)

## 按顺序操作

1. 等 MoviePilot 完成下载和整理，打开已登录的 CloudDrive2，启用第三脚本。
2. 点击 **导入 Excel，选择黄色项**，选择最新报告。此时只排队，不读取或删除云盘文件。
3. 点击 **打开豆瓣／登录准备**，在豆瓣手动完成登录或验证，返回后勾选可以访问。
4. 点击 **开始复核**；暂停后点 **继续复核**。运行时保持工作标签页，不手动切换云盘目录。
5. 展开每季结果，查看豆瓣对应季、集数、完整版本、保留文件与拟删除文件。匹配错误时可填写正确豆瓣详情链接，点击 **绑定豆瓣详情并重查**，再继续复核。
6. 如有可执行清理计划，逐项检查后点击 **执行已列清理清单**，再确认弹窗中的季数、文件数和普通删除范围。复核本身不会删除文件。
7. 点击 **导出复核清理报告**，保存新文件；检查主表颜色与新增的清理明细工作表。

## 如何理解结果

| 情况 | 处理 |
| --- | --- |
| 已确认播完、齐全且没有待处理异常 | 可标绿并交第四脚本 |
| 一个完整版本，另有归属明确的多余文件 | 生成清理计划；确认执行并验证后再判断绿色 |
| 两个或更多完整版本 | 标记人工判断，脚本不替你选一个删除 |
| 只有多个不完整版本拼起来齐全 | 不自动删除混版，保留待核实 |
| 豆瓣匹配失败、集数不明或访问限制 | 保留问题说明；修正匹配或恢复访问后再复核 |
| 删除请求已发出但结果不明 | 使用 **核实上次删除结果**；不要清空本机记录后重试 |

“日期最新”指云盘列表显示的文件修改时间。脚本不检查视频画质或真实播放内容；文件名无法区分版本时留给人工判断。

暂停会等待已发出的删除完成核实，再停止后续操作。刷新后重新导入对应报告，按面板提示核实上次操作。完整字段见[报告与追溯](../../REPORT.md)。


## v1.1.3：文件列表可用性判定修复

顶部的 “Disconnected / Connecting…” 不再作为停止条件。脚本按刷新后的路径、分页、数量及稳定列表判断是否可读取，与第一脚本采用相同的列表判断基础。确有列表加载错误或超时时暂停当前项，恢复后点击继续，后续剧集不会被批量写入同一错误。

升级旧版时先保存报告，在 Tampermonkey 中替换同阶段脚本并保留个人地址配置，刷新网页、重新导入报告，再点击开始。旧页面已经写出的错误不会自动消失；重新复核会更新相应报告项。执行删除/移动仍须核对具体清单并确认，操作前后核实保留。

## v1.1.4：缺少目录时继续复核

第三脚本在只读复核时，页面明确提示本季目录不存在，会记录“目录不存在，已跳过”及路径、具体错误，并继续下一剧集。原颜色保持不变，视频数量未知，不填0、不查询该缺失目录的豆瓣，也不生成删除计划。修正路径或补齐目录后可重新复核。

权限、网络、超时或无法确定原因的错误仍暂停；删除、移动及其结果核实期间不会把目录不存在当作可跳过或成功。第四脚本仅同步共享模块，归档仍保留暂停核实规则。

### v1.1.5 补充

已覆盖 CloudDrive2 实际的“路径未找到”和 `get_subfiles … not found … under …` 提示。当前季或祖先剧目录明确缺失时，只读复核记录跳过并继续；加载中的上一目录错误不作为当前结果。

## v1.2.0：“复核阶段报告”按钮

点击开始复核后，任务结束或暂停时，可点击 **复核阶段报告**，另存为“原文件名_复核阶段报告.xlsx”。报告包含：

- 复核概况：原报告、开始/结束时间、状态、黄色项数量及尝试次数。
- 逐项复核：目录和季号、每次起止时间、结束环节、结果、豆瓣集数和链接、视频/集号数量、缺集、拟保留版本及原因。
- 版本分析：每个版本的完整性、已有/缺失集号、最新云盘修改时间。
- 文件计划：拟保留视频、拟删除文件及保留配套文件的路径、大小、修改时间和理由。

同一季暂停后继续或重新复核，会保留每次尝试。阶段报告是只读复核快照，后续清理不会把其“拟删除”改成“已删除”。它不替代更新原表颜色和记录实际删除结果的 **导出复核清理报告**，也不作为下一阶段的输入报告。

未开始复核时按钮禁用；运行中需先暂停再导出。时间列标为UTC。记录仅保留在当前页面内存，刷新或重新导入报告前应先导出；重新导入会重置阶段记录，旧版已完成的过程不能补录。

## v1.3.0：按季批量清理

“执行已列清理清单”现在按同一季多选普通文件并批量删除，每批最多50个，超过自动拆批。视频及已确认唯一归属的NFO/图片一起进入清单；不使用网页全选，不扩大已确认范围。

每批提交前核对完整目录快照、实际多选集合、确认窗口的全部文件名称和大小。确认窗口没有完整列出本批文件时不提交，保留错误供核实。删除后统一核对目标消失且保留文件未变，报告仍逐文件记录批次编号、原路径、属性、理由、时间和结果。

部分成功时，已确认消失的文件记成功，剩余文件记待核实，不自动重发整批。使用“核实上次删除结果”检查批次，并在确认没有在途删除后逐文件记录，再重新复核。仍兼容旧版单文件待核实记录。暂停会先核实已发出的当前批次，再停止后续批次。

## v1.3.1：清理执行独立暂停与继续

“执行已列清理清单”旁新增 **暂停执行 / 继续执行**：

- 暂停执行仅在清理运行中可用；点击后不再提交后续批次，已经发出的当前批次先完成结果核实。
- 清理暂停且没有待核实请求时，继续执行可用；沿用本次已确认的计划，只处理尚未删除的文件，不重复确认相同清单。
- 批次响应未知或部分成功待核实时，继续执行禁用，先使用“核实上次删除结果”，然后重新复核生成清单。
- 原“暂停 / 继续复核”用于只读复核，清理运行中原暂停按钮禁用，避免混淆。
- 本次继续队列保存在当前页面；刷新/升级或重新导入后需要重新复核。跨刷新删除记录仍保留用于核实、防重复；不会自动继续删除。

重新复核生成的新计划不会混入原暂停队列，须按新的清单执行确认。暂停后可导出复核清理报告查看已完成批次。


## v1.4.0：整理修复报告联动

导入第二脚本修复后的黄色报告，正常点击“开始复核”。脚本实际读到修复集号后记录“云盘文件已复核”；整季齐全、播完、版本清理等原有条件仍须满足才标绿。仍缺集或修复操作结果不明时，暂缓本季清理，不自动删除文件；将报告交回第二脚本核实。不要丢弃或手工清空修复记录列。


## v1.4.1：每次删除后刷新

单文件或批量删除返回后，先在当前季目录点击页面刷新，等待加载结束，再继续核对删除结果或进入下一批。刷新失败保留结果待核实，不重复删除。
