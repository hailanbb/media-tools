## 🌟 平台核心定位与价值

在传统的云盘影视库管理中，影视发烧友与家庭 NAS 管理员长期面临四类致命痛点：
1. **元数据撕裂与集数失真**：TMDB 众包数据常将华语综艺拆分为上下集（如 10 期拆成 21 集），而豆瓣与官方流媒体则按整期发布（10 集），导致影视管理软件频报大面积缺集或失真冲突；
2. **花絮切片污染正片**：压制组发布的“短视频切片”、“母带（Tape/Cut）”、“纯享版”等外围短视频，极易被错误识别为正片超高集号（如 S01E37），击溃全剧归档判定；
3. **物理误删与孤本覆灭**：简单的“按目录名匹配”清理极易把含有增量未归档新集的源端文件夹误删，造成不可逆的视频资产损失；
4. **人工运维成本高昂**：海量订阅停滞、卡滞转移队列、跨库集数差异核对等杂务消耗海量精力。

**MediaFlow** 应运而生。它不是简单的文件搬运工具，而是一个集成了 **智能集号/分段解析引擎**、**TMDB & 豆瓣双轨自适应拟合**、**断崖异常集号剥离**、**P0 级跨库集数差分物理安全门禁** 以及 **MoviePilot 运维双轨治理** 的全闭环智能工作台。

## ⚡ 快速上手与多平台部署

MediaFlow 提供 **Docker 容器化** 与 **Windows 原生免环境运行** 两种部署形态，底层业务逻辑与单元测试 100% 保持一致。

### 🐳 方案 A：Docker 容器一键部署（推荐 NAS / Linux 服务器）

进入 [`mediaflow-docker/`](mediaflow-docker/) 目录：

```bash
# 1. 克隆代码仓库
git clone https://github.com/hailanbb/media-tools.git
cd media-tools/mediaflow-docker

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 文件，填入 CloudDrive2 与 MoviePilot 连接凭据
vim .env

# 3. 一键启动容器
docker compose up -d

# 4. 浏览器访问工作台
# http://<服务器IP>:8080
```

### 🪟 方案 B：Windows 原生便携运行（推荐 PC / 本地主机）

进入 [`mediaflow-win/`](mediaflow-win/) 目录：

```powershell
# 1. 进入目录并配置环境变量
cd media-tools/mediaflow-win
copy .env.example .env
# 使用记事本或 VS Code 填入 .env 密钥配置

# 2. 安装依赖并启动
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8080
```

> [!TIP]
> 详细跨端环境与代码同步指引，可参阅 [版本管理与跨端同步说明 (VERSIONING.md)](mediaflow-win/VERSIONING.md)。

## 🎯 六大核心技术特性

### 1. 综艺分段与复杂命名智能解析 (`segments.py` & `episode_parser.py`)
- **多段正片原生覆盖**：全面解析 `PartA/PartB`、`Part01/Part02`、`上/下期`、`上/中/下` 等复杂分段，按实际播出期数建立精确覆盖映射，杜绝上下集综艺误报缺集；
- **全方位花絮切片拦截**：深度拦截 `Cut`、`Clip`、`Tape`、`母带`、`切片`、`看点`、`片段`、`纯享版`、`加更版` 等 18+ 模式衍生短视频，纯净提炼正片序列；
- **作品标题遮蔽保护**：智能区分作品原名中的关键词（如《Hot Ones: Extra Heat》），避免剧名本身包含“Extra”或“纯享”时被误杀为花絮。

### 2. TMDB & 豆瓣双轨自适应拟合 (`inspector.py`)
- **彻底打破单源垄断**：华语剧集/综艺初检时，主动并行拉取 TMDB 与豆瓣双源元数据；
- **双重播出版型自适应选型**：
  - 本地为 **整期版（~10集）**：自动拟合豆瓣 10 期权威口径，主动排除 TMDB 21 集上下拆分版干扰；
  - 本地为 **拆分版（~21集）**：自动适配 TMDB 拆分编号；
- **正片全齐附带特辑直接就绪**：官方正片已齐前提下，连续 1~3 集收官特辑/加更篇自动容纳，直接归为 `archive_ready`。

### 3. 断崖孤立异常集号智能剥离 (`separate_outliers`)
- 当识别集号序列中出现断崖式跳空且无后续文件（如正片 1..12 集后突兀出现单个 143MB 的孤立 E56），算法自动将其剥离为外围衍生集；
- 避免因压制组命名随意导致的虚假大面积缺集误报（如误报“缺失 13..21 集”）。

### 4. 绝对物理安全与 P0 防误删门禁体系
- **P0-1 冗余残留清理安全防御体系**：源端季目录必须为受控源根目录的严格子目录；源端未识别到有效正片集号时（如空壳残渣目录），强制拦截并转人工确认，严禁自动清理；
- **跨库深入文件集数级比对**：穿透归档目标库，断言源端集数全部被归档库包含才允许清理；源端含有增量新集时，强力保护留源；
- **字幕与重要资产终身免死**：清理仅处理明确确认的视频冗余，外挂字幕（`.srt`/`.ass`）和公共资产（`tvshow.nfo`、剧集海报）永久保留。

### 5. MoviePilot 智能补缺与订阅治理双轨分离
- **真缺集精准推送**：根据源端与归档库联合缺集清单，精准向 MoviePilot 发送缺失集号补齐指令；
- **分段综艺与普通剧集差异化处理**：普通剧集标题包含 `Part 1/2` 时，不阻断其他正片缺集检索；
- **两阶段订阅清理与资源核查**：全面核查站点资源与做种情况，提供“仅退订”与“退订并清理源视频”两种清晰操作。

### 6. 响应式现代化极简前端交互 (`index.html`)
- 基于 Tailwind CSS 3 构建，完美支持**浅色/暗黑模式自适应切换**；
- 引入 `localStorage` 任务状态持久化记忆，刷新页面无缝锚定当前任务，消灭首屏闪现跳变；
- 全站 XSS 防御，所有文件路径、剧集标题均通过安全 DOM 节点转义输出。

## 📋 初检诊断决策状态看板

系统根据文件覆盖与元数据状态，将所有扫描季自动分流至 5 大心智决策专区：

| 决策看板卡片 | 状态标识 (`status`) | 触发条件与系统行为 | 推荐操作 |
|:---|:---:|:---|:---|
| **齐备可归档** | 🟢 `archive_ready` | 官方正片全齐无缺集、无未处理重复版本，或跨库汇聚后已全集齐备 | **一键归档**（增量转移至目标库） |
| **真缺集待补** | 🔴 `download_needed` | 官方已完结但本地确有缺集，按真实缺号排列 | **补缺/整理**（推送到 MP 检索下载） |
| **异常剧集** | ⚠️ `split_conflict` / `unknown` | 官方未收录、拆分严重不一致或需人工标记 | **核对/手动处理**（确认后可持久隐藏） |
| **待复核清理** | 🟡 `review_needed` | 本地存在同集多画质版本、或源端残留空壳需人工确认 | **去重/纠偏处置**（画质优选安全清理） |
| **连载留源** | 🔵 `airing` | 官方尚未完结且正片正常连载中 | **追更留源**（保留在源目录等待更新） |

## 🛡️ 绝对零误删物理安全体系

```text
================================================================================
                    MediaFlow 物理数据安全底线规则 (P0-P2)
================================================================================
[P0-1 门禁] 源端路径越界阻断  ->  源目录必须为 MF_SOURCE_ROOT 严格子目录，根路径禁删
[P0-2 门禁] 空壳空集误删熔断  ->  源端识别正片集数为 0 时，绝对禁止误判为已归档残留
[P0-3 门禁] 跨库增量保护防线  ->  源端包含归档库未收录集数时，绝对禁止整剧/整季删除
[P1-1 守卫] 外挂字幕绝对保护  ->  .srt / .ass / .sub 等独有字幕全流程免死，自动迁移
[P1-2 守卫] 媒体资产留源机制  ->  tvshow.nfo / poster.jpg / fanart.jpg 严禁作为冗余清除
[P2-1 仲裁] 画质优先去重算法  ->  4K > 1080p > 720p，HEVC/AV1 > H.264，保留最优版本
================================================================================
```

## 📜 版本演进历史 (Changelog)

### 🚀 最新稳定版：v2.5.16 (2026-11-12)

* **批量补缺选种省容量、站点扩展与整季安全回退优化**：
  * **同做种档内省容量优先**：以本轮最高做种数 $H$ 划分同档边界 $H - \text{seeders} \le \max(1, \lfloor H \times 10\% \rfloor)$，同档内严格按实际需下载总字节升序选种；大小 `0` 或为空视作未知排在已知之后；支持跨站同种去重（保留多站来源）；多集拼包通过 Pareto 剪枝与有界搜索优先最大化覆盖并比总字节（连集包容量仅计一次），日志详列次选体积差；
  * **动态将“天空”“观众”纳入补缺默认搜索**：每次按实例实时读取 MP 默认站点 `IndexerSites` 与站点状态（禁止写死 ID），仅合并已启用有效站并统一传递至 TMDB 精确搜索、标题回退与整季补搜；MP 默认为空代表全站时保留全范围不缩窄，配置读取失败不缩窄且明确标明范围未确认；
  * **散集不全时安全回退整季包并保护已有集**：合格散集能补齐时优先散集；存在未覆盖缺号且同季队列无文件重叠时，优先凭文件清单、完整分集表或显式全集声明严格核验 `1..total_episodes`（拒收仅标 `S03`、缺段综艺或部分已播集），然后触发最多一次原名/别名整季补搜与单次提交；提交前仅清理真实缺号的明确冲突整理记录，绝不传 `episodes=None` 清空全季历史，提交超时先查 MP 下载队列防重。

#### v2.5.15 (2026-11-11)

* **批量一键归档加速、完成判断修正与安全并发体系**：
  * **增量合并完成条件修正（P0）**：显式区分“读取成功且为空”与“读取失败”。当末次读取源季失败时，记为待核实，保存已处理文件并安全保留源季，坚决杜绝误标已归档或误删源目录；
  * **杜绝盲目删除非视频伴生资产（P0）**：同名字幕、NFO、海报可能内容不同，默认两端保留并列出冲突，未知附件严格留源；
  * **归档写入统一启用跳过同名策略（P0）**：整季移动、单文件增量移动及公共资产迁移统一使用 `skip_existing=True`，杜绝任何同名覆盖；
  * **目标多候选安全熔断（P0）**：目标库匹配到多个候选季目录时安全停止，展示候选路径转入人工核实；
