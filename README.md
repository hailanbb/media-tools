## 📌 需求背景与痛点深度解构

在现代家庭影音与私人媒体库实践中，用户通常采用 **「115 网盘 + CloudDrive2 (CD2) 挂载 + MoviePilot 追更 + Emby/Jellyfin 播放」** 的全自动链路。然而，当剧集从“日常追更”流转到“完结归档”的深水区时，现有工作流往往暴露出致命痛点：

### 痛点一：MoviePilot 媒体整理跳过入库（历史记录拦截）
- **现象**：当追更过程由于网络断流或种子做种不足缺失某几集（例如缺第 14 集）时，用户在补缺或重下整季包后，发现新下载的视频**一直停留在下载目录，无法移动或软链接入库**。
- **根本原因**：MoviePilot 依赖数据库中的“转移历史”（Transfer History）。如果该剧集此前曾有过整理记录，MoviePilot 自动整理监控器会判定为**“已整理过”而直接跳过**。
- **MediaFlow 独家解法**：在发起补缺下载前，系统自动评估下载整季还是部分集，联动 MoviePilot API 精准检索该剧该季对应的旧整理历史，**执行「仅删除转移记录」（严格锁定 `deletesrc=false&deletedest=false`，绝不误删物理文件）**。彻底解除拦截，保证新下载剧集 100% 自动入库！

### 痛点二：混版共存误判与误删孤本
- **现象**：当剧集存在不同分辨率/版本（如 1~10 集为 1080p，4~15 集为 2160p）时，传统脚本往往直接判定为集数冲突或在去重时误删唯一存在的剧集。
- **MediaFlow 独家解法**：确立**【混版全集保全第一定律】**——系统优先保障剧集齐备，仅清理在更高画质中完全重叠的冗余版本；任何未在更高规格中出现的低码率孤本（例如仅在 1080p 存在的第 1~3 集）将受到 100% 绝对保护！

### 痛点三：假性拆分冲突与热播连载剧误报
- **现象**：热播连载中剧集（官方计划 40 集，当前更新至 12 集）常被误判为“拆分冲突”或“集数失真”。
- **MediaFlow 独家解法**：实时结合 TMDB 连载状态与最后活跃日期，区分“已完结真实缺集”与“连载热播更新中”，绝不误扰用户注意。

### 痛点四：归档源端残留与废弃目录堆积
- **现象**：将完结剧集从追更库归档到完结库后，源目录遗留下大量空目录、废弃的 `tvshow.nfo` 和海报，造成网盘目录臃肿凌乱。
- **MediaFlow 独家解法**：实现全自动化**增量单季搬移**与**全剧零残留清理**。归档完成后，若源端已无其他有效剧季，自动深度清理残留空文件夹与元数据，实现真正的物理零残留！

## ⚡ 极速上手

### 1. Windows 原生版快速启动
1. 确保安装了 **Python 3.10+**（安装时勾选 `Add python.exe to PATH`）。
2. 进入 [`mediaflow-win`](mediaflow-win/) 目录，双击 **`start.bat`**。
3. 首次启动会自动生成 `.env` 模板，在记事本中填写 CloudDrive2 和 MoviePilot 密钥后保存。
4. 再次双击 `start.bat`，系统将自动拉起服务并在浏览器中打开控制台：`http://127.0.0.1:8080`。

### 2. Docker 容器版极速启动
1. 进入 [`mediaflow-docker`](mediaflow-docker/) 目录。
2. 复制配置文件：`cp .env.example .env`，填入你的服务地址与 Token。
3. 一键启动容器：
   ```bash
   docker compose up -d --build
   ```
4. 浏览器访问：`http://<NAS_IP>:8080`。

## 🖥️ 核心业务操作说明

MediaFlow 界面采用直观的驾驶舱交互布局，将复杂的媒体库治理化繁为简：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        MediaFlow 驾驶舱控制台                          │
├───────────────┬────────────────────────────────────────────────────────┤
│  [新建任务]   │  [真缺集待补 (1)]  [待复核清理 (2)]  [可归档就绪 (5)]  │
│  选择挂载路径 │  [连载更新中 (8)]  [异常待定 (0)]                      │
├───────────────┴────────────────────────────────────────────────────────┤
│  • 香港探秘地图 (2026) [tmdbid=277870] - S01                           │
│    状态: 缺 1 集 (E14)  [做种≥2 优质源检测]                             │
│    操作: [推送补缺] ➔ 自动解绑旧转移记录 ➔ 提交下载                    │
│                                                                        │
│  • 少年，注意 (2026) [tmdbid=322723] - S01                             │
│    状态: 全集 24/24 已齐备                                             │
│    操作: [单季归档] ➔ 增量剪切搬移 ➔ 源端零残留清理                    │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 任务创建与极速初检
- 点击左上角“新建任务”，通过内置的 CloudDrive2 目录树选择任意待整理网盘路径。
- 启动初检，系统将深度扫描目录结构、解析集号格式，并对齐 TMDB 官方季集标准。

### 2. 真缺集智能补缺流程
- 点击“真缺集待补”分类下的剧集“推送补缺”按钮。
- **流程全自动化**：
  1. **资源优选**：根据做种数（≥2）与清晰度梯队（1080p/4K 优选）评分。
  2. **能效评估**：评估下载整季包更优还是单集补齐更优。
  3. **转移历史解绑**：自动请求 MoviePilot 转移历史，**仅清除冲突转移记录**（不删文件），避免跳过整理。
  4. **提交下载**：任务送入下载队列，等待完成后即可自动入库。

### 3. 复核清理（混版去重）
- 在“待复核清理”中，系统呈现重复集与不同版本明细。
- 点击“清理冗余”，系统遵循【孤本保全第一定律】：高码率集替换低码率集，孤本集绝对保留，清理后自动进入“可归档就绪”。

### 4. 单季/全剧零残留归档
- 点击“单季归档”，选定季度的所有视频文件将完整剪切至目标归档库。
- 若源端已无其他有效季度，系统将自动清除空目录、废弃海报和 `tvshow.nfo`，彻底做到源端干净无残留。

### 5. MoviePilot 智能订阅运维双轨分离
- 在“订阅管理”页中，系统智能区分电视剧与电影：
  - **电视剧**：全季完结且集数已齐备 ➔ 高置信度建议安全退订；热播连载中 ➔ 绝对拦截保护。
  - **电影**：已完结入库 ➔ 允许清理；下载中/待映 ➔ 坚决拦截保护。

## 🛡️ 架构设计与工程质量保证

### 1. 安全不变量红线（Safety Invariants）
- **绝不误删物理文件**：向 MoviePilot 调用 `DELETE /api/v1/history/transfer` 时，强行断言并传递 `deletesrc=false&deletedest=false`，绝不因误传参数破坏原盘与媒体库。
- **孤本保全绝对优先**：任何清理算法必须在保证集数完整度的前提下执行，集数齐全永远优先于清理冗余。
